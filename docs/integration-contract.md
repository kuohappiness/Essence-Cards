# Essence Cards｜文件交接與整合約定

版本：0.1
更新日期：2026-10-07（Asia/Taipei）
狀態：依 C-022，第一階段須保留可整合邊界；以下是交接設計草案，欄位名稱、檔案配置與程式介面尚未定案，尚未實作或驗收。

## 兩邊的責任

第一階段的 Essence Cards 接受既有筆記及手動／既有卡片，製作與使用材料、保存學習事件並提供檢核。第二階段的獨立來源整理工具取得來源、整理 AI 候選、人工核對並保存可讀文件。兩邊透過文件約定交接，不要求同時執行，也不共用所有可變內部狀態。

現階段先以使用者選擇文件的交接方式為候選；之後可增加一鍵傳送或任務 API。獨立輸入工具的宿主、介面及 repo 分法未定，不能把 Obsidian、雲端服務或特定模型當作它的已確認必要條件。Essence Cards 的第一版仍依 C-014 使用 Obsidian。

## 最小交接資訊｜助理提案

| 資訊 | 交接用途 | 設計邊界 |
|---|---|---|
| 可讀正文 | Markdown 筆記作為整理成果，也可供製作教材 | 可獨立閱讀；一般筆記可接入，不要求先填滿學習欄位 |
| 文件識別 | 判斷重複交接與後續版本 | 不只依檔名辨識；既有筆記缺少 ID 時可在採用端建立，方法待議 |
| 來源參照 | 回到原始網址、文件或原文片段核對 | 頁碼／時間點在有資料時保留；未知或失效須明示，不編造定位 |
| 必要附件 | 保存圖片與其他理解內容所需的檔案 | 路徑需能隨文件移動；缺少附件時明示並保留採用前核對 |
| 文件與交接版本 | 區分內容新版與交接格式變更 | 採用的材料可追溯依據版本；格式不相容時先說明，不能默默誤讀 |
| 整理／採用狀態 | 區分 AI 候選、已核對文件及已用於學習的內容 | 核對筆記不等於已核對所有衍生題目；不自動製卡或加入複習 |

上述資訊是語意上的約定，並未選定 YAML 欄位、JSON schema、資料夾或資料庫。純筆記可以保持簡單；採用端補齊必要關聯，不強迫來源工具保存學習事件或排程資料。

## 採用、更新與修訂

1. Essence Cards 讀取交接資料，核對可讀性、來源、附件與版本；讓使用者選擇要採用的內容。
2. 首次採用保留文件識別與依據版本，再依需求製作材料或補上概念關聯；已有材料可直接使用，不依賴來源工具。
3. 同一文件再交接時，區分重複內容與新版。新版列出可能受影響的材料，核對後採用，不清空舊卡片、學習進度或作答事件。
4. 兩邊保留各自人工修訂。來源工具重新轉換、Essence Cards 檢核回寫或重複匯入，都不能無提示覆蓋另一邊的新修改；衝突時由使用者比對及選擇。
5. 跨工具的修訂以「文件識別、依據版本、建議內容及理由」交接，由接收端核對後更新；不直接改寫另一邊的內部資料。尚未開發來源工具時，Essence Cards 仍可在已有筆記／材料上完成核對與修訂。

共用知識基礎仍依 C-011 保留：同一工作區的材料引用可核對的筆記，不在不同介面各維護一份未追蹤的知識副本。跨工具是否引用相同實體檔案或採用版本副本待資料設計確認；資料所有權與版本關係必須明確。

## 第一階段先驗整合能力

輸入工具尚未完成時，使用手動準備的交接樣本檢查接收端。樣本格式在規格確認後建立，不以第二階段的程式作為第一階段驗收先決條件。

| 情境 | 驗收方向 |
|---|---|
| 一般既有筆記 | 不安裝輸入工具也能選用正文，補上需要的來源／識別並製作或使用材料 |
| 含圖片的交接文件 | 必要附件可讀；缺失明示，搬移後仍能核對連結 |
| 同一份文件再次交接 | 不無聲產生重複資料，原卡片與進度保留 |
| 文件新版或人工修訂 | 顯示差異及材料影響，由使用者選擇更新；舊事件仍能理解 |
| 未知格式版本或來源失效 | 說明哪些資料不能採用或追溯，不假裝整合成功 |
| 接上第二階段工具 | 真實整理成果能沿用第一階段約定；來源工具停止後，已有材料仍可複習與檢核 |

這些是待實作的設計驗收情境。正式跨裝置事件、併發、備份與回復仍另依 P0／F-018 驗證，文件交接通過不能取代完整保存驗證。
