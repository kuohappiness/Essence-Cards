# Essence Cards｜開發原則與品質目標

集中保存使用者對開發方式與軟體品質的期待，作為輸入、輸出、檢核及共用核心的參照。功能點子仍放入[點子收集箱](ideas.md)，已確認原則由[共識 C-021](consensus.md#c-021-開發協作與跨模組品質目標已確認)連到看板；討論經過另存。

## P-001 主動提出不同建議｜已確認

使用者原意：如果助理有不同的建議，可以主動提出。

協作方式：發現較好的作法、需求衝突或重要取捨時，主動說明建議、理由與影響；建議與已確認結論分開記錄，不把新提案直接當作使用者已採用的決策。

## Q-001 程式碼盡量簡潔｜已確認目標

使用者原意：希望程式碼能夠盡量簡潔。

助理提案：以容易閱讀、維護及修改為優先，減少重複邏輯、不必要的相依套件與尚無需求的抽象；共用核心只承載當前模組需要的能力。程式行數不單獨作為簡潔的衡量方式，必要的資料保存與同步處理仍需保留。

待釐清：哪些相依套件與抽象具有實際價值？每個模組交付時如何檢查維護負擔？以上具體做法尚未逐項確認。

## Q-002 手機與電腦都能流暢使用｜已確認目標

使用者原意：用手機跟電腦都能夠流暢。

適用範圍：依 C-014 的 Windows／iPhone 與 C-020／C-022 的三種責任、兩工具及兩階段方向，檢查各裝置所支援的使用情境；流暢目標不表示手機必須具有所有電腦功能。

助理提案：每次交付可用功能時，以小型與較大量的真實資料，在實際裝置檢查開啟、切卡、作答、儲存與同步中的互動。耗時工作考慮分批處理及進度回饋；具體技術與數值門檻尚未選定。

待釐清：測試裝置、資料規模、可接受等待時間及耗時工作的回饋方式。先前最小原型通過不代表正式功能的效能已通過。
