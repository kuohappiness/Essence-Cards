## 下一次對話從這裡開始

依序處理，一次一題（[本輪討論紀錄](archive/discussions/2026-10-10-old-plugin-followups.md)）：

1. **舊外掛分析剩下的待討論題**（[§9](research/old-flashcard-plugin.md#9-待討論)）：
   - ~~一行多個填空~~ ✅ 一行＝一題，一次全挖（D-049）
   - ~~反向與雙向語法~~ ✅ 不沿用 `;;`、`:::`、`{{fc}}`，每個方向各寫一行（D-050）
   - ~~介面技術~~ ✅ React 加 Motion、純 CSS 與自己的設計規範（D-051、D-052）
   - ~~開發流程~~ ✅ 三段式、Retrospective、CI、一鍵安裝、分層檢查；AGENTS.md 只寫真正需要的（D-053）
   - ~~匯入舊外掛~~ ✅ 卡片與進度都不匯入（D-054）
   - 卡片管理介面要做到什麼程度。💡 助理看法：
     - v1 不做完整的卡片庫。卡片就寫在卡組筆記裡；Obsidian 的檔案樹、搜尋、標籤與 Bases（依屬性列出筆記的表格）已能瀏覽與篩選卡組。
     - 只做一個小的「總覽」，放 Obsidian 算不出來的東西：今天要複習幾張、待審核的草稿卡組、考試範圍、常錯的卡。
     - 完整的管理與儀表板留到之後（D-024）。
2. **複習與檢核細節**的十二個問題（[backlog](backlog.md#複習與檢核細節v1-範圍確定後展開)），包括自評段數，以及「一課 40 個單字每天快速翻一遍」的情境
3. **成功標準的量測方式**
4. **出題語法定稿**：把 D-045、D-046 與上面的結論寫成正式規範

另一條專題討論：**AI 規劃**（[紀錄](archive/discussions/2026-10-11-ai-planning.md)），待決題目見 [backlog](backlog.md#ai-規劃2026-10-11-起的專題討論)。
