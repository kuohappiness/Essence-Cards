## 使用方式與確認邊界

使用者已同意以知識學習架構藍圖為參考，逐項從功能切入，先建立目錄，再從來源資料匯入與管理開始。每輪聚焦一個核心問題，功能討論仍須檢查前後資料與完整使用情境。

下列 ID 是穩定的討論索引，不是固定流程編號，不要求按表依序操作；功能可合併、拆分或重新排序。拆分後給予新 ID，保留原項目的去向。表中的候選優先級是助理建議，並非使用者確認的第一版範圍：

- 起步候選：建議先討論其最小形式，支撐來源、概念與學習紀錄的連接。
- 簡化候選：建議評估第一版是否只提供手動或基本功能。
- 深化候選：完整能力較適合後續評估，不代表第一版完全排除。
- 基線驗證：沿用技術路線圖的 P0 驗證需求，不表示能力已通過。

討論順序與開發順序分開；P0 的真實裝置、同步、離線事件及回復驗證保留，不因開始功能討論而視為通過。

## 每個功能的討論紀錄骨架

以真實操作情境開始，逐步填寫以下內容，不要求使用者一輪回答所有欄位：

- 使用者目標與例子。
- 已確認方向、助理提案與待驗證假設。
- 輸入、產出與保留的資料。
- 操作流程、電腦／手機分工與 AI 介入邊界。
- 與前後功能的關係。
- 重複執行、失敗、內容修改與版本處理。
- 第一版候選範圍、後續候選及完成標準。
- 本輪的一個核心問題、回答與待決項目。

沒有結論的欄位明列待討論，不以助理預設代替使用者確認。

## 完整情境檢查

助理建議選同一份使用者願意用來驗證的教材，檢查下列路徑。實際教材尚未選定，也未進行試用：

- 來源 → 選取 → 概念筆記 → 記憶卡 → 作答紀錄 → 複習安排。
- 既有筆記 → 概念關聯 → 題目 → 錯因確認 → 補強與核對後修訂。
- 匯入真題 → 補上概念關聯 → 作答；不強迫先重新製作全部筆記。
- 筆記修訂 → 提示受影響材料 → 使用者核對 → 保留舊作答紀錄。
- 手機離線作答 → 回存 → 電腦讀取；事件保留與個別回復由 P0 另行驗證。

每完成一組相連功能，就檢查資料是否接得上、是否要求重複輸入，以及回饋是否能帶到具體的下一個操作。
