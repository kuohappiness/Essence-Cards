## 使用方式與確認邊界

使用者已同意以知識學習架構藍圖為參考，逐項從功能切入，先建立目錄，再從來源資料匯入與管理開始。每輪聚焦一個核心問題，功能討論仍須檢查前後資料與完整使用情境。

下列 ID 是穩定的討論索引，不是固定流程編號，不要求按表依序操作；功能可合併、拆分或重新排序。拆分後給予新 ID，保留原項目的去向。表中的候選優先級是助理建議，並非使用者確認的第一版範圍：

- 起步候選：建議先討論其最小形式，支撐來源、概念與學習紀錄的連接。
- 簡化候選：建議評估第一版是否只提供手動或基本功能。
- 深化候選：完整能力較適合後續評估，不代表第一版完全排除。
- 基線驗證：沿用技術路線圖的 P0 驗證需求，不表示能力已通過。

討論順序與開發順序分開；P0 的真實裝置、同步、離線事件及回復驗證保留，不因開始功能討論而視為通過。

## 討論順序與共用規則

目前仍先釐清 F-001 的主要來源；以下按實際使用情境安排討論批次，可依回答調整，不是固定操作步驟：

| 討論焦點 | 一起檢查的功能 | 需要釐清的連接 |
|---|---|---|
| 來源、選段與概念 | F-001／F-002／F-003，加上 F-016／F-018 的最小規則 | 識別與定位、保存依據、收藏用途；來源失效如何明示 |
| 少量材料與作答 | F-006／F-007／F-009／F-010，連到 F-015 | 候選預覽、採用、回看原文後返回；獨立／提示後作答如何記錄 |
| 手機疑問與電腦修訂 | F-019／F-011／F-012／F-016 | 分類、核對、影響清單、處理及結案，舊紀錄保留 |
| 複習安排與負擔 | F-013，回查 F-009／F-010 | 協助與練習模式的影響，新卡、積欠、份量及同源題規則 |
| 進一步整理、教材與復盤 | F-004／F-005／F-008／F-014 | 比較、架構、互動材料及學習計畫的必要程度 |
| AI 與資料保護的深化 | F-017／F-018 | AI 接入人工操作、完整備份、個別回復及測試門檻 |

F-018 的基線驗證與各功能的保存要求持續進行；以上最後一列指深化討論，不將 P0 或最小保存規則延後。

## 內容狀態與待處理事項

使用者已同意把下列區分納入設計。具體欄位、名稱、轉換條件與是否需要每種狀態，仍在各功能細化：

| 對象／面向 | 要區分的行為 | 待細化重點 |
|---|---|---|
| 來源用途 | 收藏、選取整理或用於學習 | 收藏不自動製卡或加入複習；可稍後處理 |
| 材料採用 | 候選草稿、核對後採用 | 採用前查看題目、答案、依據與測試目標；已有真題可直接核對 |
| 材料使用 | 啟用、暫停或待核對 | 採用與是否排程是不同面向；修改或疑義如何影響使用待議 |
| 作答條件 | 獨立作答、提示後回答或看過答案 | 保存協助及練習模式，不能直接當作同一種正確紀錄 |
| 待處理原因 | 學習需要補強、內容可能有誤 | 一般忘記可只安排複習；核對前不自動判定題目無效 |
| 處理進度 | 提出、核對、處理與結案 | 詳細狀態及重新開啟方式見 [F-019](functions/issue-queue.md)，尚未定欄位 |

以上是不同對象與面向，不將所有內容強制塞入單一路徑或要求每次填完所有欄位。

## F-018 的保存用途分項

保留 F-018 作共同入口，以下是其子議題，不更換既有 ID：

| 用途 | 驗收情境方向 | 與其他用途的邊界 |
|---|---|---|
| 跨裝置同步 | 電腦內容及必要附件可在手機讀取；手機離線事件回到電腦後仍保留 | iCloud 的實際能力由 P0 驗證；同步不等於保有歷史版本 |
| 可讀匯出 | 匯出筆記／表格後仍可閱讀，並明示哪些資料未保留 | 可讀或交換格式不自動承諾完整回復 |
| 完整備份 | 在隔離位置回復附件、ID、關聯、題目版本與事件，再檢查遺漏 | 具體格式及完整性門檻待定，不只確認文字存在 |
| 個別回復 | 救回指定筆記／材料後核對關聯，保留較新的作答與待處理事項 | 保留 Git 的已 commit／已 push 邊界；未保存版本不宣稱可救回 |

## 每個功能的討論紀錄骨架

以真實操作情境開始，逐步填寫以下內容，不要求使用者一輪回答所有欄位：

- 使用者目標與例子。
- 研究對應與採用理由；區分官方能力、研究推論與本案決策。
- 最小人工操作方式；先確認沒有 AI 時如何完成，AI 接入另議。
- 已確認方向、助理提案與待驗證假設。
- 輸入、產出與保留的資料。
- 操作流程、電腦／手機分工與 AI 介入邊界。
- 與前後功能的關係。
- 重複執行、失敗、內容修改與版本處理。
- 第一版候選範圍、後續候選及完成標準。
- 具體驗收情境、觀察方式與仍未決的門檻；不以抽象的「支援」代替。
- 本輪的一個核心問題、回答與待決項目。

沒有結論的欄位明列待討論，不以助理預設代替使用者確認。

## 完整情境檢查

助理建議選同一份使用者願意用來驗證的教材，檢查下列路徑。實際教材尚未選定，也未進行試用：

- 來源 → 選取 → 概念筆記 → 記憶卡 → 作答紀錄 → 複習安排。
- 既有筆記 → 概念關聯 → 題目 → 錯因確認 → 補強與核對後修訂。
- 匯入真題 → 補上概念關聯 → 作答；不強迫先重新製作全部筆記。
- 筆記修訂 → 提示受影響材料 → 使用者核對 → 保留舊作答紀錄。
- 手機作答 → 回看依據並回原題 → 標記補強需求或內容疑義 → 電腦核對 → 修訂與影響清單 → 結案或安排再練習。
- 獨立作答與提示後作答分開記錄；核對誤題後保留原事件，評量與排程處理另行驗證。
- 手機離線作答 → 回存 → 電腦讀取；事件、待處理事項與個別回復由 P0 另行驗證。
- 可讀匯出 → 檢查保留範圍；完整備份 → 隔離還原；單檔救回 → 保留較新紀錄。

每完成一組相連功能，就檢查資料是否接得上、是否要求重複輸入，以及回饋是否能帶到具體的下一個操作。
