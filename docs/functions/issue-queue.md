# F-019｜學習疑問與待處理佇列

## 使用者目標與已確認方向

在手機複習時留下可處理的問題，回到電腦能找到相關題目、概念、來源及當時紀錄，進行核對、補強或修訂，再追蹤至結案。

使用者已同意新增這個獨立功能討論單位，並保留兩類原因：

- 學習者需要補強：例如概念易混淆、想補例子或不會應用。
- 內容可能有誤：例如題意不清、答案有疑問或來源定位失效。

一般忘記可以只交給複習安排，不預設每次答錯都建立待處理事項。提出內容疑義不立即判定題目無效，也不刪除原作答紀錄。

## 責任與功能邊界

| 功能 | 負責的內容 |
|---|---|
| F-009／F-015 | 在作答或回看時提出問題，保留返回原題與進度的位置 |
| F-010 | 保存當時作答事件；待處理事項可引用事件，不能取代它 |
| F-011 | 核對學習缺口與可能錯因，資料不足時保留未知 |
| F-019 | 保存問題、原因、相關位置與處理進度，讓問題可被找到及追蹤 |
| F-012 | 執行補強、訂正與核對後回寫，將處理結果連回問題 |
| F-016 | 保存版本及列出可能受影響的材料，供逐項核對 |
| F-018 | 處理待處理事項的保存、同步、備份與回復，真實能力需驗證 |

## 研究對應與採用理由

U-02 提供手機標記、電腦集中核對的候選；U-06 提供反覆答錯的補強入口；U-09 提供修訂後材料影響的接續方向。

採用獨立討論單位的理由：原先分散在作答、紀錄與訂正中的責任，需要明確交接，才能避免問題留下後無人核對或找不到當時內容。參考能力與本案推論見研究文件；未宣稱已驗證學習效果。

## 最小人工操作方式｜細節草案

- 手機從當前材料標記疑問或補強需求，短註可選填；需要的 ID、版本及位置由工具保留。
- 電腦查看待處理事項，開啟相關材料／來源，判斷是補強、修訂或不需變更。
- 人工補例子、比較、修題或安排練習；涉及內容正確性的修改先核對。
- 查看可能受影響的材料，保留、修訂或暫停的操作方式另議。
- 記錄處理結果，結案或保留待處理；重新開啟方式待定。

此流程先討論人工操作，AI 可後續協助分類及草擬，並非每次處理的必要依賴。疑似錯誤是否能暫停題目、何時重新啟用，仍待確認。

## 狀態與欄位候選｜未決

候選進度為待處理、核對中、已處理或不採用；具體名稱、重新開啟及轉換規則未決。處理進度與原因、材料啟用狀態各自記錄，不能因問題結案就自動啟用或刪除題目。

候選資料包括問題 ID、原因、可選短註、材料／概念／來源關聯、提出時版本與相關事件、進度與處理結果。哪些是必要欄位、由工具自動填入哪些資料，以及如何以 Markdown／事件保存，需配合 F-016／F-018 設計。

## 具體驗收情境｜待確認門檻及實測

| 情境 | 預期要檢查的行為 |
|---|---|
| 手機發現答案疑問 | 標記後仍能回原題，繼續複習；電腦找到同一問題及提出時的依據 |
| 手機發現概念混淆 | 以補強需求呈現，不自動判定題目有誤；可連到比較或變式練習 |
| 電腦核對修訂 | 處理結果可追溯到修訂與影響核對，舊作答仍保留當時題目脈絡 |
| 核對後不需修改 | 可留下理由並結案，問題與原事件仍可追溯 |
| 來源或材料改名／移動 | 問題仍能關聯到內容；定位失效時明示，不能默默跳到別處 |
| 手機離線標記與後續同步 | 回到電腦後問題與作答皆保留；併發及重複事件由 P0／F-018 驗證 |
| 個別檔案回復 | 較新的待處理事項與作答不因救回舊筆記而被覆寫 |

這些是應討論的驗收情境，尚未確認資料格式、性能門檻或通過實機測試。

## 待討論的核心問題

本功能在來源與基本製卡／作答之後細化。屆時先問：手機上哪些最少的標記選項足以讓電腦知道下一步該核對或補強什麼？不要求使用者在每次作答填寫完整診斷問卷。

其他未決：多個問題是否合併、重複提出如何處理、跨裝置同時標記如何合併、問題與內容不同步時如何顯示，以及題目確認有誤後統計與排程如何重算。
