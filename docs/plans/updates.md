# Essence Cards｜更新與相容

狀態：✅ 已定案（2026-10-28，[D-149](../decisions.md#d-149-更新與相容版本紀錄讀取閘門與正式安裝)、[D-150](../decisions.md#d-150-備份與還原)、[D-151](../decisions.md#d-151-內建製卡規則改版內建跟著外掛改了就是自訂版)）；[更新防線](../../tasks/update-safeguards.md)已完成（2026-10-29，`0.1.0`）；下一步是外掛內的備份與還原

[v1 任務入口](../backlog.md#v1-需要做的任務)｜[文件存放規則](README.md)｜[討論稿](<../../Claude Codex Discussion/2026-10-28-updates-and-compatibility.md>)（Claude 與 Codex 三輪，含所有反例與理由）

使用者 2026-10-25 在專案討論串「規劃 Essence Cards 更新功能」開題，2026-10-26 確認範圍是三件事：

1. 新版程式怎麼送到電腦和 iPhone，出問題時怎麼退回。
2. 更新時卡組、複習紀錄、排程和設定不壞、進度不丟（資料相容）。
3. 內建製卡規則與科目預設改版時，家長改過的規則和已有的卡組怎麼辦。

不在範圍：課本改版或轉錄稿更新（[D-008](../decisions.md#d-008-學習紀錄與來源修改)，只提示不自動改卡）、AI 模型推薦的更新（[模型自動更新](ai-and-ecosystem.md#發音檢查與語音模型)）、學習地圖的調整（[D-136](../decisions.md#d-136-學習地圖課本是起點加深可以超出課本)）。Obsidian 自己的改版見 [D-138](../decisions.md#d-138-obsidian-出新的次版本時做一次相容性檢查)。

**北極星**：更新的價值是把更好的規則、修好的錯送到學生手上；最大的風險是更新本身打斷複習、讓排程亂掉或弄丟進度。**改進送得到，複習不中斷，進度不會丟。**

## 實作順序

1. **更新防線**（[任務說明](../../tasks/update-safeguards.md)）：✅ 2026-10-29 完成，第一個正式版 `0.1.0`（tag `v0.1.0`）已裝到正式使用的 vault。
2. **外掛內的備份與還原**（D-150 第 1～8 點，含 D-148 的主機接點）：[任務說明](../../tasks/plugin-backup.md)已寫，分備份與還原畫面兩部分，還原畫面放到 v1 結案前（使用者 2026-10-29），在那之前由 AI 用還原工具代做；更新命令的備份要不要拿掉（它也是發布前比較的凍結輸入），在外掛內備份裝到正式 vault 之後問使用者。
3. 設定頁開工時：D-149 第 7 點的設定保存規則。
4. AI 製卡模組開工時：D-151 的規則分層與自訂版。
5. 第一個不相容的寫法（例如 D-136 的課外層標法）上線時：「需要哪一版」的寫入端，照兩段發布。
6. 第二階段（給其他家庭之前）：GitHub Release、BRAT、上架社群外掛、外掛裡「這次更新了什麼」的畫面、改用測試 vault 做發布前比較、考前提醒移到設定頁。

## 更新前的備份

已定案，見 [D-150](../decisions.md#d-150-備份與還原)：外掛在電腦上自己備份到本機（新版改寫前、每月一次、隨時手動），使用者不用 Git、不用命令列；失敗時學生照常複習、Cards 先不改寫卡組；還原逐檔看差異，紀錄只補不刪。過渡期間由更新命令在安裝前代做（[更新防線](../../tasks/update-safeguards.md)）。這一節保留給舊連結。
