# Essence Cards｜更新與相容

[v1 任務入口](../backlog.md#v1-需要做的任務)｜[文件存放規則](README.md)

💬 討論中：使用者 2026-10-25 在專案討論串「規劃 Essence Cards 更新功能」開題，2026-10-26 確認範圍是三件事：

1. 新版程式怎麼送到電腦和 iPhone，出問題時怎麼退回。
2. 更新時卡組、複習紀錄、排程和設定不壞、進度不丟（資料相容）。
3. 內建製卡規則與科目預設改版時，家長改過的規則和已有的卡組怎麼辦。

不在範圍：課本改版或轉錄稿更新（[D-008](../decisions.md#d-008-學習紀錄與來源修改)，只提示不自動改卡）、AI 模型推薦的更新（[模型自動更新](ai-and-ecosystem.md#發音檢查與語音模型)）、學習地圖的調整（[D-136](../decisions.md#d-136-學習地圖課本是起點加深可以超出課本)）。Obsidian 自己的改版見 [D-138](../decisions.md#d-138-obsidian-出新的次版本時做一次相容性檢查)。

**北極星**：更新的價值是把更好的規則、修好的錯送到學生手上；最大的風險是更新本身打斷複習、讓排程亂掉或弄丟進度。設計目標：**改進送得到，複習不中斷，進度不會丟。**

**時機**：W6 合併後，學生就會開始每天真的使用，之後 AI 製卡、範圍與目錄、Capture 還會一版一版加上去。下面標「v1」的提案要在那之前做好；有些事只能在早期版本做（舊版不會自己學會面對新版的資料，當下沒記的版本也補不回來）。

## 已定

- ✅ 使用說明書要有一章詳細教使用者怎麼更新外掛（[D-048](../decisions.md#d-048-使用說明書) 補充 2026-10-26）。
- ✅ Obsidian 出新的次版本時，由維護的 AI 做一次相容性檢查（[D-138](../decisions.md#d-138-obsidian-出新的次版本時做一次相容性檢查)）。

## 現況

- 安裝：電腦跑 `npm run install-vault`，把 `main.js`、`manifest.json`、`styles.css` 複製到 vault 的外掛資料夾，iCloud 同步到 iPhone；打 git tag 記版本，GitHub Release 等有其他使用者再做（[D-053](../decisions.md#d-053-開發流程)）。目前 `manifest.json` 是 0.0.1，repo 還沒有 tag。
- 格式：公開格式只新增欄位、不改舊欄位的意思，讀取時忽略不認得的欄位與屬性（[syntax.md](../syntax.md) 開頭）。
- 排程不存檔，每台裝置每次從全部紀錄重算，v1 沒有快取（D-035、D-110）；補 ID 與存檔只在電腦，iPhone 只寫自己的紀錄檔（D-134）；每次作答立刻寫入（D-074）；AI 快照記規則版本與雜湊（D-042、D-115）。

## 注意事項與提案

標 💡 的是 Claude 2026-10-25 的提案，尚未決定。

1. **iPhone 和電腦會有一段時間跑不同版本**：iPhone 要等 iCloud 同步完、Obsidian 完全關掉重開才換，iOS 讓 Obsidian 在背景掛好幾天很常見；iCloud 也可能先到 `manifest.json`、`main.js` 還沒到，「版本」命令顯示新版號、跑的卻是舊程式。
   - 💡 v1：每台裝置第一次跑新版時，在自己的紀錄檔寫一行 `{"t":"…","set":"app","val":"0.4.0"}`，版本號在建置時寫進 `main.js`（不讀 `manifest.json`）。現在的 `parseLine` 已把不認得的 `set` 當成變更、排程不讀，舊版讀到不會出事。用途：電腦看得到 iPhone 實際跑哪一版；回測時知道每筆作答是哪一版程式排的（D-105、D-115 同一個道理）。
2. **舊版讀新資料：讀錯比讀不懂更糟**。「忽略不認得的欄位」只在新東西不改變舊東西的意思時安全。
   - 例：D-136 的課外層目標要算延伸（[技術債](../backlog.md#技術債)）。新版加上標法後，還沒更新的 iPhone 看不懂，就把課外層目標當成課本內容，考前優先出、用 90% 排。
   - 例：W6 讓中翻英的答案格用 ` | ` 分開好幾個正確答案；假如這是 iPhone 用了幾個月才加的，舊版會把整串當成一個答案，打對也判錯。
   - 💡 v1：新語法「先讓每台裝置都換成讀得懂的版本，再開始寫」，一家人用時靠第 1 點的版本紀錄確認。第二階段（給其他家庭之前）：紀錄與卡組加上「需要哪一版才讀得懂」的標記，舊版遇到就跳過那一筆、提示更新，不猜。
   - 💡 永遠不改：學習目標 ID 的格式、題目指紋的算法、紀錄的時間格式與檔名、清晨 4 點換日。W6 讓 ` | ` 拆開後指紋仍照整個答案格算，就是在守這一條。非改不可時，新版要同時認得新舊兩種。
3. **排程每次重算：不必搬資料，但會回溯**。改排程、佇列或升級 ts-fsrs 的更新，會一次改掉所有卡的到期日；兩台裝置版本不同時排出的份也不同。
   - 💡 v1：改到 `src/core/study/` 或升級 ts-fsrs 時，發布前用真實紀錄比較新舊版的今天的份與未來 30 天每天到期數，差異寫進更新說明。ts-fsrs 維持釘死版本，升級當成產品決定。之後若加排程快取（D-110），快取記下產生它的程式版本，版本不同就整個重算。
4. **新版的解析可能讓卡消失或多出來**：D-135 這類修正會讓新舊版讀出不同的目標與題目。新版讀不到的目標會安靜地不再出題（紀錄還在）；多認出來、沒有 ID 的目標存檔時配新 ID、從頭複習。D-134 的保護只比對同一次載入，換版重開後兩種都不會被發現。
   - 💡 v1：發布前的解析差異報告。用 Node 版的檔案存取（D-110）在家長的電腦上讓新舊兩版各讀一次真正使用的 vault，比對每篇卡組的目標 ID、題目指紋與問題清單，每個差異都要是預期的。私人資料只在本機讀，報告不進 repo（D-003）；AI 能做。
5. **寫回筆記與搬資料**：
   - 💡 新版不在載入時自動改寫全部卡組；要改舊筆記的寫法時，只在電腦、家長按按鈕、先看會改哪些、先備份、改完記一行紀錄。紀錄檔永遠不改寫（D-035），舊紀錄怎麼解讀由新版的讀取程式負責。
   - 💡 寫設定頁時：`data.json` 會跟著 iCloud 同步，讀的時候補預設值，存的時候保留不認得的欄位（不然舊版的 iPhone 存一次就把新版的設定洗掉）；只存使用者改過的值，預設值改了才會生效，生效時照 D-105 記一行 `set`。
6. **出問題時能退回**：
   - 💡 v1：每次裝到真正使用的 vault 都升版號、打 tag、保留上一版的建置；退得回去的前提是第 2 點。安裝前備份 `Essence Cards/`（iCloud 不是備份，刪除也會同步），和 backlog 的「Git 備份與回復策略（舊 T-009）」一起定。開發版只裝測試 vault（W5 第二部分的 L2 找到開發版的 `save` 在 iPhone 改得動卡組）。
   - 💡 考前不更新：考試範圍有考試期間（D-098），段考前幾天到考完不裝新版到學生用的 vault，安裝程式讀考試範圍自動擋下。
   - 💡 以上包成一個命令（例如 `npm run update-vault`）：檢查 → 備份 → 考前檢查 → 建置正式版 → 安裝 → 提醒重開 iPhone 的 Obsidian。
7. **內建製卡規則與科目預設改版**（原 backlog「內建規則改版時，家長改過的規則檔怎麼處理」，AI 製卡模組開工前要定）：D-020 讓規則存在 vault 的 Markdown、家長可以改；外掛帶來新規則時，不能蓋掉家長改過的，也不讓已有的卡組自動重做。
   - 💡 內建的三層（通用、知識類型、科目預設）跟著外掛，vault 只放家長調整那一層；想看內建規則時放一份標明「更新時會被覆蓋」的唯讀副本。家長真要改內建層，就複製成「自訂版（基於 通用 v0.13）」，這一層從此不自動更新；新版出來時「給家長」提示並附差異，家長選留著、換新或請 AI 合併。
   - 已有的卡組不因規則更新重做（D-008 的精神），新規則用在新的製卡與之後的加深；哪張卡出自哪一版規則，快照查得到。第三輪後重整成「共用核心＋模組」時，版本以模組為單位。
8. **兩個外掛之間**：Capture 和 Cards 各自更新，轉錄稿格式是唯一接點（[syntax.md §1](../syntax.md#1-轉錄稿)），同樣只增不改。💡 Capture 開工時，轉錄稿屬性多記轉錄程式的版本。
9. **給其他家庭與獨立 App（第二階段）**：GitHub Release、`versions.json`、BRAT 測試版，最後上架社群外掛（先過 G1 的授權與條款）；別人的裝置何時更新管不到，第 2 點的「需要哪一版」標記從最好有變成一定要有，獨立 App 和 Obsidian 版之間更是永遠有版本差。外掛裡的「這次更新了什麼」畫面也在這時做；一家人用時 repo 的更新紀錄就夠。
