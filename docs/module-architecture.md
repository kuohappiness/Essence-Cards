# Essence Cards｜三模組架構與逐步交付

版本：0.1
更新日期：2026-10-07（Asia/Taipei）
狀態：三個主要模組、輸入／輸出獨立使用與逐步整合已依 C-020 確認；細部責任、資料格式、教材種類、檢核對象及交付範圍仍待討論。

## 已確認的產品邊界

| M-ID | 主要模組 | 使用目的 | 可獨立完成的情境 |
|---|---|---|---|
| M-001 | 輸入 | 取得、選取及整理來源，形成可保存的筆記 | 只將 YouTube 整理成筆記，保存後即可結束，不強制製卡或接受檢核 |
| M-002 | 輸出 | 製作、呈現及使用學習材料，包含教材、心智圖與閃卡等方向 | 直接使用既有或手動建立的閃卡複習，不必先走來源匯入，也不必啟用完整檢核工作區 |
| M-003 | 檢核 | 檢查內容或學習結果，提供回饋 | 可接入已有材料／紀錄；檢核對象、入口與必要資料尚未細化 |

「輸出」是學習材料製作與使用的模組名稱，不指所有操作的任何產出。因此 M-001 可以自行產生可讀筆記；筆記不必送進 M-002 才算完成。獨立使用仍依賴 Obsidian 與必要的共用資料存取；YouTube 處理可能需要來源取得、字幕／逐字稿或模型能力，實際方式待驗證。

M-001 → M-002 → M-003 是可選交接，不是每次必走的流程。加入新模組不得破壞原有獨立使用方式。M-001、M-002 都保留各自的入口與完成結果；不必先建立完整概念關聯才能使用既有材料，之後可補上來源與概念連結。

## 與學習循環的關係

三模組描述產品責任與開發邊界；「輸入 → 整理 → 學習 → 回饋」描述整體學習循環。兩者是不同視角，不將學習循環重新改成三個固定步驟。

- 輸入與來源整理主要落在 M-001。
- 教材製作、知識呈現與練習操作主要落在 M-002。
- 深入檢核與回饋可由 M-003 接入，再帶回筆記或材料。
- 同一概念與來源可跨模組使用，沿用 C-011 的共用知識基礎。

完整 [Mermaid 架構與 F-ID 對照](diagrams/functions.md)與[學習、技術、路線圖](diagrams/README.md)互相參照。

## 功能責任對照｜助理拆分提案

F-ID 保留為討論索引，不要求一個功能對應一個程式模組。以下是目前候選歸納，跨模組責任仍須細化：

| 主要責任 | 功能對應 | 邊界與待議事項 |
|---|---|---|
| M-001 輸入 | F-001、F-002、F-003 | 來源管理、選段、筆記建立；YouTube 的取得方式及筆記內容待議 |
| M-002 輸出 | F-004 至 F-009 | 比較、架構、卡片、題目、互動材料與學習操作；心智圖是已提出方向，形式及第一版支援待議 |
| M-003 檢核 | F-011 至 F-014、F-019；另涉及 F-009 的評量 | 錯因、補強、進階安排、復盤及疑問追蹤；不把全部能力當作已採用的第一版需求 |
| 共用基礎 | F-010、F-015 至 F-018；必要的基礎複習規則 | 紀錄、入口／搜尋、關聯／版本、可選 AI 與資料保存；是支援三模組的基礎，不另列第四個主要模組 |

F-009 同時包含練習操作與評量；F-013 包含複習規則與份量安排。基本翻卡、必要自評與基礎複習規則應能供 M-002 使用，不讓完整 M-003 成為閃卡使用的先決條件；精確服務分工及算法待議。作答事件由操作端保存，M-003 可讀取，但不得為重新統計而改寫原始作答的意義。

「不啟用檢核模組」不表示自動採用 AI 草稿。人工核對可在當前輸入／輸出操作完成，不強迫使用者另進 M-003；AI 轉筆記、製卡或生成教材仍保留來源與採用責任。檢核是核對教材內容、評量學習者，或同時提供兩種入口，留待逐項確認。

## 交接與共用小核心｜方向採用，細節待定

先維持一個 Obsidian 外掛，內部分模組；每完成一個可用單位就接入現有工具。共用核心只實作目前交付所需的內容，不先建立全部未來能力。

- 共用識別與最小資料格式：讓筆記、材料、卡片及紀錄能補上關聯；哪些欄位必填、如何遷移尚未定案。
- 明確交接：輸入提供筆記／來源參照，輸出提供材料／學習事件，檢核提供建議或可核對修訂。各模組經約定介面交接，不任意改寫其他模組的內部資料。
- 內容與事件版本：新增模組後保留舊卡片、複習進度及作答紀錄；筆記／材料修訂須核對，舊事件仍可理解。
- 資料存取與跨裝置：沿用 Obsidian／既有 iCloud 驗證基線；正式事件、附件、併發與 Git 回復仍依 P0 驗證。
- 可選服務：AI 不成為手動閃卡的一般使用先決；輸入是否使用模型由來源情境決定。

## 逐步交付

先釐清最小可用閃卡的範圍，讓 M-002 能用既有／手動資料建立、編輯及複習卡片，保存必要進度。F-001 的主要來源問題保留，另以 YouTube → 筆記作為 M-001 的獨立需求情境；沒有承諾它會是第一個完成的匯入格式。

之後加入輸入或檢核能力，每次都同時驗收「新增能力」及「既有獨立模式仍正常」。精確交付順序、卡型、排程與 YouTube 處理方式待規格討論；P0／P1 的資料與保存驗證不因模組拆分而取消。

## 具體驗收情境｜尚未執行

| 情境 | 要驗收的結果 |
|---|---|
| 只用閃卡 | M-001 與完整 M-003 未啟用，仍能用手動／既有卡片複習並保存必要進度 |
| 只把 YouTube 轉成筆記 | M-002、M-003 未啟用，仍可依已選取得方式保存可讀筆記及來源，結束處理；方法尚未選定 |
| 後來加入輸入 | 舊卡片與紀錄保留；新筆記可選擇交給輸出製作候選，不自動加入複習 |
| 後來加入檢核 | 可以使用已有材料／事件提供回饋；停用深入檢核仍可繼續一般閃卡複習 |
| 修訂或升級 | 核對後更新指定內容，保留較新的事件；格式升級不清空舊資料 |
| 純人工使用 | 沒有 AI 服務也能完成手動製卡與複習；有 AI 候選時仍能在當前操作核對再採用 |

這些是設計驗收要求，不是正式功能已完成的證據。最小 UI／讀寫原型已依使用者回報通過雙端測試，完整 P0 與正式三模組尚未完成。
