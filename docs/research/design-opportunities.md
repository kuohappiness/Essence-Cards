## 核心判斷

本專案已確認「共用概念筆記、多情境介面、分錯因補強及可核對回寫」（C-008、C-011）。本輪的價值在於把方向細化為可操作、可追蹤的機制：從題目回到依據，讓內容改動連到受影響材料，讓手機發現的疑問能回到電腦處理。

我建議最優先討論三項：**卡片與來源互相跳轉、手機待修訂佇列、筆記修改後的材料影響清單**。它們共同支援「發現問題 → 核對 → 修訂 → 再練習」，符合本案既定方向，也能先以人工操作驗證。

各產品分別提供部分能力；本輪證據不足以認定任何一項已完整實現本案的錯因診斷與概念回寫循環。下列整合方式及其預期價值是本案推論，學習效果仍待測試。

## 功能討論目錄的採用進度

使用者同意依助理建議修改目錄，[C-017](../archive/v0-planning/consensus.md)確認：提早討論共用關聯規則、新增 F-019、區分內容使用狀態、共同設計作答／事件／排程、補上負擔控制議題，以及分開保存用途與驗收。各功能紀錄補上研究對應、最小人工操作及具體驗收情境。

[功能目錄 v0.2](../archive/v0-planning/function-discussions.md)保存調整後的討論路徑；[F-019](../archive/v0-planning/functions/issue-queue.md)負責手機提出問題至電腦處理結案，F-012 執行補強／修訂，F-016 檢查影響。

這是部分方向的採用，不代表下表的每個 A／U 行為全數確認。來源格式、資料欄位、精確狀態、算法、第一版範圍及實機能力仍待確認與驗證。

## 值得細化的設計架構

| ID | 架構優化 | 相較現有藍圖的具體細化 | 參考與理由 | 建議階段 |
|---|---|---|---|---|
| A-01 | 概念、衍生材料與學習事件分開管理 | 概念保有可自然編輯的正文；題目保存自己的問法、答案及版本並引用概念；作答另存事件。同一概念跨主題共用，各種題型各自記錄表現 | Anki 的筆記／卡片分工、RemNote 筆記製卡、Mochi 互連；減少重複內容，保留不同能力的差異 | P1 資料骨架 |
| A-02 | 來源定位成為共用能力 | 關聯保存來源 ID、版本、摘錄與可用定位；首版先處理 Markdown 區塊／選段。PDF 頁碼與影音時間碼分批驗證。原文變動或附件不存在時明示，不能靜默跳到別段 | Readwise 標註連結、NotebookLM 引用解析；引用應幫助核對實際依據 | P1 定義，P2 基本跳轉 |
| A-03 | 版本與材料依賴關係 | 材料記錄依據哪個概念／片段及版本；概念修訂後列可能受影響的題目，顯示差異再確認。舊作答仍連到當時題目版本，重新命名不更換 ID | Anki 共用欄位更新、Readwise 追加式匯出的邊界；本案需進一步保障修訂與舊紀錄脈絡 | P1 關聯，P2 提醒，P3 協助修訂 |
| A-04 | 評量、排程與診斷分工 | 作答保存正誤／自評、提示使用、當時版本與練習模式；信心與錯因可選填。排程使用明確規則，主題回顧另解讀紀錄。題目確認有誤後可排除其評量影響，保留原事件 | Anki 排程、Brainscape 信心、Recall 提示與題型；自覺熟悉、提示後答對及獨立答對不能混為同一訊號 | P1 最小事件，P2 基本規則 |
| A-05 | 收藏、整理草稿與正式學習分流 | 允許只收藏或選段；選擇值得理解／記憶的內容後再製作材料。AI 結果先為草稿，顯示依據與目標；採用前核對版本。任務紀錄保存在本案，模型可替換 | SuperMemo 漸進摘錄、Readwise 閱讀收集、NotebookLM 來源導向生成；控制處理量與複習負擔 | P2 人工流程，P3 AI |
| A-06 | 可讀資料與完整回復各有用途 | Markdown／CSV 用於閱讀或交換；完整回復須涵蓋附件、ID、關聯、題目版本與事件。提供遺漏檢查及隔離還原驗證，個別救回時保留較新事件 | Mochi 明確區分原生完整匯出與有損文字匯出；避免「文字仍在」但學習脈絡已丟失 | P0 救回驗證，P1 格式 |

這些細化沿用既有 Obsidian 外掛及 iCloud 驗證基線。穩定 ID、獨立事件與可重建索引已在技術路線圖提出，本輪補上其面向學習的用途，沒有宣稱 iCloud 併發寫入已可靠。

題目不必只是一份概念正文的即時顯示：它可以有特定條件、問法與評分要點。共用概念與保存題目版本同時必要。單純排版修改、答案實質修改及概念拆合對排程的影響，仍須另訂規則。

## 特殊而實用的功能候選

U-01 至 U-09 是本文件的優化候選定位，與功能目錄的 F-001 至 F-018 分開，研究時均為助理提案；其中部分方向已依 C-017 納入目錄，其餘細節及功能候選維持提案。產品參考指出靈感來源；具體整合行為不冒充該產品已有能力。

| ID | 功能 | 建議的具體操作 | 實用價值與參考 | 優先程度 |
|---|---|---|---|---|
| U-01 | 卡片↔概念↔來源互相跳轉 | 答後可展開概念與原文摘錄，再回同一張卡及進度；作答前查看材料也記錄為受到協助 | 減少核對時的切換與迷失。參考 Readwise、NotebookLM、Recall | 第一版優先 |
| U-02 | 手機待修訂佇列 | 複習時標記「題意不清、答案有疑問、想補例子、概念易混淆」，附短註；電腦集中核對、修訂及結案。疑似內容錯誤可選擇暫停該題 | 讓手機複習產生可處理的回饋。參考 RemNote Edit Later；一般忘記不必送去修題 | 第一版優先 |
| U-03 | 選段製卡與候選預覽 | 從選定段落產生／手寫少量候選，並列題目、答案、依據與測試目標；採用後才加入複習，可先比對同概念既有題 | 控制卡片數量及核對品質。參考 SuperMemo、NotebookLM、Mochi；首版可先人工，AI 屬 P3 | 第一版人工流程；AI 後續 |
| U-04 | 易混淆概念對照與變式練習 | 在混淆紀錄中選兩個概念，建立比較表、辨別題及新情境題；補強後再用不同問法檢查 | 將「知道定義」與「能區分／應用」分開觀察。參考 Recall 多題型及本案 I-003、I-006；診斷效果待驗證 | 首版可手動對照；自動化後續 |
| U-05 | 時間預算與新卡節流 | 選擇短時間複習，優先處理到期內容；積欠時減少新卡，清楚保留剩餘待複習數。估時需由實際紀錄校準 | 避免生成速度超過可學習份量。參考 Anki 每日上限；時間預算是本案延伸 | 第一版基本份量控制 |
| U-06 | 反覆答錯的補強入口 | 達到可調的提醒條件後，提供回原文、比較、補例子、拆題或申疑；讓使用者選原因與下一步 | 將反覆失敗導向可處理活動。參考 Anki leech；不依單次答錯自動認定缺乏理解 | 先有手動入口；診斷後續 |
| U-07 | 提示分層與獨立回想紀錄 | 可先給方向，再給關鍵線索，最後顯示答案；保存提示程度，回顧時區分獨立答對、提示後答對及看答案 | 避免把受到協助的結果當作獨立回想。參考 Recall 提示；如何影響排程另行驗證 | 有提示功能時必備紀錄 |
| U-08 | 同源題錯開出現 | 同一概念的反向題或近似填空可延後出現，降低上一題剛揭露答案對下一題的影響；刻意做比較練習時可例外 | 多題型各自有表現紀錄，也避免相鄰題洩漏答案。參考 Anki sibling burying；規則待試用 | 首版有多張同源題時評估 |
| U-09 | 筆記修改後的材料影響清單 | 改完筆記列出引用舊版本的卡片／教材；逐項選保留、修訂或暫停，確認後再測。先做保守提醒，不宣稱精準判斷每個變更 | 使一次修訂能有秩序地傳遞至學習材料。細化 C-011，參考共用內容與版本設計 | 第一版基本提醒；AI 比對後續 |

U-02 與 U-06 可共用「待處理」入口，但必須保留不同原因：學習者需要補強與題目需要修正是不同工作。提出疑問不立即刪除作答或判定題目無效；核對後再更新衍生統計與排程處理，保留原紀錄。

後續再評估的特色：

- **圖片遮蔽並連回概念**：適合構造圖等材料，參考 Anki／RemNote；先驗證手機呈現與附件保存，再擴充 OCR 自動製卡。Memory Toast 的拍照流程作輸入參考。
- **考前專項練習**：按主題、題型、弱項或考試日期組合練習；另記模式，明確選擇是否影響日常排程，不能把短期重練當作長期掌握。
- **主題缺口清單**：列出需要回想、辨別、應用或修題的概念，附資料量與可直接執行的活動；資料不足時保留未知，避免只有單一掌握百分比。

## 第一版的建議收斂

依既有 P0–P4 路線圖安排，先確認資料在真實 Windows／iPhone 上可保存、同步及救回，再驗證功能。功能研究不取代 P0。

| 階段 | 建議納入的最小範圍 | 暫不擴張的部分 |
|---|---|---|
| P0 | 小型 vault 的文字、附件、離線作答及個別回復 | 在同步／回復未通過前大量製卡 |
| P1 | 概念／來源／題目 ID、基本版本依據、最小事件及可重建索引 | 強制每張卡填寫完整信心、錯因、難度問卷 |
| P2 | 基本問答／填空、來源回看、待修訂標記、人工修訂、材料影響提醒及可控制的複習份量 | 完整七題型、複雜知識圖譜與自動診斷 |
| P3 | 選段生成候選、引用及修訂差異預覽、版本核對、可重試 AI 任務 | 未核對生成結果直接加入排程或覆寫全部衍生材料 |
| P4 | 用同一份真實教材比較操作阻力、內容品質、延後回想及變式作答 | 只以卡片數、連續登入或當次正確率宣稱成效 |

第一版題型、提示、算法及具體交付範圍仍待 T-005／T-006 討論。基本流程先支援人工製卡與修訂，AI 可以接入而不成為每次複習的必要依賴，符合免費／無月訂閱優先及電腦整理、手機複習的方向。

## 具體試例與驗收方向

以同一份合法可用的生物教材，挑選兩個易混淆概念，例如有絲分裂與減數分裂；內容以教材核對，不在此文件新增知識結論。

1. 選段建立兩個概念及比較筆記，先製作少量問答／填空。
2. 手機作答後標記一次混淆、一題題意疑問；回看原文仍能回到原題與進度。
3. 電腦處理疑問，補充比較或修訂題目；查看哪些材料需要核對，保存舊作答脈絡。
4. 用不同問法再測，區分獨立作答與提示後作答；之後做延後檢查。
5. 加入離線作答、筆記改名與單檔救回，確認附件、關聯與較新事件仍在。

觀察：找回來源的耗時／切換次數、選段至採用卡片的工作量、修訂是否能結案、誤題是否影響評量、版本連動遺漏，以及不同問法與延後作答表現。這些是驗收方向，門檻與樣本數尚未確認。
