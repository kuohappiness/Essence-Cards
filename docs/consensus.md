# Essence Cards｜專案共識

版本：0.4  
更新日期：2026-10-06（Asia/Taipei）  
目前階段：需求探索與文件管理；正式英文名稱已確認

## 1. 專案目標｜已確認

使用者曾製作基於間隔重複（spaced repetition）的 Obsidian 閃卡外掛，現希望重構新的軟體，以更有效率、更深入地萃取知識，在有限時間內學習更多內容，並對考試成績有所幫助。

使用者本輪明確提出的三個設計概念：知識萃取、利用閃卡複習、加強記憶。加強記憶為預期目標，具體效果與驗證方式尚待規劃。

上述為產品目標，實際學習效果尚待驗證。目標使用者、教材範圍、時間限制與成功標準尚未確定。新軟體是否仍為 Obsidian 外掛，尚未決定。

## 2. 討論方式｜已確認

- 每輪聚焦一個核心問題，允許自由延伸，由助理整理需求、取捨與未解問題。
- 持續維護同一份共識文件，保留重要決策的理由與更新紀錄。
- 以真實教材驗證抽象需求；學習理論的研究依據與本產品假設分開記錄。
- 使用者明確需求、助理提案、待驗證推測分開標示；未反對不等於已同意。
- 階段收尾時檢查遺漏、矛盾及範圍偏移。

狀態：已確認、提案中、待驗證、暫緩、已排除／已取代。

## 3. 共識文件呈現｜已確認

- Markdown 保存完整共識與決策紀錄。
- HTML 呈現具有固定分區的無限畫板，並可切換文字綱要。
- 卡片顯示短摘要及狀態；點選後查看完整內容、理由與來源。
- 畫板與綱要依據同一份 Markdown 內容更新。

理由：以畫板掌握全貌與關聯，同時透過綱要逐項檢查，保留可下載、可移交的文字紀錄。

## 4. 同步規劃｜方向已確認，實作方式為提案

使用者已確認 Markdown 與 HTML 應保持同步。

建議採單一內容來源：修改 Markdown → 產生 HTML → 檢查內容與互動 → 保存相同版本 → 若已上線則發布更新。

- 不在兩份檔案各自維護共識文字，避免內容分歧。
- Markdown 與 HTML 都顯示相同版本號與更新日期。
- 更新正式結論時先更新 Markdown；HTML 由產生程式重新建立。
- 共識項目規劃使用固定識別碼，供畫板卡片、關聯與變更紀錄引用；語法尚待設計。
- 網頁初期作為閱讀與探索介面；若日後需要直接編輯並回存 Markdown，須另設計儲存與衝突處理。

實作狀態：本文件為初版規劃；HTML 產生程式、正式畫板及自動發布流程尚未建立。

## 5. GitHub 與網頁發布｜公開方向已確認，流程待實作

需求：希望了解將 HTML 發布為可透過網際網路開啟的網頁。

使用者已確認：整個專案使用同一個公開 GitHub 儲存庫，包含 Markdown 共識文件、HTML 畫板、後續新增的專案文件及開發程式碼。使用者已建立公開儲存庫：https://github.com/kuohappiness/Essence-Cards 。正式英文名稱為 Essence Cards。

GitHub Pages 作為畫板的發布方向；儲存庫已確認，網站與 Markdown → HTML 同步流程尚未建立。以本 repo 中的 docs/consensus.md 作為後續共識的正式版本；每輪有實質決定時更新並提交。後續新增的專案文件與程式碼也保存在此 repo。

建議內容配置：README.md 放專案介紹；docs/ 放共識、需求、決策與研究；src/ 放程式碼；scripts/ 放文件與畫板產生程式；tests/ 放必要驗證。實際目錄隨技術選型調整。

公開範圍為專案文件與程式碼；API 金鑰、登入憑證及私人學習資料不屬於公開專案內容。軟體授權條款另行決定。

GitHub Pages 支援 HTML、CSS、JavaScript，GitHub Free 可透過公開儲存庫使用；預設 github.io 網址支援 HTTPS。網址形式為 https://帳號.github.io/儲存庫名稱/ 。

簡易發布流程：

1. 使用者已建立公開儲存庫 Essence-Cards。
2. 上傳可獨立開啟的正式畫板，首頁命名 index.html；若樣式、程式或圖片為獨立檔案，一併上傳。
3. 在 Settings → Pages 選擇 Deploy from a branch，指定 main 與 /(root)，儲存後等待發布。
4. 後續將更新後的 HTML 推送至發布來源，網站會重新發布。

正式同步的建議流程：在 GitHub Actions 設定 Markdown 變更後執行產生程式，再發布生成的 HTML。此流程需另行實作；對話中更新檔案不會自行更新外部網站。

存取條件：使用者同意網站公開可讀。網站可從能連線至該服務的網路開啟，實際仍受網路封鎖與服務可用性影響。

## 6. 軟體命名｜Essence Cards 已確認，中文名稱待定

已確認的命名偏好：簡潔、有力、優雅。先選名稱，再建立 GitHub 儲存庫。

使用者已排除第一批 Quint／知粹、知核、澄知、凝知、萃知；後續要求先選英文名稱，再搭配中文。使用者進一步指定萃取、蒸餾的命名意象，並明確表示喜歡 Essence。

正式英文名稱：Essence Cards。儲存庫名稱：Essence-Cards。中文名稱尚未確認。

命名理由：Essence 呼應知識的精華，Cards 呼應閃卡複習；使用者已明確選定此名稱。

命名過程中的提案：

| 候選 | 命名意象 | 取捨 |
|---|---|---|
| Essence | 主名稱保持簡潔，涵蓋萃取後的知識精華 | 優雅、擴充空間大；名稱本身較少表達複習 |
| Essence Loop | 萃取、複習、回饋形成循環 | 有流程感，可連結間隔複習意象 |
| Essence Recall | 萃取精華後練習回想 | 強調記憶與作答，較直接 |
| Essence Cards | 將知識精華轉為閃卡 | 功能容易理解；名稱較聚焦閃卡 |

Essence Cards 已選定，其餘延伸保留為歷史提案；商標、網域及套件名稱可用性未完成確認。

助理提出的產品概念：萃取核心 → 化成問題 → 間隔複習。以同一核心概念連結來源內容、理解與複習；是否採用、如何實作均待討論。
