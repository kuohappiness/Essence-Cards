# 2026-10-10｜資料存放、v1 範圍與舊外掛分析

摘要，不是逐字紀錄。決定的完整內容見[決策紀錄](../../decisions.md)。

## 架構釐清第 6 步：資料存放

- 使用者回答上一輪的問題：
  - 影片不標時間點（D-031）。
  - 教材目錄邊用邊長（D-033）。
  - v1 的材料可以是筆記，也可以是 PDF；限定只用課本 PDF 不符合實際情境（D-032）。
  - 出題語法在開始寫程式前，參考舊外掛定稿。
- 使用者選擇：
  - 教材目錄從卡組自動組成（D-033）。
  - 學習目標 ID 由程式產生隨機短碼（D-034）。
  - 複習紀錄每台裝置每月一個檔（D-035）。
- 使用者問到：為什麼複習紀錄不一直追加在同一個檔案？助理說明同步量、損壞範圍與開啟速度三個理由，維持按月分檔。

## 架構釐清第 7 步：v1 範圍

- **卡組編輯與審核**：家長可以直接在 Obsidian 編輯卡組（D-036）。AI 製卡的結果在卡組筆記裡審核（D-037）。
- **AI 接法**：v1 做複製貼上與 API 直連兩種。
- **Capture 與增強版**：Capture 不提前。發音朗讀移到增強版，之後比較 iOS 的語音做法。
- **一般知識情境**：使用者提出學業以外的知識（攝影、YouTube 醫學影片）。
  - 結論：一個 vault 對應一位學習者，分類容納各種領域（D-038）。
  - v1 範圍定案（D-039）。
- **卡組位置**：使用者希望學業放一個資料夾，其他卡組自由擺放；選擇只放在 `Essence Cards/` 裡（D-040）。
- **分類**：使用者提議用標籤。結論是分類用 YAML 屬性，自由分類用 Obsidian 內建標籤，範圍可以選標籤（D-041）。
- **AI 製卡快照**：使用者要求先看實際流程再決定。
  - 使用者另提「卡片標 active／inactive」的做法，比較後採用快照（D-042）。
  - 使用者補充：家長大多沒空修改 AI 的卡，但修改權限要保留。

## 舊外掛分析

- **提供 repo**：使用者提供舊外掛 AI-Enriched Flashcards 的 repo。助理讀完全部程式，寫成[分析報告](../../research/old-flashcard-plugin.md)。
- **使用原則**：使用者強調舊 repo 只用來找出有幫助的觀念，不直接拿來用；要先以最高標準想最好的做法（寫進 AGENTS.md）。
  - 報告第二版依此重新設計 14 個項目。
- **使用者確認**：
  - 排程採用 FSRS，未來可依每個人調整（D-043）。
  - 介面體驗是重點方向（D-044）。
  - 語法方向沿用 `::`、縮排、`==`（D-030 附註）。
  - 學習目標用清單縮排（D-045）。
  - 題目用內容指紋識別（D-046）。
- **實測**：
  - 舊外掛的 69 個測試全部通過，並用它的程式重現 5 個問題。
  - 使用者開放網路後，助理在雲端安裝 Obsidian 實際操作，另外發現：打字時補 ID 會吃掉文字、方向鍵移動不會補 ID、答錯的卡同一次不會再出現（報告附錄二）。
- **電腦操作**：使用者想讓助理用電腦操作功能；這個雲端對話連不到使用者的電腦，所以改在雲端環境測試。
