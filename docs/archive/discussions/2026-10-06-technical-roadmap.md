# 技術架構、平台選型與 Git 回復

日期：2026-10-06（Asia/Taipei）。本頁為討論摘要，不冒充逐字對話。

## 使用者需求與限制

- 希望先比較免費／開源平台，避免每月訂閱，詢問 Obsidian、ZenNotes、SilverBullet 與 Joplin 等候選。
- 原提出電腦外掛、Dropbox 同步及手機外掛／自製 App；之後明確決定先採 Obsidian 外掛。
- 實際 iPhone vault 使用 iCloud，不能直接開 Dropbox vault；使用者目前已經透過 iCloud 同步電腦與手機，質疑增加 Remotely Save／Dropbox 的複雜度。
- 要求評估第一版是否有致命障礙，並詢問 GitHub 外掛的版本回復對 iCloud 信心不足是否有幫助。
- 本次要求如同知識學習架構藍圖，將技術架構與開發路線圖繪圖、放入畫板與 GitHub，完整保存未來 Git 設計。

## 助理提案與取捨

- 先重用 Obsidian 的筆記及裝置環境，沿用既有 iCloud，減少第一版額外操作。Git 是版本與備份層，不作第二個日常雙向同步服務。
- 當前沒有已知必然阻止核心學習流程的限制，但 Windows iCloud、離線事件及併發寫入是重要待驗證風險；不能直接宣稱已通過。
- 電腦主要修改內容；手機追加獨立學習事件，避免競爭覆寫同一累計檔。概念與題目用穩定 ID／版本，索引可重建，AI 回寫先核對版本。
- 跨模型 AI 透過共通任務資料及轉接層處理；不承諾所有模型免費或零修改接管，也不要求手機依賴桌面 Node.js／Electron 或持續背景任務。
- Git 僅電腦啟用、歷史目錄移出 iCloud，明確設定 commit／push 與拉取行為；批次修改前後留版本。回復選個別檔，保留新事件；私人學習備份與公開專案 repo 分開。
- Git 只保護已留存的版本；手機未同步資料、未 commit 與未 push 的內容各有保護邊界。
- 建議先做 P0 真實裝置驗證，再做 P1 資料骨架、P2 最小循環、P3 AI 任務、P4 教材試用；詳細順序與驗收尺度仍需確認。
