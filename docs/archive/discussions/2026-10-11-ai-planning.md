# 2026-10-11｜AI 規劃專題討論

使用者另開一條討論，專門談 Essence Cards 裡所有和 AI 有關的規劃。本紀錄是摘要，不是逐字紀錄；討論進行中，有新進展再補。

## 1. NotebookLM 都做得到，Essence Cards 還有角色嗎？

**使用者提出**：閃卡、圖文資訊卡、心智圖、測驗題，Gemini Notebook（NotebookLM）匯入資料後都能直接完成，相比之下這個專案還有角色嗎？

**助理查證**（第三方資料為主，見 [R-009](../../research/software.md#r-009-notebooklm官網初查完成)）：NotebookLM 的閃卡只有 Got it／Missed it 和「只練錯的卡」，沒有跨日的間隔排程；常見做法是匯出到 Anki，用 FSRS 排程。

**助理看法**：

- 有角色，但要講得更窄。NotebookLM 擅長「把教材變成各種材料」，這件事已經幾乎不用成本；它不知道學生三週後忘了哪一張，沒有北極星要的閉環。
- 用國二上自然 2-1 說明：NotebookLM 第 1 天產生 25 張卡，之後不會在第 3、8、20 天把快忘的卡帶回來；5 科 × 10 節會散在幾十本 notebook。
- 真正的對照組是「NotebookLM 製卡＋Anki 排程」。我們多的是：題目池共用排程（D-028）、少而精的製卡規則、卡組在 Obsidian 能跳回出處、家長審核、所有科目同一個今日佇列。
- 坦白的風險：Google 如果加上長期排程，差異會變小。作為家長為孩子打造、接在 Obsidian 裡的工具仍成立；作為市場產品，護城河薄。

**助理提出三點（💡）**：

1. AI 只做「產生值得長期排程的少量學習目標」；理解用的材料交給 NotebookLM。
2. NotebookLM 可以當上游，例如複製貼上模式的 AI。
3. 先做對照實驗，比較 NotebookLM 的閃卡和我們的製卡規則。

**結果**：使用者同意把對照實驗排入計畫 → 列入路線圖「v1 開發前要做的事」，試用方式寫在[製卡規則](../../card-rules/README.md#notebooklm-對照實驗)。

**修正**：第 1 點原本建議把「心智圖」改列「不做」。整理文件時發現，點子收集箱「多種呈現方式」的心智圖是挖掉節點的提取練習，可以排程，D-051 也把它列為選 React 的理由之一。改為：只有當閱讀材料用的心智圖交給 NotebookLM，提取練習用的心智圖仍留在之後。

## 2. 能不能把 NotebookLM 的產出自動接進來，當低成本的資料來源？

**使用者提出**：有沒有可能把 Gemini Notebook 的產出自動化接入專案，成為低成本的資料來源？

**助理查證**：沒有個人可用的官方 API。2025 年 9 月的 Enterprise API 需要 Google Cloud 和企業／教育授權；非官方工具（notebooklm-py）用逆向工程，需要 Google 登入狀態。閃卡可以從介面下載 CSV，但各來源說法不一致。

**助理看法（💡）**：

- 全自動不建議：沒有官方管道，非官方工具隨時可能失效，還要處理登入狀態。
- NotebookLM 背後就是 Gemini。想要自動又低成本，直接用 Gemini API 的免費額度：官方、穩定、能直接讀 PDF，也能用我們的製卡規則與出題語法。這也表示 API 直連的成本不一定是問題。
- NotebookLM 適合半自動接入的三個位置：
  - 複製貼上模式的 AI（v1 已規劃）。
  - Capture 的位置：YouTube 影片與沒有課本的領域，先整理成筆記放進 vault；學業科目仍直接用課本（D-021）。
  - 閃卡 CSV 匯入：會跳過製卡規則，等對照實驗結果再決定。

## 3. 模型偏好與心智圖外掛

**使用者提出**：

1. 模型首選免費或開源，CP 值高、成本低的也可以，不一定是 Gemini。
2. 可以接受資料被拿去訓練。
3. 未來想在 Obsidian 開發心智圖外掛，希望保留對接的彈性。

**結果**：第 1、2 點寫成 [D-055](../../decisions.md#d-055-ai-模型的選擇原則)，第 3 點寫成 [D-056](../../decisions.md#d-056-保留和心智圖外掛對接的彈性)。兩項的具體做法都是助理提案，待使用者確認。

**助理提案（💡）**：

- 模型（[架構 §6](../../architecture.md#6-ai-的位置-細節之後專門討論)）：
  - API 直連只做 OpenAI 相容介面，免費額度、開源模型 API、本機的 Ollama 都能接。
  - 教材轉成頁面圖片加文字送出。
  - 一學期用量便宜的模型不到 1 美元，真正的成本是審核時間，所以預設模型依卡片品質挑，用對照實驗的教材比較 2～3 個候選。
  - 開源模型要檢查台灣用語。台灣的 Breeze 2 是繁中、能看圖的開源模型，但只有 3B／8B，能力可能不夠，可以列為本機候選。
- 心智圖對接（[架構 §3](../../architecture.md#3-模組邊界-第-5-步)）：
  - 用檔案對接。
  - v1 只要學習目標 ID 用 Obsidian 原生區塊 ID、格式寫進說明書當公開格式、排程狀態可以從紀錄算出。
  - 之後再由 Cards 提供介面，讓心智圖外掛查記憶狀態、寫入複習紀錄。

## 4. 區塊 ID 的顯示、上色地圖、本機模型

**使用者提出**：

1. 同一個區塊 ID，能不能在不同筆記和心智圖節點裡連結，但顯示不同的內容？
2. 喜歡心智圖節點依複習狀態變色，甚至想做進儀表板，一目了然。
3. 一般使用者沒有獨立顯卡，本機開源模型可以列為保留擴充；最主要的用途是產生語音複習材料。外掛經 iCloud 同步，模型能不能包進外掛？檔案會不會暴增？

**助理回答與提案**：

- 第 1 點：可以。`[[卡組#^id|顯示文字]]` 每個地方可以顯示不同文字，嵌入則顯示原文（包括答案）。已知限制：學習目標搬到另一篇卡組時，寫著舊檔名的連結會失效，所以外掛應以 ID 找學習目標，檔名只當提示。
- 第 2 點：顏色由 FSRS 的記憶保持率決定，心智圖外掛和儀表板共用同一套算法。💡 儀表板可以直接用教材目錄畫成地圖，不必等心智圖外掛；點紅色區域就當成複習範圍。
- 第 3 點：💡 不要包進外掛。外掛資料夾在 vault 裡，會同步到 iPhone；語音模型約 90～330 MB，語言模型要數 GB，會拖慢啟動，iCloud 也可能把大檔案從 iPhone 移除。iPhone 也不需要模型：在電腦上預先產生音檔，只同步音檔，一課 40 個字約 1～2 MB。小型語音模型（例如 Kokoro）用 CPU 就能跑，所以「沒有獨立顯卡」不影響這個用途。

**結果**：本機開源模型列為保留擴充，不在 v1，寫進 [D-055](../../decisions.md#d-055-ai-模型的選擇原則) 的補充；語音材料的做法併入[增強版的發音朗讀](../../backlog.md#增強版待討論)；上色地圖記入儀表板（之後，D-024）。

5. 同意模型不包進外掛。→ D-059。

## 6. 錯題分析

**助理提案**：

- 用 2-1 段考走一遍：家長選考試範圍、上傳錯題 → AI 對照範圍內的學習目標，產生「錯題本」草稿 → 家長審核 → 採用時補強題放回原卡組，「忘記」記成一筆複習紀錄。
- 三點調整：
  - 「忘記」寫成複習紀錄，不另存標記。
  - 錯因由 AI 判斷並寫理由，家長可以改。
  - 錯題規則搬到通用規則。
- 可以移出 v1：
  - 複習中常錯的卡請 AI 改寫，放到之後。
  - C-008 縮小。

**結果**：使用者同意整體流程 → [D-061](../../decisions.md#d-061-錯題補強的流程)。自評值的名稱等「複習與檢核細節」第 1 題（另一個 session 處理）決定後再填。

**使用者接著提出**：

1. 卡片可以用標籤管理嗎？例如「錯題」、「新卡」、「啟動／停用」，用詞可以再優化。
2. 錯因可以點選，或加一個打字的欄位，但家長大多沒有心力打字。
3. 不同科目的錯因分析不同，製卡規則要確認是否完善。

**助理建議（💡，待確認）**：

- 標籤分四種：狀態、來源、學習狀況（自動計算）、自訂標籤。「停用」改「暫停」，「錯題」改「錯題補強」。
- 錯因預設不用操作；需要時點選；AI 拿不準時選代價低的錯因。
- 通用規則放錯題框架，自然、英文補各科細節，英文新增「文法句型」。

細節見 [backlog「AI 規劃」](../../backlog.md#ai-規劃2026-10-11-起的專題討論)。

**使用者回覆**：

1. 自訂標籤不要用 Obsidian 標籤，才不會污染整個 vault；改成可以打字的備註欄位。
2. 其他建議都同意。

**結果**：

- [D-061](../../decisions.md#d-061-錯題補強的流程) 補充：錯因預設不用動手、拿不準時選代價低的；各科錯因規則；v1 只處理考卷與作業錯題；C-008 縮小。
- 製卡規則：通用 v0.3 加入錯題處理與錯題本格式，自然 v0.1、英文 v0.4 補各科情況與「文法句型」，試用說明加入錯題（[製卡規則](../../card-rules/README.md)）。

## 8. 卡組分類也不用 Obsidian 標籤

**助理提問**：D-041 的卡組層級分類用 Obsidian 標籤（例如 `#醫學`），要不要比照 D-063 一起改？A 維持；B 改成 YAML 屬性（助理建議）。

**使用者回覆**：選 B。不想要卡片使用 Obsidian 標籤，但 Essence Capture 產出的筆記可以使用。

**結果**：[D-064](../../decisions.md#d-064-卡組分類改用屬性)：卡組的自由分類改用 YAML 屬性（例如 `分類`），Essence Cards 的卡組與卡片完全不用 Obsidian 標籤；範圍可以選分類；Capture 的筆記可以用標籤。D-041 對應的部分標為已取代。

另外，自評段數已在另一個 session 定案（D-062：太簡單／想到了／差一點／沒印象），D-060 的待確認一併解決。

## 9. AI 評測集；AI 一定要 API 嗎？

**助理提案**：v1 不做評測工具。採用率（快照比對卡組）與漏掉率（錯題本的「卡片沒涵蓋」加上家長自己補的目標）會自動累積；固定案例的評測集放到之後，教材不進 repo。

**結果**：使用者同意 → [D-042](../../decisions.md#d-042-ai-製卡快照) 補充。

**使用者接著問**：AI 主要用在「從來源筆記產生卡片」與「評估檢核」，兩者幾乎不可或缺；就算家長自己產卡，也得靠 AI 檢核，所以勢必要找一個 API？

**助理回答**：

- 不一定要 API：製卡與錯題分析都能用複製貼上（免費、不用金鑰），API 直連只是省去貼來貼去；v1 沒有 AI 也能完整使用（D-007、原則 6）。
- 「評估檢核」先確認指哪一種：
  - 若指 AI 檢查家長手寫卡片的品質，可以用同一套複製貼上。
  - 若指複習時由 AI 判斷學生的答案，v1 刻意用自評：每天上百張要打字、等回應，零碎時間做不完；手機沒網路就不能複習；免費額度也撐不住。
  - 自評高估的風險由短答案、拼字用程式比對、四級自評（D-062），以及考試錯題（D-061）來補。

**使用者澄清**：「評估檢核」既不是 A 也不是 B，指的是錯題分析與重新產卡（D-061）。

**助理回答**：AI 的兩個主要功能（製卡、錯題分析）都在 v1；兩者都能用複製貼上，錯題分析需要的「範圍內學習目標清單」由外掛組進提示，所以 API 不是必須。建議 v1 完成後申請一把免費的 API 金鑰當日常用，複製貼上當備用。「AI 是加速器」的原則不變：AI 出問題時，複習不中斷，家長也能手寫。

**助理提議**：v1 會用到的 AI 部分已談完，可以先收尾去試用。

**使用者回覆**：

2. 同意說明書加一節「怎麼申請免費 API 金鑰」，並提醒申請方法與免費金鑰的來源未來都可能更新。→ [D-048](../../decisions.md#d-048-使用說明書) 補充：寫查核日期、連到官方頁面不照抄、發布前重新查核、外掛接受任何 OpenAI 相容網址。

## 11. 英文記憶錨點、AI 產生反方向題

**助理提案（💡）**：

1. 錨點只在需要時才加：常錯的英文單字一鍵補錨點，沿用錯題補強的流程（D-061），放進 v1，因為英文情境的成功標準寫了「再補強記憶錨點」。另一個 session 補充：依「差一點」與「沒印象」的次數選錨點的種類。
2. 調整錨點的種類：
   - 字首字尾只寫常見的。
   - 易混淆字只對之前學過的字加。
   - 聯想只用在難記的字。
   - 圖片先用 emoji。
3. AI 產生反方向題放到之後。

**使用者回覆**：

- 第 2、3 點同意 → [英文規則 v0.5](../../card-rules/english.md)；backlog 的「AI 產生反方向題」改為之後。
- 第 1 點使用者問：反向題型幾乎只用在英文單字，英翻中是先知道字義，中翻英是知道怎麼寫、怎麼用，這樣的情境對建議有沒有差？

**助理回答**：有差，錨點的種類要看哪個方向常錯：

- 英→中常錯（看到字想不起意思）：適合聯想、emoji、字首字尾、例句情境。
- 中→英或拼字常錯（想不起字、拼不出來）：適合拆音節、發音和拼法的對應、常見搭配、易混淆字；諧音聯想不用。
- 錨點只加在常錯的那個方向的卡片背面。

「先英→中、再中→英」可能代表出題順序的要求，屬於複習與檢核細節第 12 題，已把使用者原話交給另一個 session。

**結果**：使用者同意調整後的提案 1 → [D-067](../../decisions.md#d-067-英文記憶錨點需要時才補)；英文規則加入「常錯單字的錨點」。

## 12. NotebookLM 對照實驗暫緩

**使用者提出**：沒有時間做 NotebookLM 的實驗，能不能暫時跳過往下？

**助理判斷**：可以，沒有東西被它擋住：

- 預設模型的比較改由「API 規劃與選型」在 `experiments/` 實測。那邊會設計成使用者只要提供教材和金鑰。
- 製卡規則照常改進。
- NotebookLM 當複製貼上的 AI、閃卡 CSV 匯入，本來就是選用。

**結果**：實驗從 v1 開發前要做的事移除，改為暫緩、有空再做；D-059、D-042 補充、架構 §6、backlog、製卡規則說明同步調整。錯題試用不必另外安排，等下次真的有考卷發回來再拍照試。
