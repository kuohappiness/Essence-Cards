# 2026-10-11｜AI 規劃專題討論

使用者另開一條討論，專門談 Essence Cards 裡所有和 AI 有關的規劃。本紀錄是摘要，不是逐字紀錄；討論進行中，有新進展再補。

## 1. NotebookLM 都做得到，Essence Cards 還有角色嗎？

**使用者提出**：閃卡、圖文資訊卡、心智圖、測驗題，Gemini Notebook（NotebookLM）匯入資料後都能直接完成，相比之下這個專案還有角色嗎？

**助理查證**（第三方資料為主，見 [R-009](../../research/software.md#r-009-notebooklm官網初查完成)）：NotebookLM 的閃卡只有 Got it／Missed it 和「只練錯的卡」，沒有跨日的間隔排程；常見做法是匯出到 Anki，用 FSRS 排程。

**助理看法**：

- 有角色，但要講得更窄。NotebookLM 擅長「把教材變成各種材料」，這件事已經幾乎不用成本；它不知道學生三週後忘了哪一張，沒有北極星要的閉環。
- 用國二上自然 2-1 說明：NotebookLM 第 1 天產生 25 張卡，之後不會在第 3、8、20 天把快忘的卡帶回來；5 科 × 10 節會散在幾十本 notebook。
- 真正的對照組是「NotebookLM 製卡＋Anki 排程」。我們多的是：題目池共用排程（D-028）、少而精的製卡規則、卡組在 Obsidian 能跳回出處、家長審核、所有科目同一個今日佇列。
- 坦白的風險：Google 如果加上長期排程，差異會變小。作為家長為孩子打造、接在 Obsidian 裡的工具仍成立；作為市場產品，護城河薄。

**助理提出三點（💡）**：

1. AI 只做「產生值得長期排程的少量學習目標」；理解用的材料交給 NotebookLM。
2. NotebookLM 可以當上游，例如複製貼上模式的 AI。
3. 先做對照實驗，比較 NotebookLM 的閃卡和我們的製卡規則。

**結果**：使用者同意把對照實驗排入計畫 → 列入路線圖「v1 開發前要做的事」，試用方式寫在[製卡規則](../../card-rules/README.md#notebooklm-對照實驗)。

**修正**：第 1 點原本建議把「心智圖」改列「不做」。整理文件時發現，點子收集箱「多種呈現方式」的心智圖是挖掉節點的提取練習，可以排程，D-051 也把它列為選 React 的理由之一。改為：只有當閱讀材料用的心智圖交給 NotebookLM，提取練習用的心智圖仍留在之後。

## 2. 能不能把 NotebookLM 的產出自動接進來，當低成本的資料來源？

**使用者提出**：有沒有可能把 Gemini Notebook 的產出自動化接入專案，成為低成本的資料來源？

**助理查證**：沒有個人可用的官方 API。2025 年 9 月的 Enterprise API 需要 Google Cloud 和企業／教育授權；非官方工具（notebooklm-py）用逆向工程，需要 Google 登入狀態。閃卡可以從介面下載 CSV，但各來源說法不一致。

**助理看法（💡）**：

- 全自動不建議：沒有官方管道，非官方工具隨時可能失效，還要處理登入狀態。
- NotebookLM 背後就是 Gemini。想要自動又低成本，直接用 Gemini API 的免費額度：官方、穩定、能直接讀 PDF，也能用我們的製卡規則與出題語法。這也表示 API 直連的成本不一定是問題。
- NotebookLM 適合半自動接入的三個位置：
  - 複製貼上模式的 AI（v1 已規劃）。
  - Capture 的位置：YouTube 影片與沒有課本的領域，先整理成筆記放進 vault；學業科目仍直接用課本（D-021）。
  - 閃卡 CSV 匯入：會跳過製卡規則，等對照實驗結果再決定。

## 3. 模型偏好與心智圖外掛

**使用者提出**：

1. 模型首選免費或開源，CP 值高、成本低的也可以，不一定是 Gemini。
2. 可以接受資料被拿去訓練。
3. 未來想在 Obsidian 開發心智圖外掛，希望保留對接的彈性。

**結果**：第 1、2 點寫成 [D-055](../../decisions.md#d-055-ai-模型的選擇原則)，第 3 點寫成 [D-056](../../decisions.md#d-056-保留和心智圖外掛對接的彈性)。兩項的具體做法都是助理提案，待使用者確認。

**助理提案（💡）**：

- 模型（[架構 §6](../../architecture.md#6-ai-的位置-細節之後專門討論)）：
  - API 直連只做 OpenAI 相容介面，免費額度、開源模型 API、本機的 Ollama 都能接。
  - 教材轉成頁面圖片加文字送出。
  - 一學期用量便宜的模型不到 1 美元，真正的成本是審核時間，所以預設模型依卡片品質挑，用對照實驗的教材比較 2～3 個候選。
  - 開源模型要檢查台灣用語。台灣的 Breeze 2 是繁中、能看圖的開源模型，但只有 3B／8B，能力可能不夠，可以列為本機候選。
- 心智圖對接（[架構 §3](../../architecture.md#3-模組邊界-第-5-步)）：
  - 用檔案對接。
  - v1 只要學習目標 ID 用 Obsidian 原生區塊 ID、格式寫進說明書當公開格式、排程狀態可以從紀錄算出。
  - 之後再由 Cards 提供介面，讓心智圖外掛查記憶狀態、寫入複習紀錄。

## 4. 區塊 ID 的顯示、上色地圖、本機模型

**使用者提出**：

1. 同一個區塊 ID，能不能在不同筆記和心智圖節點裡連結，但顯示不同的內容？
2. 喜歡心智圖節點依複習狀態變色，甚至想做進儀表板，一目了然。
3. 一般使用者沒有獨立顯卡，本機開源模型可以列為保留擴充；最主要的用途是產生語音複習材料。外掛經 iCloud 同步，模型能不能包進外掛？檔案會不會暴增？

**助理回答與提案**：

- 第 1 點：可以。`[[卡組#^id|顯示文字]]` 每個地方可以顯示不同文字，嵌入則顯示原文（包括答案）。已知限制：學習目標搬到另一篇卡組時，寫著舊檔名的連結會失效，所以外掛應以 ID 找學習目標，檔名只當提示。
- 第 2 點：顏色由 FSRS 的記憶保持率決定，心智圖外掛和儀表板共用同一套算法。💡 儀表板可以直接用教材目錄畫成地圖，不必等心智圖外掛；點紅色區域就當成複習範圍。
- 第 3 點：💡 不要包進外掛。外掛資料夾在 vault 裡，會同步到 iPhone；語音模型約 90～330 MB，語言模型要數 GB，會拖慢啟動，iCloud 也可能把大檔案從 iPhone 移除。iPhone 也不需要模型：在電腦上預先產生音檔，只同步音檔，一課 40 個字約 1～2 MB。小型語音模型（例如 Kokoro）用 CPU 就能跑，所以「沒有獨立顯卡」不影響這個用途。

**結果**：本機開源模型列為保留擴充，不在 v1，寫進 [D-055](../../decisions.md#d-055-ai-模型的選擇原則) 的補充；語音材料的做法併入[增強版的發音朗讀](../../backlog.md#增強版待討論)；上色地圖記入儀表板（之後，D-024）。
