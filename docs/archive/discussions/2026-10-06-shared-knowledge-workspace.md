# 多情境介面與共用概念筆記

日期：2026-10-06（Asia/Taipei）

本紀錄為討論摘要，不是逐字聊天。

## 使用者想法與確認

使用者在架構藍圖後，詢問能順暢承載所有學習流程的產品形式。助理提出以概念筆記為核心、依任務切換呈現方式的學習工作區。

使用者明確同意前一輪開發方向，要求往此方向開發，並以「前端 UI 與後端資料庫」重述：閱讀、整理理解與記憶等情境有不同 UI，後端使用同一份筆記資料來源，新的修正可回寫筆記；接著詢問理解是否正確。

## 前一輪提案與採用結果

以下產品方向已由使用者同意，納入 C-011：

- 主題是入口，概念是共用知識單位；同一概念可跨主題引用。
- 不同情境呈現原始材料、筆記、比較表、概念關係、教材、題目、閃卡或學習回饋，切換時保留概念與來源脈絡及位置。
- 先收集再整理，可從已確認部分開始學習，不要求填完所有欄位或固定走完整套流程。
- 介面聚焦當下任務；回饋可直接接到相關概念、來源與補強操作。
- 修訂可回寫筆記；概念更新後提示受影響材料，涉及內容正確性的衍生修改由使用者確認。

採用理由：讓同一份知識能從輸入延續到整理、練習及回饋，減少搬移資料與重複維護的負擔。這是設計目的，尚未以實際使用驗證。

## 本輪助理說明與待細化提案

使用者的前端與後端類比正確，描述了操作介面與共用資料的分工；是否使用遠端伺服器、哪一種資料庫或檔案格式，仍待技術選型。

為具體化回寫行為，助理提出以下資料分類說明，欄位與保存方式尚未確認：

| 資料 | 內容與更新方向 |
|---|---|
| 概念筆記 | 知識內容、解釋與概念關係；確認的理解修訂回寫此處 |
| 題目與教材 | 題幹、答案、解析或互動內容；連回相關概念，修訂時處理自身內容 |
| 學習紀錄 | 作答、評量、錯因與複習歷程；保留事件及當時脈絡 |

共同知識來源不表示所有資料都塞入同一則筆記，也不表示每次答錯都改寫知識內容。概念修訂與衍生材料更新需要處理邏輯；共用概念的呈現與需要重新檢查的獨立教材應區分。此說明延續 C-008 的可核對修訂及版本原則，具體同步、自動化與確認操作尚待討論。

## 後續追問：是否需要新的概念筆記

使用者接著詢問是否需要打造新的概念筆記，以承載前述流程。此為探索性提問，沒有將具體筆記模型視為已確認需求。

助理判斷應優先設計概念筆記的內容模型：保留自然的文件編輯體驗，同時讓系統能辨識來源、概念關係、版本及相關學習材料。知識正文、衍生材料與學習紀錄各自承擔不同職責。概念應可被穩定引用；是否一個概念對應一個頁面，或允許頁面內的概念片段，仍待討論。
