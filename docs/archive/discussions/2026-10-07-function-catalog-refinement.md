## 使用者要求與確認

使用者詢問新完成的 design-opportunities.md 研究是否能進一步優化功能討論目錄。助理對照最新研究與目錄，提出六項調整：提早討論共用關聯規則、新增待處理佇列、內容使用狀態、作答與排程共同設計、複習負擔控制，以及保存用途分項驗收。

助理另建議調整討論順序，在每個功能紀錄補上研究對應與採用理由、最小人工操作及具體驗收情境。使用者回覆「好，照你的意思修改」，確認依此更新。

## 採用與取捨

- 沿用學習循環與原 F-ID，新增 F-019 管理問題及處理進度；F-012 負責執行補強／修訂，F-016 處理版本與影響，F-010 保留事件。
- 手機問題區分學習需要補強與內容可能有誤；一般忘記不預設建立修題工作。
- 來源、選取及概念討論時帶入最小識別、定位、依據版本與保存原則，避免後段才補關聯。
- 收藏、候選採用、材料啟用與待核對分開；不把所有資料強制經過單一狀態序列。
- 作答條件、提示與模式需要保留，如何影響評量及排程仍待具體規則。
- 優先檢查少量材料、手機作答／回看、問題標記、電腦核對修訂及再練習的情境；同時保留 P0 與 Git 驗證。
