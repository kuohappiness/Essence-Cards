這次對話專門做 v1 開發前的「出題語法定稿」（[路線圖](../../roadmap.md#下一次對話從這裡開始)）。依 AGENTS.md 一次談一題，用真實教材的例子驗證。以下是摘要，不是逐字紀錄。

## 協調

- 開始前用 ListAgents 確認同一個資料夾還有「細節確認」、「AI 規劃」、「API 規劃」、「MVP 測試」等 session。出題語法定稿由這個 session 負責，預約 D-077～D-082；其他 session 遇到語法細節只記進 backlog。
- API 規劃剛定的 D-076 把「轉錄稿的頁碼標記與圖表錨點」交給語法定稿。試作場 T4 的轉錄提示詞原本把頁碼寫成 `%% 頁 45 %%`：閱讀模式看不到，也不能當連結目標。API 規劃已先改用暫定格式（看得到的 `p.45 ^p45`、圖的區塊 ID），正式格式在議程第 3 題定。

## 議程

1. 學習目標 ID 的寫法（D-034、D-048）
2. 學習目標底下的資料：出處、暫停、重要性、類型、備註、要打字（D-045、D-063、D-066）
3. 出處與轉錄稿：頁碼標記、圖表錨點、出處怎麼連（D-076）
4. 卡組屬性：YAML 欄位名稱、材料欄位、預設值（D-040、D-041、D-064）
5. 英文卡組：同一個字的兩個方向、例句、發音、記憶錨點（D-066、D-067、D-069）
6. 錯題本與錯題補強：位置、分數與班平均、每題的格式、卡組裡的標示（D-061、D-075）
7. 收尾：邊界規則、寫錯時怎麼處理、範圍檔的寫法

正式規範建議寫成新文件 `docs/syntax.md`，集中卡組筆記、轉錄稿、錯題本、範圍檔、複習紀錄這些公開格式。

## 途中的三個題目（使用者在第 1 題之前提出）

### 循序漸進加深（D-077）

- 使用者問：能不能靠製卡規則和檢核系統，讓 Essence Cards 像老師一樣，先從原子知識點與架構出卡，確認基礎都 OK 再疊加深度？
- 助理：可以，大半零件已經在設計裡（D-062、D-069、通用規則第 16 條、D-076 的教材庫）。提出兩種做法：甲是一次出完、程式逐層放出；乙是熟了才產生下一層。建議乙，並引用 Agarwal（2019）：只練事實題，高層次的題目不會跟著進步，所以要「基礎為主、熟一層加一層」，不是全部基礎熟了才深入。
- 使用者選乙，也很喜歡回答引用研究。使用者在 API 規劃補充：延伸內容也照同一個原則（D-083 補充）。

### 考試時程與目標保持率（D-078）

- 使用者問：為了配合考試時程，要不要開放自訂 FSRS 參數，例如把 7 天改成 5 天？
- 助理：7 天是「建議加深」的門檻，不是 FSRS 的參數；門檻由考試日期自動調整，家長隨時可以直接按加深。FSRS 的其他參數不開放（D-062）。只照排程複習，考試那天的預測保持率本來就在目標以上。
- 使用者接著要求：目標保持率可以自訂，介面要有說明；預設從 90% 改成 80%。
- 助理用 FSRS 預設的遺忘曲線粗估：80% 的間隔約是 90% 的 2.4 倍，隨時抽測的平均保持率約 89%（90% 約 95%）。引用 Pyc 與 Rawson（2009）支持較長的間隔，但指出考前抽測 ≥ 85% 的餘裕很薄，建議考前自動提高到 90%，並引用 Cepeda 等人（2008）。這修正了助理前一則「考前提高等抽測數字再說」的說法，因為那是以預設 90% 為前提。
- 使用者確認考試日期的情況：一份範圍裡可能有不同的考試日期，操作要簡單。結論：每一科可以有自己的日期、預設同一天；小考和段考可以同時存在，同一個單元看最近的考試；「自動」的規則見 D-078 的表格。

### Mindmap 當考題（D-056 補充）

- 使用者：Mindmap 也可以是考題的呈現；未來 Essence Mindmap 可以直接抓取引用。
- 助理：同意，設計已經預留（架構 §3、backlog「多種呈現方式」）。引用 Karpicke 與 Blunt（2011）、Blunt 與 Karpicke（2014）：看心智圖讀書不如提取練習，憑記憶填出心智圖則和提取練習一樣好，所以要先挖空回想。不需要改語法。

## 第 1 題：學習目標 ID 的寫法

- 助理提案 6 點：區塊 ID 寫在學習目標那一行行尾（單獨一張卡就寫在那張卡）；6 碼、去掉易混字元；家長與 AI 都不寫，程式補上；閱讀模式隱藏、編輯模式調淡；一張卡變成題目池時程式把 ID 搬到新的學習目標行；沿用家長自己的區塊 ID，複製造成的重複換新 ID。
- 使用者同意第 2～6 點；第 1 點問：一張卡自己就是學習目標時，同時有指紋又有 ID，會不會有問題？助理說明 ID（哪一種能力，排程）與指紋（哪一種問法）回答不同的問題；`apple` 是另一個學習目標，不屬於 borrow 的 ID。
- 使用者問指紋上萬時的效能：助理在電腦上實測（1 萬題約 30 毫秒；5 年紀錄全部重播約 1 秒，所以按月快取）；跨月學習不受影響，因為重播是一條連續的時間線。
- 使用者建議思考程度：平常 high，需要 xhigh 時告訴使用者。

## 第 2 題：學習目標底下的資料

- 助理提案 7 個欄位、「｜」分隔、用欄位名稱分辨資料與背面補充，使用者同意。
- 使用者：資料在卡片上會干擾學生，能不能懸停才顯示？→ 複習畫面完全不顯示資料，出處只留小圖示；使用者要求圖示有質感、介面高雅舒適，以比舊介面更好為目標。
- 使用者：簡寫和完整寫法有不同的規則，會增加家長負擔，希望一套規則適用全部，最上層一律是學習目標（例如 `borrow 英翻中`）；也問「重要性」屬於學習目標還是題目。→ 助理同意，規則縮成兩條；重要性屬於整個學習目標。
- 使用者：卡組筆記像資料庫，要完整、一致，不用顧慮行數。
- 使用者提議在學習目標前面加 `[學習目標]`。助理建議用樣式標示、不寫進文字（結構已經說明，重複資料容易不一致）。助理在測試 vault 用 CSS 示範，使用者可以接受（標籤換行的小問題留到正式外掛）。
- 結果寫成 D-079。

## 第 3 題：出處與轉錄稿

- 助理用 T4 的〈2-2 水溶液〉轉錄稿提案：頁碼 `p.44 ^p44`、圖表例題用課本編號當 ID、圖檔名含冊別與單元；出處寫短的，由程式透過「材料」轉成連結。
- 使用者問區塊 ID 的功能，以及不同筆記都有 `^p44` 會不會混亂。助理說明連結一定帶筆記名稱，錨點只需要同一篇不重複；學習目標 ID 才要整個 vault 不重複。
- 使用者同意，寫成 D-080。

## 第 4 題：卡組屬性

- 助理提案 6 個屬性（年級學期、科目、單元、材料、狀態、分類）與預設值；檔名加冊別與科目。
- 使用者問分類是不是 AI 產生、家長能不能編輯 → 家長決定，AI 只能從已用過的分類挑。
- 使用者問會不會汙染 vault → 屬性值不進標籤面板；名稱維持「分類」。
- 使用者問有沒有批次修改 → 補上卡組層級的批次改狀態、分類，以及分類改名或合併。
- 寫成 D-081。

## 第 5 題：英文卡組與朗讀

- 助理提案方向寫在名稱裡（「borrow 英翻中」），刪掉「作答」欄位；使用者同意，並問「打字」標籤的必要性 → 名稱已說明，拿掉。使用者的風格：每個功能都要有必要存在的意義。
- 助理提議刪掉 AI 輸出的「發音」那一行；使用者問刪的是哪種發音，並強調會念很重要，希望有聲音。助理引用 MacLeod 等人（2010）的產出效應，提議 v1 用系統語音、音檔留到增強版；喇叭按哪個念哪一段，中翻英打字確認前不能播。
- 使用者問增強版能不能乾淨拿掉 v1 的朗讀 → 做成可以替換的元件；問電腦能不能用 → AI 實查使用者的 Windows 只有中文語音，需要自己安裝英文語音，寫進說明書。
- 使用者問數千個音檔的效能與管理 → 估計約 6,000 個檔、100 MB，可以管理，但先試聽系統語音。
- 助理做了試作外掛（T6），使用者在 iPhone 上聽了覺得音質很好：v1 用 iPhone 朗讀，音檔暫停、不列入開發計畫；說明書也要教 iPhone 換高品質語音。使用者下載加強版語音後聽起來一樣，待確認。
- 寫成 D-082。

## 第 6 題：錯題本與錯題補強

- 助理提案錯題本的位置、屬性、每題的欄位、「錯題補強」欄位放在學習目標上；在測試 vault 做了示範。
- 使用者問錯題本裡的卡片語法會不會被排程（不會，系統資料夾）、資料夾結構、錯題照片要不要進 vault（不進）、不同科目是否有不同錯因（全科共用六類，各科規則說明常見情況）。
- 使用者問考試範圍和錯題本有什麼不同，並提議把「範圍」改名為「考試範圍」，助理同意。
- 寫成 D-088。

## 第 7 題：收尾細節

- 助理起草 13 條邊界規則與寫錯時的處理，使用者同意，寫成 D-089。

- 使用者希望保留候選，讓家長很快看過、合適就採用；助理估計成本很小，提議放在摺起的引言框、一鍵加入。使用者要求標題只寫「候選卡片」，並要求所有 AI 製卡都不湊數。
