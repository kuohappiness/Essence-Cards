# 2026-10-06｜模型與任務分工

日期：2026-10-06（Asia/Taipei）。本文件為討論摘要。

## 使用者想法

使用者詢問：以 Astra 極高提問時，是否可以把 GitHub 同步等較簡單的任務交給 6.1 Sol，以節省 token。助理提出分工後，使用者明確同意本專案採用，並詢問是否需要寫進專案設定。

## 助理提案與取捨

- 架構設計、需求釐清及重要取捨由使用者選擇的 Astra 極高處理。
- 已確認結論的大量文件整理、範圍明確的程式修改等任務，適合在工作量足夠時委派 6.1 Sol，使用低至中等推理強度。
- GitHub 提交、推送、重新產生 HTML 等短小操作，直接使用工具或腳本即可；委派的交接成本可能超過任務本身。
- 子代理若未指定模型與推理強度，會繼承主代理設定。因此委派時應明確指定，不把啟動子代理等同於使用較輕模型。
- 子代理需要讀取上下文、執行及回報；較輕模型不代表總 token、費用或訂閱額度必然減少。實際節省程度未驗證。

## 已確認結果

使用者授權本專案按照以上原則分配任務。規則寫入 [AGENTS.md](../../AGENTS.md#模型與任務分工)，作為後續協作者的依據；不必每次重新詢問是否可依規則委派。

此為代理的協作規則，不是對話主模型的自動切換設定，也不是未來學習工具的 AI 服務選型。分工規則的文件整理由主代理直接完成；後續手機預覽問題的程式修正，則依此原則委派 6.1 Sol，主代理負責文件、整合與提交。

## 查核依據與限制

本次詢問已查閱 [OpenAI 官方子代理說明](https://learn.chatgpt.com/docs/agent-configuration/subagents)，確認可指定子代理模型與推理強度，以及多代理工作的額外 token 消耗。官方文件未據此保證本專案可以節省多少訂閱額度。

規則需由支援並讀取 AGENTS.md 的代理執行；模型可用性仍依當次環境。指定模型不可用時需明確告知，不能宣稱已使用。
