# 2026-10-06｜手機檔案預覽空白問題

日期：2026-10-06（Asia/Taipei）。本文件為討論摘要與修正紀錄。

## 使用者回報

使用者在手機 ChatGPT 中開啟 index.html，截圖可見設計討論平台標題與切換按鈕，但下方沒有卡片內容；同一文件在電腦可顯示。

## 檢查與判斷

- 已確認的程式問題：舊版 HTML 的看板容器起初為空，全部卡片與版本日期依靠 JavaScript 產生。因此腳本未執行或在啟動時出錯，都可能只留下外框。
- 對手機環境的推測：截圖與檔案預覽未執行腳本的情況一致，但未直接檢查使用者手機的執行環境，不能把此原因當作已證實的平台限制。
- 公開網站尚未啟用成功：檢查當時 GitHub 工作流程的發布步驟因 Pages 查詢回傳 Not Found 而略過；預期 Pages 網址回傳 HTTP 404。此問題與手機檔案預覽相容性分開處理。

## 修正方式

- 從相同 Markdown 資料來源，在產生階段直接把點子、目前任務、已確認共識及參考軟體全文寫進 HTML，包含版本日期。
- 完整內容在未執行腳本時即可閱讀，不依賴 noscript 區塊或互動式展開。
- 互動看板成功啟動後才切換顯示，避免未啟動的按鈕造成誤解；啟動失敗時保留全文。
- 沿用既有內容篩選、來源連結與安全文字處理；討論歷史、暫緩任務及已取代共識不嵌入網頁。
- 依已確認的模型分工，由 6.1 Sol 處理產生程式、範本與回歸檢查，主代理處理文件、整合及 GitHub 提交。

## 驗證與後續

新增檢查涵蓋靜態全文、來源連結、安全文字處理，以及腳本正常、未執行和初始化失敗的情況。瀏覽器檢查在桌面與手機視窗尺寸執行；這些檢查不等同於使用者 iPhone 上的實機驗證。

GitHub Pages 的一次性設定仍由 [T-004](../tasks.md) 追蹤。啟用網站後，可用 Safari 開啟正式網址使用完整互動功能。
