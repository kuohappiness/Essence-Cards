# Essence Cards｜學習循環與功能藍圖

更新日期：2026-10-06（Asia/Taipei）

目前狀態：共用知識基礎、學習紀錄與回饋方向（C-008）及整體學習循環的呈現方式（C-009）已確認；其餘具體功能、介面、資料欄位與開發順序仍為候選提案，收錄不表示採用。

視覺總覽見[知識學習架構藍圖](diagrams/README.md)，依使用者手繪圖與本次確認的方向重繪。

## 整體學習循環

以「輸入 → 整理 → 學習 → 回饋」為主軸。來源經整理成概念筆記，連接比較表、教材、記憶卡與題目；學習活動留下紀錄，再依紀錄補強、修訂並安排下一輪學習，形成持續循環。這些是相互連動的功能環節，操作可依需要分支與返回。

| 循環環節 | 要解決的問題 | 功能與產出方向 |
|---|---|---|
| 輸入 | 如何帶入想學的內容並追溯原文？ | 文字、網頁、文件、圖片、影音、真題與既有筆記；來源定位 |
| 整理 | 如何理解內容並建立關係？ | 概念筆記、相似概念關聯、比較表與層級綱要 |
| 學習 | 如何理解、回想、應用並留下紀錄？ | 互動教材、記憶卡、模擬考題、作答、評量與學習紀錄；具體形式與欄位待討論 |
| 回饋 | 如何補強、修訂及安排後續學習？ | 錯因診斷、筆記與材料更新、間隔複習、主題復盤及後續計畫；可回到整理或學習 |

活動可分支、往回修正，也可從既有筆記、練習或複習進入；不要求每次依序走完。介面入口與具體操作仍待討論。

## 使用者提出的五點原意

1. 消化來源資料，寫成概念筆記，相似概念關聯、建立比較表。
2. 出模擬考題閃卡，根據真題、筆記，以及歷次錯題。
3. 針對錯題加強學習，寫回概念筆記。
4. 複雜概念做成互動式網頁；需背誦資料做成記憶卡。
5. 定期復盤，掃描每個主題的學習狀況與錯誤率，安排下週學習進度。

以上保留使用者提出的功能方向；欄位、題型、評分規則、自動化程度與第一版範圍尚未決定。

## 共用概念筆記與學習紀錄｜方向已確認，細節待討論

已確認的方向（C-008）：來源、概念與學習材料共用關聯；保存學習紀錄；評分、排程與主題復盤分工；依錯因補強；修訂可核對並保留版本；使用者可選擇整理與產出哪些材料。以下較細的關聯形式、資料分類與 AI 操作仍需逐項釐清。

以「主題 → 概念筆記 → 相關學習活動」串接整體學習循環，概念筆記作為持續改善理解的位置：

- 一則概念筆記可參考多份來源，保留原文定位。
- 一個概念可有多個相關概念、比較表、互動教材、考題與記憶卡。
- 一道題目可涉及多個概念；作答紀錄保留與題目及概念的關係。
- 答錯時能回到概念及來源，診斷後提出補強與筆記修改。
- 筆記修正後找出受影響的題目、卡片及教材；保留修改前後與舊作答紀錄。
- 互動教材與記憶卡可在初次學習或錯題補強時製作。
- 收進來的內容可區分收藏備查、需要理解及需要長期記住，避免所有內容都變成複習任務。
- AI 可協助草擬重點、解釋、關聯、題目與診斷；使用者可核對、修改並決定是否採用。

待討論：概念如何拆分與合併？筆記有哪些內容？既有筆記如何匯入？修改影響哪些學習材料？如何保留版本與來源？

## 考題閃卡與記憶卡｜助理提案

| 類型 | 主要目的 | 功能方向 |
|---|---|---|
| 考題閃卡 | 檢驗理解、判斷與應用 | 真題與生成題區別、情境與變式問題、解析、評分要點、錯題紀錄 |
| 記憶卡 | 練習快速、準確地回想 | 定義、名詞、順序、公式、圖片構造等；題型與複習規則待決定 |

兩者可連回相同概念筆記；作答紀錄與排程如何整合尚未決定。換問法或情境的檢驗用來觀察是否能應用，不能只根據熟悉原題的正確率推定完全掌握。

## 三個主要入口｜助理提案

| 入口 | 使用目的 | 內容方向 |
|---|---|---|
| 今日學習 | 開始今天的學習 | 待複習卡片、預定練習、待補強概念、上次未完成內容 |
| 主題工作區 | 深入整理主題 | 來源、概念筆記、關聯、比較表、互動教材與考題 |
| 學習回顧 | 檢視成果並調整方向 | 主題進度、錯誤分布、反覆出錯概念與下週計畫 |

以上是未來學習工具的介面提案；現有 index.html 仍為設計討論平台。軟體平台、桌面與手機形式、首頁與導覽結構尚未確認。

## 困難點與處理方向｜助理判斷，待驗證

| 面向 | 主要困難 | 處理提案 |
|---|---|---|
| 多種來源 | 各格式、版面及取用方式不同；部分內容無法自動取得 | 分批支援來源，保留貼上、上傳與人工修正入口 |
| 概念整理 | 拆分、關聯與比較可能遺漏條件或建立錯誤關係 | AI 草稿、使用者修正、回原文核對 |
| 互動教材 | 內容正確、操作、手機顯示及執行隔離都需要驗證 | 先做有限互動模板，之後擴充客製網頁；隔離執行與操作檢查 |
| 出題與評量 | 題意、答案、難度與開放式回答評分可能不可靠 | 保留依據與評分要點，區分真題和生成題，容許申疑與修正 |
| 錯題診斷 | 答錯可能是理解、混淆、遺忘、讀題，也可能是題目或答案有誤 | 協助判斷原因，不把每次答錯直接當成概念錯誤 |
| 寫回與連動 | 錯誤修改可能傳到筆記及多份材料 | 提出可檢查的更新，保留版本並標示受影響材料 |
| 復盤判斷 | 錯誤率受題數、難度、提示、熟悉題目及時間影響 | 同時看紀錄與錯因，資料不足時明示，避免單一掌握百分比 |
| 學習排程 | 每週可用時間與複習負擔不同 | 每週計畫與平日複習分開；份量可控制，建議可調整 |
| 資料保存 | 匯出後可能失去關聯、附件或學習紀錄 | 筆記、附件、卡片、紀錄及關聯可備份、匯出與還原 |
| 成效 | 有功能不表示已證明提升學習或考試表現 | 以真實教材與延後回想、變式題等方式驗證；細節待規劃 |

助理目前判斷最需要驗證的是「正確診斷學習缺口並提供有效補強」。這不是已驗證的性能結論，也沒有工期、成本或準確率承諾。

## 分階段開發｜助理提案，範圍未確認

先接通完整學習循環，再深化各模組，不將候選完整藍圖當成第一版全部交付承諾。

| 第一版候選 | 後續深化候選 |
|---|---|
| 文字與基本文件匯入、來源定位 | 複雜版面、影音與更多網站匯入 |
| 可編輯筆記、手動關聯與比較表 | 跨來源整合、重複與矛盾偵測 |
| 記憶卡、少量互動模板 | 更多互動形式與客製模擬 |
| 基本題型、作答與錯題紀錄 | 高品質變式題、開放式回答評量 |
| 訂正後提出筆記更新建議 | 關聯教材影響檢查與協助修訂 |
| 基本複習排程、每週回顧與可調整計畫 | 更細緻的弱點分析與個人化安排 |

## 研究依據與產品假設

- [Roediger 與 Karpicke，2006：Test-Enhanced Learning](https://www.psychologicalscience.org/journals/psychological-science/j.1467-9280.2006.01693.x/)：原研究在文章學習的延後測驗中觀察到回想測驗優於反覆閱讀；不能直接當作本產品已有效的證據。
- [Cepeda 等，2006：Distributed practice](https://www.yorku.ca/ncepeda/publications/CPVWR2006.html)：分散練習研究顯示練習間隔與保留時間共同影響回想；未據此選定本產品算法或固定間隔。
- [MDN：CORS](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS)：瀏覽器讀取跨來源內容受存取規則限制；這不表示所有匯入方式都不可行。
- [MDN：iframe](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe)：提供嵌入及沙盒限制的技術依據；互動教材如何隔離仍需實作設計。
- [NIST AI 600-1](https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.600-1.pdf)：生成式 AI 可能以肯定語氣提供錯誤內容；來源定位與人工修正是助理提出的應對設計，並非正確性保證。
