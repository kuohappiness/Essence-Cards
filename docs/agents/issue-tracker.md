# 工作項目在哪裡

本專案不用 GitHub Issues。給 skills（例如 `code-review`）參考：

- **目前要做的事**：`docs/roadmap.md` 的「現在在哪裡」。
- **待決問題與點子**：`docs/backlog.md`。
- **交給 Codex 的規格**：各工作資料夾裡的 `TASK.md`（例如 `experiments/t4/TASK.md`）。審查 Codex 的分支時，用對應的 `TASK.md` 當規格。
- **已確認的決定**：`docs/decisions.md`（D-ID）。commit 訊息裡的 `(D-xxx)` 指的是這裡的條目。

skill 說要「發布到 issue tracker」時，改成更新上面對應的文件；說要「抓取 ticket」時，讀對應的 `TASK.md` 或 D-ID 條目。
