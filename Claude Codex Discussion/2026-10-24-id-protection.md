## 1. 問題

學習目標 ID 是寫在目標那一行最後的 Obsidian 區塊 ID（`- 能說明擴散現象 ^k3m9x2`），複習紀錄只靠它對到目標（D-034）。現在的規則：

- 家長手寫不用寫 ID，「存檔時由程式補上」（D-034）。
- 解析只認**行尾**的 ` ^xxx`（W2）；不在行尾就當作沒有 ID。
- 補 ID 用 `assignIds`：沒有 ID 的目標配新的，`taken` 擋掉別篇的與紀錄裡出現過的。

會出事的地方：

1. **時機**：Obsidian 打字時自動存檔，沒有「存檔」這個動作。照存檔時機補，家長還在打字時，ID 會插在游標所在的行尾，最上層直接寫的題目（implicit）會被往內縮。
2. **補完之後被弄壞**：家長之後點到行尾接著打字（`- 能說明擴散 ^k3m9x2 的現象`）、按 Delete 刪到 ID、在別的編輯器改、AI 重寫筆記時漏掉 ID。現在的程式會把它當成新的目標、配新的 ID，**舊的複習紀錄就對不到了**；舊的 `^k3m9x2` 還會變成名稱的一部分。

## 2. 使用者的要求與原則（2026-10-24）

- 不要「切到別篇才補」：打完常會忘記切換。提議加一個「存檔」按鈕，有按鈕反而會記得做完要存檔。
- 「把一個可能發生錯誤的決定權交給使用者的習慣來控制太不保險了。實際情況下人可能不會去注意到這件事。這有違背本軟體要最小化摩擦力。家長只需要專注在幫助孩子學習這件事。」
- Claude 原本補了一句「按鈕補 ID 時游標要留在 ID 前面」，使用者指出這仍然靠家長之後不在 ID 後面打字。

## 3. Claude 的提案

先分兩種錯：

- **弄丟複習紀錄**：不能靠任何習慣避免，要由程式擋住。
- **新卡晚一點出現在 iPhone**：可以用提醒補。

### 3-1 時機（處理第二種錯）

- 卡組筆記的標題列加「存檔」按鈕（加一個同名命令，家長可以自己綁快速鍵）。有還沒補 ID 的目標時按鈕醒目，提示「有 3 張新卡還沒存，iPhone 不會出現」。
- 離開那篇筆記時（切到別篇、關掉分頁）自動補，當備援。
- 只在電腦上補；iPhone 不寫卡組筆記（D-019；兩端同時改同一篇，iCloud 只留一邊）。啟動時不掃描補（家長可能正在另一台電腦改）。

### 3-2 三層保護（處理第一種錯）

1. **認得**（解析；iPhone 讀的時候也適用）：目標那一行最後不是 ID，但行中間有一個**程式產生格式**的 ID（空白＋`^`＋6 碼，只用 `abcdefghjkmnpqrstuvwxyz23456789`，後面接行尾、空白或不是 `[A-Za-z0-9-]` 的字；不在行內程式碼與公式裡），就當成這個目標的 ID，記一個提示。例：`- 能說明擴散 ^k3m9x2 的現象` → ID `k3m9x2`、名稱「能說明擴散 的現象」。
2. **找回**（補 ID 時，在 `state` 算好傳給 `assignIds`）：目標沒有 ID 時，看它的題目指紋有沒有出現在複習紀錄的 `v` 裡，而且那個 `lt` 現在不在任何卡組。剛好一個候選就用回那個 ID，不配新的；零個或好幾個就配新的。ID 被整個刪掉、AI 重寫時漏掉，只要題目沒改，紀錄都接得回來。D-034「刪除後不再使用」是怕新的目標繼承別人的紀錄；同一題找回原本的 ID，Claude 認為不違反它。
3. **歸位**（補 ID 時）：把跑到行中間的 ID 移回行尾。登錄進 `deckCases`，照往返與冪等測試。

接不回來的只剩：ID 不見、同時題目也全改了（等於新卡）。

### 3-3 延後

做編輯畫面的樣式（D-047）時，再把 ID 在編輯器裡藏起來、讓游標到不了 ID 後面、刪字刪不到 ID（CodeMirror 的 transaction filter）。那時可以改成停手幾秒就自動補，連按鈕都不必按。正確性不靠這一步。

### 3-4 影響

- W5 要多改卡組模組（解析與 `assignIds`）與 syntax.md §2-3；屬於資料格式與寫回筆記，W5 的 L2 一起審。
- 寫成一條決定（D-034 的補充或新的 D-ID，由 essence-decision 判斷）。

## 4. 想請 Codex 回應的問題

1. **時機**：存檔按鈕為主＋離開筆記備援，你同意嗎？還是有更好、更不靠習慣的時機（例如現在就停手幾秒自動補，或別的做法）？
2. **認得**：這個格式會不會誤認家長本來就寫的內容（例如數學、化學式、英文縮寫）？有了「找回」，「認得」還需要嗎？
3. **找回**：
   - 「現在不在任何卡組」怎麼判斷才不會在 iCloud 還沒同步完、或卡組暫時讀不到時誤判？
   - 一個指紋對到好幾個 `lt`、或一個目標的幾題對到不同的 `lt` 時怎麼辦？
   - 家長刻意刪掉一張卡、之後又寫回同一題，接回舊紀錄是對的嗎？和 D-034 有沒有衝突？
   - 英文的兩個方向（英翻中、中翻英）指紋不同，會不會還有互相搶 ID 的情況？
4. **歸位**：和兩台裝置同時改同一篇、`vault.process` 寫回有沒有新的風險？
5. **還有沒有漏掉的破壞方式**：例如整行剪下貼到別篇、複製整篇筆記、合併兩個目標、把一個目標拆成兩個、在 Obsidian 以外批次取代文字。
6. **範圍**：三層放進 W5 合不合適？編輯器保護延到 D-047 可以接受嗎？
7. 其他你覺得 Claude 想錯的地方。
