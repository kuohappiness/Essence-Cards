# 補上錯過就補不回來的紀錄：格式查核（Codex）

狀態：待修（2026-11-09）

查核 [任務說明](../tasks/record-gaps.md) §1、§2、§6，並依 [查核請求](../tasks/record-gaps-format-review.md) 交叉核對 §3、§4 的格式邊界。基準是 main 的請求 commit 3404c3812a49bf70e6b896dcd6519156ccaa1337、分支 claude/ai-cards-mvp 的 src/state/（bc83daa40110121dae414a37f6b85e0c9f461f7f，共同祖先 f911bf8c52084c1d8ea8512f222b194800d3b3ae），舊版是 v0.3.0（5b3dc942e3e4fb3003fd55eb121aa066ee6977df）。

§1 可沿用本機觀察與既有 set 行，開工前要定跨月回撥與首次觀察的語意。§2 可沿用專用子資料夾與 JSONL，開工前要修考試分組鍵、完整性判定和取篇規則。以下 P1 是會永久漏收或留下無法判別的證據，P2 是規格及驗收須補清楚的邊界。

## 1. 只比自己的紀錄

- **照寫本機觀察。** 別台的未來時間、同時刻的相反值，或別台的狀態紀錄先於卡組到達，都不應推進本機比較基準。卡組先到時，本機照實記，後到的外部行不再觸發同值追加。這符合 [環節 4 第 4 題](<2026-10-26-plugin-architecture.md>) 最後收斂的方向：紀錄供初始化，之後比本機最後一次有效觀察，待寫的一筆算在內。任務說的「偏離」主要是怎麼存取這個基準，M4 初稿的全庫最後一筆已在後續回覆修正。
- **P1｜月份順序會讓同一筆一直追加。** 以現行 createLogWriter 加 §1 比較規則重現。11/01 本機檔最後是啟用，重開後時鐘回到 10/31，看到暫停，連三批都寫進 10 月檔，但每次找出的最後值仍是 11 月的啟用。換時區也能把新觀察送進較早的月份。同月回撥可依實際行序比較，正常跨月也可沿用舊月份的值。建議執行中以本機最後一次有效觀察為準，包含佇列。跨重開若要保證排序，須有能跨月重建且獨立於 t 的寫入順序證據。若維持零欄位、零持久狀態，規格應明訂跨月回撥時基準可能未知，並界定怎麼補觀察，不能用最大月份或最大時間宣稱已知最後值。§4 的毫秒避撞也不提供寫入順序。[writer 與分檔](../src/core/study/log.ts#L8) · [時間格式](../src/core/study/time.ts#L5)
- **P2｜衝突、還原和換碼只代表可用證據改變。** 例：原檔剩啟用，暫停只在原檔的衝突副本或還原檔，卡組仍暫停。本機會多記一次暫停。若原檔整份不見或換碼，會再起一份基準。反過來，原檔仍是啟用、外部副本有暫停、讀到的卡組也是啟用，本機不會補出中間那段。這些都可接受為本機新觀察或觀察缺口。不要把副本或還原檔當本機可追加的檔，也不要把它們的證據丟出回測。回測應從原始來源保留裝置及檔案歸屬，還原行歸回來源檔。mergeHistory.changes 會去除同鍵變更且不保留路徑，無法單獨重建各裝置時間線。裝置碼重生時無可靠資料可認定是原機。[版本行](../docs/syntax.md#5-1-版本行) · [還原檔](../docs/syntax.md#5-3-還原檔) · [合併](../src/core/study/history.ts#L157) · [裝置碼](../src/obsidian/device.ts#L15)
- **P1｜改寫「回測用最早的那一筆」。** A 在 08:00 看到暫停、08:05 看到啟用，B 直到 08:10 才看到那份暫停，或 B 的時鐘早了十分鐘。光靠值與時間無法知道 B 記的是哪次變更，取最早也無法還原實際生效時間。建議只有證據能證明是同一次變更時才合併呈現，原始觀察仍保留。能對上裝置與已知觀察時，可用設定、卡組和目標狀態解釋當次裝置的上限或暫停。兩筆之間有未觀察、身分對不上、時鐘不可信或證據矛盾時，結果保留未知。沒有出題或作答也不足以判成忘記。尤其不要用第一次看到啟用的日期回填真正啟用日。[D-105、D-115](../docs/decisions.md#d-105-回測要用的紀錄先收好) · [複習紀錄](../docs/syntax.md#5-複習紀錄)

## 2. 基準與真正轉換

- **P1｜第一行沒有辦法區分。** 舊版目錄暫停和 AI 製卡啟用會直接記 set: status。它可能是該對象第一筆，卻是真正的轉換。反過來，首次升版、換裝置碼、改名或同路徑刪掉重建，都可能讓第一筆是看到當下的值，或誤接上前一篇的狀態。最小改寫是把無足夠上下文的行定義為「在 t 觀察到值」，遇到舊行、改名、路徑重用不把第一筆解讀成真正的生效時間。如果要分出新寫的基準與已觀察到的轉換，須有明示的證據，例如可選的基準標記並規定舊行缺欄位時是未知，再用新舊讀者驗證。沿用以目前路徑識別卡組、可靠 lt 跨篇延續的方式，不從路徑推回卡組身分。[現行目錄寫入](../src/state/index.ts#L664) · [D-115 第 3 組](../docs/decisions.md#d-115-回頭查要用的證據先收好)
- **P1｜目標缺行只能當比較預設，不能當歷史基準。** 有兩條路徑都只留下第一行「暫停」：第一次載入就已暫停，或第一次載入看過啟用、第二次才改暫停。缺行也可能是這台從未看到此 lt、ID 待處理、需要新版或使用舊版。建議接受缺行時未知，明定首次暫停行只能證明當下暫停。若要證明此前啟用，須實際保存啟用基準或可驗證的基準涵蓋範圍。不要用別台缺行覆蓋另一台的已知暫停。整篇暫停與目標欄位分開記，刪除不寫暫停。[任務 §1](../tasks/record-gaps.md#1-狀態與設定的變更紀錄要格式查核) · [最低版本](../docs/syntax.md#0-1-最低版本標記)

## 3. 哪些狀態不寫

- **P1｜卡組與目標都要區分缺省和讀壞。** 實跑 parseDeck，合法缺省、空值、暫、壞 YAML、明寫啟用的 props.status 都是 active。卡組的空值、未認得值及壞 YAML 皆有提示，但只看 status 或 props.issues 都分不出。建議在讀屬性時傳出可供紀錄端判斷的結構化結果：合法缺省、合法明寫、值無效、屬性區無效。讀取端可保留既有顯示預設。目標的 paused 也把缺省、啟用、空值與未認得值都折成 false。原為暫停，編輯到「狀態：暫」時若直接比 boolean，會誤記啟用。無效、重複或屬性區已壞時都別用預設推進觀察基準，修成合法值再比。這應使用既有欄位解析結果，避免從提示文案猜。[屬性讀取](../src/core/deck/parse.ts#L52) · [目標欄位](../src/core/deck/parse.ts#L227)
- **P2｜採用可靠身分與已確認的內容。** 卡組先排除轉錄稿和一般筆記，並明訂沒有合法目標的草稿是否仍算卡組。否則 isDeckPath 只以路徑及副檔名判斷，可能替教材寫「啟用」。目標在需要新版的篇中也應略過。permits 會看 held、incomplete、需要新版的同 ID 和重複 ID，但不以它取代 tracker 的待處理列判斷。原紀錄的最新候選如果帶不能讀的 need、值無效或尾端殘缺，勿拿它當確定的有效基準，也勿忽略歧義後拿更舊的行斷言已發生轉換。比較應保留來源順序，同時沿用 §5-2 的 need 與合法物件救回規則。[路徑](../src/core/deck/read.ts#L6) · [門檻](../src/state/index.ts#L351) · [待處理列](../src/state/ids.ts#L277) · [壞行規範](../docs/syntax.md#5-2-讀不懂的行)
- **P2｜按鈕的 saved 要明說。** 分支 claude/ai-cards-mvp 的 src/state/index.ts（bc83daa40110121dae414a37f6b85e0c9f461f7f）由 changeStatus 共用暫停和啟用入口，現行 done、saved 都直接寫行。改成只在採用時觀察後，已寫入、核對讀不到或關閉而回 saved，期間又被其他裝置改回，可能一次都沒觀察到中間值。建議在 §1 與 §6 明訂「已確認採用才記」，讓核對成功後記一次，核對到不同內容只記實際採用值。若仍要保留每次成功按鈕寫入的歷史，需明訂何時可用寫入成功本身作為同一出口的證據。啟動須等卡組及紀錄初次讀取，未讀補齊即使內容和快取相同也要再比。[核對與 saved](../src/state/writes.ts#L172) · [載入順序](../src/state/index.ts#L587)

## 4. 舊版、排程與取消

- **照寫既有 set 形狀。** Node 24.13.0 用 main 與 v0.3.0 tag 原始碼，對同一份自編卡組、作答與 undo 各加入 1,004 行，含 1,000 行卡組狀態、首次 cap／retention／filter 各一行和一行目標狀態。兩版的今日排程、重播、有效作答、取消、問題和 held／incomplete 均與各自未加行時相同。changes 多 1,004 行。設定值取本機生效的 settings，空濾網保留 []，順序照規格，semester 留到設定頁。寫純證據行不加 need。探針額外加入超版 need 的 cap 行，兩版都把紀錄標為不完整。新增格式也應在有正常及已有壞行的檔各測一份，尤其補最後一行沒有換行的檔；0.3.0 只救黏行的最後尾段，直接追加可能吃掉原作答或 undo。[讀寫格式](../src/core/study/entries.ts#L73) · [合併與救回](../src/core/study/history.ts#L171) · [目前來源接法](../src/state/index.ts#L326)
- **P2｜seen 的改變是預期行為，驗收要分開。** 兩版都會把合法目標狀態行的頂層 lt 算成用過的 ID，即使從未作答，後續配號也應避開。卡組、設定行不帶 lt。已有舊取消目標、重讀與增量須一致。§4 若只查 history.reviews 和 changes 會漏掉已取消作答的 t，因為 reviews 已過濾，且 cancelled 保存的是 undo 指向的字串，沒有取消行本身的 t。舊 undo 指向不存在的 t 時，重用那個 t 會直接吃掉新作答。建議把本機原始可辨識的事件時間及既有取消引用納入避撞規格，保留各裝置同毫秒／未同步資料仍可能撞的界線。不要以最大舊時間推高每筆新紀錄。[ID 與取消](../src/core/study/history.ts#L157) · [重讀過濾](../src/core/study/history.ts#L212) · [增量過濾](../src/core/study/history.ts#L247)

## 5. 切面的檔

- **P1｜檔名鍵不能直接用識別碼或共用「無識別碼」。** 已實跑兩份無識別碼且同日的範圍，結束 A 後 chooseScope 會選 B。§2 的前綴卻會拿 A 的切面擋 B；字面識別碼等於「無識別碼」也撞。parseScope 接受手寫識別碼 term/1: A，直接放進檔名會分出路徑，Windows 也不接受其中的冒號。含空格的 ID 還會把短 ID 的前綴誤判成同一份。建議對齊 §4，用「開始日＋有 ID 的原值／無 ID 的完整範圍路徑」分組，檔名用可攜的安全鍵，具名空間分開。比對已寫檔時以合法檔頭的完整鍵確認，同一台的目標檔也不能因碰到不同鍵就算成功。保留原 ID 與 scope 路徑。無 ID 後來被補 ID 或改名時，只有證據能連起來才視為同一場，尤其不要用近似日期硬配。[分組](../src/core/catalog/scope.ts#L230) · [手寫識別碼](../src/core/catalog/scope.ts#L154) · [syntax §4](../docs/syntax.md#4-考試範圍)
- **照寫專用子資料夾與 JSONL。** t、exam、scope、start、end、units、decks、path、text 各有用途。units 明訂只取可用的單元行，照原順序，沿用 set: exam 的 unitsOf 語意，沒有把分類或看不懂的行算進去。檔頭的 decks 可驗證宣告的篇數。實跑 JSON.stringify → UTF-8 → JSON.parse，CRLF、emoji、未成對的高低代理字元、引號與反斜線都逐字還原。這個保證從 Files.read 回來的 JS 字串起算，檔案原始位元組另由備份保存。若讀取端已換掉無效的原始編碼，JSON 無法還原先前位元組。[讀取契約](../src/core/files.ts#L1) · [範圍單元欄位](../src/state/exam.ts#L43)
- **P2｜正式讀取隔離成立，更新需寫清楚。** 原位的切面在兩版都不是 isLogPath，也不是 isDeckPath，版本掃描同樣排除。更新提醒只掃考試範圍。備份會收進原始位元組；實跑 planRestore 確認缺檔會列為可補，同名異內容會擋，不走還原行或占用 ^id。實跑 changedSince 確認 --check 後新切面會要求重跑 --check，因為只豁免真正的紀錄檔。可沿用這個保守行為，補例子，不放寬 isLogPath。SUB_FOLDERS 可加指定路徑，原位有檔才有跨啟動搬移的辨識；切面名從完整日期起首，不符合通用月紀錄檔名提示。同名資料夾有重疊檔名時仍會報兩處，單獨把切面移到紀錄根層則會被當成紀錄檔，請把正確位置列入格式。開發用 dev-entry 的 logs() 目前用另一個寬鬆篩法，會把原位切面當作比對內容；若驗收用這個入口，讓它用 isLogPath。[紀錄篩選](../src/core/study/history.ts#L15) · [備份](../src/core/backup/take.ts#L69) · [還原](../src/core/backup/plan.ts#L64) · [更新](../tools/update-vault.ts#L103) · [資料夾防呆](../src/core/deck/folders.ts#L34) · [開發驗收](../src/obsidian/dev-entry.ts#L50)

## 6. 切面的時機與完整性

- **P1｜前綴命中不能代表切面已收齊。** 兩種情況不同。其一，別台的空檔、佔位、截斷檔或同一路徑的上次失敗殘檔已列得出來，§2 會永遠跳過。decks 只能在讀檔後驗證，且回測知道壞掉也救不回當天。建議只有能讀、檔頭匹配、所有 JSONL 行型別正確、篇數正確且 path 不重複的檔才可跳過。不覆寫殘檔；同裝置的基本檔名已被占用而判定無效時，另用不覆蓋的檔名。別台切面暫時讀不到時保留未知，可依規格留本機完整副本。對零篇也要定義合法且有完整檔頭。其二，A 只同步到一部分卡組，其餘連清單都沒有，unread 仍可空，A 的檔頭和行數也完全相符。B 看得到更多篇，但按 §2 會被 A 永久擋掉。建議把切面定義為每台在 t 的可見範圍，各裝置至少各留一份有效觀察，並保留差異；只在有足夠證據是同一份內容時跨裝置去重。兩台都有檔仍無法保證 iCloud 全部到齊。[Files 清單與 exists](../src/core/files.ts#L1) · [讀取等待](../src/state/reads.ts#L149) · [D-115 第 4 組](../docs/decisions.md#d-115-回頭查要用的證據先收好)
- **P1｜寫入條件要等已列出的候選都讀完。** 範圍讀取可在逾時後讓 ready() 先排程，未完成讀取在 stuck 計時前未必出現在 unread。例：A 已讀到，另一份同 ID 的提前結束副本或更早的 B 還沒讀到，照規格可能先為 A 固定切面。建議檢查首輪已 settled、相關讀取批次沒有待處理且沒有 unread，收齊或失敗恢復後重跑，即使 plan key 或讀回內容相同。背景工作應在列檔等非同步步驟後再核對同一個選定範圍、日期和採用的卡組集合，並合併同裝置同鍵的在途寫入。測試包括只改選中路徑、read 回來內容相同、讀取期間通知新篇、時間跨到 04:00 或範圍結束、另一份範圍改為選中、補齊與 today() 同時觸發。[排程及範圍通知](../src/state/index.ts#L425) · [範圍首輪與安靜狀態](../src/state/folder-files.ts#L36) · [掛起讀取](../src/state/reads.ts#L149)
- **照寫期間門檻，補日期語意。** 用 dayOf 的清晨 4 點日界與 scopePeriod 的雙端含括，單邊日期是一天。chooseScope 也可能選到尚未開始的考試，因此另驗開始日。提前結束副本可讓同 ID 整組立刻不寫。無日期、日期不合法、小考不寫。改開始日是新鍵，延期也有只改結束日的情形，應明寫同開始日照原切面。兩台可能各讀到同 ID 的不同範圍版本，檔頭保留各自的 units、scope、期間和 t。開始日過後才首次觀察時，t 可供判讀，但只回答「拍下時有什麼」。同日 04:00 後才改卡、稍後才開外掛也一樣。把「範圍的改動有 set: exam」限於外掛改檔，手改不會寫變更行，不能從目前的範圍檔補推當時所見。[日期與同組結束](../src/core/catalog/scope.ts#L230) · [範圍變更行](../docs/syntax.md#5-複習紀錄) · [D-176](../docs/decisions.md#d-176-考試範圍第二批的選擇手改的範圍檔不默默失效提前結束立刻失效)

## 7. 哪幾篇

## 8. §6 應補的回歸例子

- **狀態基準與順序。** 正常跨月、同月回撥及跨月回撥後連續通知並再重開。卡組先到及紀錄先到各一例。衝突副本、還原檔、換碼，改名後跨篇的 lt 與同路徑刪建。舊版第一筆其實是按鈕轉換，以及首次已暫停和先啟用後首次暫停。卡組與目標各測空值、非法值、重複欄位與合法缺省，不拿預設覆蓋上次已知狀態。
- **相容性與寫入。** 0.3.0、main 各驗完整行、黏行與帶未支援 need 的舊行。斷言 replay、今日順序、undo、seen、held、incomplete 和 problems。補按鈕 saved → 核對成功／核對到不同值，以及多次通知仍只追加一次。測寫入已到磁碟但回報失敗時的有效紀錄與原始行結果。補 undo 引用已不在有效 reviews 的 t、取消行本身的 t、增量後和完整重讀的有效結果。
- **切面身分與兩台。** 同日起訖、兩份無 ID、補 ID、相同 ID 有帶空白與路徑字元的手寫值、同 ID 衝突副本提前結束、只延後 end。另一台的空檔／截斷／正確頭但錯筆數或重複路徑／尚未可讀，以及它宣告的篇數正確但本機有更多已採用篇。保留有效檔、無效檔不阻止可行的寫入、同裝置兩個觸發只成功寫一次。
- **切面內容與入口。** 先排出部分範圍再補到相同文字，確認完整後仍寫。跨單元放在草稿、暫停、需要新版、無 ID 或 held 的篇，各驗是否保留及何時判未知。補零篇切面、CRLF、emoji、孤立代理字元的 UTF-8 往返，確認更新 --check 後才生成切面的行為、備份缺檔還原與同名衝突、資料夾搬移後的分類。
