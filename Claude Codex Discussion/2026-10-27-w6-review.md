### F1｜P2｜回看換卡動畫期間，數字鍵仍會改掉舊卡的評分

**軸：規格。證據：已重現（實際 Review 處理器＋Motion 替身＋真的 state／紀錄）。**

### F2｜P2｜完成畫面被固定保存，改評分與同步後仍宣稱完成

**軸：規格／設計邊界。證據：已重現（公開 Session＋真的 state）。**

**位置**：W6 `src/review/session.ts:189–195,215,256,399–405`；對照 W6 §2-5、§2-6 及 D-084 的「改成沒印象或差一點後再出」。

有兩個同源案例：

1. 自然、英文各一張。自然做完時畫面保存「自然的份完成了！／還有英文 1 張」。同步進英文答對的紀錄後，`progress()` 已是 2／2，畫面仍叫學生「接著做英文」，沒有改成全部完成與「再複習一些」。
2. 在完成畫面回看，把已做完的自然卡從 `good` 改成 `miss`，再回到目前。`progress()` 的自然已是 0／1，`state.next({ subject: '自然' })` 明確回 `card`，Session 卻還是 `kind: 'done'`，沒有恢復這科的複習路徑。

**原因**：`load()` 把整份 DoneView 存在 `finished`；`onChange()` 只清除外層 view 快取，`change()` 也只 notify。之後 `compute()` 一直優先用舊 `finished`。即使只重算完成文字，第二例還需要處理「目前沒有未作答卡、但原科目又有卡」的轉移。

**影響**：完成資訊過期；剛改成沒印象的目標可能要關掉重開才繼續出題。

**建議**：合併前修。保留「目前真的有一張未作答卡時不換卡」的規則；已完成的狀態則重新核對進度與可繼續的卡。補上述兩個案例，亦檢查 N／M 不沿用舊值。第 4 項實作選擇不能無條件套到完成畫面。

## 規格疑義與待驗證

### S1｜裸網址與全形管線的格式邊界仍不明確

**證據：解析結果已重現；是否屬於必須拒收的「連結」是規格疑義。**

`parse.ts:166–168` 完全照 W6 §0-1 列出的字元模式做，但 syntax §2-3 的上位說明是「單行英文單字或片語、不能有連結」。任務特別建議試的裸網址 `https://a.test/a|b`，實際得到 `typed: ['https://a.test/a', 'b']`、`ok: true`、沒有 problem，單打 `b` 就可被視為答對。全形 `a｜b` 則是單一答案 `['a｜b']`。

請 Fable 補清楚裸網址是否也屬於禁止的連結，並明寫全形 `｜` 是字面值還是寫錯格式；若禁止，補最小檢查與例子。不要自行擴張成完整 Markdown 解析器。本次沒有把遵循明確 marker 清單的實作直接判成 F1 格式修正失敗。

其餘新增邊界：`$5`、單一反引號、未閉合 `[[` 都拒收、`typed: null`；`A | a` 接受兩個答案；`a | two words` 只給字數 hint；含中文或去裝飾後空段停出、沒有多報字數 hint。這些結果符合目前明寫的演算法。

### S2｜iPhone 鍵盤調整的文字與現有證據沒有對齊

W6 §3-2（`tasks/w6.md:233`）指定用 `visualViewport` 調整，但新 `src/ui/` 沒有這個處理，只有固定全螢幕與 flex 版面。回查試作外掛，`visualViewport` 也只用於記錄量測，未看到調整版面的程式，因此「移植試作做法」本身不能解決這項出入。

**不能僅以缺少該 API 就斷言實機一定遮住按鈕**：Obsidian 的 iOS WebView 可能已調整可用尺寸。本次 §7 不在範圍，保留 J6 的實機驗收；Claude 應依實機結果補必要處理，或修正規格中的實作假設。未量測前不要宣稱鍵盤避讓已通過，也不建議無證據地加第二份高度調整。

### 3. 測試替身：足以支援這次斷言，但不能代表 React 19 的完整契約

**effect 順序可接受。**`tests/helpers/review-ui.ts:83–88,143–164` 以 Object.is 比 deps，layout 先於 passive，同一批先 cleanup 再 setup；對這次單一根元件的 F3 停止／朗讀順序有代表性。host 沒有包 StrictMode。本次又在真正 React 跑過 F1、F3、F7，不只依賴替身。

**useSyncExternalStore 確實可能讓不該過的測試過。**替身在 render 訂閱、通知就設 dirty，沒有比對 snapshot 身分、重訂閱或 commit 前的一致性檢查（`tests/helpers/review-ui.ts:101–103`）。隔離探針固定回傳同一個 snapshot，直接改其中的 `top.center` 再發通知：替身顯示新文字；真正 React 仍顯示舊文字。這與 [React 的 snapshot／Object.is 契約](https://react.dev/reference/react/useSyncExternalStore)一致，表示它不能驗證 snapshot 快取是否正確。這是替身的限制，沒有據此推斷目前 Session 有同一個缺陷。

**ref 也只模擬這些斷言需要的部分。**替身按 ref 物件保留假元素，移除或 keyed 子元件重掛時不清成 null，`contains` 固定 true（`tests/helpers/review-ui.ts:71–74,128–137`）；無法抓到元素消失後掉焦點或舊 ref 殘留。真正 React 會依 DOM 掛載／移除更新 ref（[官方說明](https://react.dev/learn/manipulating-the-dom-with-refs)）。因此本次用真實 DOM 補了輸入框移除後回到 `.ec-app`、返回打字卡取得新輸入框焦點及 Tab 環繞。

**建議**：保留它作為元件條件與 busy 入口的快速回歸；涉及 snapshot 身分、訂閱生命週期、ref 或焦點的改動，須用真實 React／DOM 驗證，不把這個替身的綠燈當成該契約通過。這次對應的實際組合已補測，沒有因此新增合併阻擋項。

### R1｜P2｜省略可選量測 callback，就不會執行背景重設

`onEvent` 是可選參數，但回到前景時寫成：


JavaScript 的可選呼叫在 callback 不存在時連引數也不求值，因此 `session.resume()` 一起被跳過。重現：`openReview({ app, state, pick, speech })` 不帶 `onEvent`，一般卡翻面，送 `hidden`，時鐘前進 61,001 ms，再送 `visible`。實際仍是 `revealed: true`、`shown: 0`；同例帶 callback 時，正常變成 `revealed: false`、`shown: 1`。兩例都沒有新學習紀錄。

### R2｜P3｜已排隊的鍵盤量測會在 closed 之後回報

**軸：規範與設計；證據：真實 DOM 已重現，對量測收集器的影響另經靜態核對。**位置：分支 `claude/w6` 的 `src/ui/host.tsx:81–86,95–106`，呼叫端 `src/obsidian/dev-review.ts:74–83`（`11a3ef1`）。對照這次請求第 1、2、6 點的關閉清理與量測驗收。

**建議：合併前修。**保存待處理的 rAF ID 並在 close 取消，或讓 callback 執行時先判斷已關閉就返回；若保存單一 ID，須同時考慮一幀前連續 resize／scroll 排入多個 callback。補「resize 後立即 close，等待下一幀，最後事件仍為 closed；重新開啟無上一份樣本」的案例。
