## F3　日期、提前結束與回測

**F3a｜規格推斷，清晨換日已重現。** 把 §2-2 展成下表。比較用日期本身的日編號，與 `dayOf(now, offset)` 比。基準版的 `dayOf` 實測台灣時間 10/30 03:59 是 10/29 的日編號，10/30 04:00 才是下一日。§4:221 的「結束日 03:59／04:00」須改成「結束日的下一個曆日」，避免測試早失效一天。

| 開始 | 結束 | 預期 |
|---|---|---|
| 缺 | 缺 | 日期未定，優先排範圍，不提高保持率，不自動失效 |
| 有效 A | 缺 | A～A，填好立即優先且提高，A 的下一個 04:00 失效 |
| 有效 A | 有效 B，B ≥ A | A～B（含首尾），尚未開始時也優先且提高，B 的下一個 04:00 失效 |
| 缺 | 有效 B | B～B，同一天規則。選定與檔名用原始開始還是有效開始見 F4 |
| 有效 A | 有效 B，B < A | 日期有問題，優先排範圍，不提高、不自動失效 |
| 任一邊出現不合法值 | 另一邊任意（含缺） | 日期有問題，與兩邊皆缺分開。空白／null 是否視同缺要明訂 |
| 任意 | 任意，有 `提前結束` 鍵 | 立刻排除這次考試，即使欄值空白或不能解析。原定日期保留 |

`提前結束` 的日期只到日，紀錄行的 `t` 才能指出外掛提早結束的時刻。若 11/04 02:00 按下，日曆日期是 11/04，排程日是 11/03。建議明訂檔案上的日期用本地曆日或複習日，兩者不能混用，並測試 04:00 前按下、立即失效與下一份的預勾日期判斷。家長手寫、沒同步到紀錄或紀錄寫失敗時，回測只剩日期或存在性證據，當天的切換時刻未知。D-098 與 D-105 應依 D-176 解讀，原本從日期自然失效的規則仍適用，主文的「改結束日」與不寫狀態需加上修訂指引。[任務 §2-2、§4](../tasks/exam-scope.md#2-2-考試期間) · [study/time.ts:12–17](../src/core/study/time.ts) · [D-098](../docs/decisions.md#d-098-考試範圍只用在大考日期改成考試期間) · [D-105](../docs/decisions.md#d-105-回測要用的紀錄先收好)

**F3b｜YAML 型別已重現。** 以卡組同用的 `yaml.parseDocument` 預設設定測試，裸寫 `20261028` 是 number，帶引號是 string。`2026-10-28`、斜線、點、未補零及全形寫法都是 string。空值、`null` 為 null，`true` 為 boolean，明寫 `!!timestamp 2026-10-28` 才得到 Date。若只收 JS number，`2.0261028e7` 同樣變成 20261028，十六進位也會變成數字。建議讀取時取該欄原字或 scalar 的來源，只收規格列出的日期拼法。若 `readDate` 同時收 string 和 number，number 只收八位整數，並在 YAML 接線保留字面檢查。用嚴格曆法驗證 2/30、非閏年 2/29、2028/2/29、缺年份與民國年，補測重複鍵和壞 frontmatter。欄位缺席、欄位存在但值無效、整塊 YAML 無法讀應能區分，否則可能把壞掉的提前結束讀成生效。無法安全確定屬性時，要有顯示與禁止覆寫的分支。[deck/parse.ts:1、53](../src/core/deck/parse.ts) · [任務 §2-2](../tasks/exam-scope.md#2-2-考試期間)

## F4　選定與身分

**F4a｜規格推斷。** 兩個獨立且有可用範圍的檔案同時生效時，有開始日者先、較早者先、同日按路徑。建議把有效的一日期間用於排序，僅結束日也有有效開始日。日期未定或有問題的排在有效期間後面，兩者間用固定路徑序，並測無日期平手、逆序輸入、同日大小寫路徑、只有結束日，以及最早的那份只有分類或看不懂的行。用固定字串比較，別讓系統語系影響勝者。只改名時通常不用重排，但 A/B 同日、路徑平手決勝、改名讓 B 換成勝者時，若兩份的範圍不同便應重排。應把「路徑變」的免重排限定在仍選到同一身分、排程輸入相同。[任務 §2-3、§4](../tasks/exam-scope.md#2-3-一次只有一份)

**F4b｜規格推斷。** A/B 是同一識別碼，A 已寫 `提前結束`，B 仍是舊版。先把失效檔篩掉再選會讓 B 接手，同一次考試復活。D-176 第 4 點要求立刻結束這次考試。建議先按有效識別碼分組，同身分任一副本帶提前結束時整組失效。不同識別碼的另一份若仍生效，結束後可以接手。這時原考試的倒數消失，但今天的份仍可能因另一份保持考試優先。§4 的 lane 必回平常、以及「之後再設定就是建立新檔」要限定無另一份接手，或另訂明確的處理方式。還應測同 ID 的有效副本日期／單元相異時的勝者與提示、同時改檔及跨裝置延遲到達、提前結束副本刪掉後是否允許舊副本復活。現有格式只能證明目前看得到的檔有結束標記，跨刪除仍要記得結束就需另定依據。[任務 §2-2、§2-3、§4](../tasks/exam-scope.md#2-3-一次只有一份) · [D-176 第 4 點](../docs/decisions.md#d-176-考試範圍第二批的選擇手改的範圍檔不默默失效提前結束立刻失效)
