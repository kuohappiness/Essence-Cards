## F1　辨認組名須先定分隔與括號文法（§3，開工前）

**觸發、預期與提案結果（規格推斷，真實手寫與製卡都會遇到）**

| 輸入或條件 | 預期及提案留下的問題 |
|---|---|
| `詞（意思） 字形`、`節（節日） 字義`、`寨（山寨） 字形` | 一般目標。將無分隔的括號切字會把「山寨」誤解成兩個選項，遇到恰好有挖空、答案為寨就會換題型。反過來，不切字會使漏寫分隔的 `寨（寨塞寒賽） 相似字` 降為一般目標。若靠「相似字」補救，改成 `寨（寨塞寒賽） 相似宇` 又漏認，且仍無法分辨括號內是真正的詞或一串字。 |

## F2　先判斷目標意圖與題目形狀，再分類錯誤（§3，開工前）

**觸發與實際（規格推斷）**：§3 先要求所有題目符合才辨認，接著又說「認得以後」才拒絕組內別字。若一題是 `水管＿＿住。 :: 塞`，另一題有兩格或答案在組外，規格沒說哪個分支優先；兩種順序會讓同一個目標停用或整個降成翻面。只有一題、沒有空格的普通 `台灣的首都？ :: 台北` 則應照一般卡，若只憑組名就報錯會擋掉真實的普通卡。

|---|---|
| 明確目標有有效組名，至少一題是單一可呈現空格的問答，且單行答案等於名稱詞或組內別詞 | 進入比較題檢查。每題都須符合、且答案等於本目標詞才出比較卡。組內別詞用 `pick-answer-invalid`，以該題為定位，停用該目標；也適用於其他題同時有問題的情況，避免把塞的成績記到寨（D-114）。 |

### R2-2　明確分隔的組仍會拆壞詞（F1、F6，開工前）

**依 §3 試算，實際輸入可達。** `一般型（一般型、A 型、B 型） 比較` 搭配 `這件依常態歸為＿＿。 :: 一般型`，預期三個字鍵，提案切成 `一般型、A、型、B` 後仍認得且出錯字鍵。若同組另一個目標叫 `A 型（一般型、A 型、B 型） 比較`，又因名稱詞不在拆出的組裡而漏認。英中相鄰的空白是詞的一部分。中文也有相同情況，例如手寫稿用空格標詞界的 `一般型（一般型、特 殊 型） 比較`，會認成「一般型、特、殊、型」。影響是選項及組身分改變，若主要目標的詞未被切開，這種錯不一定被提示。沒有在現有公開樣本發現這兩類寫法，屬可構造的真實科目寫法與手寫邊界。

建議頓號／逗號出現時就由它們確定項目邊界，空白可留在項目內；純空白模式仍可支援 `寨（寨 塞 寒 賽）`。若想保留「強分隔混空白」的容錯，至少把有歧義的項目提示清楚，禁止悄悄改成另一組。`寨（寨,塞，寒 賽）` 與「一個選項可以含空白」不能共用同一個無提示切法；可把標準輸入寫成 `寨（寨,塞，寒、賽）`。同理 `light（不 重）（light、lit）` 的義項會先被當清單，後面的真組被忽略，應把空白義項的限制寫明或讓只有強分隔符的括號才有資格略過前置義項。空項方面，既然規定這些分隔標點是保留字元，`寨（寨、、塞）` 沒有歧義，丟空項可結案；若將來要讓逗號本身成為字鍵，需要另外的表示法。

**方向放寬的反例。** 基準 `parseDeck` 實測 `能看出中文語序　中翻英` 加 `這裡先說地點還是時間？ :: 地點` 現在是合法一般卡。把全形空白換成 ASCII 做控制組，立即成 `zh-en`、`typed-answer-invalid`、`ok:false`，正是放寬規則對原稿的預期影響。另確認 `borrow  中翻英` 現有 `pairKey` 的確留一個尾空白，去掉能修正正常方向配對。建議兩事分開驗收：方向詞前有 ASCII 空格的既有方向修正 `pairKey`；純全形空白是否保留為方向語法要明訂。若要放寬，至少保護仍為合法一般題的案例，或提示作者確認方向，避免原卡靜默停止排程。英翻中也要測配對的變化，即使不會報打字答案錯。見 §3 第 2 點、`src/core/deck/parse.ts:132–136、219–228`。

### R2-3　also 的用途清楚，補三個寫入及讀取邊界（F4、F7，開工前）

- **「？」同時是合法組員。** 依規格試算 `？（？、！） 比較` 加 `疑問句末尾填哪個符號：你要去嗎＿＿ :: ？` 可認成比較卡，`pick:"？"` 既可表示真的點了問號，也可表示沒印象。遇到其他目標以問號為錯選，再按跳過或再選錯時，`retry` 通常能幫忙解讀，但 `pick` 欄位本身仍重疊，§6 如果用相同字串判斷，點對「？」也可能被走成 miss。建議流程用明確的跳過狀態，紀錄以 `pick:null` 代表第一次跳過、字串代表真的點了字鍵，以欄位存在辨認比較行。若保留字串哨兵，就必須保留它為禁用組員，檢查時含折寬後的 `?`。補頂層與 `also` 各自的跳過及真問號測試。見 §3 的禁用字元、§4、§6。
- **輪替按有效作答行計數。** Claude 的試算可重跑，三句 AB／CA／BC、四句 AB／CD 成立。一對一錯只改代表格，兩句仍更新，不會把錯的那一句當作唯一出過的。新增 D 時以 `AB@1, CA@2, BC@3` 為例，下次 DA；移除 B 就只在仍存在的 A、C 之間選。用取消後的有效歷史重算，`undo AB@1` 並重寫 `AB@4` 後，下一對由 AB 變成 CA，出過次數沒有變，但「最後出現」被視為改評分時間。此取捨可接受時請在 §8 寫明並測重開一致；若要保持真實出題先後，需另存原時刻。另補兩條字面相同的句子（同 `v`）的實際情境，候選及一行觀測都以不同指紋算，只有一種句子就回到一句；否則「到期兩句」可能重複同一句而灌大次數。見 §4、§5-2、`src/core/study/history.ts:164–168、194–217`。
- **三處要共享最後出題時間及次數，且與評分分開。** §4 已列 `plan.ts:113–119`（今日以前）、`session.ts:46–65`（當天）、`practice.ts:109–118`（本輪以前），讀取頂層及 `also.v` 已足以找到這三個來源，但現有 `Slot.seen` 只存時間。比較的「第一次」應明確按是否曾出題，答錯後及提早出走同一套輪替，勿走原 `last.v` 重出及 `!correct` 回基本題捷徑。到期／提早優先、`correct`、完成與 FSRS 一律看頂層 `r`；一對一錯不能因 `also` 有 good 而提前完成。§4 對 `sameReview` 請明訂比較哪些欄位。若忽略 `also.v`，同一 `t/lt/r/v`、一份副本附 B 另一份附 C，排序先遇哪份就決定 B 或 C 是否算出過，增量追加和重讀可能分歧。若仍視作一次評分，可對有效指紋作確定性的合併，保留 FSRS 一次；至少以同副本重讀與不同附加指紋的碰撞明訂預期。不必為此更改本輪已列為限制的 `undo` 同毫秒語義。

**證據範圍。** `also` 能補足 D-046 的輪替及每題觀測分母，也保留 D-115 的第一次混淆線索。第一次提交前的手滑、第二次錯選了哪項，已明說不留；題目日後改掉時不能由 `lt/v` 反推出當時期待的詞，第一輪指出的歷史範圍仍應寫明，限於仍能回查的版本即可。D-187 的一行和整首 `v` 足夠排程，選填逐格證據可等詩卡；屆時頂層代表格也要有可解出的格序（顯式寫入，或其他格完整且可唯一反推）。同句文字可重複，槽位身分與句子文字分開，整首 `v` 的出題計數只加一次。
