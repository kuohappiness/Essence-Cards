## 現況

- 目標 ID 是隨機短碼，寫成 Obsidian 的區塊 ID（`^k3m9x2`），整個 vault 不重複，刪掉後不再用（D-034）。連到目標的寫法 `[[卡組#^k3m9x2|名稱]]` 已同意（架構 §3）；錯題本的「對應」與 AI 草稿的「加進已有的學習目標」由 AI 寫 ID，存草稿時程式轉成連結。
- 目標之間現在沒有關係欄位：§2-4 只認 6 個欄位，其他「名稱：」開頭的子項目是背面補充；`先備：國一數學 比例式` 這種寫法照文字顯示（§2-5）。
- v1 的關係只是學習地圖全貌裡的句子，留在 AI 輸出快照（D-139 第 3 點：v1 不另做地點資料或圖譜）。
- 架構 §3 記下的限制：目標搬到另一篇卡組時，Obsidian 不會更新寫著舊檔名的區塊連結；對策是外掛用 ID 找目標，檔名只當提示。
- 量（Claude 粗估，請 Codex 檢查）：國小社會試用一節 15～29 個目標；一科一學期 6～10 節、同時 5～7 科，全部做成卡的話一年約兩千個目標，用十年上萬到兩萬個；每個目標平均兩三條連結，就是幾萬條。

## 1. 連結：用 Obsidian 的連結寫，外掛自己的索引讀

**💡 提案**

1. **網是資料，分層是看法**：關係寫在目標上，學習地圖的分層與縮放從網畫出來；「地圖跟著卡組」（D-136）自然成立。一張卡仍只測一個目標（D-114）。
2. **只寫一邊**：寫在比較新、比較高的目標上（B 寫「站在 A 上」，大目標寫「包含 A、C」），反方向由外掛算。「相關」沒有方向，寫在比較晚建的那一個上。好處：資料只有一份（D-141）；加連結不必改舊學期的卡組。
3. **三種連結**，種類寫在欄位名稱：
   - **先備**：B 站在 A 上。B 常錯時追到 A（[D-087](../docs/decisions.md#d-087-錯因加先備知識不足)），課外層等 A 熟了才出（D-136）。
   - **包含**：大目標的判斷一定要想起小目標。之後可能讓大目標的複習替小目標記一部分（主文的第四種關係；要改排程與回測，另談）。
   - **相關**：放在一起看，例如同一個地點在不同單元的特色、容易混淆的兩個目標。
4. **寫法沿用 Obsidian 的區塊 ID 連結**，例如：

   ```markdown
   - 能用密度與浮力判斷物體的浮沉 ^b4n7c1
       - 出處：p.62｜類型：因果
       - 包含：[[國二上自然 1-3 密度（卡片）#^d2k8m1|能用密度比較物質的輕重]]、[[國二上自然 3-2 浮力（卡片）#^f5p3q9|能說出浮力的方向]]
   ```

   欄位放同一行還是另起一行、叫什麼名稱，都還沒定；例子只是讓問題具體。
5. **外掛從檔案建索引**：ID → 在哪一篇哪一行、每條連結的種類與方向、反向連結。索引每次從檔案算，不另存資料庫。用 ID 找目標，連結裡的檔名只當提示；檔名過時時，外掛改寫成新的檔名（照 D-149 第 7 點：只在電腦、家長按按鈕、先看會改什麼、先備份）。
6. **誰寫**：AI 提出、家長確認、外掛寫進檔案；家長與學生都不手打連結語法。
7. **v1 可以做的一小步**：AI 製卡時，地圖全貌裡的關係句點名目標（已有的寫 ID）與種類，之後轉成連結就是機械式的工作。

**不做的話**：關係只是各節快照裡的句子，程式讀不到；跨單元的關係每次都要 AI 重新找，常錯時追不到先備；地圖的視覺化也只能畫單節。

**做的代價**：syntax 多一到三個欄位；解析、索引、反向連結與檔名修復；AI 多輸出、家長多審。

**更小的做法**：只做第 7 點，其他等真的有跨年級的卡組（現在只有國二上）再做。

**要 Codex 判斷**：

1. 「Obsidian 連結寫、外掛索引讀」對不對。其他做法：(a) 全靠 Obsidian：屬性區列連結，用反向連結窗格與關係圖看；(b) 外掛另存一份關係資料（JSON 或一篇專用筆記）；(c) 每節一篇地圖筆記，關係寫在地圖筆記裡、不寫在目標上。Claude 傾向寫在目標上，理由是地圖跟著卡組、目標搬家時關係跟著走；(c) 的好處是卡組檔不變、AI 輸出地圖時一次寫完。
2. 只寫一邊有沒有漏洞：A 被刪掉或合併時，指向它的連結散在很多篇，外掛要找得到（索引做得到嗎）；「相關」由比較晚建的那一個寫，兩邊都被寫了一次怎麼辦。
3. 三種夠不夠、有沒有多：包含是不是先備的特例（包含一定也是先備？），可不可以只用「先備」加一個「複習時一定用到」的標記；「相關」要不要變成資料，還是只留在地圖的句子裡，等真的有用途再說。
4. 相容（D-149 第 3 點）：舊版外掛會把 `包含：…` 當背面補充顯示。這只是畫面多一行，還是算「讀錯」？如果之後包含會影響排程，舊版的 iPhone 和新版的電腦就會排出不同的到期日，那就是讀錯，要用 `需要版本`。欄位名稱要不要現在先保留（v1 的解析器先認得名稱、不顯示），讓之後不必等每台裝置換版？
5. 索引的量：幾萬條連結，在 iPhone 上每次打開都從檔案算，負擔多大？外掛現在怎麼讀卡組（每次全讀，還是只讀範圍內的），請查證。用 metadataCache 的 links／blocks，還是外掛自己的清單解析（[D-135](../docs/decisions.md#d-135-清單解析和-obsidian-對照後的處理) 已經記下兩者不一致的地方）？

## 2. 連結的整理系統

**使用者的原話**：

> 應該也要有一個連結的整理系統，專門整理優化日後過於龐大的連結

**語意**（Claude 整理）：連結會隨年級越積越多。要有一套專門的機制定期整理，讓網保持正確、好用，不會大到沒人看得懂，也不會越來越亂。

**連結變多以後會壞在哪裡**（Claude 列，請 Codex 補）：

| 問題 | 例子 | 後果 |
|---|---|---|
| 斷掉 | 指向的目標刪了、合併了，或搬到別的卡組、檔名過時 | 點不過去；索引用 ID 還找得到的，只是顯示問題 |
| 重複的目標 | 當初 AI 沒看到舊的，同一個判斷建了兩個（主文第 3 種情形） | 孩子複習兩次，進度分成兩份 |
| 迴圈 | A 先備 B，B 又先備 A | 層次排不出來 |
| 多餘 | A 先備 B、B 先備 C，又直接寫了 A 先備 C | 地圖變亂；資料本身沒錯 |
| 太多「相關」 | 一個目標連到幾十個 | 看了等於沒看 |
| 錯的連結 | 證據對不上：B 一直熟、A 一直錯，「B 站在 A 上」可疑；被包含的小目標單獨考常錯 | 先備追錯方向；之後如果替小目標記複習，會把忘了的當成熟了 |
| 漏掉的連結 | 兩個目標的錯因常是「觀念混淆」，彼此卻沒有連結 | 錯題補強看不到該一起看的目標 |

**💡 提案：分三層，越往下做得越少**

1. **外掛每次建索引時檢查，不用 AI**：斷掉、迴圈、連到自己、連到暫停或已刪的目標、同一條寫了兩次。只有改檔名提示這種機械式的修復由外掛做（照 D-149 第 7 點）；其他列在入口的「提醒」一區（[D-163](../docs/decisions.md#d-163-入口與目錄的四批開法全部卡的一輪與提醒一區)），家長點一下處理。
2. **AI 定期整理，家長審**：學期初或目標數量過了門檻時，AI 提出候選：重複的目標、漏掉的連結、多餘的連結、種類寫錯、證據對不上的連結。每次只送一小塊網（一科，或一個目標的鄰居），不送整張網。家長一批一批核可；整理前先備份（[D-150](../docs/decisions.md#d-150-備份與還原)），AI 的原始輸出照舊存快照，改錯了能還原、能追查。
3. **畫面上的簡化不刪資料**：「看起來太多」靠地圖的縮放、只顯示直接的連結解決，不為了畫面好看刪資料。資料錯了才由第 1、2 層改。

**合併重複的目標**（主文第 3 種情形，請 Codex 一起看）：留下複習比較久的那一個，把另一個的題目搬過去，刪掉另一個；它的複習紀錄照樣保留。Claude 認為不必改 D-126：D-126 管的是兩個不同的判準合成一個新目標；真的重複時判準本來就一樣，留下的 ID 與進度都不變，和題目池加題相同。刪掉的 ID 不再用（D-034），指向它的連結要改指留下的那一個。要不要在留下的目標上記「合併自 xxxxxx」，讓舊紀錄、舊連結與錯題本的「對應」都找得到？

**不做的話**：斷掉的連結大多只是顯示問題，索引用 ID 找得到；真正有害的是重複的目標（多複習一份）與錯的包含（如果之後做了替小目標記複習）。目標還少的前幾年，第 2 層幾乎沒事可做。

**做的代價**：第 1 層是索引的一部分，多寫的不多；第 2 層多一種 AI 呼叫、一種審核畫面與整理紀錄，用量隨網變大。

**更小的做法**：只做第 1 層；重複的目標先靠製卡時的候選比對擋在入口（[「AI 看得到舊目標的什麼」](../docs/backlog.md#其他待決)）；其他候選等目標過了某個數量，或真實資料看到問題再做。

**要 Codex 判斷**：

1. 上面的問題清單漏了什麼；哪些外掛自己判得出來，哪些一定要 AI。
2. 用複習紀錄驗證連結（「B 熟、A 常錯」）可不可行：要多少筆紀錄才判得出來，自評的雜訊（D-114）會不會讓它沒用。
3. 定期整理（學期初）和事件觸發（加一篇卡組時只看它的鄰居）哪個比較好；要不要兩個都做。
4. 合併重複的目標不必改 D-126，這個解讀對不對；「合併自」要不要記、記在哪裡。
5. 除了改檔名提示，還有沒有什麼應該自動做、不必家長審的。
