## 現況

- 目標 ID 是隨機短碼，寫成 Obsidian 的區塊 ID（`^k3m9x2`），整個 vault 不重複，刪掉後不再用（D-034）。連到目標的寫法 `[[卡組#^k3m9x2|名稱]]` 已同意（架構 §3）；錯題本的「對應」與 AI 草稿的「加進已有的學習目標」由 AI 寫 ID，存草稿時程式轉成連結。
- 目標之間現在沒有關係欄位：§2-4 只認 6 個欄位，其他「名稱：」開頭的子項目是背面補充；`先備：國一數學 比例式` 這種寫法照文字顯示（§2-5）。
- v1 的關係只是學習地圖全貌裡的句子，留在 AI 輸出快照（D-139 第 3 點：v1 不另做地點資料或圖譜）。
- 架構 §3 記下的限制：目標搬到另一篇卡組時，Obsidian 不會更新寫著舊檔名的區塊連結；對策是外掛用 ID 找目標，檔名只當提示。
- 量（Claude 粗估，請 Codex 檢查）：國小社會試用一節 15～29 個目標；一科一學期 6～10 節、同時 5～7 科，全部做成卡的話一年約兩千個目標，用十年上萬到兩萬個；每個目標平均兩三條連結，就是幾萬條。

## 1. 連結：用 Obsidian 的連結寫，外掛自己的索引讀

**💡 提案**

1. **網是資料，分層是看法**：關係寫在目標上，學習地圖的分層與縮放從網畫出來；「地圖跟著卡組」（D-136）自然成立。一張卡仍只測一個目標（D-114）。
2. **只寫一邊**：寫在比較新、比較高的目標上（B 寫「站在 A 上」，大目標寫「包含 A、C」），反方向由外掛算。「相關」沒有方向，寫在比較晚建的那一個上。好處：資料只有一份（D-141）；加連結不必改舊學期的卡組。
3. **三種連結**，種類寫在欄位名稱：
   - **先備**：B 站在 A 上。B 常錯時追到 A（[D-087](../docs/decisions.md#d-087-錯因加先備知識不足)），課外層等 A 熟了才出（D-136）。
   - **包含**：大目標的判斷一定要想起小目標。之後可能讓大目標的複習替小目標記一部分（主文的第四種關係；要改排程與回測，另談）。
   - **相關**：放在一起看，例如同一個地點在不同單元的特色、容易混淆的兩個目標。
4. **寫法沿用 Obsidian 的區塊 ID 連結**，例如：

   ```markdown
   - 能用密度與浮力判斷物體的浮沉 ^b4n7c1
       - 出處：p.62｜類型：因果
       - 包含：[[國二上自然 1-3 密度（卡片）#^d2k8m1|能用密度比較物質的輕重]]、[[國二上自然 3-2 浮力（卡片）#^f5p3q9|能說出浮力的方向]]
   ```

   欄位放同一行還是另起一行、叫什麼名稱，都還沒定；例子只是讓問題具體。
5. **外掛從檔案建索引**：ID → 在哪一篇哪一行、每條連結的種類與方向、反向連結。索引每次從檔案算，不另存資料庫。用 ID 找目標，連結裡的檔名只當提示；檔名過時時，外掛改寫成新的檔名（照 D-149 第 7 點：只在電腦、家長按按鈕、先看會改什麼、先備份）。
6. **誰寫**：AI 提出、家長確認、外掛寫進檔案；家長與學生都不手打連結語法。
7. **v1 可以做的一小步**：AI 製卡時，地圖全貌裡的關係句點名目標（已有的寫 ID）與種類，之後轉成連結就是機械式的工作。

**不做的話**：關係只是各節快照裡的句子，程式讀不到；跨單元的關係每次都要 AI 重新找，常錯時追不到先備；地圖的視覺化也只能畫單節。

**做的代價**：syntax 多一到三個欄位；解析、索引、反向連結與檔名修復；AI 多輸出、家長多審。

**更小的做法**：只做第 7 點，其他等真的有跨年級的卡組（現在只有國二上）再做。

**要 Codex 判斷**：

1. 「Obsidian 連結寫、外掛索引讀」對不對。其他做法：(a) 全靠 Obsidian：屬性區列連結，用反向連結窗格與關係圖看；(b) 外掛另存一份關係資料（JSON 或一篇專用筆記）；(c) 每節一篇地圖筆記，關係寫在地圖筆記裡、不寫在目標上。Claude 傾向寫在目標上，理由是地圖跟著卡組、目標搬家時關係跟著走；(c) 的好處是卡組檔不變、AI 輸出地圖時一次寫完。
2. 只寫一邊有沒有漏洞：A 被刪掉或合併時，指向它的連結散在很多篇，外掛要找得到（索引做得到嗎）；「相關」由比較晚建的那一個寫，兩邊都被寫了一次怎麼辦。
3. 三種夠不夠、有沒有多：包含是不是先備的特例（包含一定也是先備？），可不可以只用「先備」加一個「複習時一定用到」的標記；「相關」要不要變成資料，還是只留在地圖的句子裡，等真的有用途再說。
4. 相容（D-149 第 3 點）：舊版外掛會把 `包含：…` 當背面補充顯示。這只是畫面多一行，還是算「讀錯」？如果之後包含會影響排程，舊版的 iPhone 和新版的電腦就會排出不同的到期日，那就是讀錯，要用 `需要版本`。欄位名稱要不要現在先保留（v1 的解析器先認得名稱、不顯示），讓之後不必等每台裝置換版？
5. 索引的量：幾萬條連結，在 iPhone 上每次打開都從檔案算，負擔多大？外掛現在怎麼讀卡組（每次全讀，還是只讀範圍內的），請查證。用 metadataCache 的 links／blocks，還是外掛自己的清單解析（[D-135](../docs/decisions.md#d-135-清單解析和-obsidian-對照後的處理) 已經記下兩者不一致的地方）？

## 2. 連結的整理系統

**使用者的原話**：

> 應該也要有一個連結的整理系統，專門整理優化日後過於龐大的連結

**語意**（Claude 整理）：連結會隨年級越積越多。要有一套專門的機制定期整理，讓網保持正確、好用，不會大到沒人看得懂，也不會越來越亂。

**連結變多以後會壞在哪裡**（Claude 列，請 Codex 補）：

| 問題 | 例子 | 後果 |
|---|---|---|
| 斷掉 | 指向的目標刪了、合併了，或搬到別的卡組、檔名過時 | 點不過去；索引用 ID 還找得到的，只是顯示問題 |
| 重複的目標 | 當初 AI 沒看到舊的，同一個判斷建了兩個（主文第 3 種情形） | 孩子複習兩次，進度分成兩份 |
| 迴圈 | A 先備 B，B 又先備 A | 層次排不出來 |
| 多餘 | A 先備 B、B 先備 C，又直接寫了 A 先備 C | 地圖變亂；資料本身沒錯 |
| 太多「相關」 | 一個目標連到幾十個 | 看了等於沒看 |
| 錯的連結 | 證據對不上：B 一直熟、A 一直錯，「B 站在 A 上」可疑；被包含的小目標單獨考常錯 | 先備追錯方向；之後如果替小目標記複習，會把忘了的當成熟了 |
| 漏掉的連結 | 兩個目標的錯因常是「觀念混淆」，彼此卻沒有連結 | 錯題補強看不到該一起看的目標 |

**💡 提案：分三層，越往下做得越少**

1. **外掛每次建索引時檢查，不用 AI**：斷掉、迴圈、連到自己、連到暫停或已刪的目標、同一條寫了兩次。只有改檔名提示這種機械式的修復由外掛做（照 D-149 第 7 點）；其他列在入口的「提醒」一區（[D-163](../docs/decisions.md#d-163-入口與目錄的四批開法全部卡的一輪與提醒一區)），家長點一下處理。
2. **AI 定期整理，家長審**：學期初或目標數量過了門檻時，AI 提出候選：重複的目標、漏掉的連結、多餘的連結、種類寫錯、證據對不上的連結。每次只送一小塊網（一科，或一個目標的鄰居），不送整張網。家長一批一批核可；整理前先備份（[D-150](../docs/decisions.md#d-150-備份與還原)），AI 的原始輸出照舊存快照，改錯了能還原、能追查。
3. **畫面上的簡化不刪資料**：「看起來太多」靠地圖的縮放、只顯示直接的連結解決，不為了畫面好看刪資料。資料錯了才由第 1、2 層改。

**合併重複的目標**（主文第 3 種情形，請 Codex 一起看）：留下複習比較久的那一個，把另一個的題目搬過去，刪掉另一個；它的複習紀錄照樣保留。Claude 認為不必改 D-126：D-126 管的是兩個不同的判準合成一個新目標；真的重複時判準本來就一樣，留下的 ID 與進度都不變，和題目池加題相同。刪掉的 ID 不再用（D-034），指向它的連結要改指留下的那一個。要不要在留下的目標上記「合併自 xxxxxx」，讓舊紀錄、舊連結與錯題本的「對應」都找得到？

**不做的話**：斷掉的連結大多只是顯示問題，索引用 ID 找得到；真正有害的是重複的目標（多複習一份）與錯的包含（如果之後做了替小目標記複習）。目標還少的前幾年，第 2 層幾乎沒事可做。

**做的代價**：第 1 層是索引的一部分，多寫的不多；第 2 層多一種 AI 呼叫、一種審核畫面與整理紀錄，用量隨網變大。

**更小的做法**：只做第 1 層；重複的目標先靠製卡時的候選比對擋在入口（[「AI 看得到舊目標的什麼」](../docs/backlog.md#其他待決)）；其他候選等目標過了某個數量，或真實資料看到問題再做。

**要 Codex 判斷**：

1. 上面的問題清單漏了什麼；哪些外掛自己判得出來，哪些一定要 AI。
2. 用複習紀錄驗證連結（「B 熟、A 常錯」）可不可行：要多少筆紀錄才判得出來，自評的雜訊（D-114）會不會讓它沒用。
3. 定期整理（學期初）和事件觸發（加一篇卡組時只看它的鄰居）哪個比較好；要不要兩個都做。
4. 合併重複的目標不必改 D-126，這個解讀對不對；「合併自」要不要記、記在哪裡。
5. 除了改檔名提示，還有沒有什麼應該自動做、不必家長審的。

- 大目標的複習替小目標記一部分怎麼算：要改排程（[D-012](../docs/decisions.md#d-012-排程器可替換)）、要回測（[D-105](../docs/decisions.md#d-105-回測要用的紀錄先收好)），之後另談；這裡只決定「包含」要不要是一種連結。

## Codex 回應（2026-11-03）

以下是依 c116036 查核後的提案。把跨單元的關係留下來，值得做的第一個用途是讓家長遇到反覆答錯時，能找到一個有理由回去檢查的先備目標。能省多少複習時間，留待真實使用驗證。

### 1. 連結

1. **存放位置與讀法**
   - **不做。** 現在各節快照已有關係句，家長可先用原生連結查看個別目標。還沒有反覆跨單元追查的需求時，多一套欄位、驗證與審核只會增加製卡成本。
   - **💡 同意第二階段用 Obsidian 區塊連結寫、Cards 依 ID 讀。** 關係寫在來源目標的結構化欄位，反向查詢由索引衍生。這樣目標搬家時，它寫出的關係一起搬，且單元歸屬仍由出處決定（D-142 第 3 點）。(a) 原生屬性與關係圖適合筆記級導覽，無法替 Cards 定義每個目標的關係種類；(b) 專用檔案若是唯一來源也可行，但要另外維護目標搬移、刪除與關係檔的同步；(c) 每節地圖筆記適合保留 AI 快照，跨節關係要另訂歸屬，搬目標時也得找回地圖。v1 最多試第 7 點。讓快照用一句話寫出兩端、種類和理由，已有目標才引用核對過的 ID，新目標用該次草稿內的名稱或代號。名稱不唯一、舊 ID 找不到或語意未審核的句子，日後仍須核對才能轉成連結。
2. **只寫一邊**
   - **不做。** 只看單節時，刪除或搬移偶爾靠家長找就夠了。全量反向索引還得處理同步未完與重複 ID，為了只做展示就急著修檔，可能改到錯的目標。
   - **💡 同意只存一邊，修改去重與失效規則。** 有向關係按「種類、來源 ID、目的 ID」識別，來源依語意決定。無向「相關」用排序後的兩個 ID 加種類當同一筆，新增時可優先寫在本次正在審的目標，讀到兩邊都寫就只顯示一次並報來源位置，不為此搬欄位。反向索引保留指向未知 ID 的來源位置，涵蓋所有已讀且支援格式的卡組關係；錯題本的「對應」與一般筆記是其他引用來源，須分開查，不能宣稱索引已找齊。ID 唯一且檔名過時，可在外掛內跳到現址。缺檔、版本讀不懂或同步仍在重試時標成待確認。D-157 的重複 ID 交家長選，不能靠檔名提示自行決定。
3. **關係種類**
   - **不做。** 快照中的一句話能交代條件，尤其同一地點的兩個特色，D-139 第 3 點已允許一起看。每個「有關」都加邊，會讓家長多審，也讓孩子難找真正要補的先備。
   - **💡 改成先做「先備」，另外兩種等用途驗證。** 「先備」用來提出補強線索，例如小六能用 x 表示未知數，國一解一元一次方程式卡住時，可回去抽測列式。「包含」記的是整合判斷確實需要小目標的能力，值得保留獨立語意。同樣是浮沉題，題幹直接給浮力方向時，答對沒有提供回憶浮力方向的證據，連結也無法代替逐題驗證。先在快照保留整合理由，等地圖有辨識需求再存「包含」，排程另談。「相關」先留在句子裡，試用看到容易混淆的目標確實需要互跳，再加為純導覽。「先備」也先做補強候選，待證據足夠才考慮拿來控制延伸出題。
4. **舊版相容**
   - **不做。** 現在預留欄位，會搶占家長可能已用的背面補充名稱，還得照顧已發行且仍會顯示該行的舊版。v1 快照能先承接這批內容。
   - **💡 不預留。** 等確定語法，再用舊版實測新行是否僅多顯示、是否暴露可作答提示，及是否改變讀到的卡片內容。能安全多顯示且用途僅導覽，才可視為相容。若會讀錯內容、觸發不同排程，或新增舊版無法解讀的紀錄，依 D-149 第 3 點與 syntax §0-1，分別用卡組的「需要版本」或紀錄的 `need`，先部署讀端、確認裝置換版後才開寫端。若規則跨卡組改變到期日，還要驗證同一個閘門能涵蓋受影響的目標。
5. **索引與 iPhone**
   - **不做。** v1 沒有程式化的關係讀取者，先把整張網併進冷啟動只會增加 I/O 或解析工作，尤其有 iCloud 佔位檔時。
   - **💡 第二階段沿用已解析的卡組與檔案監看。** 基準的 `src/core/deck/read.ts` 由 `listDeckPaths` 列出 `Essence Cards/` 內符合規則的 Markdown，排除五個系統子目錄。`src/state/reads.ts` 啟動先監看，再列卡組與紀錄，初載讀取該批檔案，平常變動才重讀相應路徑，複習範圍不是讀檔範圍。關係欄位用 Cards 的清單解析歸屬到目標，沿用版本、錯誤與 ID 規則（D-135、D-157）。`src/ui/sources.ts` 的 metadataCache 是先找「材料」筆記、再查區塊或標題，適合用於開啟連結及核對 Obsidian 顯示，無法單憑 links／blocks 決定哪條關係屬於哪個 Cards 目標。索引按檔維護，改動時移除舊貢獻、加入新貢獻，能延到首次開地圖或查先備的工作就延後。
   - 量級以原稿假設計算，每年約 900～4,060 個，十年約 9,000～40,600 個，兩至三條每目標約 18,000～121,800 條。每年兩千可作中間情境，試用只有國小社會，實際留存、跨年級加題和各科密度都未知。建索引若每節點與邊各掃一次，工作量隨兩者線性增加，無法從條數推定 iPhone 秒數。試作時可用 2 萬目標／6 萬條與 4 萬／12 萬條測冷啟動到可複習、首次查鄰居、單檔更新及記憶體，分開記檔案讀取和解析時間。

### 2. 整理系統

1. **要抓哪些問題**
   - **不做。** 只要外掛能開啟 ID 唯一的現址，早期多數檔名過時不用打擾家長。把每個暫停目標或每條間接路徑都列成警示，家長會花時間處理正常資料。
   - **💡 同意先做結構檢查，語意按需審。** 額外分出「目的不可判定」（缺 ID、撞 ID、讀取未完成、草稿或未支援版本）、「位置過時」（ID 唯一）及「語意需重審」（端點判準改了，ID 卻沿用，或方向與教材證據不符）。外掛可查格式、自連、重複、唯一性、已讀範圍及有向循環，無向的相關環是正常的。只有同時用於同一套層級約束的種類才合併查環。暫停目標可保留作地圖脈絡。跨兩步可達、節點過密都可用規則找出，不能直接推論直連多餘或錯誤。是否真重複、真的包含、缺了哪個先備，需要比對判準、題目與材料，家長或教師可以直接判斷，AI 可提候選並指出證據。
2. **複習紀錄能不能驗證**
   - **不做。** 「B 熟、A 常錯」可能是自評鬆緊不同、題型提示不同，或作答間隔不同。固定累積幾筆也無法消除偏差（D-114）。
   - **💡 只拿來排候選優先順序。** 先看日期相近、不同題面、沒有答案提示的作答，並排除同一輪重試；用錯因、可客觀批改的題目或一次針對性的獨立抽測交叉核對。沒有可通用的最低筆數。試作可用雙方各三個不同日期的有效作答當作開始人工抽查的門檻，記錄提示是否有用再調。證據不足就不升級提醒，紀錄本身不改邊、不改熟練度。
3. **什麼時候整理**
   - **不做。** 學期初全掃的工作量與卡組大小有關，與問題有沒有發生關係較小。每次存檔都叫 AI 又會把同步和細微改字變成額外用量。
   - **💡 結構檢查隨檔案批次更新，語意整理按需啟動。** 製卡時先擋同一判準的重複候選。新卡組或判準改動時，只更新受影響的端點與相鄰邊，候選累積後讓家長選一小批，再視需要送 AI。找重複不能只看已連上的鄰居，仍要從現有目標挑少量可能相同的候選，跨科先備也不能用科目硬切。等真實資料顯示局部整理反覆漏掉有影響的問題，再評估學期初巡檢。先量有用候選比例、家長每批審核時間與 AI 用量。
4. **重複目標與 D-126**
   - **不做。** 先在製卡時依 D-027 加題，遇到疑似重複時暫停其中一個可先減少重複出題。若判準其實不同，誤退役會掩蓋學生沒掌握的能力，還會影響考試範圍和錯題回查。
   - **💡 同意保留同判準目標的進度，採用前應補明 D-126 第 3 點的適用邊界。** 現行條文對「已複習的目標合併」直接要求新 ID，沒有同判準例外。建議明定「確認判準等價後，將題目與出處加進保留目標，再退役重複目標」可保留原 ID，判準改變的拆併仍用新 ID。核對成功條件、適用情境和代表題，由家長選保留哪一個，複習較久只作預設候選。兩個不同 ID 的重複目標和 D-157 的同 ID 撞號分開處理。
   - 建議在保留目標的結構化資料記「合併自」的退役 ID，作為 Cards 查舊引用的唯一對照。舊紀錄保留原 ID，查閱可顯示去向，計算保留目標進度時不匯入退役紀錄。正式做之前要定義保留目標再次退役時的轉址、禁止循環或一碼多去向，以及退役碼永久保留給 ID 分配器排除。Obsidian 原生舊區塊連結不會因這欄位自動跳轉，已知的關係和錯題「對應」可列入同一次預覽改指。若有檔案讀不到或同步後內容改變，先暫停操作。依 D-149、D-150 在電腦預覽並備份，寫入前重查，部分成功時能重試或還原。
5. **哪些動作可自動做**
   - **不做。** 除了查核與提醒，先不改任何筆記，避免同步期間把暫時的缺檔當刪除，或把畫面太擠當成資料錯誤。
   - **💡 自動處理衍生結果，持久修改由家長發起。** 外掛可以重算反向邊、同一條邊只顯示一次、以唯一 ID 開啟現址、先顯示直連鄰居並允許展開，以及在檔案重讀成功後撤掉已消失的提醒。這些都不必審。改檔名提示可提供批次機械修復，仍按 D-149 第 7 點由家長在電腦確認預覽並先備份。刪邊、改種類、改端點及退役目標都會改變學習資料，先保留差異與理由供家長核對。

## Claude 回應（2026-11-03）

十題都同意 Codex 的結論（`src/core/deck/read.ts` 的 `listDeckPaths` 與 `src/state/reads.ts` 的監看已核對）。補四點：

1. **v1 的一小步照 Codex 的條件寫**：地圖全貌的關係句寫出兩端、種類與理由；已有目標只引用核對過的 ID，新目標用草稿裡的名稱；沒核對的句子之後要核對才能轉成連結。要不要做，記在 backlog「AI 要看得到舊目標的什麼」那一列，由 AI 製卡模組的規格決定。
2. **同意先只做「先備」，把「包含」的觸發點寫具體**：「包含」就是使用者「小目標整合成大目標」與「小知識的全貌是大知識的一個點」想在地圖上看到的那層關係。所以「等地圖有辨識需求」寫成：**設計地圖的存法與視覺化時（[學習動機](../docs/plans/motivation.md#使用者提議把學習地圖做成有質感的視覺化)），一起決定要不要存「包含」**；在那之前，AI 在快照裡寫整合的理由。
3. **撤回原表的「多餘」那一列**：兩步可達不代表直連多餘，Codex 說得對。量級改用 Codex 的區間。
4. **D-126 要明文補例外，不靠我的解讀**：這是改已確認的決定，先請使用者確認。補充只寫原則（下面〈結論〉第 8 點）；「合併自」的欄位、轉址與再次退役的細節，做合併功能時定，開工前照 [D-140](../docs/decisions.md#d-140-fable-規劃opus-執行codex-查核) 第 4 點做格式查核。AI 製卡模組（v1）提出合併時就會用到這條，所以原則現在補。

## 結論（Claude 與 Codex 一致，2026-11-03；等使用者確認）

1. **寫法與讀法**（第二階段）：關係用 Obsidian 的區塊 ID 連結，寫在來源目標的欄位裡；Cards 用自己的清單解析與索引依 ID 讀，反向由索引算，不另存資料庫；metadataCache 只用來開啟連結、核對顯示，不判定關係屬於哪個目標。
2. **只存一邊**：有向的關係由語意決定寫在哪一端，以「種類、來源 ID、目的 ID」認同一條；「相關」用兩個 ID 加種類認同一條，兩邊都寫只顯示一次。指向找不到的 ID、檔案讀不到、版本讀不懂或同步還在重試時標待確認；同一個 ID 撞號照 D-157 由家長選。錯題本的「對應」與一般筆記是另外的引用來源，索引不宣稱找齊。
3. **先只做「先備」**：用途是孩子常錯時，提出一個有理由回頭檢查的先備目標；先不拿來控制出題。「包含」在設計地圖的存法與視覺化時決定要不要存；「相關」先留在快照的句子裡，試用看到容易混淆的目標確實需要互跳再加，只做導覽。
4. **相容**：不預留欄位名稱。語法定了以後用舊版實測；會讀錯內容、改變排程或寫出舊版讀不懂的紀錄，照 D-149 第 3 點用 `需要版本`／`need` 兩段發布。
5. **索引**：沿用現有的卡組讀取與檔案監看，按檔增量維護，能延後的延到第一次開地圖或查先備。做之前在 iPhone 用 2 萬目標／6 萬條與 4 萬／12 萬條試作，分開記冷啟動到可複習、第一次查鄰居、單檔更新與記憶體。
6. **整理系統**：
   - 外掛隨檔案更新做結構檢查：格式、連到自己、重複、ID 唯一、已讀範圍、有向循環（只在同一套層次約束的種類之間查）；問題分成「目的不可判定」「位置過時」「語意需重審」。兩步可達、連結很密只當線索，不推論成多餘或錯誤。
   - 製卡時先擋同一判準的重複候選；新卡組或判準改了，只更新受影響的端點與相鄰的連結。找重複不能只看已連上的鄰居，跨科的先備也不用科目硬切。
   - 語意整理（真的重複嗎、真的是先備嗎、漏了哪個）在候選累積時按需啟動：家長選一小批，需要時再送 AI。學期初全掃，等局部整理證明會漏掉有影響的問題再評估。先量有用候選的比例、家長每批的審核時間與 AI 用量。
   - 複習紀錄只用來排候選的先後，不改連結、不改熟練度。
7. **自動與人審的界線**：外掛自動做衍生的結果（反向連結、同一條只顯示一次、用唯一 ID 開啟現址、先顯示直接的鄰居再展開、重讀成功後撤掉已消失的提醒）。改檔名提示是家長在電腦按的批次修復（D-149 第 7 點）。刪連結、改種類、改端點與退役目標，都由家長看差異與理由後決定。
8. **重複目標的合併，補 D-126**（要使用者確認）：家長確認兩個目標的判準等價後，把題目與出處加進保留的那一個、退役另一個，保留的目標用原 ID、進度照舊；判準改變的拆分與合併照 D-126 配新 ID。保留哪一個由家長選，複習比較久的當預設。保留的目標記下「合併自」的退役 ID；退役 ID 永遠不再分配，不能一碼多去向、不能循環；退役目標的紀錄照樣保留，但不併進保留目標的進度。和 D-157 的同 ID 撞號分開處理。
9. **v1**：只有 AI 製卡模組的規格要決定，地圖的關係句要不要照上面 Claude 回應第 1 點寫。其他都是第二階段。
