## F1｜P2｜同樣禁止的連結，還有角括號與參照式寫法會通過

**軸：規格。結論：建議一起補最小拒收範圍。**位置：[請求第 22～25 行](../tasks/w6-s1-format-review.md)、[syntax §2-3](../docs/syntax.md#2-3-學習目標)；分支 `claude/w6` 的 `src/core/deck/parse.ts`（`3af5c41`）第 166～168 行。這是原有「不能有連結」與有限 marker 清單之間的缺口，不是 S1 已寫好的程式發生回歸。

**已重現（核心與 Markdown-it；未驗 Obsidian 畫面）**：

| 答案格 | 目前 W6 與只加 S1 兩個模式後的 `typed` | 證據與影響 |
|---|---|---|
| `<mailto:a@b.test>` | `['<mailto:a@b.test>']` | Markdown-it 渲染成郵件連結，畫面顯示的文字與比較用的含角括號字串不同。 |
| `<a@b.test>` | `['<a@b.test>']` | 同樣渲染為郵件連結，比對仍含角括號。 |
| `<ftp://a.test/a|b>` | `['<ftp://a.test/a', 'b>']` | 仍拆開自動連結內的管線。 |

| `[word] | b`，文末另有 `[word]: /target` | `['[word]', 'b']` | Markdown-it 的捷徑參照連結也不需要 `](`；只攔 `[...][...]` 仍不完整。 |

上表不是單憑「看起來像網址」猜測：本機 `markdown-it` 14.3.3 的 `lib/rules_inline/autolink.mjs` 與 `link.mjs` 有對應規則，實際渲染得到 `<a>`；參照定義放在清單外的最小卡組也已透過公開 `parseDeck`／`checkTyped` 重現。S1 只加 `https?://` 與 U+FF5C，不會攔到這些例子。

**建議改寫法**：延續前次 F1「打字答案只支援單字片語加四種裝飾」的範圍，把答案格中的 ASCII `[`、`]`、`<`、`>` 明列為暫不支援，在拆分前整格拒收。這是保守的字元限制：也會拒收字面括號，須寫進規格，不假裝只精確辨識連結；優點是不必找參照定義、解析 HTML 或維護所有 URL 協定。這四個字元不是現行已承諾的裝飾。若 Claude 認為有必須保留的真實英文答案例子，先回到該例子討論，不直接擴成完整 Markdown 解析。

**完成條件**：上表全部是 `typed-answer-invalid` error、`typed: null`、不報字數 hint；一般翻面題與答案以外的相同內容不受影響。這是查核建議，仍由 Claude 核對並補任務，不能直接當作新增的使用者決定。

相容性與進度證據：

- **升版但不改原文**：對 22 組答案逐一比較 W5、W6 與 S1 模擬，`answer`／`fingerprint` 全部相同。例：題幹 `Q`、答案 `https://a.test/a|b` 的指紋三者都是 `ed917eb1`。拒收不應改寫卡組或 JSONL。
- **停出後**：排程只對有效候選重播，但 `History` 中原本的作答、`v`、評分仍在。`replay` 以 `lt` 分組（`fsrs.ts` 第 16～19 行），不要求 `v` 等於現在的題目指紋。
- **今日份數會變**：用兩個目標、其中壞目標有兩題，保留前一天 `near` 與今天 `good` 兩筆原始紀錄。以現有 W6 公開介面套入拒收後應有的 `ok: false`／`typed: null`，重新 `planToday`／`progress`：原先 `done/total = 1/2`，停出後為 `0/1`；另一個目標仍可出。這不是刪掉完成紀錄或排程重置，而是統計集合變了。
- **家長修好後**：只把答案改成 `a | b`、保留原 `lt`，重新解析與排程後回到 `1/2`；仍承接前一天的記憶，兩筆歷史重播的 `reps` 仍為 2。修答案會換題目指紋，影響依 `v` 找錯題／輪題，但不會把同一學習目標變新卡。今天已經答對時，也不會因修字而強制重做一次。這是既有設計，不應在 S1 加重置或補作答機制。
- **不追溯修正舊評分**：若舊版已因錯拆答案寫過 `good`，新版仍按該筆 `r` 重播，不會由這次格式拒收自動判它無效。

**W5 已重現**：裸 HTTP(S) 網址、全形管線仍是合法的整串打字答案；W5 不拆 ASCII `|`。輸入整串（去掉裝飾、依既有比對規則）可以判對，不能說這些卡在程式上「永遠答不對」；學生用英文鍵盤正常答單字的體驗才是問題。這次沒有新增紀錄欄位，W5 讀既有 `v`／`r` 的能力不變；混用版本時，舊裝置也不會跟著停出，須沿用 W6 的各複習裝置升版條件。

## F3｜P3｜syntax 把 HTTP、大小寫與子字串範圍寫齊

**軸：規格。結論：改寫法、加例子。**位置：[請求第 25 行](../tasks/w6-s1-format-review.md)，對照同檔第 22 行與 [W6 §0-1](../tasks/w6.md#0-1-中翻英的答案格拆開-d-122)。

提議的 syntax 只寫「`https://` 開頭的網址」，比實作約束少了 `http://`、大小寫不敏感，以及「格內任何位置含有就拒收」。沒有網域的 `http://` 也應依子字串規則拒收，不需要先驗證 URL。

**建議文字**（先寫 S1 已要求的兩項；F1 若採用，再加它的明確字元限制）：

> 不能有換行、連結、嵌入、行內程式碼、公式、`\|` 或全形的 `｜`（U+FF5C）。答案格任何位置含 `http://` 或 `https://`（不分大小寫），也算不支援的網址寫法；先檢查整格，拒收時不拆答案、不自動換符號。該題報 error，所屬學習目標暫停出題，等家長改寫。

建議另明寫「不做無協定網址的辨識」：**`www.a.test` 與裸 `mailto:a@b.test` 不新增拒收規則**。它們沒有 S1 指定的協定模式或明確 Markdown 外殼，不能靠標點形狀可靠判定全部裸連結；也沒有既有的 ASCII 字元白名單可沿用。這是有限語法檢查，不是保證驗出所有網址。帶明確連結標記的 `<mailto:…>`／`[word](mailto:…)` 則適用連結拒收，不能把裸 `mailto:` 的結論套到它們。

代價須寫清楚：`www.a.test/a|b`、`mailto:a@b.test|b` 仍會按 ASCII `|` 分成候選，`b` 會被接受；已在 W6 核心重現。若需求其實是「所有像網址的文字都不能拆」，兩個協定模式無法達成，須另議判定範圍。此處建議保留 Claude 的有限檢查，不增加網域猜測或全 Unicode 限制。

### 可直接轉成驗收的邊界表

以下「S1 模擬」只在記憶體把既有整格 guard 加上 `https?:\/\/`（`i`）與 U+FF5C；不是正式分支已實作的結果。

| 原答案格 | S1 模擬結果／建議驗收 |
|---|---|
| `https://a.test/a|b`、`HTTPS://A.TEST`、`hTtP://` | error、`typed: null`，不能只留 `b` |
| `prefix http://a.test tail | b` | 同上；檢查不加開頭錨點，也不以單字邊界限制 |
| `**https://a.test/a|b**`、`<https://a.test/a|b>` | 同上；在去裝飾前已拒收 |
| `a｜b`、`a ｜ b`、`a|b｜c`、只有 `｜` | 同上，空白與 ASCII 管線混用不改結果 |
| `www.a.test`、裸 `mailto:a@b.test` | 維持單一候選；明寫未做無協定／其他裸協定辨識 |
| `www.a.test/a|b`、`mailto:a@b.test|b` | 維持兩候選；接受 `b` 是上述有限範圍的已知代價 |
| `a|b`、`a | b`、`**a | b**` | 仍為 `['a', 'b']`，無 error |
| `a | two words` | 只有 `typed-answer-words` hint；仍可出題 |
| `[word](mailto:a@b.test)`、`[[word|b]]` | 既有 `](`／`[[` guard 拒收；不是 S1 新增能力 |
| F1 表中的角括號及參照式連結 | 只加 S1 兩模式仍通過；若採 F1 最小補法，改成 error／null |

所有整格拒收案例都應同時驗 `target.ok === false`、`typed === null`、只有 `typed-answer-invalid` error、沒有字數 hint，以及原始 `answer`／固定指紋不變；再加一個目標內兩題、同篇另有合法目標的案例確認停出範圍。訊息可照請求沿用，不必為 S1 新增另一種 error code。
