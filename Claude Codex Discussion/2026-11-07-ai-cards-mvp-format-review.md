## 發現（依嚴重程度）

### F1｜P1｜「複製提示」時沒有固定保存實際提示，更新後無法重組

**結論：改寫法；格式開工前修。靜態推斷，真實路徑會發生。**

- **位置／證據**：任務 §3（第 116～117 行）只保存規則名稱、版號、雜湊與提示版號，不存提示全文；§5（第 167、209 行）到貼回存草稿才保存規則內容。D-115 第 4 點、D-126 第 4 點與 D-151 第 6 點要求留住實際送出的內容與版本。
- **觸發**：版本 A 複製提示後關閉 Obsidian，升級到規則或模板已變的版本 B，才回來貼結果。A 的規則尚未寫進「送出內容」，B 的內建規則已換掉，雜湊不能反推出文字。「照雜湊找得回來」在此不成立。即使外部保留了 A 的規則，提示模板也只有版號、沒有舊模板的內容。
- **預期／實際與影響**：預期可重組出 A 的完整提示；規格目前只能發現 B 重組出的雜湊不同，無法保存 A 的內容。快照範例的 `任務資料` 也沒列齊送出時的科目、完整單元與教材文字，單靠範例欄位不能逐字重組。
- **建議**：複製當下就持久保存當次完整提示，或保存足以逐字重組的所有不可變組件（含舊模板）；本機待貼回工作可以保存完整提示，成功匯入時再依原文寫入證據庫。快照的雜湊必須指當次送出的文字，版本更新後不可拿新版替代。教材仍照 D-126，只記取得的說明，不推定附件真的送達。
- **驗收例子**：複製 A → 改規則與模板 → 重載 → 貼回，取回的文字與原提示逐位元組相同、SHA-256 相同；另測待貼回工作過期／內容缺漏時明示證據缺口。

### F2｜P1｜重開後改當新工作，違反已約定的中斷重試契約

**結論：改寫法；格式開工前修。靜態推斷，真實路徑會發生。**

- **位置／證據**：任務 §5 第 169～171 行；[架構討論稿〈環節 8 的結論〉](2026-10-26-plugin-architecture.md#環節-8-的結論claude-與-codex-一致)第 3、4 條與驗收反例要求持久恢復、重試沿用 ID、同一工作不同輸出要報不一致。任務卻明定重開後重新配號、不做復原檔。
- **觸發**：兩篇中第一篇已建好，第二篇之前程式關閉。重開、貼回同一回覆，第一篇因新 ID 而內容不同；「改名另存」會多建一份相同內容的新目標，取消則第二篇仍缺。即使兩篇已建好，若在清掉待貼回工作前關閉，也會走相同路徑。
- **預期／實際與影響**：預期恢復同一工作、補缺篇；原稿只保證同一次執行期間可重試，跨重啟會重匯入或無法接續。同一工作貼成另一份回覆時也沒有持久的輸出雜湊可核對。
- **建議**：保留原先的快照先寫順序，增加最小持久工作資料：識別碼、已接受的輸出雜湊、配好的 ID、各篇目的地與預期內容雜湊、完成情況。恢復資料放在可整個刪除的快照資料夾以外；每篇重試先核對實際檔案，不能只信「完成」旗標。工作過期不能連同尚未完成的寫入資料一起丟掉。移動快照到最後，或只把快照 ID 算進占用，都不能單獨補足此契約。
- **驗收例子**：送出內容、快照、每一篇卡組及最後清理工作前後，分別重啟再重試；最終只有一份快照及各一篇卡組，ID 不變。同工作貼不同輸出時停止，不另配 ID 繼續。

### F3｜P1｜先寫且只建立的快照，記不了後來才知道的成功時間與發布結果

**結論：改寫法；格式開工前修。靜態推斷，真實路徑會發生。**

- **位置／證據**：任務 §5 第 167、171、177～182、208 行；D-194 第 5 點要求成功生成的基準，失敗或沒匯入不算；環節 8 第 8 條要求已成功發布的結果，不能只找日期最大的快照。
- **觸發**：先寫快照，之後卡組寫入失敗、只成功其中一篇，或等很久才重試成功。只建立的快照在寫下時無法知道未來「存草稿成功的那一刻」。孤兒快照當下連不到卡組，不代表那個路徑以後不會出現另一份同名卡組。
- **預期／實際與影響**：目前沒有持久的成功／部分成功辨識，快照卻看起來和成功結果一樣。未來只靠 `時間` 與 `對象`，可能把失敗結果當成加深基準；若孤兒 ID 之後重用，單靠 ID 比對也不能證明兩者是同一次匯入。
- **建議**：分開「快照建立時間」與「發布完成時間」，以 F2 的持久結果或另加只建立的完成紀錄，指回確切工作及實際成功的目的地／ID。多篇部分成功如何判定要寫清楚。初次製卡送出的同篇記穩 ID 集合可明定為空集合，不要以「沒記」推定為空。加深的算法可留之後，但現在的成功證據不能留空。
- **規範同步**：依 D-194 第 10 點、環節 8 第 8 條，更新 syntax §6 的「只寫不讀」：只有加深與提示讀相關證據，複習與排程仍獨立；本任務的送出內容／本機恢復若會讀取，也不要寫成一律只寫不讀。
- **驗收例子**：只有快照、只成功一篇、全部成功、卡組後來刪除或同名重建四種情況能分辨；失敗快照不會變成成功基準，成功時間能排序且不隨重試重寫。

### F4｜P1｜寫完快照才決定改名，會把 `對象` 指到舊卡組

**結論：改寫法；格式開工前修。靜態推斷，真實路徑會發生。**

- **位置／證據**：任務 §5 第 167～169、180～182 行先存 `對象`，撞名後才讓家長改名；[D-081](../docs/decisions.md#d-081-卡組屬性與檔名)要求新建檔名整個 vault 不重複，因為連結靠檔名尋找。
- **觸發**：已有 `國二上英文 L3 單字.md`，家長選另存成 `國二上英文 L3 單字 2.md`。已寫且不能改的快照仍指向沒有後綴的舊篇。同名檔在其他資料夾時，僅測目標路徑是否存在也不夠。
- **預期／實際與影響**：預期快照對應新草稿；原順序會連到舊卡組或形成歧義，D-042 的採用比對失去正確對象。
- **建議**：在寫快照之前完成全 vault 檔名碰撞處理、固定每篇的實際目的地，並持久記下；只建立遇到後來才發生的競爭時，沿 F2/F3 的結果紀錄更新映射，不把舊快照的連結宣稱為最終位置。後綴 ` 2` 已存在要繼續找 ` 3`；Windows 大小寫與不可用字元也要處理。
- **驗收例子**：同路徑撞名、別的資料夾同檔名、後綴已存在、檢查後才有人建檔、第一篇成功但第二篇改名；每份快照都能定位到實際新建的篇。

### F5｜P2｜草稿檢查的「提示可存」與正式規範衝突

**結論：改寫法；格式開工前核對。衝突已由探針確認，真實路徑會發生。**

- **位置／證據**：任務 §4 第 138～142 行；syntax §2-10 第 498 行明定製卡草稿的 `pick-mixed`、`pick-not-recognized` 等錯誤「要退回重做」。環節 8 第 9 條只接受允許的框與本次有依據的舊 ID。任務卻全部降為提示可存。
- **已重現**：`寨（寨、塞） 相似字` 底下混合 `山＿＿。 :: 寨` 和 `解釋山寨。 :: 聚居地`，`parseDeck` 回 `pick-mixed` hint，`check-syntax` 回同碼「錯誤」；照任務表會准存，照 syntax 必須退回。
- **影響**：實作者不能同時遵守這兩份規格。未知舊 ID 留框內目前不會自動改動舊目標，這個限制有效；但它仍是對環節 8 已約定接受條件的放寬，不能默默視為一致。
- **建議**：列清楚 parse 錯誤與製卡檢查每種等級如何處理。建議保留已明定的比較卡錯誤阻擋；若要讓家長審核時才改，先明示改動並同步 syntax／相關約定。一般不符（候選數、格式風格等）可提示。未知框必須保留原文且不被當候選配號，不得無聲丟內容。
- **加例子**：正常本文加一個缺答案候選框，`parseDeck` 不會讀框內目標，但 checker 已會報第 6 行 `no-answer`；新核心檢查必須保留此診斷與原始行號，且配號後仍能辨認該候選。

### F6｜P2｜拆篇缺少 Markdown 範圍與疑似篇名的處理

**結論：改寫法並加例子。靜態推斷；標題合篇結果已重現，真實 AI 輸出可能發生。**

- **位置／證據**：任務 §4 第 128～132 行、§8 的拆篇測試；英文規則 §8、國語規則〈卡組〉要求每篇先寫檔名再寫本文。
- **觸發／影響**：只用逐行字串比對時，答案續行或 fenced code 裡剛好出現 `國二上英文 L3 單字`，會誤拆。相反地，整份寫成 `## 國二上英文 L3 單字`、`## 國二上英文 L3 文法` 時，原稿明定不算篇名，卻沒明定要阻擋；探針證實兩篇會被現有解析器讀成同一篇的兩個目標，checker 也不會報拆篇錯誤。不同編號的行不符合正確編號比對，還需要另外的錯誤辨識。
- **建議**：篇名只認卡組段中 Markdown 最外層的獨立段落，不在清單接續、引言框與程式碼內切。一般最外層段落若整行符合規定，可約定就是篇名；相同文字無法再猜作者本意。`##` 形式可以繼續不接受，但必須報「篇名請另起一行、不加 #」並阻擋，不能默默合篇。疑似篇名的年級、科目、編號不符時也明確報錯。
- **第一篇前的框**：只把備註框併進第一篇合理；候選／加進已有目標若出現在第一篇之前，歸屬沒有證據，應提示移到所屬篇，不能一律歸到第一篇。
- **加例子**：上述各範圍、標題形式、錯科／錯年級／錯編號、空篇、只有候選框的一篇、前置備註與前置候選。拆篇與整理後仍回報貼上原文的行號。

### F7｜P2｜整理原文與換 ID 的契約需同步，只有改動個數不能還原 AI 原稿

**結論：改寫法。靜態對照；真實路徑是 AI 多包圍欄或自行附 ID。**

- **位置／證據**：任務 §4 的整理、§5 第 198～201 行；syntax §6 第 778 行只允許原文多出外掛配的 ID，D-042 要保留 AI 原始輸出。
- **預期／實際與影響**：BOM、CRLF 和外層圍欄的整理不改題意，可以明訂成匯入包裝整理；但拿掉 AI ID 是刪原字，`程式改動: 拿掉 AI 寫的 ID 3 個` 只有個數，不能回答原本是哪三個、是否拿錯位置。§4 只提行尾六碼，也沒涵蓋 D-134 認得的行中 ID、兩個不同 ID、自訂區塊 ID。
- **建議**：保存一份貼回原文，再保存帶正式 ID、可供 D-042 比對的快照；或者記下足以還原原文的逐項變更與位置。不要複製整份教材。限定只清理新目標／候選的名稱行；題目、答案、行內程式碼與公式、以及「加進已有」的引用 ID 不套同一個全域替換。兩份資料的用途與 syntax §6 一起寫清楚。
- **加例子**：CRLF＋BOM＋外圍欄同時出現、四個反引號包三個反引號的內文、行中／行尾／多值 ID、名稱接續行、自訂區塊 ID、正文裡像 ID 的字；正式快照與草稿的新目標／候選 ID 完全一致。

### F8｜P2｜「加進已有」存成連結的既有格式漏在任務之外

**結論：改寫法或明示延後並同步規範。靜態對照，真實路徑會發生。**

- **位置／證據**：syntax §2-9 第 464 行要求存草稿時把已有 ID 轉成連結；任務 §5 第 162、166 行只說原本文加新 ID、已有目標不配新 ID，沒有這項轉換。
- **影響**：照任務直寫只剩裸 ID，家長審核時無法從框中點回舊目標；這項連結整理與之後跨檔「加入」是不同步驟。
- **建議**：對本次清單中、目前可唯一定位的 ID，寫成 `[[卡組#^ID|原名]]` 等明確格式；遇到不存在、重複、需要新版或生成期間已變動的目標，保留原文並提示，不猜目的地。快照如何記錄此程式轉換併入 F7；若此版刻意不做，明示延後並同步 syntax。

### F9｜P2｜三個起始標記齊全，不能證明最後的卡組段已貼完

**結論：加完成條件與反例。靜態推斷，真實路徑是長回覆截斷或少複製後半段。**

- **位置／證據**：任務 §4 第 125 行只檢查三個段首標記與卡組非空；環節 8 第 4 條要求確認完整結束，不建可加入的截斷半成品。
- **觸發／影響**：三段標記都在，卡組有一個完整目標，接著本來還有第二篇，卻只複製到第一篇的最後一題。既有規則會把第一篇視為合法輸出，沒有一個欄位能辨認少了第二篇；common.md 的科目連三段標記也沒有。這和缺答案的語法錯誤不同，`parseDeck` 不能判定回覆是否結束。
- **建議**：手動接法至少在提示模板要求一個固定的回覆結束標記，檢查後移出卡組本文、原稿與快照仍保留；缺少時請使用者確認／補貼，不宣稱已確認完整。若另選方法，寫出能辨認此反例的依據。這只能驗傳輸／複製結束，不能宣稱教材已完整覆蓋。
- **驗收例子**：R3 與 common 兩條路各測「首標記／題目都合法但尾段少貼」、完整輸出、結束標記出現在引用或程式碼範例內；只認最外層真正的終止標記。

## 可沿用的格式與其限制

1. **候選 ID 占用：照寫行尾 ID，§6 改成沿用現有機制。** `src/core/deck/ids.ts:20` 的 `blockIds` 已收每一行行尾的區塊 ID；`src/state/ids.ts` 的 `presentOf` → `seen` → `taken` 已把它們用來避號。`v0.3.0` 的 `deck/ids.ts` 與目前相同；歷史 tracker 探針也避開候選的 `aaaaaa`、配出 `aaaaab`，不報目標重複。歷史探針只替換匯入路徑，沿用目前核心相依，並非重跑完整舊產物；舊版的占用鏈另已靜態核對。
   - 不要把占用縮窄成只看兩種標題、只認六碼：現在對其他框、一般行與自訂區塊 ID 也有保護。摺疊 `[!note]-`、巢狀 `>>`、框內縮排都不影響行尾掃描。沒有證據需要為此加新 `需要版本`。
