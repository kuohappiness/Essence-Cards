## 1. Claudian 是什麼（2026-10-22 查證）

- [YishenTu/claudian](https://github.com/YishenTu/claudian)：把 AI 代理嵌進 Obsidian 側欄的外掛。vault 就是代理的工作目錄，代理能讀、寫、搜尋檔案、跑指令、做多步驟的工作。MIT 授權，約 1.6 萬顆星，2025-12 開始；最新 2.3.27（2026-10-21），10 天出了 10 版，大多是修錯，一位主要維護者。
- **接的代理**：Claude Code、Codex、DeepSeek、Grok、OpenCode、Pi。Claudian 本身不含模型，要另外安裝代理的 CLI 並登入；登入可以用訂閱或 API 金鑰。
- **功能**：側欄對話、@ 檔案或資料夾、選取文字直接改（inline edit）、vault 或使用者層級的 skill 與指令（`/`、`$`）、MCP、多個對話互傳訊息。Claudian 會在代理的系統提示前面加一段自己的說明（vault 路徑、用 Obsidian CLI 搬移檔案等）。
- **權限**：Claude Code 有四種模式，預設 `auto`（由分類器自動放行），另有 `manual`（每次問）、`acceptEdits`、`yolo`（全部放行）。
- **限制**：只有電腦版（macOS、Windows、Linux），要 Obsidian 1.13 以上（使用者的是 1.14.4）。Windows 不能用 `.cmd`、`.ps1` 的 CLI 包裝，常要自己處理 PATH；環境變數裡的 `ANTHROPIC_API_KEY` 會蓋掉訂閱登入。已上架社群外掛商店。

## 2. 用訂閱跑的規定與額度

### 2-1 Claude Pro

- Anthropic 的[法務與合規頁](https://code.claude.com/docs/en/legal-and-compliance)：訂閱的 OAuth 登入是給 Claude Code 與 Anthropic 自己的 app「一般使用」；用 Agent SDK 做產品的開發者要用 API 金鑰，不能替使用者走訂閱，也不能經手登入資訊。但**不禁止使用者用自己的訂閱登入原版的 Claude Code**。
- Claudian 是用 Agent SDK 啟動使用者電腦上原版的 Claude Code，登入走 Anthropic 自己的流程，屬於灰色但目前可用的地帶。[說明中心](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan) 2026-06-15：原本要把 Agent SDK、`claude -p` 與第三方 app 移出訂閱額度的改變暫停，仍然算在訂閱額度裡；2026-10-07：Max 與 Team 多了每月的 API 額度，Pro 沒提。
- 2026 年這條規定改了好幾次：1 月開始擋第三方工具、4 月改成要另外付費、5 月宣布另給一筆額度、6 月暫停（[The Register](https://www.theregister.com/software/2026/02/20/anthropic-clarifies-ban-on-third-party-tool-access-to-claude/5014546)、[VentureBeat](https://venturebeat.com/technology/anthropic-reinstates-openclaw-and-third-party-agent-usage-on-claude-subscriptions-with-a-catch)）。之後還可能再改，Anthropic 說會先通知。

### 2-2 ChatGPT Plus（Codex）

- OpenAI 的說明中心說 Codex 包含在所有 ChatGPT 方案裡，連 Free 與 Go 都有，額度依方案不同，和 ChatGPT 的其他代理功能共用；有 5 小時與每週的上限，具體數字在價格頁（Claude 沒有查到官方數字）。
- OpenAI 本來就支援第三方 app 用 ChatGPT 帳號登入、用方案的額度。規定面比 Claude 穩。

### 2-3 一次製卡用掉多少額度

- 不知道，要實測。API 直連一次製卡約 2 萬 token 送出、3 千收回（architecture §6）；代理會多輪讀檔，每一輪都重送上下文（有快取），用量會多好幾倍。
- Pro 的 Opus 額度最緊；Plus 的 Codex 額度也和家長平常用 ChatGPT 共用。家長一學期約 60 次製卡，次數本身不多，問題是單次會不會用掉 5 小時額度的一大塊。

## 3. 對 Cards 的評估（重點）

### 3-1 Cards 裡用到 AI 的地方

| AI 工作 | 依據 | 代理代跑能多做的 | 判斷 |
|---|---|---|---|
| 從轉錄稿製卡（含候選卡） | D-039、D-091 | 自己讀轉錄稿、裡面的圖與規則檔，寫出整份草稿；家長不必複製提示、附圖、貼回；訂閱裡最強的模型不另外收費 | 幫助最大 |
| 加深這一節 | D-100 | 省下貼上。「哪些目標熟了」要由外掛用 FSRS 算好放進請求，代理自己讀紀錄算不準 | 有幫助，前提是外掛組請求 |
| 補記憶錨點 | D-108 | 同製卡 | 同製卡 |
| 錯題分析 | D-061、D-113 | 照片要讓代理看得到。貼進 Claudian 的圖會不會存進 vault 還沒查到；存進去就違反 D-088「錯題照片不進 vault」 | 先不用，查證後再談 |
| 家長審核（刪、改、啟用） | D-039、D-042 | Claudian 的 inline edit 可以一句話改一題 | 小幫助；AI 改的會被快照算成「家長改的」，採用率會失真 |
| 規則改進（外層循環） | D-114 | 開發者本來就用 Claude Code、Codex 讀 repo 與快照 | 沒有新增 |
| 依能力產生複習、精熟循環 | [backlog〈產品路線〉](../docs/backlog.md#產品路線2026-10-22-使用者) §2、§3 | 代理讀得到整個 vault，是很自然的執行者 | 之後的方向；同一個介面就能接（§4） |

### 3-2 三種接法比較

| | 複製貼上 | API 直連 | 代理代跑（例如 Claudian） |
|---|---|---|---|
| 第一次設定 | 不用 | 申請金鑰、付款開通、貼金鑰 | 裝 Claudian，另外裝 Claude Code 或 Codex 並登入；Windows 可能要處理 PATH |
| 每次製卡 | 複製提示 → 開 AI 對話 → 附教材 → 複製結果 → 貼回 | 按一下 | 按一下產生請求 → 在 Claudian 說一句 |
| 教材裡的圖 | 家長自己附 | 外掛送 | 代理自己讀 |
| 額外費用 | 0 | Terra 一學期約 4 美元；改用 GPT-6.1 Sol xhigh 約 15 美元（照第一輪 S2 一節約 0.25 美元粗估），R3 輸出更長會更多 | 0，用訂閱額度 |
| 模型 | 訂閱裡最強的 | 推薦的那一個 | 訂閱裡最強的 |
| 會不會動到別的檔 | 不會 | 不會 | 會：代理能寫檔、跑指令 |
| 結果穩不穩 | 看家長貼了什麼 | 最穩，外掛決定送出的內容 | 中：代理可能多讀、多做 |
| 規定 | 穩 | 穩 | Claude 端 2026 年改了好幾次；OpenAI 端比較穩 |

### 3-3 判斷

- **有幫助，但幫的是接法**：省家長的手動步驟、圖自動帶到、訂閱內用強模型不加錢。學習目標的品質仍由製卡規則與模型決定。
- **好處不是 Claudian 獨有**：任何能讀寫 vault 資料夾的代理都做得到，例如 Codex 的 app 或 CLI、Claude 桌面版的 Code 分頁。Claudian 多的是「留在 Obsidian 裡操作」與 inline edit。
- **不適合當預設**：大多數家長不熟 Obsidian（D-057），更不熟終端機，裝 CLI、設 PATH 做不到；它是能跑指令的第三方外掛；Claude 端的規定一年改好幾次。預設推薦照 D-085（API 直連）與 D-039（複製貼上）。
- **適合的人**：已經在用 Claude Code 或 Codex 的家長，包括第一位真實使用者（使用者本人）。

## 4. 💡 最佳做法：請求檔 → 輸出檔，不綁 Claudian

照第一原理想：真正要的是「讓家長自己的代理替他做複製貼上」，不是「接 Claudian」。

1. 外掛照常組好請求：四層規則、年級、教材連結、已有目標、熟練程度，和 API 直連送出的完全一樣（外掛決定送什麼，D-114 的「程式確認、AI 提案」不變）。
2. 多一個按鈕「交給自己的 AI 代理」：把請求寫成一個檔，並把一句話複製到剪貼簿，例如「照 [[請求檔]] 做，結果寫到 [[輸出檔]]，不要改其他檔」。
3. 代理讀請求和它連到的教材與圖，只寫輸出檔。卡組、複習紀錄、教材庫都由外掛寫。
4. 外掛收到輸出檔（檔案變動通知，D-110 檔案存取的五件事之一），走「貼回輸入框」同一段程式：語法檢查（D-089）、配 ID、存快照（D-042，接法記「代理」，模型由代理寫在輸出檔開頭）、寫入草稿卡組，最後清掉請求檔與輸出檔。

- **不寫任何 Claudian 專用的程式**，也不呼叫 Agent SDK 或 Codex SDK（§8 沒有採用）。
- **程式量很小**：複製貼上本來就要「組提示」「收結果」，只多「寫成檔」「讀檔」，用 D-110 已有的檔案存取。
- **細節在 AI 製卡模組寫規格時定**：請求檔放在 `紀錄/` 底下的哪裡、檔名、輸出檔開頭的格式、代理沒照規矩時怎麼辦。
- **時間點**：AI 製卡模組（D-111 排在入口、目錄、設定頁、編輯畫面樣式之後），現在不動 W4～W6。

## 5. Capture 與 Mindboard（簡述，之後再展開）

- **Capture**：轉錄是最吃 token、也最需要強模型的一步（D-085：GPT-6 Sol 才截得對圖），訂閱代跑省下的錢比 Cards 多。但截圖要在電腦上裁切，代理得跑程式，比 Cards 的「讀檔、寫檔」複雜。Capture 開工時（D-111 之後）和 [backlog「開始做 Essence Capture 前先找現成專案」](../docs/backlog.md#2026-10-09-新點子) 一起評估，可以沿用 §4 的介面。
- **Mindboard**（心智圖外掛，D-056）：價值在挖空回想與記憶狀態配色（D-060），都是程式的事，不需要代理。AI 能幫的是從轉錄稿的章節樹產生節點文字，同樣能用 §4 的介面。做 Mindboard 時再談。

## 6. 代價與風險

1. **安裝門檻**：要另外裝 CLI 並登入，Windows 常卡在 PATH。只當選用的接法，使用說明書寫一段選讀。
2. **改到不該改的檔**：代理能寫檔、跑指令，Claudian 預設的 `auto` 模式會自動放行；Obsidian 也[無法限制外掛的權限](https://obsidian.md/help/plugin-security)。緩解：請求檔寫明只寫輸出檔、建議 `manual` 模式、外掛只認輸出檔；複習紀錄只追加（D-115），出事用 Git 救回。
3. **規定會變**：Cards 自己不碰登入、不轉送請求，所以 Cards 不違反規定；Claudian 能不能繼續用 Claude 訂閱，是 Claudian 和 Anthropic 之間的事。Claude 端變了，家長改用 Codex 或另外兩種接法就好。
4. **額度**：見 §2-3，要實測（§7）。
5. **結果和 API 不同**：代理的系統提示（Claudian 加的一段，Claude Code、Codex 也各有一段）可能改變輸出；要比一次。
6. **第三方外掛**：一位主要維護者、改版很快。Cards 不依賴它，它停更也不影響 Cards。
7. **隱私**：學生資料送到 Anthropic 或 OpenAI，和 API 直連一樣；訂閱方案的訓練設定由家長自己決定（D-055 可以接受拿去訓練）。

## 7. 和第二輪設計（整合版）的關係

建議加兩件事，都不改 R0～R3 與盲評：

1. **成本換算**：每組記下一節的 token 與費用，換算成 API 直連一學期（約 60 次）的成本。
2. **訂閱代跑的旁測**：在「R3 開跑前用 2-1、2-2 核對長度」那一步，順便把 R3 的 2-1 寫成請求檔，用 Codex 以使用者的訂閱、同一個 GPT-6.1 Sol xhigh 代跑一次。記：額度用掉多少（`/status` 前後）、時間、有沒有跑完、輸出能不能解析、和 API 版的輸出有沒有明顯差異。不進盲評。使用者的 Codex 是 Plus 才有代表性。Claude Pro 端（Claude Code）要不要也跑一次，請使用者決定，因為會用掉使用者的 Claude 額度。

判讀：第二輪如果顯示要強模型或 R3 才夠好，API 一學期的成本會上升，代理代跑的價值跟著上升；如果 Terra 級的模型就夠，代理代跑只是省貼上。

## 8. Claude 的建議（提案，待 Codex 回應、使用者決定）

1. 不把 Claudian 當依賴、必要條件或預設推薦；D-085 的推薦與 D-039 的兩種接法不變。
2. 💡 複製貼上的請求與結果也能用檔案交換，讓家長自己的 AI 代理（Claudian、Codex、Claude 桌面版）代跑（§4）；不寫任何代理專用的程式，細節在 AI 製卡模組寫規格時定。Claude 傾向放進 v1：程式和複製貼上共用，第一位真實使用者正是這種人。但它是「優先刪減」的候選，請 Codex 一起判斷。
3. 使用說明書（D-048）加一段選讀「已經在用 Claude Code 或 Codex 的家長」；§7 的量測結果寫進 [ai-models.md](../docs/ai-models.md)。
4. 第二輪整合版加 §7 的兩件事。
5. Capture、Mindboard 開工時再評估，沿用同一個介面。

**沒有採用**：

- **Claudian 當預設接法**：安裝門檻高、有指令權限、Claude 端規定不穩（§3-3）。
- **Cards 內建代理**（自己呼叫 Claude Agent SDK 或 Codex SDK）：Anthropic 規定第三方產品用 Agent SDK 要用 API 金鑰，不能替使用者走訂閱；還要包 CLI，程式量大，違反 D-059「一種介面、程式碼最少」。
- **讓代理直接寫卡組**：沒有快照、沒有配 ID，可能改到已啟用的卡；寫回筆記要集中在卡組模組（D-042、D-110）。
- **另外寫一個 Essence Cards 的 skill**：請求檔自己寫清楚就夠，任何代理都看得懂；真的常用再加。
