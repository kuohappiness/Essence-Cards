## R4〔P2〕「照頓號、逗號、分號切段」不是現有讀法的等價分行

**位置**：`tasks/edit-markup.md:151`～`153`；依據 D-164 第 4、6 點、D-170 第 3、6 點；`src/core/deck/sources.ts:72`～`82`、`425`～`458`。

**觸發與證據：已重現；真實路徑會發生。**

| 原來的出處 | 原來的意思 | 按標點拆成子項目的結果 |
|---|---|---|
| `溶解, 擴散、p.44、p.45` | 一個舊標題 `溶解, 擴散`，再兩個頁碼 | 標題變成 `溶解` 與 `擴散` 兩個，連結意思不同 |
| `p，44、p.45、p.46` | p.44、p.45、p.46 | `p`、`44` 不再是 p.44 |

現有程式先保護連結、`「標題」` 與網址，再辨識 `p，44`；一個頓號項裡全是讀不懂的段時，還會合回原來的整個舊標題。寫回若直接使用中間的逗號切段，會失去這個邊界。斜線也是讀法接受的分隔（syntax §2-5），而 §4-3 的列舉沒說要保留在同一子項目，還是與其他分隔相同處理。

**預期／缺口與影響**：分行應保留整欄原意。R1 所述核對即使補齊，也只是拒絕這些結果，不能替分行定義唯一的切法。

**建議處理**：將「段」定成能保持現有整欄讀法的原文片段；連結與引號內、網址、頁碼容錯、會合回的舊標題都不得按字面標點拆開。不必為了分行重寫出處語法。以含標點的筆記連結、`「標題」`、Markdown 連結、網址、斜線及上表為驗收，對照分行前後的完整語意。

`｜` 的搬法本身可沿用既有語法，但還需定義**既有子項目的歸屬**：例如 `出處：p.44｜備註：A` 底下的 `重要性：高`、`錯題補強：[[考試甲]]` 仍會被 `collectFields` 遞迴讀到，不是出處值（`parse.ts:184`～`211`，既有測試 `deck.test.ts:864`、`942` 起）。只搬出處時不能刪掉或重排這些欄位。半形 `|` 接欄位名稱與全形 `｜` 都要覆蓋；連結與引號內的符號都不是欄位分隔。

## R5〔P2〕去重後的 `at`、順序驗收與「整欄一項」互相不一致

**位置**：`tasks/edit-markup.md:104`～`110`、`147`、`149`、`160`；`src/core/deck/sources.ts:444`～`475`。

**觸發與證據：已重現；真實路徑會發生。**

```text
sourceLinks(['p.44', 'p.45', '老師說過 p.44'], own)
→ 第 1 項 text = 老師說過 p.44、link = p44、problem = before
→ 第 2 項 text = p.45、link = p45
```

去重保留第一個按鈕的位置，但後一次同連結有問題時，會把第一項的 `text` 換成後一次的原文。若 `at` 指到實際有問題的第三段，就違反「照順序」；若指第一段，就不符合原文與 `text` 的驗收，也標錯需要修正的文字。不是「去重後丟掉的不用填」就能處理。假如家長將第三段修成 p.46，原本的 p.44 還在，按鈕應變三個；§4-3 第 5 點所說的「原本按鈕逐項換掉」也不是正確的預期結果。

另一個獨立的邊界：`sourceLinks(['溶解, 擴散', '睡眠的階段'], own)` 回傳**兩項** heading，並不因整欄沒讀到位置而合成一項。現有程式只在同一個頓號項的逗號等子段全是 heading 時合回；§3 所說「整欄都沒讀到時的那一項是整串」與現有行為不一致。

**預期／缺口與影響**：不改讀法與按鈕順序，又要讓可編輯範圍指向正確的原文。現在無法同時滿足列出的三個條件，會影響標示、點擊與指定第 i 項換字。

**建議處理**：分清「未去重的原文項／出現次數」「顯示按鈕」「診斷的原文來源」，定義按鈕有多個來源時怎麼選編輯對象或明確不寫。`at` 的單調性應對哪一個序列驗證也要一起改清楚；不能為了配合座標而重排現有按鈕。全沒讀懂的例子按現有的頓號項邊界定義，不擴大成整欄。

## R6〔P2〕單行座標契約未覆蓋接續行，且 `key` 定義與驗收不同

**位置**：`tasks/edit-markup.md:56`、`100`～`110`、`154`～`156`、`161`；`src/core/deck/markdown.ts:151`～`179`、`src/core/deck/parse.ts:155`～`194`。

**觸發與證據：接續行行為已重現，其餘是型別與驗收的靜態矛盾；真實路徑會發生。** 現有 `Item.text` 可能跨行，而欄位分段在整個 `node.text` 上執行：

```markdown
- 目標
    - 出處：p.44
        ｜重要性：很高
    - Q :: A
```

`出處` 的值是同一行的 `p.44`，所以 `sourceSpans` 不會是跨行的 `null`；但同一個 Item 的後一個欄位在接續行。§1-2 的問題若仍用 `node.line` 配一對 columns，就無法標到實際的 `很高`。§4-3 只禁止「那一項跨接續行」，也沒有決定這種 joined Item 能否重排、搬出處時如何保留第二行。

另外，`出處：p.44` 後接純文字 `p.45` 時，現有 `sources` 是一個 `p.44\np.45`，設定其 span 為 `null` 合理；但 `SourceField.value` 又說只記第一行的值。若用它重排整欄，須明確禁止或另行保留 continuation，不能只靠一個單行 value 範圍操作整個 Item。

**預期／缺口與影響**：原文座標應能直接拿來切原始字串，欄位 metadata 必須足以判斷哪些文字可以安全搬動。現在有些有效輸入的欄位或問題沒有可表示的位置。

**建議處理**：補以下契約，再用固定字面值驗收：

- `line` 從 0 算；column／from／to 是**原文 UTF-16 offset**，範圍採 `[from, to)`；Tab 算一個字元、全形空白也算一個。縮排的顯示欄寬 `contentColumn` 是另一種單位，插行時轉換，不能當成字串索引。
- `Item.starts` 對應每一個實際加入 `text` 的行，第一行清單符號後空白、接續行 trim 的長度均從原文取得；沒有加入 text 的空行、圍欄不列入。
- `SourceField.key` 到底包含冒號與冒號前空白嗎？第 2 點定成 `出處：`，驗收卻要求切出 `出處`。`出處 ：`、`出處\t:` 目前都是有效寫法，需寫死各自的範圍。
- `joined` 包含半形分隔與跨接續行的分段；`children` 是值子項目還是所有子項目，及子項目自己的接續行／巢狀欄位如何歸屬，需明確。欄位或 Problem 的實際行若不同於 Item 開頭，要有可表示的契約；這批不寫的形狀可明列，但讀法仍保持。
- `RAW_CUT_LIMIT` 的長度是整欄、來源項還是片段，以及遮罩前或遮罩後，需指定；`at` 缺席的情況也要有套用規則，不能只有 span 為 `null` 才停。遮罩會縮短連結，`tidy` 會刪字與合併空白，座標必須還原到原文，不能由顯示文字 `indexOf` 猜位置。

還有一個現有防禦性輸入：欄位值 `p\uE000.44` 經 `splitOutsideLinks` 會變成 `sources = ['p.44']`，原文卻沒有連續的 `p.44` 可切。§3「所有非 null span 切出來都等於 sources」需要定義這類無單一連續原文對應時的結果（例如不提供可編輯 span），不能為了通過斷言改掉既有遮罩行為。這是防禦性字元例子，與一般家長輸入的優先程度不同。

## `where: "edit"` 與回頭查修

增加 `edit` 與 syntax §9 相容：`where` 本來就可隨版本增加，錯誤紀錄不參與讀取閘門或排程，不必為此加 `需要版本`。實作時同步 `ErrorWhere` 型別與語法表即可。

只寫「哪個核對條件失敗」能定位程式分支，但不能定位哪篇筆記的哪個目標。§4-3 第 5 點宜補：呼叫既有 `record('edit', ..., { path })` 傳卡組路徑，`msg` 寫固定失敗代碼、動作（加／換／搬）、目標行號與原文項索引等數字；保留 build、時間與既有 stack 規則。用這些資訊已能回查原始筆記，不必記題目、答案或原文。現有 `lt`、`v` 只在 `report` 使用，不建議為此順便擴充其適用範圍。這是查修資訊的補述，不是第 7 個格式阻擋項。

### R9 續〔P2，規格〕名稱與冒號跨行時，key／value 仍不符合單行座標契約

- 冒號：line 2，`[8, 9)`。
- `p.44`：line 2，`[9, 13)`。

§3-3 規定 key 是「出處＋冒號前空白＋冒號」，且只有一個 `{ line; from; to }`；key.line 又是出處實際所在行。line 1 沒有冒號，line 2 沒有出處，因此不存在可滿足這個定義的單行範圍。value 還被要求和 key 同一行，也與實際值的位置不同。把 key 整體移到接續行，只解決上一輪「整個欄位從接續行開始」的例子，沒有涵蓋這一種。
