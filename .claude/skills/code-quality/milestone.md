# 里程碑檢查

改寫自 mattpocock/skills 的 retro（見 [UPSTREAM.md](UPSTREAM.md)）。

里程碑列在專案設定裡。里程碑完成時，主動提醒使用者做下面兩件事；使用者同意才開始。

## 1. 回顧：讓同樣的錯不再發生

讀這個里程碑的 commit、審查紀錄與技術債清單，依嚴重程度列出改善建議：

- **能變成自動檢查的錯**：犯過的錯如果是固定的寫法、禁用的 API、import 方向或檔案位置，加一條檢查。也確認既有的檢查真的有接上、沒有失效。
- **審查漏掉的**：哪些問題到後面才發現？審查清單或規格範本要補什麼。
- **沒有作用的指示**：每次都載入的指示檔（AGENTS.md 等）、skill 裡沒有改變任何行為的句子，刪掉或搬到按需讀取的地方。
- **找資料太慢**：花很久才找到的資訊，加一個指引連結。
- **成本花太多的地方**：昂貴的工具呼叫、重複讀取的大檔、可以交給成本較低的角色做的工作。
- **技術債清單**：觸發點已過還沒處理的；完成條件寫得不清楚的。

只提建議，改哪些由使用者決定。

## 2. 安全檢查

環境裡有 `security-review` 之類的工具就用它。沒有的話，照下面的清單檢查這個里程碑的改動，並說明少了工具造成的缺口：

- 金鑰、憑證、私人資料有沒有進到 repo、log、畫面輸出或錯誤訊息。
- 外部輸入（檔案內容、網路回應、使用者輸入）有沒有未經檢查，就拿來組路徑、指令或 HTML。
- 寫檔有沒有可能寫到預期外的位置，或在失敗時留下寫到一半的檔案。
- 相依套件的已知漏洞（例如 `npm audit`）。

改到金鑰、外部資料或檔案寫入的改動，平常審查時就要看這些，不必等到里程碑。
