## 和「不做」比較（D-153）

- **不做會怎樣**：
  - D-089 第 10 條的「編輯畫面標出問題」一直沒做，寫錯的目標只能靠存檔按鈕的數字發現，長筆記要自己找。
  - 目標那一行被按了 Tab，它和底下的題目就默默不出題（[技術債](../docs/backlog.md#技術債)〈目標那一行被按 Tab〉），編輯時完全看不出來。
  - 看不懂的出處只有存檔按鈕的提示；跨單元的出處要家長自己照規則打字。第二批的考試範圍靠出處算單元，寫錯就會少算。
  - `出處 p.45`、`來源：p.45` 默默變成背面補充：學生翻面多看到一行字，出處的圖示不出現。
  - 正式版要等第四批合併才升 `0.4.0`（[roadmap](../docs/roadmap.md#現在在哪裡)），考試範圍、小考、點選填空都還到不了學生手上。
- **做的代價**：
  - 編輯器多一層樣式，每次改字都要重新解析一次，要量速度（§1-5）。
  - 兩種會改寫筆記的動作（表單、§1-4 的修改）：要往返測試、格式查核與 L2。
  - 解析多一份原文位置（§3），讀法本身不變。
- **怎麼解決**：解析延遲到停止打字之後；原文位置只在編輯器要時才算，不放進目標裡（§3-1）；寫回前先重新解析新的字，意思不同就不寫（§4-3 第 6 點）；一次寫入是一個交易，`Ctrl+Z` 一次復原。

## 1. 結構標示（D-047）

只在電腦版的編輯器（即時預覽與原始碼模式），只在卡組筆記（和 ID 鎖定同一個判斷，`src/main.ts` 的 `lockable`）。閱讀模式、iPhone、一般筆記不顯示。草稿也顯示：家長正在做卡的時候就是草稿。

### 1-1 標示什麼

照樣式稿。顏色用 Obsidian 的 CSS 變數，跟著使用者的主題。

| 對象 | 怎麼標 | 判斷 |
|---|---|---|
| 學習目標那一行 | 左邊一條 2px 細線，`--interactive-accent`，不透明度約 0.45；在清單圓點的左邊，不推動文字 | `parseDeck` 的 `targets`（有題目才算目標，D-079）。直接寫成題目的目標（`- Q :: A`）也算 |
| 題目的 `::` | 那兩個字變 `--text-accent`，不透明度約 0.6 | 每個 `qa` 題目第一行的 `::`（`questionSyntax` 的位置）。填空照 Obsidian 的螢光筆，不另外加 |
| `error` 的問題 | 紅色波浪底線（`--text-error`） | `problems` 裡 `level: 'error'` 的；這一題不會出 |
| `hint` 的問題 | 橘色波浪底線（`--text-warning`） | `level: 'hint'` 的；照常出題。不標 `misplaced-id`（存檔時自動移回，家長不用做事）與屬性區的問題（即時預覽的屬性是 Obsidian 的表格，標不上；存檔按鈕已經提示） |
| 看不懂的出處 | 橘色波浪底線，滑過時底色微微變橘、游標變手指；點了打開 §4 的表單 | §1-3，範圍是那一段的原文（§3） |
| 出處的欄位名稱寫錯、資料欄位的半形冒號 | 橘色波浪底線，點了問一句（§1-4） | §1-4 |

- **底線的範圍**：問題有欄位的位置時（§1-2）只畫那一段；沒有時畫那一項第一行的內容，不含清單符號與行尾的 ID。
- **滑過的說明**：用 Obsidian 的 tooltip（`aria-label`），內容是問題的 `message`；看不懂的出處照 §1-3 的句子。實作時在 Obsidian 確認會顯示，不行再改成自己畫。
- 縮排錯一層（目標被按 Tab）不另外提示：細線、淡紫與波浪線一起消失，ID 也不再上鎖、露出 `^xxxx`，樣式稿第三張就是這個樣子。要不要另外提示照技術債那一列的觸發點，這批不動。

### 1-2 問題多記欄位的位置

`unknown-field-value`、`duplicate-field`、`unknown-field` 是資料欄位那一項的其中一段（`重要性：很高`）。`Problem` 多一個選填的 `columns: { line: number; from: number; to: number }`，座標照 §3-2 的約定；只有這三種會填，範圍是那一段的值（`很高`），`unknown-field` 是整段。那一段在接續行時照實填接續行的行號（回報 R6 的例子：`出處：p.44` 底下接續行的 `｜重要性：很高`）。其他問題不填，畫 `line` 那一行。`Problem` 不在 `targets` 裡，改縮排的保護（`assign.ts` 比 `targets`）不受影響。

### 1-3 看不懂的出處的說明

判斷照 [§9-5](entry-and-catalog.md#9-5-看不懂的出處)，改成**每一段原文**判斷一次（§3-3 的 `SourcePart`），不是去重後的按鈕：同一個位置寫兩次、後面那次有問題時（回報 R5 的 `p.44、p.45、老師說過 p.44`），標的是有問題的那一段。存檔按鈕的「有 N 個出處看不懂」也改數段，和畫面上的波浪線一樣多：一段裡只要有一項有問題就算一段，tooltip 用那一段裡照下表最前面的原因。和現在的數字不同的有兩種，測試照新的數字改：同一個位置寫兩次（`p.44、p.45、老師說過 p.44`，現在按鈕合併）、同一段讀出兩個有問題的按鈕（`老師說過 p.44 和 1-3 p.45` 是 `before` 與 `leftover` 兩個，改成數段是 1，回報第二輪）。

tooltip 照原因寫一句，最後都加「點一下幫你改。」；同一段有好幾個原因時用表上最前面的：

| 原因 | 說明 |
|---|---|
| `missed`，原文沒有年級學期（`1-3 p.20`、`L1`） | 沒寫年級學期，不知道是哪一個 1-3（用原文的編號） |
| `problem: 'term-only'` | 寫了年級學期，沒有完整的單元編號 |
| `problem: 'position'` | 頁碼或範圍寫反了，連不到 |
| `problem: 'before'` | 位置前面有一句話，不確定是不是出處 |
| `problem: 'leftover'` | 裡面有像單元編號的字，沒有算進去 |
| `problem: 'negative'` | 有否定的字，外掛不確定意思 |
| `needsUnit` 對不到目錄 | 找不到這個單元 |
| 舊標題在材料裡找不到 | 材料裡找不到這個標題 |
| 單元後面的字不是名稱也不是標題 | 單元後面的字看不懂 |

`1-3 p.20` 在 `deck` 裡是 `problem: 'before'` 加 `missed`（[§9-3](entry-and-catalog.md#9-3-出處一欄怎麼讀syntax-2-5d-170)），所以第一列排在 `before` 前面；原文有沒有年級學期、編號是什麼，用 §4-1 猜測的同一個函式判斷，不另寫一份。

### 1-4 出處的欄位名稱寫錯、半形冒號：問一句就改

使用者 2026-11-06 提出：家長只要點同意，外掛就改成正確的寫法；半形冒號是所有資料欄位都改（出處、類型、重要性、狀態、備註、錯題補強），全篇看起來一致。

**標哪些**：欄位名稱寫錯的兩種，只看解析後**本來是一整項背面補充**的項目（回報 R10）：目標底下直接一層、不是題目也不是欄位的項目（`shared` 的一項），或題目底下直接一層、不是欄位的項目（那一題 `extras` 的一項；答案寫在底下的多行答案不算）。題目本身、多行答案、欄位的值（`出處：`、`備註：`、`錯題補強：` 底下的子項目）、補充底下更深的一層都不標。半形冒號看所有資料欄位（和 `collectFields` 讀欄位的範圍相同）。連結、行內程式碼裡的字都不算：

| 原文 | 現在讀成 | 什麼時候標 | 改成 |
|---|---|---|---|
| `出處 p.45`（`出處` 後面接空白，沒有冒號） | 背面補充（不是題目時）或題目的補充 | 這一項沒有接續行、底下沒有子項目（改名之後子項目會變成出處的值，意思就變了）、後面的字裡沒有 `｜` 或半形 `|` 接欄位名稱（改名之後會多出別的欄位），而且後面的字照出處的讀法讀得懂：至少一段是位置或單元，每一段都沒有 §1-3 的問題 | `出處：p.45` |
| `來源：p.45`、`來源:p.45`、`來源 p.45` | 同上 | 同上 | `出處：p.45` |
| 資料欄位用半形冒號：`出處:p.45`、`類型:定義`、`重要性 : 高`（D-089 第 5 條本來就認得） | 那個欄位，讀法正確 | 一律標，包含用 `｜` 或半形 `|` 接在同一行的每一段（`出處:p.45｜類型:定義` 標兩處）；連結、行內程式碼裡的冒號不算 | 冒號換成 `：` |

- `來源：植物的光合作用` 讀不出位置，不標，照舊是補充，所以不會誤標，也不用做「這不是出處」的按鈕。
- 判斷是 `source-edit.ts` 的純函式（§4-4），不是新的 `ProblemCode`：讀法、存檔按鈕與目錄的問題數都不變，只有編輯畫面標示。
- **底線的範圍**：前兩種是那一項第一行的內容（整行都讀錯了）；半形冒號只畫欄位名稱加冒號那幾個字（`類型:`）。tooltip：「這一行看起來是出處，點一下改成正確的寫法。」「冒號改成全形，和其他欄位一致。點一下就改。」
- **點了之後**：跳出和表單同一種浮動面板，一句話加兩個按鈕「修改」「不用」：
  - 欄位名稱寫錯的：「改成「出處：p.45」？」（引號裡是改完的整項，最長顯示 40 個字，多的用 `…`）。
  - 半形冒號的：「冒號改成全形？」；這篇還有別處半形冒號時寫「冒號改成全形？這篇共 5 處，一起改」，按「修改」一次改完整篇的半形冒號（家長不用一處一處點）。欄位名稱寫錯的不跟著一起改，各自問。
  - 按「不用」只是關掉，標示還在。
- **怎麼改**見 §4-4。

### 1-5 什麼時候更新、樣式放哪裡

- 打開卡組時馬上算；改字之後停 250 ms 沒再改才重新解析整篇，中間的標示跟著改動平移（`DecorationSet.map`）。
- 看不懂的判斷要看材料與目錄：state 的卡組或目錄有變、材料的 `metadataCache` 更新時也重算。材料的快取還沒建好時照 §9-5 不提示。
- **速度**：自編一篇 300 個目標、每個三題的卡組，在這台電腦量一次解析（含 `layout`）加產生標示的時間，寫進〈結果〉。超過 30 ms 時先停下來想辦法（例如只重新解析改到的那個目標），不把等待拉長。
- 樣式放 `src/obsidian/markup.css`，class 名稱用 `essence-cards-` 開頭。即時預覽的清單行有自己的縮排與 `text-indent`，細線的位置要在 Obsidian 裡對過（§6-3），不要改到 Obsidian 的清單樣式。

## 2. 表單的入口（D-169 第 5 點、D-170 第 10 點）

1. **點看不懂的出處**：游標照常放到點的位置，同時打開那一段的表單（§4）；焦點留在編輯器，直接打字就照常編輯，改到筆記時表單關掉。`Esc`、點表單外面也關掉。
2. **游標在出處那一行**：主要的選取是空的、而且在某個目標的 `出處` 欄位那一行，或它分行的子項目上時，那一欄的第一行行尾出現一個小圖示（樣式稿的方框加號，`--text-faint`，滑過變 `--text-accent`），`aria-label`「填出處」。點了打開空白的表單，用來加一項。按下去不移動游標（`mousedown` 擋掉預設）。一篇只有一個圖示。
3. **命令「填出處」**（`editorCheckCallback`）：游標在某個目標裡（目標那一行到它的最後一個子項目）才可用。游標在看不懂的出處上時打開那一段的表單，否則打開空白的表單。

## 3. 出處的原文位置（要格式查核）

[§9-1](entry-and-catalog.md#9-1-模組) 寫著「第四批再加編輯要的原文位置」。讀法與按鈕都不變，只多一份位置。

### 3-1 放在哪裡

原文位置**不放進 `Target` 或 `Fields`**：改縮排的保護（`src/core/deck/assign.ts:41`）比的是整個 `targets` 的 JSON，`src/state/ids.ts:196` 也比目標的 JSON，座標放進去會讓合法的修正被退回（回報 R2）。做法：

- `parseDeck(text, { layout: true })` 才另外回傳 `layout: Map<number, TargetLayout>`（鍵是目標那一行），沒給選項時結果和現在完全一樣。只有編輯器的標示與寫回會要它。
- 欄位用同一次遞迴（`collectFields`）收集，不另寫一套掃描，順序和 `fields.sources` 一致。

### 3-2 座標的約定

- `line` 從 0 算，是檔案的第幾行；`from`、`to` 是那一行原文的 UTF-16 位置，範圍是 `[from, to)`。Tab、全形空白各算一個字元。
- 縮排的顯示寬度（`Item.indent`、`contentColumn`，Tab 展開成 4 欄）是另一種單位，只在插入新的行時用，不能拿來切字串。
- `listTree` 的 `Item` 多一個 `starts: { line: number; column: number }[]`，和 `text.split('\n')` 一一對應：第一行是清單符號與後面的空白之後；接續行是那一行去掉前面空白之後。沒有加進 `text` 的行（空行、圍欄、分隔線之後的行）不列。

### 3-3 一欄出處的原文段

`TargetLayout` 是這個目標的：

1. **`fields: SourceFieldLayout[]`**：每一個 `出處` 欄位，照遞迴的順序。同一行用 `｜` 寫了兩個 `出處：` 算兩個（回報：`出處：p.44｜出處：p.45` 不是 `duplicate-field`）。
   - `line`：欄位那一項的第一行。
   - `name: { line; from; to }`：`出處` 這兩個字；`colon: { line; from; to }`：後面那個冒號。兩個各帶自己的行號（回報 R9 與第三輪）：出處從接續行開始時（`類型：定義` 底下接續行的 `｜出處：p.44`）就是接續行；名稱後面換行才打冒號時（`出處` 底下接續行的 `:p.44`，現在的讀法照樣認得，`\s*` 含換行），`name` 在第一行、`colon` 在接續行。冒號前的空白不在兩者裡面。
   - `value: { line; from; to } | null`：從冒號後面第一個不是空白的字，到這一段結束（`｜` 或那一行結束）之前，去掉後面的空白，行號是值實際所在的那一行；冒號後面那一行沒有字（值寫在子項目，或沒有值）是 `null`。
   - `joined: boolean`：這一項有沒有用 `｜` 或半形 `|`（後面接欄位名稱）接別的欄位，包含在接續行接的。
   - `continued: boolean`：這一項的文字有沒有接續行。
   - `children: number[]`：當成出處值的子項目（不是欄位開頭的那些）的第一行，照順序。子項目底下的欄位照現在的遞迴歸到它自己。
2. **`entries: ({ line; from; to } | null)[]`**：和 `fields.sources` 一一對應（頓號切開、去掉前後空白之後的每一項）。跨了接續行，或原文裡沒有一段連續的字等於它（例如藏在私用區字元的防呆例子 `p.44`，回報 R6）時是 `null`。
3. **`parts: SourcePart[]`**：`sourceLinks` 讀的時候實際切出的每一段，**去重之前**，照原文順序：
   - `entry`：出自 `sources` 的第幾項；`from`、`to`：在那一項原文裡的位置（去掉前後的分隔符號與空白）。一項切不出原文（`entries` 是 `null`、那一項超過 `RAW_CUT_LIMIT`，這個長度照現在 `sources.ts:322` 量的是那一項的原文）時是 `null`。
   - `items`：這一段讀出的項目（`SourceItem`，可能不只一個，例如 `p.44 p.45`）。
   - `follows: 'place' | 'term' | null`：這一段的讀法用到前一段的哪一種（回報 R8）：`place` 是接著前一個位置，和前一段同一個單元（`p.44、45` 的 `45`、`圖2-13a、b` 的 `b`）；`term` 是沿用前一個單元的學期，是**另一個單元**（`國二上 1-3、1-8` 的 `1-8`）。只記往前的依賴；往後看的（`44、46頁` 的 `44` 靠下一段的「頁」）不記，由 §4-3 第 6 點的整欄重讀擋。
   - `scope`：讀這一段時位置跟著哪個單元（`this`、別的單元、或不知道）；`國二上 1-3、p.44` 的 `p.44` 跟著 1-3（D-170 第 6 點）。
   - 一項切成好幾段、全部沒讀懂而併回一個舊標題的（`溶解, 擴散`），是一段，範圍是那一項。只在同一項裡併，不跨項（`['溶解, 擴散', '睡眠的階段']` 是兩段，回報 R5）。
4. **`fieldColons: { field; name: { line; from; to }; colon: { line; from; to } }[]`**：這個目標所有資料欄位（六個都算，同一行用 `｜` 接的每一段也算）的名稱與冒號，照遞迴的順序；座標的意思和 `SourceFieldLayout` 的 `name`、`colon` 相同，可以跨行。§1-4 的半形冒號標示與 §4-4 的修改只用它，不另外找冒號。標示的底線：名稱與冒號同一行時畫一段（`類型:`），跨行時各畫一段。
5. **按鈕不變**：`sourceLinks` 照舊回傳去重後的按鈕，順序與內容都不變；實作上由 `parts` 攤平再去重得到，現有的 `sources.test.ts` 預期值不改。

### 3-4 驗收

共用範例清單（`tests/sources.test.ts`）的每一個例子，加上打字雜訊之後也成立：
- `parts` 攤平去重的結果等於 `sourceLinks`（逐欄位比）。`parts` 要等整欄讀完才定稿，不能每段各自讀再接起來，也不能讓去重改到 `parts` 裡的項目（回報第二輪，各寫一個固定例子）：
  - 否定段會回頭改前一段（`國二上 1-3、不算這個` 的前一段變成 `negative`）；
  - 往後看的段（`44、46頁`）；
  - 同一項併回舊標題（`國二上 1-3、溶解, 1-8`），不能標成 `remark`；
  - 內部的 `codeLike`、`written` 照現在的步驟用完；`國二上 L1-2 p.20、p.20` 最後仍有 `needsUnit`；
  - 去重時把保留的按鈕換成後一次的文字與問題，只改按鈕的複本，`parts` 裡的第一段照原文。
- `SourceFieldLayout` 的 `name`、`colon`、`value` 切出來是那幾個字，寫死座標：出處從接續行開始的例子（回報 R9）；名稱與冒號跨行的 `- 出處` ＋接續行 `:p.44`（第三輪：`name` 第 1 行 `[6, 8)`、`colon` 第 2 行 `[8, 9)`、`value` 第 2 行 `[9, 13)`）；以及 `類型：定義` 接續行 `｜出處`、再下一行才有 `:p.44` 的變體。這兩種都是 `continued`，表單不寫回；半形冒號的修改照 `colon` 的位置換那一個字，改完 `parseDeck` 的結果不變。
- 每一個有位置的段，切出來的原文去掉私用區字元再 `tidy`，等於讀的時候用的那一段；段照原文順序、不重疊。
- 回報裡的例子寫死：`p.44, 45`、`p，44`、`ｐ　．　４４`、`溶解, 擴散`、`[[a、b]]`、`「c、d」`、連結內的 `｜` 與 `|類型：`、長連結、超過 `RAW_CUT_LIMIT` 的兩側。

`deckCases` 的每一篇：`entries` 切出來等於 `sources` 那一項（`null` 的除外，並列出哪幾個例子是 `null`）；`name` 切出來是 `出處`，`colon` 是 `：` 或 `:`；`fieldColons` 的每一個切出來是那個欄位名稱與冒號；`parseDeck(text)` 不給選項時的結果和給選項時的 `targets`、`problems` 一樣。

## 4. 小表單

照樣式稿：浮在那段文字或圖示的下方，下面放不下就往上開。一列單元、一列以上的位置、一列說明、預覽兩行（會寫成、會算進）、取消與套用。

### 4-1 先填好的內容（猜測）

純函式，放 `src/core/catalog/source-guess.ts`（要看目錄，所以在 catalog；只建議，不改歸屬，D-170 第 2 點）。輸入是那一段（`SourcePart`，加上它的接續段，見 §4-3 第 1 點）、這一篇的屬性、同一科的單元清單（年級學期、編號、名稱）。輸出每一欄的值，並標明來源：**原文**（照實帶進來）、**猜的**（虛線框加「猜的」）、**沒選**。

- **單元的選項**：「這一篇」、候選的單元、「其他單元…」。「其他單元…」展開兩個選單：年級學期（目錄裡同一科有的）與那一學期的單元（顯示編號與名稱）。只列目錄裡有的（D-169 第 5 點）。
- 這一段本來就跟著別的單元（`scope`，例如 `國二上 1-3 p.20、老師說過 p.21` 的第二段）：單元預設是那個單元，**原文**。

### 4-2 會寫成什麼

純函式，和 §4-1 同一個檔。

- 一段的寫法：`[單元] [位置…] [說明]`，中間一個半形空白。
  - 單元是「這一篇」時不寫；但寫進的位置跟著別的單元（§4-3 第 1、2 點決定位置之後才知道）時，前面加 `本單元`（syntax §2-5：「別的單元後面要接這一篇的位置時，寫 `本單元 p.44`」）。
  - 別的單元寫 `年級學期 編號`（用目錄顯示的原字）。
  - 位置：頁 `p.20`、圖 `圖 2-14`、表 `表 2-1`、例題 `例題 2-3`、筆記連結 `[[筆記#標題]]`（家長打的字沒有括號時補上）。好幾個位置用空白隔開，寫在同一段（`國二上 1-3 p.20 p.21`，D-170 第 5 點）。
- 位置的格式：頁是數字；圖、表、例題是數字與連字號，圖可以多一個子圖字母。格式不對時那一格標紅，不能套用。
- 「會算進」：選的單元的 `年級學期 編號 名稱`；「這一篇」寫這一篇的單元。
- 能套用的條件：選了單元、會寫成的字不是空的，而且 §4-3 第 6 點的核對成立（放在它要寫進去的位置、前後照實讀）。說明裡有像編號或頁碼的字會讀出問題，這時套用不能按，說明「說明裡有像單元或頁碼的字，請改寫，或寫在「備註」」。

### 4-3 寫回筆記（要格式查核）

純函式，放 `src/core/deck/source-edit.ts`：輸入筆記全文、目標那一行、動作與 §4-2 的字，輸出要改的範圍（`{ from; to; insert }[]`，全文的位置）。Obsidian 層用一個交易送出（`userEvent: 'input.essence-source'`），`Ctrl+Z` 一次復原。

編輯的單位是 §3-3 的**原文段**，不是按鈕。只有兩種動作：

1. **換掉一段**（只用在看不懂的段）：換掉的範圍是那一段，**加上接在它後面、`follows: 'place'` 的那一串**（例如 `1-3 p.20、21` 的 `21`），連同中間的分隔符號；表單上這些位置一起列出（§4-1）。`follows: 'term'` 的段是別的單元，不收進來，照「沒動到的段」核對（回報 R8 的 `國二上 1-3 和 1-8、1-9 p.21`：點第一段只換第一段，1-9 的 p.21 改完還要讀成 1-9，不成立就照第 4 點不寫）。寫在原地之後，後面別的段的 `scope` 會改變（例如換成別的單元，後面還有本來跟著這一篇的位置）時，把新的這一段搬到這一欄最後（D-164 第 5 點：別的單元後寫）。
2. **加一段**：
   - 這一篇的位置：加在第一個跟著別的單元的段前面（D-164 第 5 點：這一篇的先寫）；整欄都是別的單元時加在最前面；空的 `出處：` 寫進那一欄；目標沒有 `出處` 欄位時，在目標底下的第一個子項目前面加一行 `出處：…`，縮排和第一個子項目相同。
   - 別的單元：加在最後。
3. **分行**（使用者 2026-11-06 選定，D-164 第 4 點）：寫完之後這一欄有三個以上的按鈕，或裡面有連結，而且現在寫在同一行，就改成分行：
   - `出處：` 單獨一行，底下**每一個頓號項一行**（就是 `sources` 的每一項，切法和讀的時候完全一樣），所以讀法不會變。同一項裡的逗號、分號、斜線不拆，`溶解, 擴散`、`p，44` 都留在同一行（回報 R4）。
   - 子項目的位置是欄位那一項內容開始的顯示欄寬再加 4 欄，換回這篇的縮排字元（這篇用 Tab 就用 Tab）；數字清單、`*` 清單照它自己的內容位置算。
   - 那一項用 `｜` 接了別的欄位：只把 `出處` 那一段搬出來，其他欄位留在原本那一行，原本那一行底下的子項目（例如 `重要性：高`、`錯題補強：…`）不動、不重排；分行的 `出處：` 一律放在原本那一行前面，不放後面，才不會把那一行的子項目搶過來。
   - 已經分行的照舊分行，加一段就多一個子項目。按鈕變少不改回同一行。
4. **不寫的情況**：表單照樣打開，套用不能按，寫一句原因：
   - 這個目標有兩個以上的 `出處` 欄位（照 §3-3 數，同一行兩個也算）：「這個目標寫了兩處「出處」，先合併成一處」。
   - 要改的段沒有位置（`null`），或那一欄有接續行（`continued`）：「這一項分在兩行，請直接改字」。
   - 這篇「需要新版」（syntax §2-1，外掛不寫它，屬性讀不懂的也算）：「這篇需要新版的外掛才能改」。
   - 換掉或搬動之後，別的段的讀法還是會變（第 6 點不成立）：「改完之後，後面的「45」會跟著改，請直接改字」（引號裡是第一個變了的段的原文）。
5. **換行與檔案**：照這篇原本的換行（CRLF 照舊）、BOM 與檔尾有沒有換行都不動；新加的行用這篇的縮排字元。
6. **寫之前核對**（回報 R1）：把改動套到全文、重新 `parseDeck`，比較下面這些（行號與座標除外，問題的行號要扣掉插入的行數再比）：
   - 屬性（`props` 全部，`issues` 照行號平移後比）。
   - 每一個目標照順序：ID、名稱、`implicit`、`section`、方向、`pairKey`、`ok`、`group`；每一題的完整內容（題目、答案、`extras`、`typed`、填空的文字與位置、指紋）；`shared`；類型、重要性、狀態；`備註`、`錯題補強` 逐項照順序比。
   - **別的目標**的出處：按鈕逐欄位相同。
   - **這個目標**的出處：沒動到的段，原文（去掉前後空白）照原本的順序一字不差（回報 R7：`老師說過 p.44、p.45 知識快遞` 修第一段時，`知識快遞` 不能不見；分行只改段與段之間的分隔與縮排），讀出的每一項（`text`、`link`、`basis`、`problem`、`needsUnit`、`missed`）也照原本的順序相同；`remark` 可以變（它表示同一欄有沒有讀懂別的，改好一段之後別段變成說明是對的，只影響提示）。新的段讀出來就是表單上的單元與位置，沒有 `problem`，不是舊標題。
   - `problems`：除了這次改好的那幾個，沒有多也沒有少。
   - 任何一項不成立就不寫，表單寫「寫不回去，請直接改字」，並記進錯誤紀錄：新的環節 `where: "edit"`（syntax §9 的表加一格、`ErrorWhere` 型別加一個），用現有的 `record('edit', …, { path })` 帶卡組路徑；`msg` 寫固定的失敗代碼、動作（換／加／搬／分行）、目標行號與第幾段，不寫筆記的內容。

### 4-4 §1-4 的修改

同一個檔（`source-edit.ts`），同一個交易與核對方式。

- **半形冒號**：把這篇每一個標成半形冒號的欄位，冒號 `:` 換成 `：`（冒號前後的空白留著）。核對：全文只有那幾個字不同；重新解析之後，`parseDeck` 的結果（屬性、目標、問題）和改之前完全一樣。
- **`出處 p.45`、`來源：p.45`**：把開頭的名稱、冒號與後面的空白換成 `出處：`，後面的字一字不動。
  - 這個目標還沒有 `出處` 欄位：就地改好。
  - 已經有一個：把這一項讀出的段併進那一欄（照 §4-3 第 2、3 點放、分行），再刪掉這一項（§1-4 只標沒有子項目的，刪掉不會帶走別的字）。那一欄有接續行時，改成就地改名，變成第二個出處欄位，讀法照舊合併。
  - 這篇「需要新版」時三種都不改：面板只寫「這篇需要新版的外掛才能改」，沒有「修改」。
  - 已經有兩個以上：就地改名。
  - 核對：`shared`（或那一題的 `extras`）剛好少了這一整項（按原本的項目比，不是比字串的一部分），出處多了這一項讀出的段，其他照 §4-3 第 6 點。
- 改完之後這一項的標示就消失；按 `Ctrl+Z` 一次回到原文。

預期值寫死，來自這份說明、樣式稿與格式查核回報，不用同一個算法再算一次。

- **標示**（`src/obsidian/markup.ts`，和 `lock.ts` 一樣不 import `obsidian`，用 `@codemirror/state` 在 Node 測）：syntax §2-2 的自然例子，目標那幾行、每個 `::` 的位置寫死；同一篇把第二個目標按一次 Tab，那一行沒有目標的標示、它底下的 `::` 也沒有；沒有答案的題目有 `error`；`misplaced-id` 沒有標示；`重要性：很高` 只標 `很高`，在接續行時標在接續行；看不懂的出處標在原文範圍；改字之後標示跟著平移。
- **原文位置**：§3-4。
- **改縮排**：回報 R2 的例子（出處子項目從 14 欄改成 8 欄）照樣會改，寫死改完的全文；第二次一字不改。另做空白、Tab、分行出處、出處在題目底下各一個。
- **猜測與會寫成**：§4-1 表格每一列至少一個例子，加上：`二上` 在國中、國小、沒有學期的卡組；`1-3 p.20` 在國二下的卡組、目錄只有國二上 1-3 時也不預選；`1-3 p.20、21` 帶出兩個位置；位置格式不對不能套用；說明裡有 `1-8` 不能套用；跟著別的單元的段選「這一篇」時寫 `本單元`。
- **寫回**（每個例子寫死改完的全文，並重新解析核對 §4-3 第 6 點）：
  - 換掉一段：同一行；連同接續段（`1-3 p.20、21`）；換成別的單元、後面還有這一篇的位置 → 搬到最後；回報 R3 的兩個例子與學期列表、子圖接續 → 照規則改好或照第 4 點不寫。
  - 加一段：這一篇的在別的單元前面；整欄都是別的單元時在最前面；別的單元在最後；空的 `出處：`；沒有出處欄位時加一行。
  - 分行：變成三個按鈕；有連結；回報 R4 的 `溶解, 擴散、p.44、p.45` 與 `p，44、p.45、p.46`；斜線、`「標題」`、Markdown 連結、網址；`｜` 接別的欄位時出處在最前、中間、最後，兩種分隔符號，原本那一行底下有別的欄位；已經分行的加一段；按鈕變少不改回。
  - 版面：2 格、4 格、Tab、`*`、數字清單、BOM、CRLF、檔尾沒有換行。
  - 位置：欄位在題目底下、在共用補充底下，含題下補充、多行答案、第二個目標。
  - 不寫：兩個出處欄位（含同一行兩個）、接續行、需要新版（含讀不懂的需要版本）、核對不成立。
  - 核對器的反例（回報 R1、R7）：各做一個會被擋下的改法——改到背面補充、改到別的目標的出處、改到屬性、改了錯題補強的順序、別段的說明被刪（`老師說過 p.44、p.45 知識快遞` 寫成 `p.46、p.45`）。
  - 沿用學期的段（回報 R8）：`國二上 1-3 和 1-8、1-9 p.21` 點第一段，只換第一段，1-9 的 p.21 照舊；會改到它的寫法不寫。
