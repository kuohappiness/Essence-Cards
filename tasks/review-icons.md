# 複習畫面的兩個圖示：記憶錨點的燈泡、自動朗讀的喇叭（D-184、D-188，給 Claude，本機執行）

狀態：草稿（2026-11-06），[樣式稿](../experiments/mockups/review-icons.html)等使用者看過

遵守 repo 根目錄的 `AGENTS.md`。建議模型與推理等級：**Opus、高**。只改複習畫面的顯示與一個開關的樣子，不改資料格式、排程、寫回筆記的函式，不跨模組，不在 L2 的高風險範圍（[quality.md](../docs/agents/quality.md#高風險範圍要做-l2)）。

依據：[D-184](../docs/decisions.md#d-184-複習畫面不寫記憶錨點四個字改成圖示)、[D-188](../docs/decisions.md#d-188-朗讀統一成複習畫面的喇叭圖示)；[D-145](../docs/decisions.md#d-145-複習畫面再精簡拿掉分隔線答案不重複一行一個喇叭)（背面補充的名稱自己一行、一行一個喇叭）、[D-116](../docs/decisions.md#d-116-打字卡的沒印象與自動朗讀)、[D-186](../docs/decisions.md#d-186-英文自動朗讀預設開)（開關記在這台裝置、沒動過的預設開）、[D-179](../docs/decisions.md#d-179-介面的每一項都要有必要性非必要不出現)。

## 和「不做」比較（D-153）

- **不做會怎樣**：每張有記憶錨點的卡都多一行「記憶錨點」這個學術名詞；英文卡上方列是「自動朗讀」四個字加一個開關，接句卡、全詩順序卡的開關要另外放到設定頁（D-183 第 5 點、D-187 第 9 點原本的寫法），聽到一半要離開複習才能關。
- **做的代價**：改 `Review.tsx` 上方列、`screens.tsx` 的背面補充與兩支測試；開發命令讀開關狀態的地方跟著改。孩子分不分得清上方的喇叭和句子後面的小喇叭，要到 iPhone 才知道（列進下一次實機測試）。
- **更小的做法**：只拿掉「記憶錨點」四個字、不放圖示：解釋會和例句黏在一起（D-184 曾考慮）。喇叭只改樣子、不做共用：之後接句卡、全詩順序卡還是要另外加開關，等於做兩次。

## 1. 記憶錨點的燈泡（D-184）

- 背面補充開頭是 `記憶錨點：` 的那一項（`extraLabel` 的名稱是「記憶錨點」），不畫名稱那一行；內容前面放一個小燈泡，內容接在燈泡後面同一行。
- 燈泡淡色（比背面補充的灰字再淡一點）、和文字同高；螢幕閱讀器念「記憶提示」（`role="img"`、`aria-label`）。
- 內容有好幾行（D-185 第 4 點，寫在名稱底下的子項目；或英文句子加中文翻譯分成兩行，D-174）：燈泡只在第一行，其他行和內容對齊，不排到燈泡底下。
- 例句、詳解等其他名稱照舊自己一行（D-184 第 3 點）。
- 點選填空的對照（`PickCard.tsx`）本來就不寫這四個字，每一列是字加說明，不加燈泡（每一列都加會重複，D-179）。

## 2. 自動朗讀的喇叭（D-188）

- 上方列原本「自動朗讀」文字加開關那一格，換成一個喇叭按鈕：開著是喇叭加聲波、一般文字的顏色；關著時聲波換成 ×、變灰。可以點的範圍 44 點（`--ec-touch`）。
- 螢幕閱讀器：`role="switch"`、名稱「自動朗讀」、`aria-checked` 表示開或關。
- **什麼卡出現**：這張卡會自動朗讀時才出現。現在只有英文的目標（英翻中念題目、中翻英答完念答案），條件照舊是 `view.card.english`；接句卡、全詩順序卡還沒做，做中文朗讀時再接。沒有喇叭時那一格照舊留空，✕ 貼在右邊。
- **點一下**：關掉時立刻停（正在念的也停），之後每張都不念；打開時這張不補念，下一次該念時才念。狀態照舊存在這台裝置（`speech.ts` 的 `saveAutoRead`，同一個鍵），升級後沿用現在記的開或關。
- 句子後面的小喇叭不變，關掉自動朗讀也能按。
- 開發命令讀開關狀態的地方（`dev-review.ts` 的 `auto`、`dev-errors.ts` 等英文卡的上方列）改成讀新的按鈕。

## 3. 不改的

- 卡組的寫法（`記憶錨點：`）、`src/core/`、複習紀錄、`speech.ts` 存的鍵與預設值。
- 設定頁不加開關（D-188 第 3 點）。

## 4. 驗收

能用程式判斷的（`tests/review-ui.test.ts`，用現有的 `open` 與替身）：

1. 記憶錨點那一項：沒有 `.ec-ex-label`，有一個 `aria-label` 是「記憶提示」的燈泡，內容的 Markdown 照舊是冒號後面那一段，喇叭照舊。
2. 同一張卡的「例句：」照舊有名稱那一行；燈泡只出現在記憶錨點那一項。
3. 英文卡上方列有一個 `role="switch"`、名稱「自動朗讀」的按鈕；`aria-checked` 跟著開關；自然卡沒有，上方列照舊五格、✕ 在最後。
4. 開著時點一下：最後一個動作是停止，`autoRead.set(false)`，換下一張不念；再點一下打開：這張不補念（沒有新的 `say`），`autoRead.set(true)`，換下一張才念。
5. 關著時打開複習：喇叭顯示關的樣子，第一張不念。

`npm run check`、`npm run build` 通過。

## 5. 實機

- **Windows 版 Obsidian（Claude 用開發版跑）**：英文卡的上方列（開、關兩種樣子）、記憶錨點有燈泡、例句照舊，淺色與深色各截一張，和樣式稿比；點喇叭立刻停、再開不補念。
