## 和「不做」比較（D-153）

- **不做會怎樣**：小考前照現在的用法練（目錄的全部卡今天、睡前、明早各一輪），但英文同一個字的兩個方向新卡時緊接著出，第二張等於照抄；完成畫面只寫「今天複習了幾張」，看不出記熟了沒；只想練某一篇要先找到筆記；老師不考某一篇時要進筆記改屬性。考試範圍第二批發布後，之後的小考檔還會被當成壞掉的段考範圍。
- **做的代價**：`practice.ts` 的選卡多一條規則；完成畫面多一行；目錄展開後多幾列；第一個從目錄改筆記屬性的按鈕。
- **更小的做法**：只做段考讀法（§1）：小考任務需要的位置先保住，但小考前的三個缺口照舊。§1 先做、可以單獨交，就是為了這個情況。

## 1. 段考讀法跳過 `考試範圍/小考/`

`Essence Cards/考試範圍/小考/` 留給小考（D-189 第 5 點）。現在 `src/core/catalog/scope.ts` 的 `isExamPath` 是 `path.startsWith(EXAM_FOLDER + '/') && path.endsWith('.md')`，連子資料夾都讀。

- 在 `scope.ts` 加 `QUIZ_FOLDER = EXAM_FOLDER + '/小考'` 與判定小考路徑的函式；`isExamPath` 排除 `QUIZ_FOLDER + '/'` 開頭的路徑。只排除 `考試範圍/` 直接底下、名稱剛好是 `小考` 的那一層與它底下：`考試範圍/小考備份/x.md`、`考試範圍/舊的/小考/x.md` 照讀。
- 用同一個判定的地方：`src/state/exam.ts`（啟動掃描與檔案監看）、`src/obsidian/dev-exam.ts` 第 50 行與第 109 行附近（現在各自用 `startsWith(EXAM_FOLDER + '/')`）、`tools/update-vault.ts` 的 `reminder`（`listTree` 之後只篩 `.md`，再交給 `tools/exam-reminder.ts` 逐份當段考解析）。`tools/exam-reminder.ts` 的 `SCOPE_FOLDER` 改成用 `src/core/catalog` 的同一個常數與判定，在讀內容之前篩掉小考檔。
- 不改：備份照舊整棵都備；`src/core/deck/read.ts` 的 `SYSTEM_FOLDERS` 照舊（第一層是 `考試範圍` 的整棵都不當卡組）。
- 文件：[tasks/exam-scope.md §2-6](exam-scope.md#2-6-家長直接改檔d-176) 手改表那一列改成「改檔名、搬到 `小考/` 以外的子資料夾｜沒有影響」，加一列「搬進 `考試範圍/小考/`｜不算段考範圍（留給小考，D-189）」；[syntax §4](../docs/syntax.md#4-考試範圍) 加一句：`考試範圍/小考/` 留給小考，裡面的檔不算段考範圍。

**驗收**（寫成測試）：

## 2. 全部卡裡英文的兩個方向隔開

D-189 第 1 點。現在 `src/core/study/practice.ts` 的 `roundOrder` 只把英翻中排在中翻英前面，兩個都是新卡時正好相鄰。

- **對子**：同一篇裡 `pairKey` 相同、方向一個 `en-zh` 一個 `zh-en` 的兩個目標（和現在的 `roundOrder` 同一個認法）。寫成「給一個目標，找它的對方」的函式，之後接句（D-185 第 8 點：名稱最後是「接句」，同一篇、同一個詩名小標題，第 2k−1 句和第 2k 句）加一個認法就好；這次不認接句。
- **間隔**：`practiceNext` 選下一張時，一張卡的對方如果在這一輪答過，要等這一輪裡、對方最後一次作答之後，答過 10 個不同的其他學習目標才出。只算 `since` 之後、不含錯題補強的作答（和 `roundAnswers` 一樣）；對方這一輪還沒答過就沒有限制。答錯再出的（`ready`）也照這條。
- **找不到符合的卡時**：在本來就會選的那一群裡（先 `ready`，再 `fresh`）挑「對方最後一次作答之後答過最多不同目標」的；一樣多就照原本的順序。`ready` 與 `fresh` 都沒有時才輪到 `waiting`（提早出），和現在一樣；不為了湊間隔改出 `waiting`，也不擴大範圍。只剩同一對時直接出，不讓學生等。
- 10 寫成一個常數，旁邊註明是試作值（D-189）。
- 每日的份（`plan.ts`）不改：英文照 [D-069](../docs/decisions.md#d-069-新卡的開始與同一個字的兩個方向)，中翻英要等英翻中記住才出，兩個方向同一天到期只出一個。

**驗收**（寫成測試，放在 `tests/practice.test.ts`）：

- 40 個字、兩個方向都是新卡：同一個字的兩張之間至少隔 10 個不同的目標。
- 英翻中答錯、1 分鐘後到期：到期時對方還不夠隔，先出別張；夠了才出。
- 只有 3 個字（6 張）：照「隔最多的先」穿插，不會有一張等著不出；全部答對就結束。
- 只有一個字的兩個方向：直接出，不卡住。
- 中途關掉再開（新的 `since`）：從頭算，不沿用上一輪的間隔。
- 原有的 18 項練習測試照樣通過（`early` 只表示提早出的重學，意思不變）。

## 3. 完成畫面：「這輪第一次就答對」

D-189 第 2 點。`src/review/done.ts` 的 `doneView`，單元與單篇的全部卡（`pick` 有 `since`）。

- 標題下面多一行：`這輪第一次就答對 32／40`，原本「今天複習了幾張・約幾分鐘」那一行留著。
- **分母**：這一輪答過的學習目標數（`since` 之後、不含錯題補強），新卡照算，英文兩個方向各算一個。
- **分子**：這一輪每個目標的第一筆作答，評分是記住了（`good`）或太簡單（`easy`）的；打字卡要 `typed` 是 `right`。回看改了評分（`undo` 加新的一筆）時，照改過的那一筆算。
- **不顯示**：這一輪的作答裡有同步進來的（不是這台裝置這次複習寫的）；分母是 0。
- 當日卡、今天的份、`more` 的完成畫面不變。

**驗收**（寫成測試）：40 個目標裡 32 個第一次就記住、8 個先答錯後答對 → `32／40`；第一次答「差一點」（`near`）再回看改成記住了 → 算第一次就答對；打字卡第 1 步拼錯、第 2 步拼對 → 不算；這一輪有一筆別台裝置的作答 → 不顯示；當日卡的完成畫面沒有這一行。

## 4. 目錄的單篇入口

D-189 第 3 點、D-183 第 2 點。`src/ui/Entry.tsx` 的 `UnitRow`，展開後的區塊（`ec-tr-open`）。

- **單元有兩篇以上啟用的卡組時**：單元的「全部卡」底下，每一篇啟用的卡組一列：篇名、`全部卡 N`。篇名用檔名（去掉 `.md`）；同一個單元裡有同名的，篇名後面附資料夾名。N 是 `catalog.deckTargets(path)` 的數目，0 時按鈕不能按。按下去開 `{ deck: path, since: Date.now() }` 的一輪（和卡組筆記的全部卡同一種，`src/state/index.ts` 已經有），**不跳**全部卡的提醒（目錄的全部卡本來就不提醒）。
- **只有一篇啟用時**：畫面不變（單元的全部卡就是那一篇）。
- 草稿的篇照舊是打開筆記的連結；暫停的篇照 §5。
- 樣式照 `Entry.css` 現有的 `ec-u-btn` 與 `ec-tr-deck`；iPhone 寬度 375 時篇名太長要截斷，按鈕不能被擠到下一行。

**驗收**：L3 有「單字」「其他」兩篇啟用：展開後兩列各有全部卡，數字和各自筆記標題列的全部卡相同；按下去只出那一篇；只剩一篇啟用時沒有這兩列；兩篇同名、不同資料夾時看得出是哪一篇。

## 5. 暫停／恢復（只在電腦）

D-183 第 6 點、D-189 第 3 點。分開驗收：§2～§4 可以先過，這一節的寫入另外看。

- **在哪裡**：單元有兩篇以上（不論狀態）時，展開後每一篇一列（§4 的那一列，或照舊的筆記連結那一列），電腦上多一個按鈕：啟用的篇是「暫停」，暫停的篇是「恢復」。草稿沒有這個按鈕。手機上不顯示（[D-142](../docs/decisions.md#d-142-範圍與目錄模組的六項選擇) 第 4 點，手機不寫卡組），呼叫寫入的函式在手機上也要擋。
- **全部暫停或只剩一篇啟用時**：恢復的按鈕仍找得到。現在全部暫停的單元按名稱會直接打開筆記（`expandable` 的條件）；兩篇以上的單元照舊可以展開，展開後看得到每一篇的恢復。
- **寫什麼**：把那一篇屬性區的 `狀態` 改成 `暫停`／`啟用`（[syntax §2-1](../docs/syntax.md#2-1-屬性)）；沒有 `狀態` 這一行時加一行。只改這一行，其他字元不動。用和補學習目標 ID 同一條寫筆記的路徑（鎖、寫之前比對內容），寫不進去時照存檔受阻的提示，不改畫面。寫進去之後，在這台裝置的紀錄檔寫一行 `{"set":"status","deck":"<路徑>","val":"暫停"}`（[syntax §5](../docs/syntax.md#5-複習紀錄) 的例子；`val` 是 `暫停` 或 `啟用`）。
- **之後**：目錄跟著筆記變（現在就是讀屬性），iCloud 同步到手機。暫停後進度留在紀錄裡，恢復後接著排（現在的排程本來就這樣，不用改）。
- 家長直接改筆記的 `狀態` 時寫 `set: status`：不在這次（backlog 技術債，觸發點是管理模式）。

**驗收**（寫成測試，能在 Windows 開發版跑的也跑）：按暫停 → 筆記只改了 `狀態` 那一行、紀錄多一行 `set: status`、目錄那一篇變成暫停、單元的全部卡數字少了那一篇；按恢復 → 回到啟用，之前的作答紀錄照算（顏色、到期時間和暫停前一樣）；沒有 `狀態` 那一行的篇按暫停 → 多一行；筆記開著、編輯器裡有沒存的修改 → 照存檔受阻處理，不覆蓋；兩篇都暫停 → 展開還看得到兩個恢復；手機的畫面沒有這兩個按鈕。
