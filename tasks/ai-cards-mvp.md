## 和「不做」比較（D-153）

- **不做會怎樣**：外掛已在正式 vault 使用（`0.3.0`），但每篇卡組都要家長自己做：把規則檔一份份上傳到 AI 對話、自己寫任務資料、把結果貼進新筆記、手打屬性、改成草稿、看過再改成啟用。每一課約多 10 分鐘的搬運，而且容易漏：忘了寫 `狀態: 草稿`，孩子馬上會看到還沒審的卡；英文、國語一課分成幾篇，要自己拆檔、命名。AI 原稿也沒有留下，[D-042](../docs/decisions.md#d-042-ai-製卡快照) 的採用率與之後改規則都沒有資料。
- **做的代價**：一個電腦上的製卡畫面（表單、複製、貼回、檢查結果）、卡組筆記多一個「啟用」按鈕、`紀錄/AI 輸出/` 開始有檔；這台電腦多存待貼回的工作與存到一半的恢復資料。不改排程、不改複習畫面，手機不變。
- **更小的做法**：
  - 只做「複製提示」、不做貼回：省了組提示，結果還是要手動貼、手打屬性、拆篇，也沒有快照。省下的不到一半，錯的機會（漏寫草稿）還在。不夠。
  - 只做貼回、不做提示：家長仍要自己上傳規則檔，送出的規則版本也記不下來（D-151 第 6 點）。不夠。
  - 啟用不做按鈕、照舊改屬性：家長要知道 YAML 在哪、拼對「啟用」兩個字；使用者會碰到的流程不該靠手改屬性（使用者 2026-10-26：以一般使用者為準）。一個按鈕的代價小，做。

## 1. 規則組嵌進外掛

- **表**：AI 模組裡一張表，每一科一列：顯示的名稱、規則檔的路徑（照順序）、每一份的名稱與版號（手寫，例如 `國小國語 v0.7`；凍結的 R3 寫 `R3 第二輪`）。家長在畫面上看得到這一科用哪些規則與版號（唯讀的一行，不開檔）。
- **建置**：`tools/build.mjs` 照表讀檔、嵌進 `main.js`，每一份算 SHA-256（照嵌進去的文字，UTF-8、換行統一成 `\n`）。表上的檔讀不到、標記找不到就建置失敗。這是 D-151 第 1 點「建置時從權威 Markdown 嵌進外掛、記版號與雜湊」的第一步；唯讀畫面與自訂版在之後的任務。
- **送出範圍**：`docs/card-rules/` 的檔開頭有給開發者看的標題與狀態（試用時已經拿掉過，[trials.md](../docs/card-rules/trials.md) 2026-11-04：狀態裡的「估 35～45 個」會影響目標數）。在每一份要嵌的檔裡加一行標記 `<!-- 以下送給 AI -->`，只送標記以下；`experiments/` 的 R3 四份沒有狀態，整份送、不加標記。
  - 加標記只加這一行。狀態框裡有給 AI 的句子時（english.md 狀態框最後一段「搭配通用規則（common.md）使用；與通用規則衝突時，以本檔為準」），把那一段搬到標記下面，字不改。common.md 開頭的狀態只有版本紀錄，整段在標記上面。
  - 規則裡的 Markdown 連結（`[D-190](../decisions.md#…)`）照原樣送，和試用時相同。
- **提示模板的版本**：§3 的任務資料與附加說明是程式裡的模板，記一個版號（例如 `提示 v1`），改字就加一。

## 2. 製卡畫面（電腦）

- **入口**：命令「AI 製卡」，加左側功能列一個圖示。手機不註冊（D-039：手機上不製卡）。入口畫面、目錄不放（D-100：入口是孩子每天用的）。
- **全螢幕或 Obsidian 的視窗**照入口與目錄的共用掛法擇一，實作時選，回報寫理由。
- **第一步：填單元**（家長填，學生不碰）：

| 欄位 | 寫法 | 預設 |
|---|---|---|
| 科目 | 下拉，只列 §0 開了的 | 上一次選的 |
| 年級學期 | 下拉：目錄認得的寫法（小一上～高三下）；選了科目後，已有卡組的年級學期排前面 | 上一次選的 |
| 單元 | 一欄「編號 名稱」，和屬性 `單元` 同一個寫法（[syntax §2-1](../docs/syntax.md#2-1-屬性)）；第一個空白前要有編號 | 空 |
| 學習目的 | 下拉：準備段考、準備小考、平常複習 | 準備段考 |
| 允許 AI 補充 | 勾選 | R3 的科目勾，其他不勾（照試用時的設定，[第二輪 README](../experiments/t4/arch/第二輪/README.md)） |
| 這次的調整 | 一行文字，選填，例如「這次最多 8 個目標」；寫進任務資料的「家長調整」 | 空 |
| 教材 | 一行文字，選填，例如「課本 p.40～51 的照片」；只是家長自己的說明，寫進快照，不送給 AI 之外的地方 | 空 |

- 同一個年級學期、科目、單元編號已經有卡組時，寫出那幾篇的檔名與狀態，問「還是要做一份新的嗎？」（不擋；舊的不動）。真的撞檔名在 §5 處理。
- **學生已有的學習目標**：同一科、年級學期在這一篇之前或相同的卡組（目錄的排序認得的才比得出先後；認不得的年級學期只算完全相同的），啟用與暫停的卡組裡、讀得懂的目標，草稿與需要新版的不算。每一個送「ID 名稱｜出處」一行，照年級學期、單元、筆記順序排。畫面寫出「會一起送出 N 個已有的學習目標」。沒有就寫「無」。
  - 只送名稱，AI 可能把不同判準的題目加進舊目標（backlog「跨單元加題時，AI 要看得到舊目標的什麼」的 2026-11-03 證據）。這一份不怕：加進已有的學習目標只留在引言框、不會自動合併，家長看得到。送基本題、判準或分兩段，跟「加入」的任務一起定。
- **第二步：複製提示**：按「複製提示」把整份提示放進剪貼簿，畫面寫出字數，以及下一步：「到 ChatGPT 或 Claude 開一個新對話，附上課本頁面的照片或 PDF，貼上提示送出；AI 回完後，把整段回覆複製回來」。同時存一份**待貼回的工作**（§3）。
- **第三步：貼回**：一個大的輸入框，按「檢查」跑 §4，結果列在下面；按「存成草稿」才寫檔（§5）。按「取消」或關掉，什麼都不寫；工作留著，下次可以接著貼回。
- 重開命令時，有待貼回的工作就先問：「接著貼回上一次的結果（國二上英文 L3，10 分鐘前複製）」或「做新的一課」。

## 3. 提示與待貼回的工作

- **提示的組成**：一串**部分**，照順序、中間空一行接起來：§1 規則組的每一份 → **任務段**。任務段是程式照模板填好的整段文字：`## 這一次的任務`、任務資料、附加說明。每一部分各算 SHA-256；整份提示另算一個。
- **任務資料**照試用的寫法（`國小國語設定.json` 的 `任務資料`）：

  ```
  - 學生：國小五年級（小五上）
  - 科目：國語
  - 單元：L7 美景閒情──詩兩首
  - 學習目的：準備段考
  - 允許 AI 補充：是
  - 家長調整：無
  - 教材：附件的課本頁面
  - 學生已有的學習目標：
    - k3m9qa 長 讀音｜小五上 L3 p.30
    - ……
  ```

  「學生」由年級學期換算（`國二上` → `國中二年級（國二上）`）。
- **附加說明**（模板，記在 §1 的提示版號裡）：
  - 教材在附件。附件沒有圖檔可以連，**不要寫 `![[…]]`**；要提到課本的圖，在出處寫圖號（例如 `p.42、圖 2`）。
  - 一課分成幾篇時，篇名照 `<年級學期><科目> <單元編號> <篇名>` 寫，例如 `國二上英文 L3 單字`，單獨一行、前面不加 `#`（english.md §8、elementary-chinese.md 的卡組）。
  - 不要寫學習目標 ID 與屬性區，程式會加。
  - R3 的科目另外一句：照規則交三段，標記照抄（`<<<全貌>>>`、`<<<架構>>>`、`<<<卡組>>>`）。
  - **回覆的最後單獨一行寫 `<<<完>>>`**（所有科目；格式查核 F9）。
- **待貼回的工作**存在這台電腦（`src/ui/prefs.ts` 的裝置偏好），不寫進 vault。**按「複製提示」的當下就存**（格式查核 F1）：
  - 識別碼（6 碼字串，和考試範圍同一套產生法，範圍是 AI 工作）、複製的時間（含時分秒與時區）、表單的值。
  - **每一部分的全文**、名稱、版號與 SHA-256，以及整份提示的 SHA-256。外掛之後更新、規則或模板改了，這一份照舊是當時送出的文字；貼回時不重組、不拿新版代替。
  - 最多留 5 個、14 天；過期的只丟**還沒開始存草稿的**工作，存到一半的不丟（§5）。找不到工作時不能貼回，請家長重新複製一次（沒有送出的證據就不建快照，D-126 第 4 點）。
  - 存成草稿全部完成、核對過之後才拿掉那一個。

## 4. 貼回與檢查（要格式查核）

**整理**（只改包裝，不改內容）：拿掉開頭的 BOM、把換行統一成 `\n`；整段被最外層的一對圍欄（三個以上的反引號或波浪號，開頭可帶 `markdown`）包起來時拿掉那一對，裡面較短的圍欄不動。之後回報的行號一律指**貼上的原文**（整理前），由程式換算。

**分段與結束**：

- 有 `<<<…>>>` 標記（R3）：照最外層、單獨一行的標記切。要有 `<<<卡組>>>`，卡組段之後只能接 `<<<完>>>`；全貌、架構段照原樣留給快照。R3 的科目三個標記缺一個，或卡組段是空的，是錯誤（沒有貼完整）。
- 沒有段標記（common.md 的科目）：`<<<完>>>` 之前整段就是卡組段。第一個非空行前面的開場白（例如「好的，以下是……」）**不猜**，當成錯誤，請家長只貼回覆本身。
- **結束標記**：最後一個非空行是單獨的 `<<<完>>>`（在引言框、清單或程式碼裡的不算）。沒有時結果畫面寫「最後一行沒有 `<<<完>>>`：回覆可能沒貼完整，或 AI 還沒寫完」，要家長勾「我確定整段都貼了」才能存。這只證明複製到了結尾，不證明內容涵蓋了整課。結束標記不寫進卡組，快照照原文留著。

**拆篇**：

- 篇名行只認卡組段裡**最外層的獨立段落**（前後是空行或段落邊界；不在清單項目的接續、引言框、程式碼區塊裡），整行等於 `<年級學期><科目> <單元編號>` 或它加一個空白再加篇名（用表單的值比，不猜）。篇名行之間是一篇的本文。
- 沒有篇名行：整段是一篇，檔名照 D-081：`<年級學期><科目> <單元>（卡片）`，例如 `國二上自然 2-2 水溶液（卡片）`。
- 有篇名行：每一篇的檔名就是那一行；同一個篇名出現兩次是錯誤；一篇沒有任何學習目標是錯誤。
- **錯誤，要家長改**（格式查核 F6）：
  - **疑似篇名**：最外層的獨立段落或標題，先拿掉標題的 `#` 與空白，剩下的開頭是認得的年級學期寫法（syntax §2-1 的目錄排序認得的）、接著科目、空白、單元編號格式的一段。疑似篇名一律照下面兩條核對，標題與段落共用同一套比法（第二輪 R2-5）：
    - 年級學期、科目或編號和表單不同（不管是不是標題）：「這一行像篇名，但和這次填的單元不同」。
    - 和表單相同但寫成標題（`## 國二上英文 L3 單字`）：「篇名請另起一行，不加 #」。不能默默讀成同一篇的兩個小標題。
    - 不是疑似篇名的一般小標題（`## 2 擴散現象`）照原本的卡組規則。
  - 第一個篇名行前面：只有「給家長的備註」引言框時，併進第一篇的最上面；有候選卡片、加進已有的學習目標或其他內容時，「請移到它所屬的那一篇」。
- 檔名裡 Windows 不能用的字（`\ / : * ? " < > |`）與會破壞連結的字（`# ^ [ ] |`）換成全形；開頭結尾的空白與句點拿掉。

**檢查**：每一篇用 `parseDeck` 讀，再跑草稿專用的檢查（環節 8 第 9 條）：把 [`experiments/t4/check-syntax.mjs`](../experiments/t4/check-syntax.mjs) 的規則搬進 `src/core/`，等級照它與 [syntax §2-10](../docs/syntax.md#2-10-寫錯時) 最後一段：**它算「錯誤」的要退回，算「不符」的提示**（格式查核 F5；比 §2-10 的表嚴，是 syntax 已定的）。候選卡片框裡的目標也檢查（例如缺答案），行號照原文。

| 擋住，不能存 | 提示，可以存 |
|---|---|
| 上面「整理、分段、拆篇」的錯誤 | `check-syntax` 算「不符」的（每個字少於兩句、整個答案出現在題目裡） |
| `check-syntax` 算「錯誤」的，包含 §2-10 算寫錯的學習目標、比較卡認不出來或混了別種題目（`pick-not-recognized`、`pick-mixed`） | 沒有 `<<<完>>>`（要勾確認，見上） |
| AI 寫了屬性區（開頭的 `---`） | AI 自己寫的 ID（見下）：拿掉、記下，存草稿時重配 |
| 新目標或候選的名稱行中間有 ID（D-134 認得的那種）、或一行兩個 ID | 不認得的引言框：原文照留，裡面的東西不配 ID、不算候選 |
|  | 加進已有的學習目標的 ID 不在這次送出的清單裡、找不到或重複：照原文留在框裡，不轉成連結（§5） |
|  | `![[…]]` 圖片連結：照樣留著，寫出「附件沒有圖檔，這張圖不會顯示」 |
|  | 候選卡片超過 5 個 |

- **AI 自己寫的 ID**：只看新目標與候選的名稱行**行尾**的區塊 ID（` ^` 後面接英數字與 `-`，和 D-134 認行尾 ID 的寫法相同，不限 6 碼）。題目、答案、背面補充、行內程式碼與公式、加進已有的學習目標裡的 ID 都不動。拿掉時記下原文的行號與拿掉的字（§5 的 `程式改動`）。
- 可以存的時候，結果畫面每一篇一列：檔名（含 §5 的改名）、學習目標數、題數、候選卡片數、加進已有的學習目標數；底下列出提示。有擋住的就沒有「存成草稿」，只有原因與行號、一句可以怎麼改；輸入框可以直接改字再檢查。

## 5. 存草稿與快照（要格式查核）

**寫在哪**：卡組照 D-040 的預設編排：`Essence Cards/學業/<年級學期>/<科目>/<檔名>.md`；一般知識放 `Essence Cards/<檔名>.md`。快照照 [syntax §6](../docs/syntax.md#6-ai-輸出快照)：`Essence Cards/紀錄/AI 輸出/<日期> <年級學期><科目> <單元>.md`（一般知識用表單的單元欄當名稱）。原文：`Essence Cards/紀錄/AI 輸出/原文/<SHA-256 前 12 碼>.md`，放送出的每一部分與收回的回覆原文（第二輪 R2-4；原本叫「送出內容」）。

**檔名在寫之前就定好**（格式查核 F4）：檢查通過時，每一篇的目的地先和**整個 vault** 的檔名比（D-081：檔名整個 vault 不重複；大小寫不同也算撞），撞了就自動往後加 ` 2`、` 3`……直到沒有人用，結果畫面寫出「已有同名的卡組（位置），這一篇存成 ○○ 2」。快照檔名撞了也一樣往後加。

**卡組的內容**：

```markdown
---
年級學期: 國二上
科目: 英文
單元: "L3 Sports: Week 1"
狀態: 草稿
---

（AI 交回的這一篇本文；新目標與候選的名稱行行尾加上配好的 ID，AI 自己寫的 ID 已拿掉；加進已有的學習目標轉成連結）
```

- 屬性用 YAML 序列化寫，不直接把表單的字串插進去（`L3 Sports: Week 1` 沒加引號會讓屬性區讀不懂、狀態退成啟用，草稿就被排程了；格式查核〈可沿用的格式〉第 2 點）。
- 有比較卡時加 `需要版本`，值照 [syntax §2-1](../docs/syntax.md#2-1-屬性) 的規則（D-191）。其他屬性不寫：沒有轉錄稿，`材料` 留空（出處只能讀、不能跳回）。一般知識的卡組不寫年級學期、科目、單元（syntax §2-1：不是學業卡組），只寫狀態。
- **ID**：新目標與候選卡片都配（[syntax §2-9](../docs/syntax.md#2-9-ai-製卡交回的草稿)：候選在存草稿時就配好，快照和卡組用同一組）。候選的 ID 寫在引言框裡那個目標名稱那一行最後（`> - 能說明溫度對溶解度的影響 ^k3m9qa`）。配法照 D-134：避開所有卡組（含引言框裡的行尾 ID，§6）、複習紀錄出現過的 `lt`，以及這次其他篇已配出的。
- **加進已有的學習目標轉成連結**（syntax §2-9「存草稿時程式把 ID 轉成連結」；格式查核 F8）：每一項開頭的 `ID 名稱`，ID 在這次送出的清單裡、現在剛好找得到一個讀得懂的目標時，改成 `[[卡組檔名#^ID|現在的名稱]]`；找不到、重複、需要新版、或和送出時不在同一篇的，照原文留著並提示，不猜。

**順序**（格式查核 F2、F3，第二輪 R2-1、R2-2：快照最後寫，**快照寫成＝發布**）：

1. 在記憶體檢查、定好每一篇的目的地、配好 ID，做出每一篇卡組的**全文**。
2. **先把恢復資料存進待貼回的工作**（這台電腦，§3，不在 `紀錄/AI 輸出/` 裡）：回覆原文（家長貼上的整段，照輸入框交出的文字）與它的 SHA-256、每一篇的目的地與**要寫的全文**與 SHA-256、配好的 ID、快照的目的地。之後每一步都照這份寫，不重新整理、不重新查已有目標、不重新配號；重開之後不用家長再貼一次。
3. 寫原文：送出的每一部分（§3）與回覆原文各一份，只建立；已存在而且內容相同就跳過，內容不同是錯誤（不蓋掉，提示「原文的檔對不上」）。讀不到不算不存在。
4. 一篇一篇建卡組，每一篇分三拍（第三輪 R3-1、第四輪 R4-1）：先在恢復資料把那一篇記成**開始建了**、存好，才去建檔（只建立）；建好、讀回核對過，再記成**寫出過**。沒有記成開始建了的篇，才確定從來沒碰過 vault。
5. **準備發布**：核對每一篇都寫成（見下面〈中斷與重試〉怎麼算寫成），這時取 `時間`、做出快照的全文，把快照全文與 SHA-256 存進恢復資料。
6. **發布**：照存下的全文建快照，只建立。快照寫成、讀回來 SHA-256 相同，就是這次製卡成功。
7. 清理：從這台電腦拿掉這個工作，通知「已存成草稿」。

都經過 `state` 的寫入佇列（環節 8 第 3 條），受同一組門檻：電腦、讀完、備份成功（D-150 第 3 點）、未完成工作的預留已載入（見下面〈ID 的預留〉）。屬性與 ID 寫完要重讀核對：狀態是草稿、屬性和要寫的相同、每個新目標與候選的 ID 都在、`需要版本` 有寫到。

**中斷與重試**（環節 8 第 4 條的反例）：

- 重開命令時有沒完成的工作就先問「繼續存上一次的結果」。繼續時**先看快照**：
  - 恢復資料裡有快照全文、那個位置的檔存在而且 SHA-256 相同：**已發布**，只做第 7 步清理。卡組之後被家長改字、改成啟用、甚至刪掉，都不影響（D-042 的比對留給之後），不再核對卡組。
  - 那個位置有檔但內容不同：停下，寫出是哪一個檔，不覆蓋。（快照檔名在第 5 步之前撞名時，照〈檔名在寫之前就定好〉往後加，再存進恢復資料。）
  - 沒有快照：從第 3 步照恢復資料逐一核對實際的檔。
- **一篇卡組怎麼核對**（第三輪 R3-1）：先問 `state` 這一篇配的 ID 現在在哪幾篇卡組裡（含引言框的行尾 ID），再看目的地：
  - 目的地的檔在，內容的 SHA-256 和恢復資料相同；或內容不同、但這一篇配的每一個 ID 都在這個檔裡（寫成之後被家長改過字）：**算寫成**。
  - 這一篇的 ID 全部在**另一篇**卡組裡（家長把它改名或搬走了）：照現在的位置算寫成，恢復資料的目的地與快照要寫的 `對象` 跟著改、存回去，不在舊位置再建一份。
  - 這一篇的 ID 一個都不在任何卡組，而且這一篇**沒有**記成開始建了：照恢復資料的全文在目的地建（目的地被別人用了，照〈檔名在寫之前就定好〉往後加）。
  - 其他情況都停在那一篇，不自動補回：記成開始建了或寫出過、但 ID 一個都找不到（可能建好之後在記下之前中斷、家長又刪了這一篇，也可能真的沒建成，分不出來就照實說「上一次建這一篇時中斷，現在找不到它」）；ID 分在好幾篇或只剩一部分（家長拆開、刪了一些目標）；目的地有檔、裡面沒有這一篇的 ID 而這一篇的 ID 又不在別處（不是這次寫的檔）。寫出看到的情形，讓家長選「跳過這一篇」（快照的 `對象` 不列它，其他篇照常發布）、「重建這一篇」（只在 ID 一個都找不到時可以選；目的地被用了就往後加）或「放棄」。
- 同一個工作貼上不同的回覆（回覆原文的 SHA-256 不同）：停下，「這次的提示已經用另一份回覆存過一部分，要繼續上一次的，或放棄它」，不另配 ID 接著寫。
- **放棄**：只有還沒發布的工作能放棄。已寫成的卡組照樣是草稿、不刪（Cards 不刪家長的檔），沒有快照，等於手動貼進去的卡組（D-042：直接貼進卡組筆記照樣能用，只是沒有快照）；已寫的原文留著（按內容存，不屬於哪一次）。通知寫出留下了哪幾篇。
- 沒完成的工作不過期，直到發布、清理或放棄。

**ID 的預留**（第二輪 R2-3；環節 8 第 3 條「ID 占用包含……其他未完成工作保留的 ID」、環節 4 結論第 2 條「未完成工作的預留還沒載入」的門檻）：

- 外掛載入時，先讀這台電腦所有沒完成的工作，把它們配好的 ID 全部交給 `state` 當占用，之後才放行任何配 ID 的寫入（補 ID、另一次 AI 製卡）。恢復同一個工作時沿用自己的 ID；其他工作與補 ID 都要避開。
- 釋放：發布並清理後，ID 已經在卡組裡，照一般的占用。放棄或跳過時，只有**沒記成開始建了、而且不在任何卡組裡**的篇的 ID 從預留拿掉；記成開始建了或寫出過的篇（不管現在找不找得到）的 ID 留在這台電腦的「不再配出」清單，不再配給別的目標（D-134「刪掉的 ID 不再配出」的精神；草稿沒有複習紀錄，靠這份清單擋）。這份清單只增不減，一次製卡最多幾十個 ID。
- 限制照實寫：預留只在這台電腦。兩台電腦同時各做一份，仍靠隨機的 6 碼避開；手機不配 ID，不受影響。

**快照**（syntax §6 加欄位；同一個分支改 syntax §6）：

```markdown
---
日期: 2026-11-07
時間: 2026-11-07T10:23:45+08:00
識別碼: m4k8q2
工作: 製卡
對象:
  - "[[國二上英文 L3 單字]]"
  - "[[國二上英文 L3 文法 2]]"
規則版本: 通用 v0.15、英文 v0.14
送出:
  - "通用 v0.15 3f9a0c1d2e4b…（64 碼）"
  - "英文 v0.14 a17c55e0b9d2…（64 碼）"
  - "任務段 提示 v1 5be1c0a9f377…（64 碼）"
提示雜湊: 9c0e…（64 碼）
回覆原文: 41d2…（64 碼）
複製時間: 2026-11-07T10:02:11+08:00
已有目標: 42
記穩目標: 無（初次製卡）
教材說明: 課本 p.84～91 的照片
接法: 複製貼上
服務: ChatGPT
模型: 未記錄
程式改動:
  - "第 37 行 拿掉 ^abc123"
---

（整理後的整段回覆：全貌、架構、卡組三段與 `<<<完>>>` 照原文；卡組段的新目標與候選名稱行只多了配好的 ID、少了 `程式改動` 記下的 AI 的 ID。加進已有的學習目標照 AI 的原文，不轉成連結）
```

- `時間` 是**準備發布**（第 5 步：所有卡組都寫成、做出快照全文）的那一刻，存進恢復資料後就不再改，重試沿用；`複製時間` 是按「複製提示」的那一刻。D-194 第 5 點的「成功生成時」看 `時間`；初次製卡送給 AI 的記穩目標明寫「無」，不靠沒寫來推定。
- `送出` 照送出的順序，每一項「名稱 版號 完整 SHA-256」，`原文/` 的檔名是前 12 碼，讀的時候要比完整的雜湊。家長調整、已有目標清單都在任務段裡，跟著任務段一起存。`規則版本` 照 syntax §6 原本的一行寫法留著，給人看。這一版的規則都是內建的；之後有自訂版時每一項再加註。
- `已有目標` 只是個數，清單在任務段。
- `教材說明` 是家長自己寫的，程式沒有看過教材；沒填就不寫這一行（D-126 第 4 點：拿不到的證據不寫成已確認）。
- `服務`：貼回時下拉選填（ChatGPT、Claude、Gemini、其他），沒選就不寫。`模型` 一律「未記錄」：複製貼上拿不到確切的模型，服務名稱不冒充模型（格式查核〈可沿用的格式〉第 5 點）。
- `程式改動`：每一項是原文的行號與拿掉的字；沒有就不寫這一行。
- `回覆原文`：回覆原文的完整 SHA-256，原文本身存在 `原文/`。快照本文是整理後、配好 ID 的版本，用來和卡組比對（D-042）；整理（BOM、換行、最外層圍欄）是多對一，從快照本文還原不回原文，要看原文就開 `原文/` 那一份（第二輪 R2-4）。
- `對象` 是實際寫成的篇（含自動改名後的名字）。

**原文的檔**：送出的每一部分與收回的回覆原文，內容就是那一段文字（D-115 第 4 點「依雜湊去重後存一份」）。回覆原文每次製卡多一份，約 10～40 KB（R3 的三段比較長）；一學期約 60 次，多 1～2 MB，比 D-115 原本估的多，換來原稿完整。只建立；同名不同內容不蓋掉、報錯；備份還原照 syntax §6 最後一點（只補缺的檔、同名異文列成衝突）。

**syntax §6 跟著改**（同一個分支）：加上面的新欄位與「成功才有快照」；「只寫不讀」改成「複習與排程不讀；加深與它的提示讀（D-194 第 10 點、環節 8 第 8 條）」；`原文/` 的資料夾與檔名。

## 6. 引言框裡的 ID 算占用

現有的程式已經做到，**不用改**（格式查核〈可沿用的格式〉第 1 點）：`src/core/deck/ids.ts` 的 `blockIds` 收每一行行尾的區塊 ID，`src/state/ids.ts` 配新 ID 時避開它們，所以候選框裡的 ID 不會再配出去；它們不是學習目標，不出題、不算 D-157 的重複（既定規則）。`0.3.0` 也一樣。

- 不要另寫只看兩種框、只認 6 碼的版本：現在對其他框、一般行與自訂區塊 ID 的保護比那樣寬。
- 補測試：候選框的 ID 不再配出；剪下貼成目標後照舊出題、不重複；複製出兩個真正的目標時兩個一起停出（D-157）；跨檔搬移、重新載入之後一樣。

## 8. 測試與實機

**單元測試**（只用 syntax.md 的例子或自編的內容，教材有版權）：

- 提示：同樣的表單、規則與已有目標，組出的文字一字不差、雜湊相同；`學生` 的換算；已有目標的挑法（同科、之前的年級學期、草稿不算、認不得的年級學期只算相同的）與排序。
- 待貼回的工作：複製 A → 改規則與模板（模擬外掛更新）→ 重新載入 → 貼回，存進 `原文/` 的文字和 A 的每一部分逐位元組相同、SHA-256 相同；工作過期或缺欄位時不能貼回、寫出原因（格式查核 F1）。
- 整理與分段：CRLF＋BOM＋最外層圍欄同時出現；四個反引號包著三個反引號的內文；三段齊全、少一段、卡組段空白、標記寫錯；沒有段標記時有開場白；行號換算回原文。
- 結束標記：R3 與 common 兩條路各測完整、尾段少貼（標記與題目都合法但沒有 `<<<完>>>`）、`<<<完>>>` 出現在引言框或程式碼裡（不算）（F9）。
- 拆篇：沒有篇名行、兩篇、篇名重複、空篇、只有候選框的一篇；篇名字串出現在答案的接續行、引言框、程式碼裡（不拆）；`## 篇名` 形式（擋）；年級學期、科目、編號不同（擋）；第一篇前面有備註框（併入）、候選框（擋）；檔名的不能用的字（F6）。
- 檢查：表上每一列各一個例子；`pick-mixed`（擋）；候選框裡缺答案（擋，行號對）；AI 寫的 ID 在行尾、行中、一行兩個、名稱寫兩行、自訂區塊 ID、題目或答案裡像 ID 的字（只拿掉名稱行行尾的，F7）；加進已有的 ID 不在清單裡、找不到、重複（F8）。
- 存草稿：屬性用 YAML 序列化（`L3 Sports: Week 1` 讀回來仍是草稿）；寫後核對；ID 不撞（卡組、引言框、紀錄的 `lt`、同一次的其他篇）；快照與卡組的新目標、候選 ID 完全一致；加進已有的轉成連結。
- 檔名：同路徑撞名、別的資料夾同檔名、大小寫不同、` 2` 已經有人用（要用 ` 3`）、檢查之後才有人建了同名檔（F4）。
- 中斷與重試（F2、F3、R2-1、R2-2）：只存了恢復資料（還沒寫任何 vault 檔）、寫了原文、每一篇卡組、準備發布、快照、清理之前，各在之後模擬關掉再繼續，**不再貼一次**就補出全部的檔，位元組與恢復資料相同，最後只有一份快照、各一篇卡組，ID 不變；同一個工作貼不同的回覆會停下；放棄後留下的篇是草稿、沒有快照、已發布的不能放棄；只寫了原文、只寫了一篇、全部寫成但沒有快照、已發布四種情況分得出來（只有最後一種有快照）。快照寫成、清理前重開，卡組維持原文、被改字、被改成啟用三種都只清理；卡組寫成後被改字再繼續，算寫成；隔數小時才補快照，`時間` 照存下的值。原文同名異文（擋）、讀不到（不當成不存在）。
- 搬走與刪掉（R3-1）：第一篇寫成、第二篇還沒寫 → 把第一篇改名、搬到別的資料夾、刪掉、拆一部分目標到別篇 → 重新載入再繼續：改名與搬走跟到新位置、快照的 `對象` 指到實際位置、不多建同 ID 的篇；刪掉與拆開停下，不默默補回；放棄後記成開始建了或寫出過的 ID 不再配出。另外在「記成開始建了 → 建檔」與「建檔 → 記成寫出過」兩個間隔各中斷一次、重開前刪掉草稿，繼續、跳過、放棄三種都不自動重建、不把 ID 當成沒用過；記成開始建了、檔還沒建就中斷時，照實停下問家長（R4-1）。
- ID 的預留（R2-3）：A 存了恢復資料就關掉 → 重新載入 → 固定亂數替一般卡組補 ID、做 B 工作 → 恢復 A，三邊不撞號；兩個沒完成的工作也一樣；放棄後沒寫成的篇的 ID 拿掉預留。
- 原文（R2-4）：有 BOM、CRLF、三或四個反引號或波浪號的外框、結尾有沒有換行的回覆，存進 `原文/` 的和輸入框交出的文字逐位元組相同；兩份不同的原文整理後相同時，快照的 `回覆原文` 不同。
- 疑似篇名（R2-5）：年級學期、科目、編號正確或錯誤，各配純文字與 `##` 兩種寫法；錯單元加標題也擋；`## 2 擴散現象` 不受影響。往返與冪等登錄進 `tests/deck.test.ts` 的 `deckCases`。
- 引言框的 ID：§6 的四個情境。
- 啟用：草稿 → 啟用寫一行 `set: status`；暫停的卡組、需要新版的卡組、屬性區讀不懂的照舊；手機不寫。
