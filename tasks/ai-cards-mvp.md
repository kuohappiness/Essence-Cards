## 和「不做」比較（D-153）

- **不做會怎樣**：外掛已在正式 vault 使用（`0.3.0`），但每篇卡組都要家長自己做：把規則檔一份份上傳到 AI 對話、自己寫任務資料、把結果貼進新筆記、手打屬性、改成草稿、看過再改成啟用。每一課約多 10 分鐘的搬運，而且容易漏：忘了寫 `狀態: 草稿`，孩子馬上會看到還沒審的卡；英文、國語一課分成幾篇，要自己拆檔、命名。AI 原稿也沒有留下，[D-042](../docs/decisions.md#d-042-ai-製卡快照) 的採用率與之後改規則都沒有資料。
- **做的代價**：一個電腦上的製卡畫面（表單、複製、貼回、檢查結果）、卡組筆記多一個「啟用」按鈕、`紀錄/AI 輸出/` 開始有檔；`state` 的 ID 占用多算引言框裡的 ID。不改排程、不改複習畫面，手機不變。
- **更小的做法**：
  - 只做「複製提示」、不做貼回：省了組提示，結果還是要手動貼、手打屬性、拆篇，也沒有快照。省下的不到一半，錯的機會（漏寫草稿）還在。不夠。
  - 只做貼回、不做提示：家長仍要自己上傳規則檔，送出的規則版本也記不下來（D-151 第 6 點）。不夠。
  - 啟用不做按鈕、照舊改屬性：家長要知道 YAML 在哪、拼對「啟用」兩個字；使用者會碰到的流程不該靠手改屬性（使用者 2026-10-26：以一般使用者為準）。一個按鈕的代價小，做。

## 1. 規則組嵌進外掛

- **表**：AI 模組裡一張表，每一科一列：顯示的名稱、規則檔的路徑（照順序）、每一份的名稱與版號（手寫，例如 `國小國語 v0.7`；凍結的 R3 寫 `R3 第二輪`）。家長在畫面上看得到這一科用哪些規則與版號（唯讀的一行，不開檔）。
- **建置**：`tools/build.mjs` 照表讀檔、嵌進 `main.js`，每一份算 SHA-256（照嵌進去的文字，UTF-8、換行統一成 `\n`）。表上的檔讀不到、標記找不到就建置失敗。這是 D-151 第 1 點「建置時從權威 Markdown 嵌進外掛、記版號與雜湊」的第一步；唯讀畫面與自訂版在之後的任務。
- **送出範圍**：`docs/card-rules/` 的檔開頭有給開發者看的標題與狀態（試用時已經拿掉過，[trials.md](../docs/card-rules/trials.md) 2026-11-04：狀態裡的「估 35～45 個」會影響目標數）。在每一份要嵌的檔裡加一行標記 `<!-- 以下送給 AI -->`，只送標記以下；`experiments/` 的 R3 四份沒有狀態，整份送、不加標記。
  - 加標記只加這一行。狀態框裡有給 AI 的句子時（english.md 狀態框最後一段「搭配通用規則（common.md）使用；與通用規則衝突時，以本檔為準」），把那一段搬到標記下面，字不改。common.md 開頭的狀態只有版本紀錄，整段在標記上面。
  - 規則裡的 Markdown 連結（`[D-190](../decisions.md#…)`）照原樣送，和試用時相同。
- **提示模板的版本**：§3 的任務資料與附加說明是程式裡的模板，記一個版號（例如 `提示 v1`），改字就加一。

## 2. 製卡畫面（電腦）

- **入口**：命令「AI 製卡」，加左側功能列一個圖示。手機不註冊（D-039：手機上不製卡）。入口畫面、目錄不放（D-100：入口是孩子每天用的）。
- **全螢幕或 Obsidian 的視窗**照入口與目錄的共用掛法擇一，實作時選，回報寫理由。
- **第一步：填單元**（家長填，學生不碰）：

| 欄位 | 寫法 | 預設 |
|---|---|---|
| 科目 | 下拉，只列 §0 開了的 | 上一次選的 |
| 年級學期 | 下拉：目錄認得的寫法（小一上～高三下）；選了科目後，已有卡組的年級學期排前面 | 上一次選的 |
| 單元 | 一欄「編號 名稱」，和屬性 `單元` 同一個寫法（[syntax §2-1](../docs/syntax.md#2-1-屬性)）；第一個空白前要有編號 | 空 |
| 學習目的 | 下拉：準備段考、準備小考、平常複習 | 準備段考 |
| 允許 AI 補充 | 勾選 | R3 的科目勾，其他不勾（照試用時的設定，[第二輪 README](../experiments/t4/arch/第二輪/README.md)） |
| 這次的調整 | 一行文字，選填，例如「這次最多 8 個目標」；寫進任務資料的「家長調整」 | 空 |
| 教材 | 一行文字，選填，例如「課本 p.40～51 的照片」；只是家長自己的說明，寫進快照，不送給 AI 之外的地方 | 空 |

- 同一個年級學期、科目、單元編號已經有卡組時，寫出那幾篇的檔名與狀態，問「還是要做一份新的嗎？」（不擋；舊的不動）。真的撞檔名在 §5 處理。
- **學生已有的學習目標**：同一科、年級學期在這一篇之前或相同的卡組（目錄的排序認得的才比得出先後；認不得的年級學期只算完全相同的），啟用與暫停的卡組裡、讀得懂的目標，草稿與需要新版的不算。每一個送「ID 名稱｜出處」一行，照年級學期、單元、筆記順序排。畫面寫出「會一起送出 N 個已有的學習目標」。沒有就寫「無」。
  - 只送名稱，AI 可能把不同判準的題目加進舊目標（backlog「跨單元加題時，AI 要看得到舊目標的什麼」的 2026-11-03 證據）。這一份不怕：加進已有的學習目標只留在引言框、不會自動合併，家長看得到。送基本題、判準或分兩段，跟「加入」的任務一起定。
- **第二步：複製提示**：按「複製提示」把整份提示放進剪貼簿，畫面寫出字數，以及下一步：「到 ChatGPT 或 Claude 開一個新對話，附上課本頁面的照片或 PDF，貼上提示送出；AI 回完後，把整段回覆複製回來」。同時存一份**待貼回的工作**（§3）。
- **第三步：貼回**：一個大的輸入框，按「檢查」跑 §4，結果列在下面；按「存成草稿」才寫檔（§5）。按「取消」或關掉，什麼都不寫；工作留著，下次可以接著貼回。
- 重開命令時，有待貼回的工作就先問：「接著貼回上一次的結果（國二上英文 L3，10 分鐘前複製）」或「做新的一課」。

## 3. 提示與待貼回的工作

- **提示的組成**（照順序，中間空一行）：§1 規則組的文字 → `## 這一次的任務` 與任務資料 → 附加說明。
- **任務資料**照試用的寫法（`國小國語設定.json` 的 `任務資料`）：

  ```
  - 學生：國小五年級（小五上）
  - 科目：國語
  - 單元：L7 美景閒情──詩兩首
  - 學習目的：準備段考
  - 允許 AI 補充：是
  - 家長調整：無
  - 教材：附件的課本頁面
  - 學生已有的學習目標：
    - k3m9qa 長 讀音｜小五上 L3 p.30
    - ……
  ```

  「學生」由年級學期換算（`國二上` → `國中二年級（國二上）`）。
- **附加說明**（模板，記在 §1 的提示版號裡）：
  - 教材在附件。附件沒有圖檔可以連，**不要寫 `![[…]]`**；要提到課本的圖，在出處寫圖號（例如 `p.42、圖 2`）。
  - 一課分成幾篇時，篇名照 `<年級學期><科目> <單元編號> <篇名>` 寫，例如 `國二上英文 L3 單字`，單獨一行（english.md §8、elementary-chinese.md 的卡組）。
  - 不要寫學習目標 ID 與屬性區，程式會加。
  - R3 的科目另外一句：照規則交三段，標記照抄（`<<<全貌>>>`、`<<<架構>>>`、`<<<卡組>>>`）。
- **待貼回的工作**存在這台電腦（`src/ui/prefs.ts` 的裝置偏好），不寫進 vault：識別碼（6 碼，和考試範圍同一套產生法）、複製的時間（含時分秒與時區）、表單的值、規則組（每一份的名稱、版號、雜湊）、提示版號、已有目標清單的文字、整份提示的雜湊。最多留 5 個、14 天；存成草稿成功就拿掉那一個。
  - 不存整份提示：規則照雜湊找得回來（§5 的送出內容），其他欄位就夠重組。重組出來的雜湊和存的不同（例如外掛在中間更新了），存草稿時照實寫進快照，不擋。

## 4. 貼回與檢查（要格式查核）

**整理**（只改包裝，不改內容）：拿掉開頭的 BOM、把換行統一成 `\n`；整段被一對 ` ``` `／` ```markdown ` 包起來時拿掉那一對。

**分段**：

- 有 `<<<…>>>` 標記（R3）：照標記切。要有 `<<<卡組>>>`，卡組段之後沒有其他標記；全貌、架構段照原樣留給快照。R3 的科目三個標記缺一個，或卡組段是空的，當成**沒有貼完整**（AI 的回覆被截斷或少複製一段）。
- 沒有標記（common.md 的科目）：整段就是卡組段。第一個非空行前面的開場白（例如「好的，以下是……」）**不猜**，當成錯誤，請家長只貼卡組的部分。

**拆篇**：卡組段裡，單獨一行、整行等於 `<年級學期><科目> <單元編號>` 或它加一個空白再加篇名的，是篇名行（年級學期、科目、編號用表單的值比，不用猜）。篇名行之間是一篇的本文。

- 沒有篇名行：整段是一篇，檔名照 D-081：`<年級學期><科目> <單元>（卡片）`，例如 `國二上自然 2-2 水溶液（卡片）`。
- 有篇名行：每一篇的檔名就是那一行；同一個篇名出現兩次是錯誤。第一個篇名行前面只有引言框時，併進第一篇的最上面；有其他內容是錯誤。
- 篇名行的編號和表單不同（例如貼錯課）是錯誤。

**檢查**：每一篇用 `parseDeck` 讀，加上草稿專用的檢查（環節 8 第 9 條；規則照 [`experiments/t4/check-syntax.mjs`](../experiments/t4/check-syntax.mjs) 搬進 `src/core/`，它比 [syntax §2-10](../docs/syntax.md#2-10-寫錯時) 的表嚴）：

| 擋住，不能存 | 提示，可以存 |
|---|---|
| 上面「整理、分段、拆篇」的錯誤 | §2-10 算寫錯的學習目標（存了照樣只跳過那個目標） |
| 一篇裡沒有任何學習目標 | `check-syntax.mjs` 算錯誤、§2-10 不算的（比較卡認不出來等） |
| AI 寫了屬性區（開頭的 `---`） | AI 自己寫的學習目標 ID（行尾的 ` ^xxxxxx`）：拿掉，存草稿時重配 |
|  | 引言框不是這三種：給家長的備註、加進已有的學習目標、候選卡片（一般知識是「給學習者的備註」） |
|  | 加進已有的學習目標的 ID 不在這次送出的清單裡：照樣留在框裡（不會被加入），寫出是哪幾行 |
|  | `![[…]]` 圖片連結：照樣留著，寫出「附件沒有圖檔，這張圖不會顯示」 |
|  | 候選卡片超過 5 個 |

**結果畫面**：每一篇一列：檔名、學習目標數、題數、候選卡片數、加進已有的學習目標數；底下列出擋住與提示的原因，寫行號（貼上的文字的行號）與一句可以怎麼改。有擋住的就沒有「存成草稿」，只有「回去改」（輸入框可以直接改字再檢查）。

## 5. 存草稿與快照（要格式查核）

**寫在哪**：卡組照 D-040 的預設編排：`Essence Cards/學業/<年級學期>/<科目>/<檔名>.md`；一般知識放 `Essence Cards/<檔名>.md`。快照照 [syntax §6](../docs/syntax.md#6-ai-輸出快照)：`Essence Cards/紀錄/AI 輸出/<日期> <年級學期><科目> <單元>.md`，撞名加後綴 ` 2`、` 3`。送出內容：`Essence Cards/紀錄/AI 輸出/送出內容/<雜湊前 12 碼>.md`。

**卡組的內容**：

```markdown
---
年級學期: 國二上
科目: 英文
單元: L3 Sports
狀態: 草稿
---

（AI 交回的這一篇本文；學習目標行尾加上配好的 ID，AI 自己寫的 ID 已拿掉）
```

- 有比較卡時加 `需要版本`，值照 [syntax §2-1](../docs/syntax.md#2-1-屬性) 的規則（D-191）。其他屬性不寫：沒有轉錄稿，`材料` 留空（出處只能讀、不能跳回）。
- **ID**：學習目標與候選卡片都配（[syntax §2-9](../docs/syntax.md#2-9-ai-製卡交回的草稿)：候選在存草稿時就配好，快照和卡組用同一組）。候選的 ID 寫在引言框裡那個目標名稱那一行最後（`> - 能說明溫度對溶解度的影響 ^k3m9qa`）。加進已有的學習目標的項目不配新 ID。配法照 D-134：避開所有卡組（含引言框裡的，見 §6）、複習紀錄出現過的 `lt`，以及這次其他篇已配出的。
- **順序**（環節 8 第 4 條）：在記憶體檢查、配好 ID → 寫送出內容（只建立、已存在就跳過；同名內容不同是錯誤）→ 寫快照（只建立）→ 一篇一篇建卡組（只建立）→ 照實際寫成的結果回報。都經過 `state` 的寫入佇列（環節 8 第 3 條），受同一組門檻：電腦、讀完、備份成功（D-150 第 3 點）。
- **撞名與重試**：
  - 卡組檔名已經存在：不蓋掉。內容和這次要寫的完全相同（同一次存草稿的重試）算已寫成；不同就停在那一篇，寫出「已有一篇同名的卡組」，讓家長選「改名另存」（檔名加 ` 2`）或取消。已寫成的篇與快照不刪。
  - 寫到一半失敗：按「重試」沿用同一個識別碼與同一組 ID，從沒寫成的那一份繼續。
  - Obsidian 中途關掉：待貼回的工作還在（§3 只有成功才拿掉），重新貼回是**新的一次**、配新的 ID；上一次已寫成的卡組會撞名，照上一條讓家長處理。上一次只寫了快照、沒寫成卡組時，那份快照留著（`對象` 連不到），它配出的 ID 不算占用。照實寫進說明書的疑難排解，不另做復原檔。
- **快照的屬性**（syntax §6 加欄位，格式查核）：

  ```markdown
  ---
  日期: 2026-11-07
  時間: 2026-11-07T10:23:45+08:00
  識別碼: m4k8q2
  工作: 製卡
  對象:
    - "[[國二上英文 L3 單字]]"
    - "[[國二上英文 L3 文法]]"
  規則版本: 通用 v0.15、英文 v0.14
  規則:
    - "通用 v0.15 3f9a0c1d2e4b"
    - "英文 v0.14 a17c55e0b9d2"
  提示: 提示 v1
  提示雜湊: 9c0e…（64 碼）
  任務資料:
    - 學生：國中二年級（國二上）
    - 學習目的：準備段考
    - 允許 AI 補充：否
    - 家長調整：無
  已有目標: 42 個 5be1c0a9f377
  教材說明: 課本 p.84～91 的照片
  接法: 複製貼上
  模型: 未記錄
  程式改動: 拿掉 AI 寫的 ID 3 個
  ---

  （整理後的整段回覆：全貌、架構、卡組三段照原樣，卡組段只多了配好的 ID、少了拿掉的 ID）
  ```

  - `規則` 每一項「名稱 版號 雜湊前 12 碼」，照送出的順序；`規則版本` 照 syntax §6 原本的一行寫法留著，給人看。
  - `已有目標` 是個數加送出那段清單的雜湊前 12 碼；清單本身存進送出內容。
  - `教材說明` 是家長自己寫的，程式沒有看過教材；沒填就不寫這一行（D-126 第 4 點：拿不到的證據不寫成已確認）。
  - `模型`：貼回時下拉選填（ChatGPT、Claude、Gemini、其他），沒選寫「未記錄」。
  - `時間` 是存草稿成功的那一刻；之後加深的主動提示要的基準（D-194 第 5 點）由那個任務定，這裡只先留精確時間。
- **送出內容的檔**：規則每一份、已有目標清單各存一份，檔名是內容的雜湊前 12 碼，內容就是送出的文字（D-115 第 4 點「生效的製卡規則依雜湊去重後存一份」）。和快照一樣只寫不讀；備份還原時照 syntax §6 最後一點處理。

## 6. 引言框裡的 ID 算占用

- 草稿的候選卡片、之後的加深框裡，引言框中目標名稱行尾的 ID，`state` 配新 ID 時要避開（環節 8 第 3 條「ID 占用包含卡組、候選與加深框」）；它們不是學習目標，不出題、不算 [D-157](../docs/decisions.md#d-157-重複的學習目標-id先停家長選) 的重複，也不進目錄的數字。
- 範圍：`Essence Cards/` 卡組裡，標題是「候選卡片」「加深的學習目標」的引言框，最上層清單項目那一行最後的 ` ^xxxxxx`（和 D-134 認 ID 的寫法相同）。
- 家長把候選剪下貼到清單裡，它就變成一般的學習目標，ID 照舊；和別的目標撞號時照 D-157。

## 7. 審核與啟用

- **存成草稿之後**：打開第一篇（新分頁），通知「已存成草稿：2 篇、45 個學習目標。看過、改好後按『啟用』，孩子才看得到」。快照不打開。
- 草稿照現在的做法：目錄標「草稿」，孩子的入口與今天的份不出（已有）；卡組筆記標題列的「預覽」可以看（D-163 第 3 點，已有）。
- **啟用按鈕**：草稿卡組的標題列加「啟用」，加同名命令「啟用這一篇」；只在電腦，掛法和「全部卡」「預覽」相同（`src/obsidian/deck-actions.ts`）。按下先問：

  > 啟用後，孩子就會開始複習這一篇的 45 個學習目標。
  > 還有：2 個學習目標寫法有問題，會先跳過；候選卡片 3 個、加進已有的學習目標 1 項還在引言框裡，不會出題。
  > 同一課還有 1 篇草稿：國二上英文 L3 文法。

  （沒有的那一句不寫。）按「啟用」只改這一篇的 `狀態: 啟用`；同一課的其他篇另外按。
- **寫法**：`state.setDeckStatus` 現在遇到草稿回 `unchanged`（`src/state/index.ts` 的 `plan`），`DeckStatusValue` 只有啟用、暫停。加一個「草稿 → 啟用」的路線，其他照舊：同一列寫入、同樣的門檻、寫成才記一行 `set: status`（`val: 啟用`），iPhone 不寫。目錄的暫停／恢復不能把暫停的卡組改回草稿，也不能把草稿直接改成暫停（照舊）。
- 啟用之後孩子那邊什麼時候看得到，照現在的同步與讀取，不另做。

## 8. 測試與實機

**單元測試**（只用 syntax.md 的例子或自編的內容，教材有版權）：

- 提示：同樣的表單、規則與已有目標，組出的文字一字不差、雜湊相同；`學生` 的換算；已有目標的挑法（同科、之前的年級學期、草稿不算、認不得的年級學期只算相同的）與排序。
- 整理與分段：包了 code fence、CRLF、BOM；三段齊全、少一段、卡組段空白、標記寫錯；沒有標記時有開場白。
- 拆篇：沒有篇名行、兩篇、篇名重複、編號不同、第一篇前面有引言框或其他文字、篇名行長得像小標題（`## 國二上英文 L3 單字`，照規則不是篇名行，結果要寫進測試）。
- 檢查：表上每一列各一個例子；AI 寫的 ID 拿掉後再配；加進已有的 ID 不在清單裡。
- 存草稿：屬性、檔名、ID 不撞（卡組、引言框、紀錄的 `lt`、同一次的其他篇）；快照與卡組的 ID 一致；寫送出內容時同名同內容跳過、不同內容是錯誤；卡組撞名（相同內容算寫成、不同內容停下）；寫到第二篇失敗後重試只多出缺的那一篇（環節 8 的反例「快照寫成、草稿失敗後重試只得到一份」）。往返與冪等登錄進 `tests/deck.test.ts` 的 `deckCases`。
- 引言框的 ID：配新 ID 時避開；不出題、不算重複。
- 啟用：草稿 → 啟用寫一行 `set: status`；暫停的卡組、需要新版的卡組、屬性區讀不懂的照舊；手機不寫。

**Windows 實機**（開發版，加一個開發命令跑上面能自動跑的部分，結果檔照 [quality.md](../docs/agents/quality.md) 的口徑）：

1. 用自編的內容跑完整流程：填表 → 複製 → 貼回一段準備好的回覆（R3 三段、英文兩篇各一份）→ 存草稿 → 預覽 → 啟用；檢查檔、快照、送出內容、紀錄的 `set: status`。
2. 拿使用者電腦上已有的真實試用輸出（例如專案檔案的 `國小社會試用/2-1 地形 製卡輸出.md` 的三段，只在測試 vault、不進 repo）貼回，看檢查有沒有誤擋。
3. **使用者做一次真的**（AI 沒辦法替使用者登入 ChatGPT、Claude 網頁）：選一科、最長的規則組（英文），複製提示貼到 ChatGPT 與 Claude 網頁各一次，附課本頁面；記下：整份提示有沒有被收下（貼上時會不會被截斷、變成附件）、回覆有沒有一次交完、貼回後的檢查結果、從按複製到存成草稿花了幾分鐘。整份貼不進去時，另做「存成檔案」讓家長上傳，回報寫結果再定。
4. iPhone：草稿不出現在今天的份、啟用後出現；併入下一次 iPhone 實機測試。
