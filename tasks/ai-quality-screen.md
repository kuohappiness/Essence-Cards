# AI 品質初篩：精簡指令對完整製卡規則（給 Codex）

遵守 repo 根目錄的 `AGENTS.md`。建議推理等級：**中等**（規格都定好了；要寫的是組提示、存檔、解析與統計，沒有演算法）。

[D-114](../docs/decisions.md#d-114-產品核心以學習目標為單位回饋先找原因) 的推論有一個還沒驗證的前提：我們的製卡規則做出來的學習目標，比一般 AI 好。這次用不花使用者時間的方式先量一次：同一個模型、同一份教材、同一種輸出格式，只差在有沒有完整的製卡規則，看規則多帶來多少可用的內容、少了多少刪改，用來決定規則值得投入多少。設計在[討論稿](<../Claude Codex Discussion/2026-10-20-core-chain-and-rule-loop.md>)的「Codex 回應 §4」與「Claude 第二輪 §2」。

這叫 **AI 品質初篩**：它不能證明產品比其他工具好，也不能證明學業成效，不擋 v1。

分工：Codex 寫程式、跑生成、做盲評包；評分由另一個 Claude 對話做（評分者和生成者不同，也不知道組別）；Claude 檢查程式與結果。

## 開工條件與基準

- 基準是這份說明所在的 commit。開工前用 `git log -1 --format=%h -- tasks/ai-quality-screen.md` 找到它，再用 `git diff <那個 commit> -- docs/card-rules/ experiments/t4/screen/ docs/syntax.md` 看有沒有改過；有改，以新版為準，並在回報裡註明。寫這份說明時通用規則是 v0.12、自然預設是 v0.4。
- 在本機用 `git worktree add ../Essence-Cards-screen -b codex/ai-quality-screen main` 開在旁邊的資料夾，在分支 `codex/ai-quality-screen` 上 commit；在新資料夾的 `experiments/t4/` 執行 `npm install`。**不要在原資料夾切換分支**：其他 AI 可能正在 main 上改文件。
- 結果資料夾（`--out`）在測試 vault 裡，路徑寫在交給你的訊息。裡面已經有 Claude 在生成之前寫好的 `能力清單/`，只讀不改。

- 只新增或修改：`experiments/t4/screen.mjs`（要拆檔就用 `experiments/t4/screen-*.mjs`）、`experiments/t4/README.md`（加一小節用法），以及 `experiments/t4/api.mjs`（只加下面「生成」說的選擇性參數）。其他檔案只讀不改，包括 `experiments/t4/screen/`、`docs/`、`prompts/`、`models.json`、`check-syntax.mjs`、`t4.mjs`、`core.mjs` 與這份說明；有疑問寫在回報裡。
- Node 24、ES modules，不加新套件。
- 金鑰照 T4：讀 `%USERPROFILE%\.essence-api-keys.env`，同名環境變數優先；不能出現在程式碼、畫面、紀錄檔或任何結果檔裡。`送出.json` 不存 HTTP 標頭。

- 這次只跑第 1 次（4 個請求，失敗的重送不算）。不要跑 `--run 2`；已經有輸出的格子不能重跑或覆蓋：所有結果都保留，不挑最好的一次。
- 不評分、不填評分表、不改能力清單。回報裡不寫代號和組別的對照，也不貼輸出內容。

## 要做什麼

```
node screen.mjs run --out <資料夾> [--material <材料>=<教材路徑>]… [--run <N>]
node screen.mjs blind --out <資料夾>
node screen.mjs report --out <資料夾>
node screen.mjs selftest
```

`--run` 預設 1；`--out` 照 T4 用 `validateOut` 檢查。結果資料夾的樣子：

```
<out>/
  能力清單/<材料>.md          Claude 在生成前寫的，只讀
  材料/<材料>/教材.md、圖/、版本.json
  生成/<材料>/<組別>-<次>.md、.送出.json、.回覆.json、.檢查.md、.統計.json
  生成/組別對照.json、生成/機械統計.md
  盲評/README.md、盲評/<代號>.md、盲評/評分/<代號>.md
  紀錄.json                    ApiClient 的請求紀錄
  初篩報告.md                  report 產生
```

評分者只看 `能力清單/`、`材料/`、`盲評/`；會透露組別的東西都放在 `生成/`。

### 讀檔的共通處理

所有文字檔讀進來先去掉 BOM、把 CRLF 換成 LF（這個 repo 的 `core.autocrlf` 是 true，worktree 裡的檔案可能是 CRLF），sha256 用換行統一後的內容算。

### run：生成

1. **材料**：每段材料第一次用到時，把教材複製成 `材料/<材料>/教材.md`，教材裡 `![[…]]` 用到的圖（在教材旁邊的 `圖/`）複製到 `材料/<材料>/圖/`，寫 `版本.json`：來源路徑、教材與每張圖的 sha256、時間。之後一律從這份複本送出；又給了 `--material` 而內容和 `版本.json` 不同時停下來，提示改用新的 `--out`。還沒有複本、`教材` 是 `null`、又沒給 `--material` 時，跳過那段材料並提示。
2. **提示**：照 `設定.json` 的 `groups` 依序讀檔，`{科目預設}` 換成那段材料的 `科目預設`，每份 `trimEnd()` 後用一個空行接起來；結尾檔的 `{{任務資料}}` 換成 `任務資料`。換完還有 `{{` 或 `{科目預設}` 就停下來。
3. **user**：`教材全文：\n` 加教材；再照第一次出現的順序，每張圖一個 `教材的圖：<檔名>` 加圖片（`imagePart`），同一張只送一次。兩組用同一份。
4. **送出前**：`git status --porcelain -- experiments/t4/screen docs/card-rules` 有未 commit 的修改就停下來；記下 `git rev-parse HEAD`。
5. **送出**：用 `ApiClient`，`step` 寫 `screen`、`variant` 寫 `<材料>/<組別>-<次>`，供應商設定與價格從 `models.json` 取。順序：材料依序，每段材料兩組各一次。`<組別>-<次>.md` 已經存在的格子跳過並提示「沿用」，絕不重送、不覆蓋；失敗的格子不留檔，重跑同一個指令會補上。
6. **存檔**，在 `生成/<材料>/`：
   - `<組別>-<次>.md`：模型交回的原文。
   - `<組別>-<次>.送出.json`：時間、材料、組別、次、commit、模型（供應商、模型名稱、網址、參數）、每個 system 檔的路徑與 sha256、完整的 system 文字、user 的每一段（文字原樣；圖片只寫 `材料/` 裡的檔名與 sha256，不放 base64）。
   - `<組別>-<次>.回覆.json`：回覆裡的 `model`、`system_fingerprint`、`finish_reason`、`usage`、秒數。`api.mjs` 現在只回傳文字，可以加一個選擇性的參數讓呼叫端拿到這些；不傳時行為與輸出完全不變，`node t4.mjs selftest` 仍要通過。
7. 每存好一份就做下面的機械檢查。

### 機械檢查

用 `check-syntax.mjs` 匯出的 `check(輸出, { subject, unit, transcript: 教材 })`，`subject`、`unit` 取自 `設定.json` 的 `checkSyntax`。精簡組沒有被告知製卡規則，所以問題要分類，只有「格式錯誤」拿來比兩組：

| 分類 | 哪些 | 說明 |
|---|---|---|
| 格式錯誤 | 所有「錯誤」，加上這些「不符」：`yaml`、`para`、`code`、`callout-unknown`、`callout-prefix`、`top-question`、`target-name`、`no-question`、`no-source`、`source-empty`、`source-unknown`、`source-unresolved`、`double-colon`、`colon-space` | `格式.md` 兩組都有講到的 |
| 用語 | `simplified`、`mainland-term` | 兩組都算，家長都要改 |
| 不計 | `too-many-targets` | 規則 v0.11 拿掉了每頁上限，`check-syntax.mjs` 還沒跟上 |
| 規則類 | 其他「不符」，包括以後新增的代碼 | 只有完整組被告知，當參考 |
| 提醒 | 所有「提醒」 | 只記數量 |

- `<組別>-<次>.檢查.md`：照 `check-syntax.mjs` 的報告寫法，分上面五類列出行號與代碼。
- `<組別>-<次>.統計.json`：學習目標數、題目數、附圖數、候選卡片數、給家長的備註項數、加進已有的項數；各分類的數量（規則類依代碼分）；給家長的備註與候選卡片的名稱（報告附錄用）；token、秒數、費用。
- `生成/機械統計.md`：每份一列的總表。

### blind：盲評包

1. 每段有輸出的材料都要有 `能力清單/<材料>.md`，沒有就停下來，提示「先寫能力清單」。解析 `## 必須涵蓋的能力` 底下第一張表的 `代號` 與 `能力` 兩欄；代號重複或表格讀不到就停下來。
2. 每份還沒有代號的輸出給一個代號：隨機 3 個大寫英文字母，不用 I、O，不重複；記在 `生成/組別對照.json`（代號、材料、組別、次、輸出檔）。代號不能透露組別或先後。
3. 寫 `盲評/<代號>.md`，只放會排程的內容，把會透露組別的寫法拿掉：

   ```
   # <代號>

   材料：<材料>｜學習目標 <n> 個（給家長的備註與候選卡片不列）

   ## <小標題>

   ### 目標 1：<名稱>
   - 出處：<出處；沒寫就寫「（沒寫）」>
   - 題 1：<正面>
       - 答案：<背面；多行答案用「 ／ 」接起來>
       - 題目附圖：<檔名>
       - 背面附圖：<檔名>
       - 背面補充：<文字>
   - 題 2：……
   - 共用補充：<文字>
   ```

   - 用 `check()` 的 `targets`；目標從 1 起整份連續編號，小標題照原文。
   - 拿掉：類型、重要性等出處以外的資料欄位，`**` 粗體記號，給家長的備註，候選卡片，加進已有的學習目標。
   - 填空題用 `check()` 給的正面（空格是［＿］）與背面。
   - 圖只寫檔名，照位置分題目附圖、答案附圖、背面附圖；評分者到 `材料/<材料>/圖/` 看。
   - 有「錯誤」落在某個目標的範圍內時，照樣列出，名稱後面加「（程式會跳過：<代碼>）」。
   - 一個目標都讀不出來時，寫「程式讀不出學習目標」，下面用程式碼區塊附上原文。
4. 寫 `盲評/評分/<代號>.md`，格式見下面的[評分表](#評分表)；已經存在的不覆蓋（可能已經填了）。
5. 重寫 `盲評/README.md`：要評的代號，依材料分組，每組裡的順序隨機；每個代號標「待評」或「已評」；附上 `材料/`、`能力清單/` 的位置，以及「評分方式見 repo 的 `tasks/ai-quality-screen.md` 的〈評分〉一節」。
6. `盲評/` 裡的任何檔案都不能出現組別名稱、第幾次、模型名稱、token 或費用。

### report：初篩報告

不連網。讀 `組別對照.json`、每份的 `.統計.json` 與評分表，寫 `<out>/初篩報告.md`。報告以「材料 × 次」為單位，不把不同輸出的學習目標混在一起算：

1. **總表**，每段材料一張，每份輸出一列（依次、組別排）：目標數｜格式錯誤｜必要能力 完整／部分／沒有｜內容有錯的目標｜洩漏的目標（題數）｜一池不同能力｜多餘｜重複｜保留／小改／大改／刪除｜要刪改（小改＋大改＋刪除）｜可用目標（保留＋小改）。
2. 同一段材料兩組都有評分時，每組各列平均與「完整減精簡」；註明每格只有幾次，只當參考。不做顯著性檢定。
3. **能力覆蓋明細**：每段材料一張，列是能力、欄是每份輸出（標組別與次）。
4. **交給使用者判斷**：評分表裡以「爭議：」開頭的問題，附代號、目標與原文。
5. **評分表的問題**：還有「待填」的列為未評分；值不合規定的列出檔名、列與原因。這些不算進總表，也不能讓整份報告失敗。
6. **附錄（程式算的）**：每份的給家長的備註、候選卡片名稱、規則類不符（依代碼）、用語、提醒數、token、秒數、費用。

## 評分

這一節給評分的 Claude 對話，不是 Codex 的工作。

- **評分者**：開一個新的 Claude 對話。只看 `<out>` 的 `能力清單/`、`材料/`、`盲評/`；在填完全部評分表之前，不看 `生成/`、`紀錄.json`、`初篩報告.md`，也不看 Codex 的回報或這次試驗的 git 紀錄。
- **能力清單是生成前寫的**，看了輸出之後不改。發現清單本身有問題時寫在「整體」，並在給使用者的結果裡說明，不偷偷改。
- **標準**：家長拿到這份草稿，要怎麼處理才能放心讓孩子複習。依據是教材與產品的定義（學習目標是可以獨立判斷會不會的一項能力，同一個題目池共用排程），不是「有沒有照製卡規則」；不看格式細節，那是程式算的。
- 照 `盲評/README.md` 的順序評，每份對照教材與能力清單評，不拿兩份互相比；但前後的標準要一致。
- 各欄的意思：
  - **涵蓋**：完整＝有目標測到這項能力，可接受的答案的重點都在；部分＝只測到一部分，或只在別的目標裡順帶提到；沒有。對到的目標正確是「否」或要刪除時，最多算部分。候選卡片不算。
  - **正確**：題目或答案有錯、和教材矛盾就是「否」（教材和一般說法不同時以教材為準）。沒錯但缺了重點，填「是」，處置填小改並說明。
  - **洩漏**：題目本身（包括放在題目那一行的圖上的字）透露了答案，或寫成是非題、二選一，用猜的就有一半會對。判斷的問法是「不會的學生用猜的，能不能自評答對」（2026-10-20 第 1 次評完後補）：
    - 算：答案只是在兩邊挑一邊，題目又沒問原因，就算沒寫出選項也算，例如「哪種顏色吸收較快？」（深或淺）、「濃度如何變化？」（大或小）、「水通常稱為什麼？」（溶質或溶劑）。
    - 不算：題目要說出原因或機制，猜對方向也寫不出來，例如「溫度一定比較低嗎？為什麼？」；或答案要寫出兩件以上的事，例如「深色吸收快、淺色光亮反射多」。
    - 同一池有別題問原因，也不能抵銷：排程輪到那一題時，學生還是可以用猜的答對。
  - **同一能力**：池裡每一題能不能用同一句「學會了的判準」解釋，學生不會長期一題會、另一題不會，而且原因是不同的能力。只有一題就填「是」；填「否」時寫出是哪兩種能力。
  - **多餘**：不值得花複習時間，例如能力清單「不該做成學習目標」的內容、敘述性的細節、教材沒有的內容、多步驟的計算。**重複 N**：和目標 N 測的是同一種能力，標在後面那一個。教材裡值得記、但不在必須清單裡的目標不算多餘。
  - **處置**：保留＝直接能用；小改＝改字、改一題的問法、刪一題或補一句答案，家長一分鐘內改得完；大改＝要拆開、合併、重寫大部分題目或改目標本身；刪除＝整個目標不要。
- 拿不準的寫「爭議：」，交給使用者；不為了填滿而硬判。
- 全部填完後執行 `node screen.mjs report --out <資料夾>`。

已知的偏差，寫結果時要一起說：評分的 Claude 和寫規則的是同一方，可能偏好照規則寫的樣子；拿掉格式標記後，文字風格仍可能透露組別；第二段材料是 Claude 自寫的；每格只有一兩次。

## 自我測試

`node screen.mjs selftest` 不連網，用暫存資料夾與假的 `fetch`，至少檢查：

1. 組提示：兩組的 user 逐位元組相同；精簡組的 system 依序是兩個檔，完整組在中間多了規則與科目預設；兩個結尾只差那一句；沒有剩下的 `{{`；CRLF 與 BOM 會被處理掉。
2. 生成：用假的 `fetch` 跑完 2 段材料 × 2 組，檔案都在；再跑一次不送請求、不覆蓋；換了材料內容會停下來；`screen` 或 `card-rules` 有未 commit 的修改會停下來（可以用假的 git 結果）；用一把假金鑰，掃過所有寫出的檔案都找不到它。
3. 機械檢查：用自己編的輸出，五個分類各至少一例分對；沒列在表上的「不符」代碼算規則類。
4. 盲評包：從一份有類型、重要性、粗體、填空、三種位置的圖、給家長的備註與候選卡片的假輸出，產生的檔案沒有這些資料欄位、`**`、備註與候選，編號連續，圖的位置標對；代號不重複、格式對；`盲評/` 裡找不到 `精簡指令`、`完整規則` 與模型名稱；已填的評分表不被覆蓋。
5. 評分表與報告：一份填好的、一份還有待填的、一份值不合規定的；報告的數字對、未評分與錯誤有列出、爭議有列出。

另外 `node t4.mjs selftest` 與 `node check-syntax.mjs --selftest` 仍要通過。

## 執行

交給你的訊息會寫 `--out` 與自然 2-2 轉錄稿的路徑。

1. 跑完三個自我測試。
2. `node screen.mjs run --out <資料夾> --material 自然2-2=<轉錄稿路徑>`，產生 4 份輸出。有格子因為額度或錯誤失敗，等一下重跑同一個指令補上。
3. `node screen.mjs blind --out <資料夾>`。
4. 不要跑 `report`：評分表還沒填。
