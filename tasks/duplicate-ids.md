## 和「不做」比較（D-153）

- **不做會怎樣**：照現在的規則，重複的 ID 由位置（同一篇排在前面的，`src/core/deck/assign.ts:96`、`src/core/study/plan.ts:80`）或路徑（路徑排在前面的卡組）決定誰保留。`0a393c5` 實測：把目標整段複製來改、貼在原本那個的上面，或貼到路徑排在前面的卡組，副本接手原本的記憶狀態，作答記在錯的目標上；紀錄只追加，之後很難分開。同一篇貼在上面時，存檔還把原本那個換成新 ID、進度歸零。貼到路徑排在後面的卡組，副本默默不出題。AI 製卡做好之前，卡組都是家長手寫，「整段複製來改」是最自然的寫法。
- **做的代價**：照 D-157 的代價——把目標整段複製來改時，原本那個也先停，要等家長選一次；家長處理之前這幾個目標都不出題；重複被看見之前已經記錯的紀錄不會修好。程式上 `state` 多一份衝突的結果、待處理多一種、作答多一道擋、複習畫面的卡會失效、小視窗多一種列法、離開筆記多一則通知；要 L2。
- **更小的做法**：
  - 只在排程擋（`planToday` 改成都不出）、存檔不改：存檔照樣把同一篇的第二個換號（`assign.ts:96`），貼在上面時原本那個被換掉，最嚴重的那一種擋不住。不夠。
  - 只停、不做家長選的入口：家長不知道 ID 存在（D-079：家長與 AI 都不寫 ID；畫面只說「加入複習」「進度連結」，`src/obsidian/save.ts:8`），只能把副本刪掉重寫；副本本身是家長要的。不夠。
  - 貼上的當下就拿掉副本的 ID：延後（D-157，見〈這次不做〉）。

## 1. 哪些算衝突（格式查核）

- **範圍**：`state` 讀得懂的卡組（`decks()`，不含需要新版的 `blocked().decks`），用 `state` 最近讀到的內容。讀不到的那一篇保留上一次讀到的內容（讀不到不算刪除）；從來沒讀到的不知道內容，不算。
- **對象**：`parseDeck` 認出的學習目標（`deck.targets`），`id` 不是 null。草稿、暫停的卡組，暫停（`狀態：暫停`）、寫錯（`ok: false`）的目標都算。家長自訂的 ID（例如 `^Mine-1`）也算，不是只看程式產生的 6 碼。名稱那一行中間的 ID（`misplaced-id`）照 D-134 就是那個目標的 ID，也算；同一個值在那一行出現兩次算一個 ID。名稱寫成兩行時看第一行的 ID（D-135）。
- **不算**：引言框、程式碼區塊、一般筆記（底下沒有題目）、轉錄稿、題目那一行的區塊 ID；只寫在名稱接續行尾的 ID（`id` 是 null）；`ambiguous-id` 的目標（那一行有兩個不同的值，`id` 是 null，候選不當成確定的 ID，照原本待處理）；隱含目標（題目行尾有 ID 也一樣，`id` 是 null）。
- **衝突**：同一個 ID 有兩個以上的目標，同一篇或不同篇都算。結果是衝突的 ID，以及每個 ID 的目標（路徑、行號、名稱），照路徑、行號排。
- **時機**：在拿掉待處理的目標（`tracker.lines`）與需要新版的 ID（`gatedIds`）之前算，待處理的目標照樣占著它的 ID（Codex 的邊界表：否則一個被拿掉的目標會讓另一個冒充唯一的）。每次 `rebuild` 照目前的內容重算，不看讀到的先後、不另外記住：重開之後照目前的內容重算，兩台裝置讀到同樣的內容就停同一個 ID。
- **需要新版的卡組**（Codex F4）：不參與衝突的計數，也不給選；它的 ID 照原本（`gatedIds`）停出。只有一個讀得懂的目標和它同一個 ID 時，不算衝突、只是不出。兩個以上讀得懂的目標同一個 ID 時照常列衝突；家長處理到只剩一個之後，那一個仍照 `gatedIds` 不出，等更新外掛。不拿那一篇的位置猜身分。
- **只維護一份**：判斷寫成核心的一個純函式（放 `src/core/deck/` 或 `src/core/study/`，施工時定），`state` 與 `planToday` 的防呆（§6）都用它，不另寫第二份。還原的全庫 ID 檢查（`src/core/backup/plan.ts`）目的不同（連 `ambiguous-id` 的候選也算占用），不改用這個判斷。`state` 公開一個查詢衝突的方法（例如 `conflicts()`，回每個衝突的 ID 與它的目標），複習畫面（§5）與開發命令（§6）用它。

## 2. 停：不出題、不收新的作答

- **不出題**：衝突的 ID 的所有目標從 `planList` 拿掉，和待處理的目標一樣：今天的份與「再複習一些」都沒有；不占英文的配對（另一個方向照「這個方向不在」算，和待處理的目標相同）；作答不算進估秒（`subjectOf` 沒有它）。`deckStatus(path).missing` 不算它們（它們不補）。
- **不收新的作答**：`answer` 的作答與學習目標的狀態變更（`set` 加 `lt`）牽涉衝突的 ID 時不寫、回 null；`canAnswer(lt)` 回 false。
- **取消照原本的門檻**：`answer({ undo })` 不因衝突擋，只看它指的作答原本的門檻（需要新版、紀錄讀不懂、紀錄不完整）。Codex 的理由：不能只因重複就禁止撤銷先前的誤記。複習畫面的改評分是取消加新的作答，會因 `canAnswer` 是 false 整個不做。
- **iPhone 照算照擋**：手機的 `state` 一樣算衝突、一樣擋；處理留在電腦（D-134：iPhone 不寫卡組）。

## 3. 不自動換號、家長選（格式查核）

### 3-1 一般存檔與離開筆記

- 存檔（`tracker.fill`）與離開筆記的備援（`fillIds`）都跳過衝突的目標那一行，和待處理的一樣：不換 ID、不把行中的 ID 移回行尾、不改縮排。其他沒有 ID 的目標照補，配新 ID 時衝突的 ID 照樣算用過。
- **核心的契約**：`assignIds` 不再換「同一篇裡和前面重複的」ID（拿掉 `assign.ts:96` 的換號）；已經有 ID 的目標一律不換，不靠呼叫端記得傳 `skip`。`AssignOptions.replace` 沒有產品程式用，一起刪掉，`tests/deck.test.ts` 用到它的三個測試照新契約改寫或刪掉。
- **`parseDeck` 的 `duplicate-id`**：照舊是提示（`hint`，不影響 `ok`）、只標同一篇後面那一個，代碼不變（發布前比較的快照記代碼，`tools/compare/adapter.ts:68`）；文字改成不承諾換新，例如「這個學習目標 ID 和同一篇前面的重複；用了同一個 ID 的目標先都不出題，等家長選哪一個是新加的」。停不停只看 §1，不看這個提示。

### 3-2 家長選「這一個是新加的」

- **待處理多一種**：`IdIssueKind` 加 `'duplicate'`。每個衝突的目標在它那一篇有一個問題，`restore` 是 null（沒有可以還原的）；另外帶 `others`：同一個 ID 的其他目標（路徑、行號、名稱）。
- **物件身分**（Codex F2）：`duplicate` 的選擇綁定顯示時的那一行。行號、名稱、題目指紋或 ID 任一個變了，就換新的問題物件，舊的回 `stale`（副本同名同題時可能互換位置，不能靠最近的行號猜）。只有 `others` 變了（別的目標改動）時保留同一個物件、原地更新 `others`。小視窗收到 `onChange` 會重畫，家長看到的是新的物件。`lost`、`changed`、`ambiguous` 的追蹤規則不改；例外（Codex L2 的 F1、再審的 R1）：`changed` 的未知 ID 在這一版或上一版不只一個目標在用時，只有名稱和題目都沒變的目標才算同一個，還原的選項只跟著一樣的內容；認不出來時 `changed` 結束或不給還原的選項，不交給另一個目標。代價：ID 共用期間改了那個目標的名稱或任何一題，就不能從這裡還原，紀錄不動。
- **`resolve(issue, 'new', editor)`**：
  - 送出時核對（D-134：寫回前重新確認）：編輯器的那一篇是 `issue.path`（別篇的不能從這裡改，`src/state/index.ts:409`）；用編輯器現在的文字重新比對（可能比 `state` 讀到的新），`issue.line` 那一行還是同一個目標（名稱、題目指紋、ID 相同），而且這個 ID 照 `state` 所知加上這份文字仍然有兩個以上的目標。不成立回 `stale`，問題照目前的內容重算。
  - 只換那一行的 ID（D-034 的格式；避開 `taken`：見過的、紀錄裡的、刻意拿掉的、待處理問題的 `restore`）。同一篇其他衝突的目標、待處理的目標不動；同一篇其他沒有 ID 的目標照一般規則補（和現在的「當成新的」相同）；別篇不動。
  - 採用時（核對讀取確認寫成了）：新 ID 記成見過；舊 ID 照下面〈刻意拿掉〉。
  - `resolve(issue, 'restore', …)` 對 `duplicate` 回 `stale`，什麼都不寫。
- **寫回的字面輸出**（Codex F3）：沿用現在「當成新的」的寫回（`setTargetId` 加 `assignIds`），這次不改它們。新 ID 一定在名稱第一行的最後、後面沒有空白（syntax §2-3）；其他行與換行符號（CRLF）逐字不動；寫回之後再存一次不改任何字。被選的那一行照下表（␠ 是空格、⇥ 是 Tab）：

  | 被選的那一行 | 寫回之後 | 說明 |
  |---|---|---|
  | `- A ^舊` | `- A ^新` | |
  | `- A ^舊␠␠` | `- A ^新` | ID 後面的空白拿掉 |
  | `- A⇥^舊` | `- A ^新` | 分隔的 Tab 換成一個空格 |
  | `- A ^舊 B` | `- A B ^新` | 行中的 ID 移到行尾 |
  | `- A ^舊 B␠␠` | `- A B␠␠␠^新` | 原本行尾的空白留在 ID 前面 |
  | `- A ^舊`，下一行是接續文字 | `- A ^新`，接續文字不動 | D-135 |
  | `- A ^舊␠␠`，下一行是接續文字 | `- A ^新`，接續文字不動 | 第一行尾的兩格拿掉：閱讀模式少一個換行（已知代價，只在這個組合） |

  不把 ID 放在行尾空白之前：ID 後面帶空白時 Obsidian 認不認得、閱讀模式藏不藏得住沒有驗過，而且要連現有的補 ID 一起改、帶進 D5。
- **連結裡的 `^id`（D5，Codex I1）**：這次不改 `setTargetId`、`nameIds`、`maskLinks`、`lock.ts`，D5 的觸發點不到，那一列照舊留著。已知限制照舊：`- A [資料 [補充] ^b4rw7k](note.md)` 會被認成 ID `b4rw7k`，選「新加的」時連結裡的字會被拿掉。衝突的判斷以 `parseDeck` 的結果為準，不另寫一份只給衝突用的連結辨識。施工時發現非改它們不可，就把 D5 的完成條件一起帶進來。
- **紀錄**：複習紀錄的格式不變（syntax §5，不加欄位、不寫新種類的行）。被選中的那一個用新 ID 從頭複習；舊 ID 的紀錄不改，留給之後只剩下的那一個沿用。
- **刻意拿掉**（Codex F1，所有種類都適用）：任何問題的選項（`duplicate`、`changed`、`ambiguous` 的 `new` 與 `restore`）採用寫回時，被拿掉的 ID 照採用後的內容與 `state` 所知的其他內容仍在別的學習目標上，就不記成刻意拿掉（現在一律記，`src/state/ids.ts:311`）。家長在編輯器裡刪掉副本整個目標時，`removedInEditor` 報來的 ID 若照 `state` 所知仍在別篇的目標上，也不記（Claude 補的；同一篇裡還有這個 ID 時 `lock.ts` 本來就不報，`src/obsidian/lock.ts:273`）。否則之後那個目標弄丟 ID 會偵測不到（D-134）。
- **同一個目標同時是待處理（`lost`、`changed`）與衝突**：兩個問題都列；家長處理其中一個之後，另一個照目前的內容重算。選了「新加的」時，這個目標的問題一起結束，不移給還用著舊 ID 的副本（Codex L2 的 F1）。

### 3-3 家長看得到（文字照 §9 截圖再定）

定案（使用者 2026-11-02 看截圖）：小視窗的說明只寫一次，不是下面提案的每一列一句：「下面的學習目標用了同一個編號（可能是整段複製來改的），先都不出題。選要改寫成新內容的那一個：它會從頭複習；只剩一個時，那一個沿用原本的進度。」每一列寫「第 N 行〈名稱〉」與「同一個編號也用在：…」，別種問題排在前面；存檔按鈕的說明與離開筆記的通知照提案。

- **存檔按鈕**：有 `duplicate` 問題時照現有待處理的樣子（⚠、`TIPS.issues`）。
- **按存檔時跳出小視窗**：沿用現有的開法（存檔之後 `deckStatus(path).issues` 不是空的就開，`src/obsidian/save.ts:249`）。每個 `duplicate` 問題一列：說明（提案「〈名稱〉和別的學習目標用了同一個編號（可能是整段複製來改的），先都不出題」），列出 `others`（同一篇寫「第 N 行〈名稱〉」；別篇寫「〈卡組〉第 N 行〈名稱〉」，可以點，打開那一篇、捲到那一行），按鈕「這一個是新加的，從頭複習」。兩個名稱一樣時（貼上之後還沒改字就按存檔），家長只能靠行號分：文字要讓家長選「要改寫成新內容的那一個」。
- **離開筆記時**（備援）：`fillIds` 結束後（回 true 或 false），那一篇有 `duplicate` 問題就用通知說一次（提案「〈卡組〉有 N 個學習目標和別的目標用了同一個編號，先都不出題；打開這篇按存檔，選哪一個是新加的」）；`fillIds` reject 時照現在交給 `onError`、不通知。離開時不開小視窗。外掛已經卸載就不通知（技術債 W2 的 `alive`）。
- **手機**：沒有存檔按鈕，不提示；那幾個目標只是不出。

## 4. 恢復

- 只剩一個時（家長刪掉副本、選了新加的，或同步晚到的刪除到了），剩下的那個沿用這個 ID 繼續，其他門檻（待處理、需要新版、紀錄讀不懂、暫停、濾網、到期）照查；它用這個 ID 原本的紀錄。不保證剩下的就是歷史上原本那一個（D-157 代價第 3 點）。
- 讀不到不算刪除（§1）；重開之後照目前的內容重算。

## 8. 測試（驗收條件）

照 code-quality〈測試〉：只透過公開介面（`createState`、記憶體的 `Files`、測試用的編輯器、複習畫面的 `Session`、`planToday`、`assignIds`、`parseDeck`）；預期值是自編的字面值；一個 commit 一個決定或一項審查發現。共用的例子：

```markdown
- borrow 英翻中 ^b4rw7k
    - borrow :: 借入
```

加一筆 2026-10-01 對 `b4rw7k` 的 `good`；副本是整段複製、名稱與題目改成 `lend 英翻中`／`lend :: 借出`、ID 照留。

**停與不換號**（backlog 那一列的測試全部在這裡）：

1. 篇內貼在下面、貼在上面；跨篇副本的路徑在前、在後；第一次載入就重複：`today()` 的 `share` 與 `more` 都沒有 `b4rw7k`；`canAnswer('b4rw7k')` 是 false；`answer` 一筆作答回 null、紀錄檔沒有多一行；兩邊的 `deckStatus(path).issues` 都有 `duplicate`，`missing` 不算它們；`conflicts()` 列出這個 ID 與兩個目標。
2. 存檔與離開筆記的備援不偷偷解掉衝突：`save` 與 `fillIds` 之後，衝突的兩行逐字不變（篇內貼在上面時，原本那個仍是 `^b4rw7k`）；同一篇另一個沒有 ID 的目標照樣補上。
3. 三份同一個 ID，家長選第二份：只有那一行換成新 ID，第一、三份仍是 `^b4rw7k`、仍然衝突、仍然不出；別篇的檔逐字不變。
4. 送出時核對：小視窗拿到問題之後，那一行改了名稱、被搬到別行、或副本已經刪掉，`resolve` 回 `stale`、檔案不變，問題照目前的內容重算。搬行要測兩種：等 `state` 重讀之後才送舊物件、`state` 還沒重讀就送（編輯器的文字已經變了）。兩份同名同題互換位置時舊物件回 `stale`。只有別的目標改動（`others` 變了）時舊物件照樣能用。
5. 恢復：刪掉副本（或另一台的刪除經同步到了），`b4rw7k` 又出現在今天的份，用的是 10-01 那筆的記憶；`canAnswer` 回 true。
6. 讀不到不當刪除：副本那一篇讀不到（`Files.read` 失敗）時衝突照舊；之後讀到、內容沒有副本才解除。
7. 兩台讀取順序不同：裝置甲一開始就讀到兩篇，裝置乙先只讀到副本那一篇、原本那篇晚到；兩台都讀到之後 `conflicts()` 相同，兩台都不出、都不收 `b4rw7k` 的作答。
8. 舊卡寫不進去（`Session`）：顯示 `b4rw7k` 的卡時加入副本，畫面換掉這張、紀錄沒有新的 `b4rw7k`；刪掉副本之後，這次 `Session` 回看裡衝突前做過的 `b4rw7k` 不能改評分；之後重新抽到、作答的照常寫。
9. 處理副本後，原本的目標在外部弄丟 ID 仍會待處理：(a) 選副本是新加的；(b) 在編輯器刪掉別篇的副本（`removedInEditor`）。之後在 Obsidian 以外拿掉原本那個的 `^b4rw7k`，`deckStatus` 有 `lost`、`restore` 是 `b4rw7k`。(c) `changed` 的兩個選項也一樣（Codex F1，基準程式重現）：首次讀到 A 的 `- A ^aaaaaa`，外部改成 `- A ^bbbbbb`（`changed`，可還原 `aaaaaa`），B 新增 `- B ^bbbbbb`；A 用 `changed` 的問題選 `new`、選 `restore` 各做一次，之後外部拿掉 B 的 `^bbbbbb`：B 有 `lost`、`restore` 是 `bbbbbb`（兩個目標底下都有題目）。
10. 取消照原本的門檻：衝突期間 `answer({ undo: <10-01 那筆的 t> })` 照寫；`Session` 的改評分不做。
11. iPhone（`fillIds: false`）：衝突照算、作答照擋，卡組不寫。

**邊界**（底下的目標都帶題目，否則是一般筆記）：

12. 草稿卡組、暫停的卡組、暫停的目標、寫錯的目標（中翻英答案有中文）裡的副本，各自和啟用的 `b4rw7k` 衝突，列出兩個目標。名稱行中間的 `^b4rw7k`、名稱寫成兩行時第一行的 `^b4rw7k`、家長自訂的 `^Mine-1` 重複、`- A ^b4rw7k B ^b4rw7k`（同一個值兩次，確定的 ID）也算。
13. 另有一個真正的 `b4rw7k` 目標時，下面這些都不造成衝突、那個目標照其他門檻出題：一般筆記 `- 筆記 ^b4rw7k`（底下沒有題目）、引言框裡帶題目的 `> - borrow 英翻中 ^b4rw7k`、程式碼區塊裡的、帶 `來源類型` 的轉錄稿裡的、題目行的 `^b4rw7k`、只寫在接續行尾的 `^b4rw7k`、最上層直接寫題目而行尾有 `^b4rw7k` 的。
14. `ambiguous-id`：先載入 `- A ^b4rw7k`，改成同一行有 `^b4rw7k` 與 `^p7q2w8`（`ambiguous`，`restore` 是 `b4rw7k`），別篇再加 `- B ^b4rw7k`：不列 `duplicate`，`ambiguous` 照原本待處理；選「還原」回 `stale`（原本的檢查，`src/state/ids.ts` 的 `resolve`）。
15. 需要新版的卡組：(a) 一個讀得懂的目標和它同是 `b4rw7k`：不列衝突，讀得懂的那一個照原本停。(b)（Codex F4）讀得懂的 A、B 和需要新版的 C 都是 `b4rw7k`：A、B 列 `duplicate`、`others` 不含 C；家長選 A 是新加的之後，A 用新 ID 照常出，B 不再有問題、仍然不出、`canAnswer` 是 false。
16. 跨層：另一份先被待處理拿掉。載入 `- borrow ^aaaaaa` 加題目，在 Obsidian 以外把 ID 改成 `^bbbbbb`（`changed` 待處理），再在別篇加 `- lend ^bbbbbb` 加題目：`lend` 不出，`conflicts()` 列出兩個 `bbbbbb` 的目標。
17. 同一個目標同時是 `changed` 與衝突：兩個問題都列；選「當成新的」之後兩個都消失。另一個副本在同一篇也一樣：它沒有問題、照常出題（Codex L2 的 F1）。ID 共用時，同名、題目不同或只有幾題相同的目標都拿不到還原的選項（再審的 R1）。
18. 重開之後照目前的內容重算：衝突還在時新開的 `state` 照停；解除後寫回的檔，新開的 `state` 沒有衝突。

**核心與畫面**：

19. `planToday` 直接收到重複的 ID：那個 ID 都不出、不丟錯，其他目標照常；英翻中是重複的時，中翻英照「英翻中不在」排。`today.test.ts` 的 T8 照新規則改（`g4` 兩篇都不出，補「草稿裡的副本讓啟用的也不出」）；`Today` 沒有 `problems`（型別檢查擋）。
