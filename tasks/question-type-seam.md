## §1 接點的形狀

**一句話**：一種題型 = 四張表各填一列。共同的流程（拿下一張、進度、回看、切走 60 秒重來、寫紀錄、預覽）只透過接點和題型說話，不再判斷是哪一種。新增題型時 `QuestionType` 多一個值，TypeScript 會指出每張表缺哪一列（`Record<QuestionType, …>`），是機械檢查，不靠人記得。

| 接點 | 位置 | 這一列要回答什麼 | 翻面 | 打字 | 比較點選 |
|---|---|---|---|---|---|
| 認得出來 | `src/core/deck/question-types.ts` | 名稱與題目怎麼認、哪些算寫錯 | 其他全部 | 名稱「 中翻英」，答案能比對 | 名稱「字（組） 結尾」，每題一個空格、答案在組裡（§3） |
| 怎麼組成一張卡 | `src/core/study/compose.ts` | 這張卡有哪幾格、出哪一題 | 一格 | 一格 | 同組到期的併成一張（§5） |
| 怎麼作答 | `src/review/flow.ts` 與各題型一個檔 | 孩子做什麼、程式怎麼判、對到哪個評分、寫哪幾行 | 翻面、四級 | 三步（D-121） | 點字、對答案、再選一次（§6） |
| 畫面 | `src/ui/screens.tsx` 與各題型一個檔 | 題目區、底部那一排、點卡片做什麼 | | | |

不做可以安裝的模組（D-181 曾考慮的做法）：表就是 `const` 物件，不做註冊機制。

### 1-1 一張卡（`Card`，`src/core/study/types.ts`）

```ts
interface Blank { lt: string; target: Target; prompt: Prompt }   // 一格，只對一個目標（D-114）
interface Card {
  lt; deck; target; prompt; isNew; typed; early;                 // 不變；好幾格時是選中的那一格
  blanks: readonly Blank[];                                      // 新增，至少一格；翻面、打字就是自己那一格
  group: CardGroup | null;                                       // 第二步才加：字鍵與整組對照
}
```

`questionType(card)` 是唯一判斷題型的地方（`group` 有值是比較點選，`typed` 是打字，其他是翻面）；`Card` 不再多存一份題型。`nextCard`、`practiceNext` 與預覽各自重複的 `typed: prompt.kind === 'qa' && …` 併成一個 `cardOf`。

**全詩順序卡（D-187）這次不做，形狀要容得下**：它是比較點選的一種（第 8 點），不是第四種題型，多的是三條規則：空格全部一起出、字鍵用過就淡掉、好幾格一個目標取最差的一格。它用填空語法、沒有括號，§3 不會認成比較卡；接上時從名稱最後兩個字「排序」認，`Blank` 多一個「這一題的第幾格」，`CardGroup` 多一個旗標，字鍵放整句。`Card` 不落地，到時改形狀不用遷移；紀錄照 §4，`also` 多一個格序，不用改格式，最上層的代表格也要解得出是第幾格（直接寫，或其他格完整、可以唯一反推）；`v` 是整首，出題次數一首只加一次。兩句文字相同時兩個位置都要留，位置和文字分開，字鍵不照組員的規則去重。上線時要不要把 D-191 的標記升到它的版號，到時照 D-149 第 3 點判斷。

### 1-2 作答流程（`Flow`，`src/review/flow.ts`）

一張卡從題目走到有結果的整段狀態，一個物件。Session 與預覽都只透過它：

```ts
interface Flow {
  view(): FlowView;                       // 畫面要的：revealed、allowed、speakable、typed（第二步加 pick）
  autoRead: readonly string[] | null;     // 這一刻該念的；每個有效動作開頭清掉（D-116）
  revealedAt: number | null;              // 答案出現的時間，0.3 秒內的自評不算（D-096）
  act(action: FlowAction): boolean;       // 一個動作；回傳算不算數（不算就不通知畫面）
  settle(rating: Rating | null): Settled; // 記下來：要寫哪幾行、回看要的東西
}
interface Settled {
  lines: readonly ReviewLine[];           // 一個目標一行；翻面、打字一行
  look: LookBack;                         // 回看時的 typed／pick、能改成哪些評分、改了之後寫哪幾行
}
type FlowAction = { kind: 'reveal' } | { kind: 'input'; text: string } | { kind: 'submit' } | { kind: 'skip' };  // 第二步加 key、row、check
```

`createFlow(card, { now })` 照 `questionType(card)` 查表。預覽的打字走另一個流程（`createPreviewTyped`：不走三步，D-161），翻面走同一個（多一個 `revealed` 的起點）。預覽什麼都不寫，自評也不等 0.3 秒，所以它的流程（`createPreviewFlow`）沒有 `settle`、`revealedAt`。第一步的 `settle` 只收評分；第二步要 `settle(null)` 時才放寬。按下的評分留在 Session，第一步不放進 `Settled`。

**四種邊界都試過**（D-181 要求接點試過這些）：孩子自評（翻面：`allowed` 全部）；一張卡走好幾步（打字：`act` 走三步，`allowed` 由第 1 步決定）；一張卡好幾格好幾個目標（比較點選：`lines` 好幾行，`settle(null)` 不用選評分）；程式判一部分、孩子自評一部分（找錯題，還沒定案：`act` 判位置、`allowed` 限制評分、`lines` 帶證據，不用改 Session）。D-187 多一種：好幾格一個目標（全詩順序卡：`lines` 一行，取最差的一格），和 §4 同一個目標兩格是同一條規則，第二步用兩個選項的組就走得到。

Session 留下：取卡、`top`、回看清單、切走重來、衝突與停用、0.3 秒、寫紀錄。`Session` 的方法與 `CardView` 的欄位都不變，`reveal`、`input`、`submit`、`skip` 轉成 `act`；第二步新增 `act(action)`（字鍵、句子、對答案）與 `commit()`（有錯時的「下一張」），新題型不用再加方法。

## §3 卡組：名稱與題目（⏳ 格式查核）

寫法照 [D-182](../docs/decisions.md#d-182-比較點選各科都能用家長出題時勾選) 與[規畫〈卡組怎麼寫〉](../docs/plans/similar-chars.md#卡組怎麼寫)：程式認括號，不認結尾的詞；結尾是卡片的標題；各科都能用，字和詞都放得下，程式不分科。這份說明寫「字」的地方，詞也一樣。`parseDeck` 的結果：

```ts
interface PickGroup { word: string; members: readonly string[]; key: string; title: string }
interface Target { …; group?: PickGroup }   // 選填：沒有就是一般目標，舊測試的 deepEqual 不用改
```

**判斷的順序**（格式查核 F1、F2、F7，第二輪 R2-2、R2-4）：先看目標與題目的形狀，再看組，最後才分類錯誤；每個目標只有一種結果，比較卡的診斷最多一種。解析與 `check-syntax`（§10）共用同一個結果。括號本來就有別的用途（D-125 的 `light（輕的）`、預設的 `節（節日） 字義`），所以多半的情況是照原題型，不算寫錯。

1. 最上層直接寫題目（`implicit`）、名稱有 `==`（現有語法把這一行當隱式填空），或名稱裡有空格（`＿`，算法見〈空格怎麼數〉）：照原題型，不看組。第三種是補 ID 留下來的：`- 寨（寨、塞） 山＿＿ :: 寨` 補 ID 後是明確目標 `寨（寨、塞） 山＿＿ ^id`，底下留著原來的題目（`assignIds`，R2-4 重現）；比較卡的名稱不會有空格，所以分得開。沒有空格的隱式問答補 ID 後，題目仍然沒有空格，落在下表最後一列。補 ID 前後結果都相同。
2. 結尾是中翻英、英翻中，前面的空白半形全形都算：照舊，不看組。兩件事分開驗收（R2-2）：① `pairKey` 不留尾端空白，`borrow  中翻英` 現在是 `borrow `，配不上 `borrow 英翻中`；② `src/core/deck/parse.ts:132` 放寬到全形空白（記憶 `tolerate-typing-noise`，不另外為它加提示）。② 的代價：`能看出中文語序　中翻英` 底下答案不能比對的題目現在是一般卡，放寬後和半形空白一樣是 `typed-answer-invalid`，家長看得到，改個名稱就好；repo 裡的範例沒有這種目標（R2-4 的掃描），正式使用的 vault 還沒有卡組（💡 實作者的選擇，見文末）。
3. 每一題都是填空的目標不會是比較卡：接句卡（D-185）、全詩順序卡（D-187）都是填空，括號再像組也照填空；結尾是相似字、比較時有 `pick-not-recognized`。這兩種之後在填空的分支認結尾的詞，和這裡不互搶。問答和填空混在一起的，進第 5 點的表。
4. 讀不出組（見〈組怎麼讀〉）：一般目標；結尾是相似字、比較時有 `pick-not-recognized`。
5. 讀得出組，看每一題，由上往下第一個符合的就是結果：

| 這個目標的題目 | 結果 |
|---|---|
| 有一般語法錯誤（空答案、空題目） | 照 §2-10 原來的錯誤，不往下判；改好之後才看比較卡的問題 |
| 有比較句的答案是組裡別的字（`寨（寨、塞）` 底下 `下班時間大＿＿車。 :: 塞`） | error `pick-answer-invalid`，定位到每一個這樣的題目，跳過這個目標（§2-10）。一格只對一個目標（D-114），答案是塞卻記到寨，紀錄就錯了 |
| 每一題都是比較句，答案都是名稱的字或詞 | 比較卡 |
| 有比較句的答案是名稱的字或詞，但混了別的（沒有空格、兩格、填空、多行、組外的答案） | 照原題型，hint `pick-mixed`，按題指出不符合的，存檔按鈕與目錄照現有的路。不同能力請拆成不同目標 |
| 其他：沒有一題是答案為名稱字詞的比較句（`台北（台北、高雄） 首都` 底下 `台灣的首都？ :: 台北`；`寨（寨、塞） 比較` 底下 `這是＿＿。 :: 村`） | 照原題型，算寫錯的話一般的卡就不出題了；結尾是相似字、比較時 hint `pick-not-recognized`，指出組外的答案。沒有結尾或結尾是別的詞時沒有提示：程式看不出家長想做比較卡（D-182 第 4 點） |

**比較句**：問答題，題幹剛好一個空格，答案單行。答案只有一個子項目時，解析本來就是單行（已驗）；`寨。` 帶標點和 `寨` 不同，算組外。

**空格怎麼數**（R2-4）：連續的 `＿` 算一格（`＿`、`＿＿`）；`＿ ＿`、`＿**＿**` 算兩格；半形 `__` 不算（可能是 Markdown）。不看行內程式碼、公式、整個圖片（網址和替代文字，`![底線＿](圖＿片.png)`）、連結目的地、HTML 標籤與 `%%` 註解；連結文字算，字元參照 `&#65343;`、`&#xFF3F;` 當一個 `＿`（渲染後就是）。畫面找空格是 `src/ui/rendered.ts` 的 `insertLines`：受保護內容以外的第一段 `＿`。兩邊應該相同，但 Obsidian 的渲染器和 markdown-it 不完全一樣，所以有保底：**畫面找不到空格時，空格放在句尾**，這張照常能答（💡 實作者的選擇，見文末）。這幾種寫法用真的渲染器跑一次（§10）。

**結尾**：組的括號後面的字（在連續的括號之後）；沒有組時是名稱最後一段，前面要有空白或右括號。`title` 照寫的保留。提示只在結尾整段等於「相似字」「比較」時才有，`能依照密度進行比較`、`這兩個字的比較` 都不算。只有提示看結尾的詞，認不認得出不看（D-182 第 4 點，結尾打錯也不會壞）。`pick-not-recognized` 寫出怎麼補（例如括號裡用頓號隔開）。

**組怎麼讀**：

- 名稱是字或詞，接著連續的括號（中間可以有空白），再來是結尾。括號半形全形都算，左右寬度可以不同，要成對；缺右括號、巢狀的不讀。比對用已移掉 ID 的 `target.name`，字或詞外層成對的 `**` 去掉。
- 連續的括號裡，**第一個清單形狀（裡面有頓號、逗號或空白）、又含括號前面的字或詞的**是組；其他的是義項，留在目標名稱裡（D-125）。所以 `light（不 重）（light、lit）`、`light（不、重）（light、lit）` 都認得，`節（省、不浪費）` 沒有組。這個括號讀不成有效的組就是沒有組，不再往後找；結尾裡的括號不算（`寨（塞、寒） 相似字（寨、塞）`）。
- 切項目：頓號、逗號一定分隔。完全沒有頓號或逗號時，空白都分隔（`寨（寨 塞 寒 賽）`）。有頓號或逗號時，空白兩邊都是漢字才分隔（`寒 賽` 是少打了頓號，中文不靠空白分詞）；碰到英文或數字的空白是詞的一部分（`make up`、`A 型`、`pH 值`，中英之間加空白是常見的排版）。空的項目丟掉（`寨（寨、、塞）` 是兩項，打字雜訊）。限制：`特 殊 型` 會切成三項；中文詞中間本來不會有空白，字鍵在預覽看得到，`check-syntax` 提醒（§10）。
- 有效的組：正規化後去掉重複至少兩項，括號前面的字或詞在組裡，沒有 `` ` ``、`$`、`[`、`]`、`<`、`>`（字鍵不畫 Markdown，這些會被當語法；折完全半形才檢查，`［`、`＄` 也擋）。

**正規化**（比對答案、組員與 `key`）：去掉成對的 `**`、`==` 與前後空白，連續空白（含全形）當一個，英文不分大小寫，只折全半形（U+FF01～FF5E），不做整串 NFKC（`①` 和 `1` 不同），不切 UTF-16（`𠮷` 是一項）。句首的 `Borrow` 對得上 `borrow`（D-158 的方向）。字鍵照括號裡寫的顯示；指紋照 §2-8，和正規化無關。

**舊版讀到比較卡**（[D-191](../docs/decisions.md#d-191-比較卡舊裝置整篇擋住每個字鍵一格就多放一句)）：使用者決定整篇擋住，提示更新，更新後才能複習那一篇。不擋的後果格式查核 F3 重現過：`0.3.0` 當一般翻面卡出題，同一個 `lt` 寫進另一種成功判準的自評。讀取端與提示 `v0.3.0` 已經有（`src/core/deck/parse.ts:77`、`src/state/index.ts:218`；`src/main.ts:32`、`src/obsidian/save.ts:38`），這次只加寫入端，它是第一個寫 `需要版本` 的功能（syntax §0-1）。下面的細節都是 💡 Claude 的提案，使用者還沒看過，第三輪查：

- **版號**：`src/core/version/release.ts` 新增常數 `PICK_NEEDS`，第一個讀得懂比較卡的正式版號，定了不再改。合併時定成下一個沒用過的版號（比 `git tag --list 'v*'` 最新的新），`package.json`、`manifest.json`、`package-lock.json` 同一個 commit 升到它，寫死版號的測試跟著改；正式發布時只打 tag。所以之後每個建置（含開發版 `x.y.z+commit`）都讀得懂自己寫的標記，測試固定 `canRead(PICK_NEEDS, releaseOf(BUILD))`。另一條路是版號留到發布才升、寫入端用 `canRead` 開關：開發版寫不出標記，實機測不到，發布時也可能默默關著。
- **什麼時候寫**：`assignIds` 多一個選項 `need`（`state` 傳 `PICK_NEEDS`），這篇有比較卡或 `pick-answer-invalid` 的目標時，和補 ID 一起寫。同一條路：存檔按鈕、離開筆記時自動補（`src/obsidian/save.ts:377`）、處理 ID 問題；只在電腦（D-134）；受同一個備份閘門（D-150 第 3 點）；不在載入時寫（D-149 第 7 點）。ID 都有了只缺標記時也要寫：`status` 多回一項，按鈕不是「沒有要做的」。
- **怎麼寫**：`需要版本: 0.x.0`，沒有屬性區就建一個，有就加在屬性區最後一行。已有比 `PICK_NEEDS` 舊的值就改成它；新的值不動。屬性區讀不出來（YAML 寫壞）時不寫，照現有的提示，補 ID 照舊。只加不拿掉：比較卡後來改掉了，標記留著只是多擋舊裝置，無害，也不用判斷。先補 ID 再加屬性，`assigned[].line` 是寫回後的行號（`skip` 仍是原文的行號）。第二次跑一字不改。
- **發布**：讀和寫同一版（D-191 第 4 點）。退回照舊檢查（D-149 第 4 點）。
- **還有的窗口**：已有 ID 的卡組被舊版電腦改成比較卡的寫法、新版電腦還沒打開過時，舊裝置照翻面出到標記寫入為止。發布後照 §5-1 的版本行確認每台都換好，這個窗口就沒了。

## §4 紀錄（⏳ 格式查核）

每個字一行，沿用 `lt`、`r`、`v`。同一張卡的行只讀一次時鐘，逐行加 1 毫秒（§5-4 第 2 點）：

```
{"t":"2026-11-05T20:15:03.250+08:00","lt":"寨的 ID","r":"near","v":"a1b2c3d4","pick":"塞","retry":"right"}
{"t":"2026-11-05T20:15:03.251+08:00","lt":"塞的 ID","r":"good","v":"9f0e1d2c","pick":"塞"}
{"t":"2026-11-05T20:15:03.252+08:00","lt":"寒的 ID","r":"miss","v":"77aa1c0e","pick":null}
{"t":"2026-11-05T20:16:10.000+08:00","lt":"borrow 的 ID","r":"near","v":"5e6f7a8b","pick":"lend","retry":"right","also":[{"v":"0c1d2e3f","r":"good","pick":"borrow"}]}
```

| 欄位 | 內容 |
|---|---|
| `pick` | 只寫在比較卡，每一行都有：對答案時那一格的字，照字鍵上寫的（對的也寫）。第一次按「沒印象」是 `null`（畫面上那一格顯示「？」；`？` 可以是組員，不能共用一個字串，R2-3）。所以有沒有這個欄位就分得出比較卡和翻面的紀錄，不用另外的欄位。對答案前改過的不留，手滑分不出來（規畫〈每一格怎麼評分〉）。順序在 `typed` 的位置之後、`retry` 之前 |
| `retry` | 比較卡沿用：第一次選錯時，再選的結果 `right`／`wrong`／`skip`（再選時按「沒印象」）。第一次就對、第一次按「沒印象」都不寫。`not-needed` 只屬於打字卡。再選錯了選哪個字不記 |
| `r` | 第一次對 `good`；全對又按太簡單時每一行都是 `easy`；第一次錯、再選對 `near`；再選也錯、按「沒印象」`miss` |
| `v` | 這一句的指紋 |
| `also` | 選填，同一個目標還有別的格時才有：其他每格一個物件，`v`、`r`、`pick`、`retry` 的意思和上面相同。順序在 `retry` 之後、`src` 之前 |

- 同一張卡同一個目標有好幾格（兩個選項的組、多放的一句；之後的全詩順序卡）：一行，FSRS 算一次作答（D-187 第 5 點）。最差的那格的 `r`、`v`、`pick`、`retry` 放最上層，一樣差取畫面上前面那一格；其他格放 `also`。
- `also` 的理由（格式查核 F4）：畫面順序由指紋算（§5-3），同一對句子每次順序相同，全對時永遠記前面那格，三句的組有八分之六的順序會讓某一句永遠沒紀錄、張張都出（§5-2 的試算）；只記最差的格也會讓「總是答錯的題目」（D-046）沒有分母，另一格選了什麼（D-115）事後補不回來。多一個選填欄位就都解決。
- 全詩順序卡之後在 `also` 多一個格序，最上層的 `v` 仍是整題：選填欄位不用 `need`（§0-1），現在不用先定欄名。
- 不寫 `typed`、`need`、`src`。舊版讀到 `pick`、`retry`、`also` 都忽略（`src/core/study/entries.ts:40` 只取認得的欄位，`v0.3.0` 到現在沒改），每一行都是合法的作答：不用 `need`。
- `parseLine` 多讀兩件事（`ReviewEntry` 多兩個選填欄位，舊測試的 deepEqual 不用改）：有沒有 `pick`（`picked?: true`，秒數用，§5-4）、`also` 裡的 `v`（`also?: readonly string[]`，形狀不對就當沒有）。`pick`、`retry` 的值與 `also` 的其他欄位只是證據（D-115），程式不讀。
- **出題歷史和評分分開**（R2-3）：新增一個函式算「每個目標每一句最後出的時間與次數」，最上層和 `also` 的 `v` 都算，不看 `r`，`src/core/study/` 的 `plan.ts:113–119`（今天以前）、`session.ts:46–65`（當天）、`practice.ts:109–118`（本輪以前）三處共用（現有的 `Slot.seen` 只有時間）。到期與提早出的順序、`correct`、完成與 FSRS 一律只看最上層的 `r`：一對一錯不會因為 `also` 有 `good` 就算完成。以取消後還有效的行算（§8）。
- **`sameReview`**（`src/core/study/history.ts:19`）：現有的 `lt`、`r`、`v`、`typed`、`src` 之外多比 `also` 的指紋（排序後）；`pick`、`retry` 不比。iCloud 衝突副本逐字相同；同一個 `t`、同一句、`also` 卻不同，是兩台裝置各做了一次，兩筆都留，和這個函式現有的原則相同，結果不看讀檔順序，`mergeHistory` 與 `appendLine` 一致。
- **證據的範圍**：`lt`、`v` 只回查得到還在筆記裡的句子；句子改掉後，查不回當時的題幹與期待的字（`r`、`pick` 還在）。第一次提交前的手滑、再選錯選了哪個字，明說不留。
- 一行寫不進去（那個目標被停掉，`state.answer` 回 null）：其他行照寫，每一行本來就獨立；全部寫不進去照現有的做法換下一張。
- 合併時 `docs/syntax.md` 照[報告〈規格同步與驗收清單〉](<../Claude Codex Discussion/2026-11-05-question-type-seam-format-review.md>)改；批次欄位不做，`pick` 與 `also` 以這一節為準（`pick` 的跳過是 `null`，不是報告當時的 `？`）。

| 不在範圍裡（暫停、寫錯、ID 重複、被停掉、別科、不在 `targets`） | 不併，字鍵與對照照樣有 | 同左 |

### 5-2 每格出哪一句

`choosePrompt` 對比較卡改成：最久沒出的（沒出過的先）；一樣久的，出過次數少的先；再一樣照筆記順序。出過包含 `also`，時間與次數來自 §4 的出題歷史。第一次就是基本題（這個字還沒出過句子，不看排程狀態）；答錯再出、提早出都走同一套輪替（規畫〈怎麼出題〉、D-028），不走其他題型「答錯出同一題」「沒答對回基本題」的捷徑，這是唯一的差別。指紋相同的句子算一句，候選與次數都照不同的指紋算；只有一種句子就還是那一句，「到期兩句」也只出一句。句子增刪照現在還在的算（`AB@1, CA@2, BC@3` 加一句 D，下一次是 DA）。

**只有兩個選項的組**（D-182 第 7 點）：出過的字到期時出兩句（最久沒出的兩句），同一個字兩格，紀錄取比較差的那格（§4），全猜對的機會從 1/2 降到 1/4。只有一句就一句。新的字照舊一句，第一次的規則不變。

**多放一句**（[D-191](../docs/decisions.md#d-191-比較卡舊裝置整篇擋住每個字鍵一格就多放一句) 第 2 點）：這張卡每個字鍵剛好一格時（第一次整組一起出，或後來剛好全部到期），多放一句，刪去法才不好用；從還有別句的字裡選，都沒有別句就不加。

| 兩個選項的組（每個字三句） | 格數 |
|---|---|
| 全新 | 3：每個字一句，再多放一句 |
| 只有一個字到期 | 2：這個字兩句；另一個字只在字鍵上 |
| 兩個都到期 | 4：各兩句 |
| 一個新的、一個到期 | 3：新的一句，到期的兩句 |

同一個字兩格時兩句都算出過（§4 的 `also`）。一張卡的兩句時間相同，所以要有平手的規則，否則三句的組每張都有第一句。兩格一張、跑 400 次的試算（[報告〈Claude 回應〉](<../Claude Codex Discussion/2026-11-05-question-type-seam-format-review.md>)）：

| 紀錄與平手 | 三句 | 四句 | 五句 |
|---|---|---|---|
| 只記最差的格，某一句永遠不是最差 | AB BC CA CB CA CB，那一句 50% | 那一句 50% | 那一句 50% |
| 兩句都記，平手照筆記順序 | AB CA BA CA BA，A 50% | AB CD AB CD | A、B 各 25%，其他 17% |
| 兩句都記，平手次數少的先 | AB CA BC AB CA BC，各 33% | AB CD AB CD，各 25% | AB CD EA BC DE，各 20% |

### 5-3 打散

字鍵與句子的順序由這張卡的指紋（每格的 `v` 接起來）算出，同一張卡重來（切走 60 秒）不變，換句子就變；三個字鍵以上時，順序一定和括號的順序不同（示意頁的 `shuffled`）；只有兩個時不強制，否則永遠是反過來，等於固定位置。放在 `compose.ts`，純計算，不用 `Math.random`，測試與回放才固定。多放的那一句挑哪個字也用同一個來源。

### 5-4 新卡整組進、秒數（⏳ 格式查核只看第 2 點）

1. **整組進**（`planToday`）：排好順序後，新的目標（`new`、`exam-new`）碰到同組的第一個時，同組其他新的目標緊接在它後面。
2. **秒數**（D-120，`secondsBySubject`）：兩筆都是比較卡的行（都有 `pick`）、又剛好差 1 毫秒時，不算一個間隔，當成同一張卡（`previous` 照常往後）。翻面、打字的行完全不動，所以只有這兩種的紀錄，秒數一定和現在相同。做得到是因為同一張卡的幾行**只讀一次時鐘**：第一行照現有的 `max(now, last + 1)`，後面的行接 `last + 1`（`createLogWriter` 的 `write` 多一個參數，`state` 新增 `answerAll(lines)`，`rate` 與 `change` 用它；一行的卡和現在逐字相同），所以中間卡住也還是連續的。不同的卡至少隔 0.3 秒（`RATE_DELAY`）；時鐘往回撥、或兩台裝置剛好接上時，只是少一個樣本。第一輪的 200 毫秒改掉了：R2-1 重現它會吞掉回看改評分的翻面行，也會被卡住切開。批次欄位仍然不做：這個做法在 R2-1 的兩個案例都和批次 ID 算出一樣的秒數，不多一個欄位（💡 和 Codex 的建議不同，試算在[報告〈Claude 回應（第二輪）〉](<../Claude Codex Discussion/2026-11-05-question-type-seam-format-review.md>)，第三輪再查）。
3. **一張算一次**：同一組裡第一個放進今天的份的目標才占時間；後面同組的不再占，也不受「第一個放不下的和它後面的全部進 more」影響（它們和第一個同一張）。第一個放不下，同組全部進 `more`。放好之後，那張卡的秒數平均分給它的幾個目標（`QueueItem.seconds` 可以有小數），`remainingSeconds` 隨答對遞減，總和不變；入口已經無條件進位（`src/review/entry.ts:30`）。
4. **完成**：照目標算，不改（規畫〈要改的地方〉）：`scopeCount`、`progress`、`todayLeft` 不動，「還剩 N 張」一次少好幾個。

## §6 作答流程（`src/review/pick.ts`）

照示意頁的 `tapKey`、`fill`、`tapRow`、`tapCheck`、`skip`，搬成純程式（時間由 `now` 給）。

| 動作 | 階段 | 結果 |
|---|---|---|
| `key(字)` | 作答 | 目前這格填這個字，游標跳到下一個空格（往後繞一圈）；0.3 秒內同一個字不算（規畫的防連點）；沒有游標時不填 |
| `key(字)` | 再選 | 剛才選的字不能按；這格記下，對的 `near`，錯的 `miss`，跳到下一個要再選的格；沒有了就到結果 |
| `row(i)` | 作答 | 游標移到第 i 格，再點字直接換掉 |
| `row(i)` | 再選 | 只有要再選的格可以點 |
| `skip` | 作答 | 這格記成跳過，畫面顯示「？」（對答案前都能改）；游標同 `key` |
| `skip` | 再選 | 這格 `miss`，同 `key` |
| `check` | 作答 | 有空格：游標跳到第一個空格，不對答案。最後一次填字後 0.35 秒內不算。否則判定：對的 `right`；跳過的 `miss`；其他要再選；沒有要再選的就到結果 |

跳過是流程裡明確的狀態，不比字串：`？` 可以是組員，點了它就是點了它（R2-3）。

`allowed`：只有結果階段、而且每格都 `right` 時是 `['good','easy']`；其他都是空的。`settle(null)`（「下一張」）只在結果階段有錯時算數；`settle('good'|'easy')` 只在全對時算數。兩者都要過 `revealedAt` 的 0.3 秒（進結果階段時設）。「第一次對」與評分的對應只有一份，對照 §4 的表。

組只有兩個選項時，再選只剩一個字，一定選對，照表記 `near`（第一次錯最多到 Again，第二次只分差一點或沒印象，兩者都是 Again，差別是約 10 分鐘或約 1 分鐘後再出；這裡的 `near` 不代表認得，只是唯一剩下的選項；💡 實作者的選擇，見文末）。再選時按「沒印象」仍是 `miss`。同一個字兩格的卡，孩子不能靠「一個字一格」刪去，這是刻意的。

切走超過 60 秒、回來從頭開始：照現有的規則（`src/review/session.ts:501`），包括已經在結果階段還沒按的（D-074 的「已經翻面但還沒按」）；這時什麼都沒寫。

## §7 畫面（`src/ui/PickCard.tsx`、`PickCard.css`）

照示意頁與規畫〈畫面與防點錯〉，CSS 用 `tokens.css` 的變數。拿掉的五樣都維持拿掉（D-179 第 5 點）。要點：

- 每張卡都有的那一行（路徑、「新」）照舊在最上面；標題接在下面：`title`、全形冒號、括號順序的組（「相似字：寨、塞、寒、賽」、「比較：borrow、lend」）；沒有結尾時只列組。同一張卡的幾個字結尾不同時，用選中的那一格。
- 顏色（D-182 第 8 點，示意頁已改）：空格灰色底線，待答的那一格紫色粗線，這一句很淡的底；填進去的字是一般文字的顏色，大小和句子相同，底線回到灰色；對答案後字變色，第一次對綠色、差一點橙色、沒印象紅色，底線照舊灰色；字鍵同樣的框線，剛才選的字變淡。紫色只用在待填空格的底線和翻面對照裡的部件。樣式只寫一份，全詩順序卡之後多一條「填完清除底線」。
- 字鍵：6 個以內排一排，7 個以上排兩排；句子放不下就捲動，字鍵固定在下面（D-182 第 6 點）。要放得下詞（`affect`、`質量`、`make up`）：大小與排法還沒量過，實作時在 375 寬量，結果記回[規畫〈待決〉](../docs/plans/similar-chars.md#待決)。
- 句子用 `Markdown`（粗體、圖照樣，D-089 第 7 條），`mode: 'typed'`、一條線；`Markdown` 新增 `slotNode`，和 `tail` 一樣用 `createPortal` 放進空格，按鈕就是空格本身。
- 對照：每個字一行。第一行是記憶錨點去掉「記憶錨點：」、去掉最後一個全形冒號之後的部分（`Markdown`，粗體是紫色），第二行是常用詞（冒號後面；沒有冒號就沒有這行）；右邊是這張卡的結果，這次沒出句子的字沒有。
- 字鍵與兩個動作放在 `.ec-actions`（底部），結果階段換成評分或「下一張」。不用 hook：飛過去的動畫用 `event.currentTarget` 與 `querySelector`，尊重 `prefers-reduced-motion`。
- 鍵盤：結果階段的 3、4 照舊評分；Space、Enter 是「對答案」與「下一張」。字鍵用滑鼠點或 Tab，不加數字鍵（D-179，主要在 iPhone）。
- 手勢、旗子、✕、回看的按鈕照舊。旗子交出去的是選中的那一格（`card.lt`）。

## §8 回看與復原

一張卡一筆（D-084「回看這一次做過的每一張」），不是一個字一筆。回看顯示結果階段的畫面，字鍵不出現。

規畫〈待決〉：**回看時能不能改比較卡的結果**。💡 先照 Claude 的建議做，使用者 2026-11-05 問過還沒選，不算確認：孩子自己選的才能改，程式判的不能改，所以全對的可以在記住了、太簡單之間改，有錯的不能改。要換成別的做法只改 `pick.ts` 的 `changeable` 一處。

改評分時（D-074）：只動這張卡當時實際寫進去的行（`written`），當時沒寫進去的目標不補。每一行先 `undo`，再用 `answerAll` 寫新的行（`also` 跟著重寫），一起寫或一起不寫：先問過每一行的取消與新的作答都不會被拒（`state` 新增 `permits(entry)`，把現有的內部函式公開），有一行不行就都不寫。這裡的「一起」是不會被拒，不是磁碟上的原子寫入：背景照現有的 writer 逐行追加，失敗留在佇列重試（`src/core/study/log.ts:26`）。`undo` 只靠 `t`，兩台裝置恰好同一毫秒時會一起取消，是現有的限制，比較卡不另外處理。

改評分的取捨（R2-3）：重寫的行帶新的 `t`，所以那一句「最後出的時間」變成改的時間，次數不變（`AB@1, CA@2, BC@3` 之後 `undo AB@1` 再寫 `AB@4`，下一對由 AB 變成 CA）。可以接受：改評分很少，差別只是輪替的順序；要保留真實的出題時間得多一個欄位，不值得。

ID 變成重複（D-157）：目前這張牽涉的任何一個目標衝突，整張丟掉重新取卡，什麼都不寫；回看裡牽涉衝突的卡不能改。停用（`canAnswer`）同樣看每一個目標。

## §9 預覽（D-161）

- 一組一張「第一次」的卡（每個字第一句加多放的一句），剩下的句子各一張（一格，字鍵照樣整組；兩個選項的組也一樣，預覽要的是每一句都看得到）。每一句都看得到一次，孩子實際會看到的兩種樣子也都有。
- 作答與複習同一個流程；評分與「下一張」只換下一張，不寫。
- 「預覽時自動展開答案」：直接到結果階段，空格是答案，沒有對錯記號與結果。

**紀錄**：§4 表的每一列；比較卡的行用舊版 `parseLine` 讀得懂；欄位順序 `pick`、`retry`、`also`；第一次按沒印象是 `pick: null` 沒有 `retry`，最上層與 `also` 各一次；`？（？、！） 比較` 點了 `？` 是 `pick: "？"`、照一般字鍵判定，和沒印象分得開；同一個字兩格一行、最差的在最上層、另一格在 `also`；`also` 形狀不對當沒有；一張卡的幾行 `t` 連續，寫第一行後時鐘跳 250 毫秒也一樣，時鐘倒退時照樣遞增；`sameReview`：逐字相同的副本算一筆，`also` 不同算兩筆，讀檔順序不影響；第一行已落盤、第二行暫時失敗後重試，重開重併的行與結果固定；重新 `mergeHistory` 與 `appendLine` 結果相同；既有的翻面、打字行逐字不變。

## 實作者自己選的做法（L2 請先看）

規格沒寫、由 Claude 決定的：

1. 判斷的順序與 `pick-mixed`、`pick-not-recognized` 兩種提示（§3，D-182 第 4 點說邊界由格式查核定，表的主體來自 Codex F2）：答案是組裡別的字才算寫錯、跳過；題目不符的照原題型，有提示。
2. 多放一句的條件放寬到「格數等於字鍵數」（§5-2）：使用者 2026-11-05 同意（D-191 第 2 點），留在這裡只是記得來源。
3. 句子順序也打散（規畫只寫字鍵，§5-3）：免得第一句永遠是第一個字。
4. 打散用指紋算，不用亂數（§5-3）。
5. 同一張卡的判斷靠「都有 `pick`、差 1 毫秒」加「一張卡只讀一次時鐘」，不加批次欄位（§5-4）：和 Codex F5、R2-1 的建議不同，理由與試算在報告。
6. 一張卡的秒數平均分給幾個目標（§5-4）。
7. `pick` 每一行都寫，對的也寫（§4）：有沒有這個欄位就分得出比較卡和翻面的紀錄，所以也不用為了辨認來源加欄位。第一次按沒印象的 `null` 是 Codex R2-3 指出 `？` 會和組員衝突後改的。
8. 預覽的組法（§9）。
9. 沒有分隔符號不切字，不靠結尾認（§3）：另一條路是只在結尾是相似字時容忍，和 D-182 第 4 點「結尾打錯也不會壞」相反。Codex 同意；漏寫分隔的靠 `pick-not-recognized` 與 `check-syntax`。
10. 中翻英、英翻中優先於括號，全形空白也算方向（§3）：放寬現有解析，不加保護，因為錯誤和半形空白相同，看得到。
11. 同一個字兩格，其他格記在 `also`（§4）：這裡原本不加欄位，Codex F4 指出後改了；平手「次數少的先」（§5-2）是核對時補的，只有 `also` 輪不開。
12. 兩個選項的組，字鍵順序不強制和括號不同（§5-3）；再選只剩一個字時照舊記 `near`（§6）。
13. 翻面對照不放小燈泡（§7）：D-184 說的是一般卡的背面，對照的每一行都是記憶錨點，沒有要分開的東西。
14. 有頓號或逗號時，空白兩邊都是漢字才分隔，碰到英文或數字的不切；空的項目丟掉（§3）：Codex R2-2 建議有頓號時空白一律不切。差別在 `寨（寨、塞、寒 賽）`：這裡當打字雜訊容忍，限制是 `特 殊 型` 會被切開，理由與對照在報告。
15. `需要版本` 的寫入細節（§3）：使用者定的是結果（D-191 第 1 點）；版號在合併時升、和補 ID 同一條路、只加不拿掉、讀寫同一版發布都是提案。
16. 畫面找不到空格時，空格放在句尾（§3）：解析和畫面不可能每種寫法都相同，保底比補更多規則便宜。
17. 有組但沒有比較句、又沒有提示用的結尾時不出提示（§3）：看不出想做比較卡。
