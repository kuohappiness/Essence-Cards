## 和「不做」比較（D-153）

- **不做會怎樣**：更新之外的資料損失沒有保護。開發期間的更新有更新命令先備份，但其他外掛或 AI 直接改壞卡組、整個資料夾被誤刪超過 iCloud 的保留期、iCloud 衝突蓋掉內容，都沒有可以回去的那一份；Obsidian 的「檔案復原」只留各篇筆記最近幾天的編輯。還原現在只有命令列工具，一般使用者用不了（產品原則 5，使用者 2026-10-26：一般使用者不會 Git 和命令列）。給其他家庭時更是只能靠外掛自己。
- **做的代價**：第一次寫 D-148 的電腦專用資料夾與它的三道防線、`Files` 多一個讀原始位元組的方法、外掛的第一個設定分頁、`state` 多一個寫入閘門的原因、還原畫面；之後要維護的是一套和更新命令共用的備份程式。使用者要學的只有設定頁那一列。
- **更小的做法**：
  - 排除 Capture 教材（D-150 第 4 點）先不做：現在 vault 裡沒有 Capture 寫的教材與圖片，排除省不到空間，卻要做全 vault 的引用查核。照「不確定就備份」全部備份；觸發點寫進 backlog（見〈這次不做〉）。
  - 入口畫面的「給家長」一區還沒做：失敗時先用 Obsidian 的通知與設定頁那一列，入口做好再搬過去。
  - 還原畫面（第二部分）晚一點做：使用者 2026-10-29 選放到 v1 結案前；在那之前由維護的 AI 用更新防線的還原工具代做。

## 1. 第一部分：外掛內的備份

### 1-1 主機接點（D-148 第一次實作）

- 照 D-148 開電腦專用的資料夾（例如 `src/desktop/`）：`main.ts` 在 `Platform.isDesktopApp` 成立後才動態 import，不經共用的重新匯出檔；載入時沒有副作用；外掛卸載時取消進行中的備份。
- 對外只給具體的動作，不交出 `fs`。至少：
  - **位置**：預設位置（同 §8 與 `tools/vault-io.ts` 的 `defaultBackupFolder`）、檢查一個位置（實際路徑、在不在 vault 裡、是否被 MSIX 導走，同 `virtualizedReason`）。
  - **寫一份備份**：給 zip 的位元組與檔名，用暫存名寫完、讀回比雜湊、不覆寫地提交成正式檔名（§1-8 的第 1 列）。
  - **列出備份**：只回傳格式與清單都檢查過的（syntax §8「讀備份的一方」），附各自的時間、`build`、`by`、vault。
  - **讀一份備份**（第二部分用）、**刪一份舊備份**（只給清理用，條件見 §1-7）。
  - **打開備份資料夾**（系統的檔案總管）與**選資料夾**。
- 共用的檢查放在 `tools/vault-io.ts` 與這個資料夾都能用的地方，不要寫兩份；Node 版的工具測試照舊通過。
- **選資料夾**先在 Windows 的 Obsidian 實測：Electron 的資料夾對話框叫不叫得到、怎麼叫。叫不到就改成一個文字欄位貼路徑，按下「使用這個位置」時照上面的檢查；兩種都把實測結果寫進回報。

### 1-2 讀原始位元組

- `Files` 加一個讀原始位元組的方法：不存在是 `null`，讀不到（權限、iCloud 雲端佔位檔）丟錯並保留原因（D-154）。Obsidian 版與 Node 版都實作，契約檢查（`src/dev/files-contract.ts`、對應的測試）加上這一項。
- Obsidian 的檔案索引不含設定資料夾，`data.json` 改用 `app.vault.configDir` 加 adapter 讀；包在同一個小介面裡，不讓備份程序直接碰 adapter。
- 先在 Windows 實測 `Files.list('Essence Cards')` 和磁碟上的檔案是否一致（`.jsonl`、圖片、剛同步來還沒被索引的新檔）。不一致時停下來回報，不要另開一條用 Node 讀 vault 的路。

### 1-3 備份程序搬進核心

- 把 `tools/backup.ts` 裡和平台無關的部分搬進 `src/core/backup/`：讀兩次比對（集合、雜湊、紀錄只多了後面的行）、最多 3 次、`notes`、清單、zip、讀回檢查、用 `parseDeck` 比學習目標 ID 與題目指紋。讀檔與寫檔由呼叫的一方傳進來。
- `tools/backup.ts` 改用它，**行為與既有測試都不變**；外掛用同一份。
- 範圍照 §8：`Essence Cards/` 全部加 `data.json`，`excluded` 是空的（見〈和「不做」比較〉）。

### 1-4 什麼時候備份，與寫入的閘門

- **新版第一次**：電腦上，localStorage 記的「上次成功備份」（建置版本、時間、檔名、雜湊、位置）和現在的 `BUILD` 不同、或沒有、或對不到備份資料夾裡一份存在且檢查過的檔，就在 `state` 讀完之後馬上備份（`by: new-version`）。在那之前與失敗期間，`state` 的寫入閘門 `writable` 多一個原因（例如 `backup`）：存檔按鈕、離開時補 ID、還原與當成新的待處理、之後的採用草稿都經過它。紀錄的追加照常，學生照常複習。
- **每月**：距離上次成功備份超過 30 天就做一次（`by: monthly`）。外掛載入時看一次，開著時每 6 小時看一次（`registerInterval`）；文案不承諾「固定每月幾號」。
- **手動**：設定頁的「立即備份」（`by: manual`）。
- 同一時間只跑一份；第二個要求等前一份做完，拿同一個結果：前一份成功就不重做，失敗就是失敗，不當成功。同時符合新版與每月時記 `new-version`。
- 「對得到」是：記的那份還在、整份通過 syntax §8 的檢查、雜湊和記的相同、`vault` 是這個 vault；任何一項不成立都當成沒有成功的備份。
- localStorage 用這個 vault 專用的（同 `device.ts`），不放 `data.json`（D-149 第 7 點）。被清掉時當成沒有備份，重新做一份，不推定成功。
- iPhone 什麼都不做。

### 1-5 設定頁（外掛的第一個設定分頁）

- 照 D-104 用 Obsidian 內建的設定分頁，這次只放「備份」一區（依功能分區、不寫「給家長」，[D-156](../docs/decisions.md#d-156-設定頁依功能分區不寫給家長)），其他區（複習、學期、AI 製卡）之後的任務再加；照環節 5 的結論寫成 `wireX(host)`，`main.ts` 只組合。
- 電腦版這一列有：
  - 備份位置（顯示實際路徑）、「變更…」（§1-1 的選資料夾）、「用預設位置」。
  - 位置下面只放一行短說明：「預設存在這台電腦，外掛不會上傳。」旁邊一個 ⓘ（和 D-104 的目標保持率一樣），點開才看到三點：
    - 不能選 vault 裡面或連到 vault 的資料夾（備份會被當成卡組讀進來）。
    - 選有雲端同步的資料夾，備份會跟著上傳。
    - 選外接硬碟時，沒接上的那次備份會失敗；成功之前先暫停修改卡組。
  - 使用者 2026-10-29：原本整段放在位置下面太長，設定頁要顧到美觀，所以改成一行加 ⓘ（使用者 2026-10-29 要求的「在設定頁說明不能指定的位置」由 ⓘ 與選錯時當場的說明一起做到）。文字照上面，版面在 §1-10 截圖給使用者看過再定。
  - 上次備份：時間與結果；失敗時寫是哪一步、哪個檔（D-154 的說法，例如「讀不到 `Essence Cards/…`：檔案只在 iCloud 雲端」）。
  - 「立即備份」「打開備份資料夾」；第二部分加「還原…」。
- iPhone 上這一列只寫一行：「備份在電腦上做」。
- 選了不能用的位置：當場說明原因，不換位置。

### 1-6 失敗時

- 寫入閘門保持關著，直到有一份成功的備份（D-150 第 3 點）。
- 通知：每次失敗跳一次 Obsidian 通知（「Essence Cards：備份失敗，暫停修改卡組；複習照常。到設定頁看原因」，不寫角色，D-156），同一個原因這次載入只跳一次；入口的「給家長」一區做好後搬過去。
- 存檔按鈕：受阻原因是備份時，說明寫「筆記已自動儲存；備份還沒成功，先不把新目標加入複習，到設定頁看原因」（`TIPS` 多一條）。這是 backlog「存檔按鈕的受阻原因各自判斷」那一列的第三個原因，照那一列的完成條件決定要不要讓 `deckStatus` 帶一份原因的快照。
- 失敗不刪任何既有的備份。

### 1-7 保留與清理

Codex 格式查核（[討論稿](<../Claude Codex Discussion/2026-10-28-updates-and-compatibility.md>)〈Codex 格式查核：外掛內備份〉BF1～BF3、BR1～BR3）之後的寫法：

- 只在新備份成功（讀回檢查、用正式檔名提交）之後清理。
- **候選**：照 syntax §8「自動清理只認完整的備份」，而且 `vault` 是這個 vault（syntax §8 `vault` 那一列：名稱與實際路徑；`config` 不同仍算同一個，同名不同路徑不算）。更新命令放在同一個資料夾的備份一起算；手動搬回來、符合這些條件的舊備份也一樣參與，清單分不出是不是手動搬的（D-150 第 6 點只承諾不動「不是這個格式、別的 vault、不在備份位置」的檔）。不是候選的一律不動。
- **保留**：候選照 `started` 換成的絕對時間排序（同一毫秒再照檔名的字元碼），留最新 10 份、每個月最後一份（月份是各份 `started` 自己記的當地 `YYYY-MM`）、這次成功的那一份，三者取聯集；其他刪掉。這次那份一定留，時鐘倒退或資料夾裡有未來時間的備份時，才不會刪掉剛做好的、讓下次又重做。
- **刪之前再確認**：資料夾的實際路徑沒變、還是一般檔、大小與雜湊還是剛才驗過的；對不上就跳過。
- **刪不掉**：備份本身已成功，閘門照開、成功紀錄照存；記下清理沒做完與路徑，下次成功備份後再試。
- **`.zip.tmp`**：只收掉這次自己建立、身分還相同的暫存檔；之前留下的（寫到一半 Obsidian 被關掉）不列出、不算成功、不計數、不刪，也不擋新的備份。
- 換過位置時，舊位置的備份不動、不搬。

### 1-8 這次一起完成的技術債

backlog 技術債裡這四列的觸發點到了，照各自的完成條件做，做完刪掉那一列（commit 寫在 roadmap 的已完成）：

1. 「備份與還原只考慮一個程序在跑」：外掛的每月備份可能和更新命令同時跑。正式檔名改成獨占的提交（不覆寫）。
2. 「讀備份時，zip 的註解裡剛好有 EOCD 簽章」：觸發點是外掛內的備份交付前。
3. 「存檔按鈕的受阻原因各自判斷」：見 §1-6。
4. 「D-148 的檢查會漏掉別的 `require` 寫法」：ESLint 擋到整個 `src/`（含別名、成員與字串索引存取），開發命令用 Electron 有明確的放法；建置用 metafile 查每個外部模組是哪個檔引入的；用 `isDesktopApp=false`、碰到 Node／Electron 就丟錯的替身載入正式的 `main.js`，確認沒載入電腦專用的資料夾。

### 1-9 第一部分的測試

- 核心：搬過來的程序和 `tools/backup.ts` 原本的測試照舊通過；外掛那條路也跑同一組情境（同長度改字、中途多檔少檔、紀錄多一行、讀不到、語法問題記在 `notes`、讀回雜湊）。
- 閘門：沒有成功的備份之前，存檔、離開時補 ID、待處理的兩個選項都回 `blocked`（原因是備份）；作答照常寫；備份成功後恢復；失敗後再成功也恢復。
- 時機：新的 `BUILD`、localStorage 被清掉、記的檔不見了或雜湊不符都會備份（`new-version`）；同一個 `BUILD` 重開、30 天內不再備份；恰好 30 天不做、超過才補做（`monthly`）；兩個同時符合記 `new-version`；同時兩個要求只做一份，等著的遇到前一份失敗不當成功。
- 清理：10 份加每月最後一份的邊界（跨月的 `started`／`finished`、不同時區的先後、同一毫秒）；較新的壞 zip 不擠掉舊的好備份；別的 vault、同名不同路徑、壞掉的、檔名和清單對不上的、子資料夾裡的、連結、`.zip.tmp`（寫到一半、完整的、別的程序正在寫的）都不刪；同路徑不同 `config` 合在一起算；時鐘倒退時這次的那份不被刪；刪舊檔失敗時成功紀錄照存；新備份失敗時不清理。
- 位置：vault 裡、連到 vault 的連結、MSIX 導走的都被拒，原因寫得出來。
- 手機：替身載入正式的 `main.js` 時沒有載入電腦專用的資料夾，也沒有建立任何備份的計時器。
- 既有測試照舊通過。

### 1-10 Windows 實機（AI 用開發版在測試 vault 做）

設定頁「備份」一列的截圖（含 ⓘ 點開、選錯位置時的說明、失敗時），**交使用者看過版面**；選資料夾與打開資料夾；外接硬碟（或一個暫時拔掉的位置）讀不到時的失敗、通知、存檔按鈕的說明，接回來按「立即備份」後恢復；把一篇卡組設成雲端佔位檔時的失敗原因；重開 Obsidian 不重做；改系統時間或替身時鐘驗每月。結果寫進回報。iPhone 這次沒有要驗的。

## 2. 第二部分：還原畫面（D-150 第 7、8 點）

只在電腦。設定頁「還原…」打開一個視窗：

1. 列出備份資料夾裡讀得懂的備份（新的在上，時間、建置版本、做的原因）。
2. 選一份 → 用 `planRestore` 算計畫：和現在不同的檔（改過、不見；備份後才有的列出但不動）、擋住的與原因（ID 會重複、相依沒滿足、位置確定不了）、要補的紀錄行數。
3. 每個檔可以點開看文字差異（`tools/restore.ts` 的 `textDiff` 搬到兩邊共用的地方，不另寫一份；圖片只列大小與雜湊）；勾選要還原的。
4. 按「還原」：先做一份備份（`by: restore`）；寫入期間 `state` 的閘門關著，取消那些檔的離開時補 ID；每個檔寫之前重新確認還是計畫裡的那一份；紀錄照 syntax §5-3 寫還原檔；寫回 vault 經 `Files`，不用 Node。
5. 寫完明確重讀（不能只等檔案通知，`state` 會略過自己紀錄檔的通知）、重排、讓開著的複習畫面失效；列出每個檔的結果（已還原、跳過、擋住、失敗）。再開一次視窗重新比對就是續做。

測試：更新防線 §1-6 的還原情境（C4 的兩個反例、衝突副本、演練、中途失敗後續做、ID 重複擋住、計畫後被改過的跳過）都在外掛這條路上再跑一次；加上「還原時那篇開在編輯器裡」「還原中途關掉外掛」。Windows 實機：在測試 vault 演練一次完整的還原。
