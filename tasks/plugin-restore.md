## 和「不做」比較（D-153、D-177）

- **不做會怎樣**：備份做得出來，卻只有維護的 AI 用命令列還得回去（`tools/restore.ts`，還要先關 Obsidian）。卡組被改壞、被誤刪超過 iCloud 的保留期時，一般家長拿著一堆 zip 也回不去；自己解壓縮蓋回去更糟，舊的紀錄檔會蓋掉之後的作答（D-150 的理由）。這個外掛之後要給別的家長用，他們沒有維護的 AI。
- **做的代價**：`Files` 多一個方法、`state` 多一段獨占的時段、一個視窗、一個開發命令，還有一輪高風險的 L2。學生的畫面不變，設定頁多一列；平常不打擾。
- **更小的做法**：
  - 只放「打開備份資料夾」，說明書教解壓縮：就是上面會蓋掉作答的做法，不採用。
  - 不看差異、不逐檔、一鍵回到某一天：D-150 第 7 點明定不做。一份舊備份和現在通常差很多篇，一鍵會把這段時間的編輯全部蓋掉。
  - 先不還原 `data.json`：只差五個值，最壞重選一次（D-150 第 2 點的補充也這樣看）。但 `planRestore` 已經算好它，要特別擋住反而多寫一段；它壞掉時還原是唯一不用手改檔的救法。程式只多一個小函式，一起做。
  - 開著的筆記直接擋住、請家長自己關：程式少一點，但家長要離開視窗、關分頁、重新選一次，正好是最常見的情況（剛發現筆記壞了，它就開著）。見〈小選擇〉第 1 項。

**第 1 類（合併前做足）**：計畫算對（改過、不見、備份後才有、擋住）；還原前一定有現況備份；被蓋掉的內容一定在那份備份裡；計畫之後才改的不蓋掉；ID 不重複；紀錄只補不刪，只建新檔、不碰任何裝置自己的紀錄檔；中途失敗或外掛停用之後重新比對就是續做，不重複補行；還原後排程、紀錄重播和那些檔本來就在時相同；不把還原當成「弄丟 ID」；`data.json` 寫前重讀、保留不認得的欄位；需要新版的卡組不寫；§3 的交錯測試。

**第 2 類（可以延後）**：

- Mac 與 Linux 的檔名規則實測：那兩個平台先關住入口（〈小選擇〉第 2 項），不會走到沒驗過的路徑，所以不算開放了卻沒測。技術債那一列留著。
- 還原之後 iPhone 看到還原的卡組與還原檔：寫成「補測：」一列，併進第 ③ 項的 iPhone 實機測試。出錯時不會壞資料：還原檔的格式 iPhone 現在就讀得懂（`tools/restore.ts` 用的同一種），電腦上再比對一次就知道狀況。
- 幾百個差異檔時的版面：先照一般長度做（可捲動）。資料沒有風險。

## 和舊的第二部分比，改了什麼

舊稿寫在 2026-10 底，之後多了設定頁、AI 輸出快照、考試切面與 D-162。

| 舊稿 | 現在 |
|---|---|
| 「每個檔可以勾選」 | 只有卡組與 `Essence Cards/` 裡其他一般的檔能勾。`紀錄/` 裡不是複習 JSONL 的檔（AI 輸出快照、原文、考試切面）照 §5-4、§6 不和卡組一起勾：不見的一律補回，同名不同內容列成衝突不動。舊稿沒分，`planRestore` 也還把它們當可選 |
| 寫回都經 `Files` | `Files.modify` 是文字，圖片與 BOM、壞掉的編碼會變；要加寫原始位元組的方法（§3-3）。`data.json` 不在 `Files` 裡，經設定的隊伍（§4） |
| `data.json` 當普通檔整份蓋 | 現在有真實的值、會跟著同步：寫前重讀，只換認得的欄位，不認得的保留（D-149 第 7 點），差異用人看得懂的欄位列出 |
| 「先做一份備份」 | runner 的 `by` 沒有 `restore`，正在跑別份時會共用那一份；要加，而且不共用。清理不能刪掉正在用的那一份（D-162 之後更新命令的備份也在同一個資料夾，一起算保留的 10 份） |
| 「閘門關著」 | 還要涵蓋範圍檔、小考檔、AI 製卡、考試切面的寫入與開著的編輯器（§3-2） |
| 「取消那些檔的離開時補 ID」 | 閘門關著時補 ID 本來就回 false，不用另外取消；換成空白分頁觸發的「離開」也擋在閘門（§3-2） |
| 「讓開著的複習畫面失效」 | 複習與入口在開始時直接關掉（§5）。複習畫面的 `onChange` 只在 ID 重複時換卡，靠它不會失效 |

| D-150 第 7 點的「相依（例如設定指到的自訂規則）」 | 自訂規則還沒做。現在的相依只有 ID 要先釋放（`after`）；自訂規則開工時要加，寫進那份任務說明 |

## 小選擇（2026-11-10 使用者同意）

1. **開著的筆記**：要還原的那幾篇如果開著，按下「還原」時先存檔、暫時換成空白分頁，寫完開回原本的分頁。不採用「讓編輯器自己跟上檔案的變動」：還沒存的內容可能在幾秒後蓋掉還原的內容，編輯器的 ID 鎖定也可能把還原造成的差異當成家長刪掉目標。
2. **Mac 與 Linux 先關住**：設定頁那一列寫「還原目前只在 Windows 驗過」，按鈕不開放。那一列的技術債要在那些平台實測才算完成，現在沒有機器；關住只要一行判斷。給 Mac 的家長用之前要先做。
3. **預設一個都不勾**，另有「全選」：一份舊備份和現在通常差很多篇，大多是之後正常的編輯，預設全勾時多按一下就全部蓋掉。

## 1. 畫面

設定頁「備份」一區多一列「還原」，右邊一顆「還原…」（D-156）；iPhone 沒有這一列。打開 Obsidian 的 Modal，三步，都在同一個視窗；介面只放必要的東西，版面在 §8 截圖給使用者看過再定。

**選一份備份**：新的在上，一列一份：當地時間、做的原因（新版第一次、每月、手動、還原前、更新前、手動工具）、建置版本。名稱或路徑不是這個 vault 的標「別的 vault：<名稱>」，仍可選（搬過 vault 是合理的情況，ID 檢查照樣擋）。讀不懂的備份不列，最下面一行寫「有 N 份讀不懂，沒有列出」。

**看差異、勾選**：
- 可以還原：一列一個檔，勾選框、短路徑、「改過」或「不見了」、增減行數；點開看文字差異（前後各 2 行）；不是文字的只寫兩邊的大小。預設不勾，有「全選」。
- `data.json` 排在最前，名稱是「設定」，差異用欄位列出（每日時間上限 30 分鐘 → 45 分鐘）；五個欄位都相同的不列。
- 擋住：列出檔名與原因，不能勾（例：「學習目標 ID k3m9x2 現在在「國二上自然 2-1」」）。每次勾選都重算，勾掉別篇造成的擋住馬上看到。
- 紀錄一行：「複習紀錄會補回 N 行；AI 輸出與考試切面補回 M 個不見的檔（不用勾選，只補不刪）」；有衝突的再一行列出，不動。
- 備份後才有的：一行「有 K 篇是備份之後才有的，不會動」，點開看名單。
- 底下一顆「還原 N 篇」與一行「還原前會先備份現況」。沒有勾、也沒有紀錄要補時不能按。

**結果**：每個檔的結果（已還原、跳過、擋住、失敗）與原因、補了幾行、還原前那份備份的檔名；一顆「重新比對」回到同一份備份的第二步，這就是續做。過程中寫「正在還原…」，不能按關閉以外的東西；關掉視窗不中斷。

## 2. 計畫（`src/core/backup/plan.ts`，不寫任何檔）

沿用 `planRestore`，補上：

- 平台才知道的擋住原因由呼叫的一方算好傳進來（一個回傳原因的函式）：以點開頭的檔（外掛讀不到現況）、路徑上有連結（`assertNoLinks` 從 `tools/vault-io.ts` 搬到 `src/desktop/io.ts`，工具改 import）、系統資料夾不在原位（`displaced`）。
- 卡組的備份版或現在版的 `需要版本` 這一版讀不懂：擋住，寫「需要新版」（D-149 第 3 點：Cards 不寫它）。
- 勾選的集合由畫面給，`紀錄/` 裡不是複習 JSONL、狀態是 `missing` 的一律算進去（syntax §5-4、§6）。
- `data.json` 比欄位：五個欄位都相同的當成相同。
- `tools/restore.ts` 的 `textDiff` 搬到 `src/core/backup/diff.ts`，工具改 import，不留兩份。

現況用 `filesReader` 讀原始位元組（和備份同一條路）。讀不到任何一個檔就不出計畫，照 D-154 寫是哪個檔、什麼原因：讀不到的檔可能占著 ID，也可能讓紀錄重複補。

## 3. 寫入協調與再確認（`src/core/backup/restore.ts` 加 `state` 的獨占時段）

### 3-1 順序

1. 關閘門、等隊伍（3-2）。
2. 開著的那幾篇先存檔、換成空白分頁（〈小選擇〉第 1 項）。
3. 先備份現況，`by: restore`：runner 正在做別份就等它做完再另做一份（不共用，那份可能早於閘門關上）。失敗就什麼都不寫，寫明是哪一步。這次的清理不刪正在用的那一份備份（`staleBackups` 的 `keep` 改成集合）。
4. 用記憶體裡這份備份和重新讀的現況再算一次計畫：畫面上勾選的檔，sha 和畫面當時不同的跳過（「比對之後改過，重新比對看新的差異」）；要蓋掉的內容，sha 必須和第 3 步那份備份的清單相同，否則也跳過。
5. 照計畫的 `order` 寫檔（3-3），再寫還原檔（3-4），再寫 `data.json`（§4）。
6. 明確重讀（§5），開回分頁，放開閘門；不論成敗，閘門在 `finally` 放開。外掛停用時停在下一個檔之前。

### 3-2 誰會同時寫、怎麼協調（技術債「還原只考慮一個程序在跑」要的契約）

| 寫的一方 | 協調方式 |
|---|---|
| 存檔按鈕、待處理的選項、離開時補 ID、暫停與恢復、啟用草稿、AI 製卡 | 同一列寫入（`writes.enqueue`）：還原排進去之前先把 `blockedNow` 設成新原因 `restore`，正在跑的那一份做完，還沒開始的輪到時回受阻。存檔按鈕加一句說明，AI 製卡的 `BLOCKED` 表跟著加 |
| 範圍檔、小考檔 | 它們的隊伍排在還原後面；輪到時照舊核對畫面打開的那一份（`changed`） |
| 作答、版本行、設定變更行 | 照常，學生不受影響：只追加自己的月檔，還原不碰任何裝置自己的紀錄檔 |
| 考試切面 | 兩邊都只建立，同名不動 |
| 設定頁 | `SettingsStore` 同一條隊伍（§4） |
| 開著的編輯器 | 先存、換成空白分頁；之後寫不到磁碟。開著時的未存內容存下來之後 sha 不同，照第 4 步跳過，不蓋掉 |
| 備份 runner | 3-1 第 3 步 |
| 系統資料夾的防呆 | `Files` 的 `pause` 照舊；不在原位的先擋住 |
| iCloud、別的編輯器、別的外掛 | 控制不了，見下 |

**不受控制的程序的處理前提**：還原是偵測、不是鎖定。每個檔在寫之前的最後一步才重新讀、比 sha，只有這一步和寫入之間有空檔（一次讀到一次寫，毫秒等級）。在空檔之外到的修改都不會被蓋掉；剛好落在空檔裡的修改會被蓋掉，而且看不出來。這和現在外掛補 ID 面對 iCloud 的情況相同，不再加鎖，也加不了。iPhone 不寫卡組（D-134）；會同時改卡組的只有另一台電腦。iCloud 事後產生的衝突副本照 D-157 當成重複 ID 處理，下次比對也看得到。

### 3-3 寫一個檔

依序，任何一步不成立就照表記結果、不寫：

1. `after` 列的檔都寫成了（否則跳過）。
2. 卡組：重新讀現在全部的卡組，這篇要加回的 ID 不在別篇（`deckIds`；讀不到別篇也算確定不了，跳過）。
3. 路徑上沒有連結（經 `src/desktop` 的一個具體動作，D-148）。
4. `Files` 新方法 `replace(path, check, bytes)`：和 `modify`、`append` 同一個同路徑隊伍；讀現在的原始位元組交給 `check`，不通過回 `false` 不寫；檔案不存在時建立含上層資料夾；原樣寫入位元組，不轉編碼與換行。Obsidian 版用 `readBinary` 加 `modifyBinary`／`createBinary`；Node 版同一份契約（`src/dev/files-contract.ts`）。
5. 讀回比 sha，不同算失敗。
6. 卡組走 `writes` 的 `begin`、`end` 與核對讀取：確認寫成後 `tracker.wrote`，所以舊版本有、備份沒有的 ID 不算弄丟，不會多跳待處理的問題。

沒有暫存檔：寫到一半失敗時，現況在第 3 步的備份裡，重新比對就看得到，同一條路再還原。

### 3-4 還原檔

照 syntax §5-3，用 `restoreLogName` 和這台的裝置碼；用 `replace` 的「現在必須不存在」建立，已存在就換下一個編號。一次寫完、讀回比 sha。

## 4. `data.json`

- `SettingsStore` 加 `restore`，走同一條隊伍：寫前重讀，以讀到的內容為底，五個欄位換成備份的值（備份沒有的欄位就拿掉，回到預設），不認得的欄位保留，只有 `saveData` 這一條寫入路徑。
- 重讀的內容和計畫當時不同就跳過，同 §3-1 第 4 步。備份裡的 `data.json` 讀不懂時擋住；現在的讀不懂（不是合法的 JSON 物件）時以空的當底，這正是還原最有用的時候。
- 寫成之後 store 會讀回、通知 `applySettings`，`set:` 紀錄行照 record-gaps 的偵測自己寫，這裡不另外寫。
- 這個檔跟著 iCloud，別的裝置之後也會換成還原的值；設定那一列寫一句。

## 5. 重讀與舊畫面

- 寫過的卡組、紀錄、範圍檔、小考檔都明確排重讀並等讀完（`reads.reread` 與範圍檔那邊對應的入口），不靠 Obsidian 的檔案通知。重讀之後重排、通知一次。
- 開始時關掉開著的複習畫面與入口（什麼都不寫，D-074）；還原期間不開新的，提示「正在還原」。

## 6. 失敗時

D-154：寫清楚哪一步、哪個檔。步驟：讀備份、讀 vault、先備份現況、寫 `<檔名>`、補紀錄、寫設定。一個檔失敗不停止其他沒有相依的檔。記進錯誤紀錄（syntax §9 多一個 `where: "restore"`，`msg` 是步驟與原因）。失敗的備份照舊讓閘門關著，直到有一份成功（D-150 第 3 點）。

## 7. 測試

都在外掛這條路上跑（記憶體 `Files` 或暫存資料夾），不碰真的 vault。

**更新防線 §1-6 的情境再跑一次**：C4 兩個反例（同一刻的作答補成還原檔後到期相同；壞行救回 `seen`）；衝突副本、還原檔、來源檔的排序；演練（備份 → 新作答與 `undo`、搬目標、改字 → 還原 → 原有紀錄一行不少、選的內容正確、全庫 ID 不重複 → 再比對沒有要補的）；中途失敗後續做；ID 重複擋住；計畫後改過的跳過。

**新的第 1 類**：

- 交錯：替身 `Files` 在每個等待點插入修改：計畫之後、備份之後、掃描之後、最後確認之前，都不蓋掉、不造成重複 ID；`after` 的前一個沒寫成，後面的不寫；排隊中的存檔、補 ID、AI 建檔、設定範圍回受阻或排在後面；閘門不論成敗都放開。
- 還原前的備份：失敗時一個檔都不寫；runner 正在跑時另做一份；清理不刪正在用的那一份；被蓋掉的內容在那份備份裡。
- 原始位元組：圖片、BOM、CRLF、不合法的 UTF-8 逐位元相同。
- `state`：還原後不多出待處理的問題；舊版本有的 ID 之後再出現不算沒見過；開著時讀到還原檔，歷史、到期和紀錄本來就在時相同（共用 §5-3 的口徑）；需要新版的擋住。
- 只補不見的：快照、原文、考試切面不見會補、同名不同內容衝突不動；錯誤紀錄不列。
- `data.json`：保留不認得的欄位；寫前重讀看到別台剛改的跳過；備份讀不懂擋住；現在的讀不懂能救回；設定立刻生效，紀錄行由偵測寫一次。
- 還原中途外掛停用：停在下一個檔之前，重新載入後比對能續做。
- 冪等：同一份備份連做兩次，第二次沒有要寫的、沒有多的還原檔。
- 手機：替身載入正式的 `main.js` 時不載入還原的程式（現有的 D-148 檢查加這個檔）。
- Mac 與 Linux 入口關住（替身平台）。

## 8. Windows 實機（AI 用開發版在測試 vault 做）

**§8 第 1 點，API 實測**（Windows、Obsidian 1.15.0）：

- `createBinary`、`modifyBinary` 對 BOM 加 CRLF、不合法的 UTF-8、NUL、PNG、空檔都逐位元相同，各送出 `create`、`modify` 一次；內容相同的 `modifyBinary` 仍會送 `modify`。

- 編輯器開著、有未存文字時，`modifyBinary` 會讓它馬上換成磁碟的新內容，所以〈小選擇〉第 1 項要先存再換空白。
- `iterateAllLeaves` 漏背景分頁，`getLeavesOfType('markdown')` 全部列得出來；延後載入的分頁沒有未存內容。
