## 限制

- 只新增或修改下列檔案：repo 最上層的 `package.json`、`package-lock.json`、`tsconfig.json`、`manifest.json`、`.gitignore`（只能往後加），以及 `src/`、`tests/`、`tools/` 底下的檔案。`docs/`、`experiments/`、這份說明都只讀不改，有疑問寫在回報裡。
- TypeScript，Node 24，ES modules，esbuild 建置；`npm install` 在 Windows 上要能直接跑，不能需要 C++ 編譯工具。
- 相依套件只用這些：
  - 執行：`react`、`react-dom`、`motion`（W1 先裝好，還不用）、`yaml`（解析 YAML 屬性）、`@noble/hashes`（同步的 SHA-256，iPhone 上不能用 Node 的 `crypto`）。
  - 開發：`obsidian`（型別）、`esbuild`、`typescript`、`@types/react`、`@types/react-dom`。
  - 測試用 Node 內建的 `node:test`，直接跑 `.ts`（Node 24 內建型別去除）。要加別的套件，先在回報說明理由。
- **`src/core/` 底下不能 import `obsidian`，也不能用 Node 的模組**（`fs`、`crypto`、`path` 等），因為它要同時在 iPhone 的外掛和 Node 的測試裡跑。寫一個測試掃描 `src/core/**/*.ts` 的 import 來檢查這一條。
- 外掛的 `main.js` 只能 `require('obsidian')`，建置時檢查（照試作外掛的做法）；`manifest.json` 的 `isDesktopOnly: false`。
- 寫法限制：tsconfig 開 `erasableSyntaxOnly`、`verbatimModuleSyntax`、`allowImportingTsExtensions`、`noEmit`、`strict`；import 寫 `.ts` 副檔名；不用 enum、namespace、建構子參數屬性。
- 範例卡組只能用 syntax.md 裡的例子，或自己編的內容；repo 是公開的，不放課本內容。
- 測試 vault 的路徑不寫進任何檔案，安裝指令用參數傳入。
- 在新分支 `codex/w1-w2` 上 commit。在本機用 `git worktree add ../Essence-Cards-w1w2 -b codex/w1-w2` 開在旁邊的資料夾，**不要在原資料夾切換分支**，因為其他 AI 可能正在 main 上改文件。

### 4. 檔案存取接點

`src/core/files.ts` 只放型別。這是核心碰 vault 唯一的路（D-110）：

```ts
export interface Files {
  /** folder 底下所有檔案的路徑，包括子資料夾；以 vault 為根、用 '/' 分隔，照字串排序。folder 不存在時回傳空陣列。 */
  list(folder: string): Promise<string[]>;
  /** 檔案不存在時回傳 null。 */
  read(path: string): Promise<string | null>;
  /** 一次讀、改、寫完。檔案不存在時用 edit('') 的結果建立檔案，包括上層資料夾；edit 回傳的文字和原本一樣時不寫入。 */
  modify(path: string, edit: (text: string) => string): Promise<void>;
  /** 在檔尾追加 line 加上 '\n'；檔案不存在時建立，包括上層資料夾。 */
  append(path: string, line: string): Promise<void>;
  /** 有檔案新增、修改、刪除或改名時呼叫 onChange（改名時舊、新路徑各呼叫一次）；回傳取消監看的函式。 */
  watch(onChange: (path: string) => void): () => void;
}
```

`tools/node-files.ts`：`createNodeFiles(root: string): Files`，以電腦上的資料夾 `root` 當作 vault。`watch` 用 `fs.watch` 的 recursive。要有測試，在暫存資料夾裡逐一驗證上面每一句註解。Obsidian 版由 Claude 在 W5 寫。

## W2 卡組模組

### 1. 介面

`src/core/deck/index.ts` 只匯出下面這些。內部怎麼拆檔案由 Codex 決定；測試只透過這些匯出測。

```ts
export function parseDeck(text: string): Deck;
export function assignIds(text: string, options: AssignOptions): AssignResult;

export interface Deck {
  props: DeckProps;
  targets: Target[];          // 照文件順序，包括寫錯的（ok 為 false）
  problems: Problem[];        // 全篇的錯誤與提示，照行號排序
}

export interface DeckProps {
  term: string | null;        // 年級學期
  subject: string | null;     // 科目
  unit: { code: string; name: string } | null;   // 「2-2 水溶液」→ code '2-2'、name '水溶液'；沒有空格時 name 是 ''
  materials: string[];        // 材料，原樣保留，例如 '[[國二上自然 2-2 水溶液]]'
  status: 'draft' | 'active' | 'paused';         // 草稿／啟用／暫停；沒寫是 active
  categories: string[];       // 分類
  isTranscript: boolean;      // 有「來源類型」屬性：這是轉錄稿，不是卡組（D-088 補充）
}

export interface Target {
  id: string | null;          // 還沒補 ID 時是 null
  name: string;               // 名稱，不含 ID
  line: number;               // 學習目標那一行，從 0 起算
  implicit: boolean;          // 最上層直接寫了題目（§2-3）：name 照 §2-3 取，prompts 只有它自己
  section: string | null;     // 上方最近的標題文字，不含 #
  fields: Fields;
  prompts: Prompt[];          // 第一題是基本題
  shared: string[];           // 學習目標底下的共用背面補充，每一項是一段 Markdown（含它的子項目）
  direction: 'en-zh' | 'zh-en' | null;   // 名稱以「 英翻中」「 中翻英」結尾
  pairKey: string | null;     // 有方向時，名稱去掉方向後的文字
  ok: boolean;                // 沒有錯誤；false 時這個學習目標不排程（§2-10）
}

export interface Fields {
  sources: string[];          // 出處，用頓號拆開的原文，例如 ['1-3 p.20', 'p.44']；解析成單元與錨點是之後「範圍與目錄」模組的事
  type: string | null;        // 類型
  importance: 'high' | 'medium' | 'low';  // 高／中／低；沒寫或認不得是 medium
  paused: boolean;            // 狀態：暫停
  remarks: string[];          // 備註
  mistakes: string[];         // 錯題補強，原文，例如 '[[國二上自然 第一次段考]]'
}

export type Prompt =
  | { kind: 'qa'; line: number; question: string; answer: string; extras: string[]; typed: string | null; fingerprint: string }
  | { kind: 'cloze'; line: number; text: string; blanks: { start: number; end: number }[]; extras: string[]; fingerprint: string };
// qa：question、answer 是 Markdown；多行答案時 answer 是每個子項目的文字，用 '\n' 接起來。
// cloze：text 是整行（不含清單符號與 ID），blanks 是每個 ==…== 在 text 裡的位置（含 == 記號，end 不含）。怎麼挖空、怎麼顯示由畫面決定。
// extras：這一題底下的背面補充，每一項是一段 Markdown。
// typed：中翻英的 qa 題，學生要打的答案（answer 拿掉 **、*、_、== 記號後去頭尾空白）；其他是 null。

export interface Problem {
  line: number;
  level: 'error' | 'hint';    // error：那個學習目標跳過；hint：照常複習，只提示
  code: ProblemCode;
  message: string;            // 給家長看的一句繁體中文，例如「這一題 :: 的左邊沒有題目」
  targetLine: number | null;  // 屬於哪個學習目標
}

export type ProblemCode =
  | 'empty-question'          // error：:: 左邊沒有題目
  | 'missing-answer'          // error：問題 :: 底下沒有答案
  | 'typed-answer-invalid'    // error：中翻英的答案是多行、空的，或含有中文
  | 'duplicate-field'         // hint：類型、重要性、狀態寫了兩次，用第一個
  | 'unknown-field-value'     // hint：值認不得，用預設值
  | 'unknown-field'           // hint：「｜」分隔的一段，名稱不是 6 個欄位之一，忽略這一段
  | 'unknown-property-value'  // hint：屬性「狀態」的值認不得，用 active
  | 'duplicate-id'            // hint：同一篇裡 ID 重複，assignIds 會換掉後面的
  | 'cloze-not-typed';        // hint：中翻英的填空題不要求打字，照一般翻面
```

```ts
export interface AssignOptions {
  taken: ReadonlySet<string>;     // 不能用的 ID：其他卡組的、刪掉的（呼叫的人負責給齊）
  replace?: ReadonlySet<string>;  // 這一篇裡要換掉的 ID：和別篇重複、別篇是原本那個時（由索引判斷）
  random?: () => number;          // 預設 Math.random；測試時傳固定的
}
export interface AssignResult {
  text: string;                   // 沒有要改時，和輸入完全相同
  assigned: { line: number; id: string }[];   // 新配的 ID 與它在新文字裡的行號
}
```

### 2. 解析：syntax.md 沒寫到的細節

- **哪些行不看**：YAML 屬性區塊、程式碼區塊（``` 與 ~~~）、引言框與引言（`>` 開頭）都不是卡片（D-089 第 8 條）。程式碼區塊與引言框裡的標題也不算 `section`。
- **清單的上下層**照 CommonMark：Tab 視為下一個 4 的倍數欄；一個項目是上一個項目的子項目，條件是它的清單符號所在的欄 ≥ 上一個項目內容開始的欄（例如 `- ` 開頭的項目，內容從第 2 欄開始）。認得 `-`、`*`、`+` 與 `1.`、`1)`。項目裡縮排的非清單行是那一項文字的延續，用 `\n` 接起來。空白行不結束清單。清單外的段落結束清單。最上層＝沒有上層的項目。之後 Claude 會在 Obsidian 拿同一批筆記對照，有出入再修。
- **行內程式碼與公式**：`` `…` ``、`$…$`、`$$…$$` 裡的 `::`、`==` 不算（D-089 第 2 條）。
- **學習目標底下的子項目怎麼分**，依序判斷：
  1. 開頭是 6 個欄位名稱之一加上全形或半形冒號，就是資料。用「｜」拆成好幾段，每段是「名稱：值」。
  2. 有 `::`，或有 `==…==`，就是題目。同一行兩個都有時是問答題，`==` 只是螢光筆（D-089 第 3 條）。`::` 取第一個，左右去頭尾空白。
  3. 其他是共用的背面補充。
- **題目底下的子項目**：問答題 `::` 右邊有答案時，子項目都是這一題的背面補充；右邊空白時，不是資料的子項目就是答案（D-089 第 4 條）。題目底下的資料行照樣算進學習目標的欄位。
- **ID**：學習目標那一行最後的 ` ^xxx`（Obsidian 區塊 ID：英數字與 `-`）。家長自己寫的任何合法區塊 ID 都沿用，不檢查是不是 6 碼。題目那一行的區塊 ID 不是學習目標 ID，從題目文字拿掉（D-089 第 9 條）。
- **欄位值**：出處、備註、錯題補強用「、」拆開，重複寫的合併、去掉重複；類型、重要性、狀態寫兩次時用第一個（`duplicate-field`）。狀態只認「暫停」與「啟用」。
- **屬性**：用 `yaml` 解析；屬性區塊壞掉時，props 全用預設值，並在第 0 行給一個 `unknown-property-value` 提示。「材料」「分類」可以是清單或單一字串。不認得的屬性忽略。
- **中翻英**：qa 題的答案拿掉格式記號後，是空的、跨多行，或含有中文字（`\p{Script=Han}`），就是 `typed-answer-invalid`。
- **題目指紋**（§2-8）：
  - 輸入：qa 題是「question＋'\n'＋answer」；cloze 題是「text＋'\n'」。
  - 先整理：拿掉清單符號、縮排與題目那一行的區塊 ID；連續的空白與換行都換成一個空格，再去掉頭尾空白。
  - 計算：SHA-256，取前 8 個十六進位字元。
  - 驗算用的值（Claude 用 Node 的 `crypto` 算的）：
    - `糖水裡，哪一個是溶質？哪一個是溶劑？` / `糖是**溶質**，水是**溶劑**` → `c7559ebd`
    - 填空 `水溫越==高==、顆粒越==小==、有==攪拌==，糖溶解得越快` → `66c1f2ef`
    - `borrow` / `v. 借入、向別人借` → `f7b07c1e`

### 3. 補 ID（`assignIds`）

- 每個 `id` 為 null 的學習目標，在那一行最後加上 ` ^` 和新的 ID。
- 新 ID：6 碼，從 `abcdefghjkmnpqrstuvwxyz23456789` 隨機取（去掉 0、o、1、l、i）；不能在 `taken` 裡，也不能和這一篇已有的或這次已配的重複。
- **最上層直接寫了題目**（`implicit`）：在它上面插一行學習目標 `- 名稱 ^新ID`，縮排和原本那一行相同；原本那一行與它所有的子項目往內縮一層。縮一層用這篇筆記已有的縮排單位：有用 Tab 的就是 Tab，否則用 4 個空格。名稱：問答題取 `::` 左邊；填空題取整行、拿掉 `==` 記號。
- **同一篇裡重複的 ID**：第一個保留，後面的換新的。`replace` 裡的 ID 全部換新的。
- **其他文字一個字都不能動**，包括換行符號（CRLF 照樣是 CRLF）與檔尾有沒有換行。
- 引言框裡的清單（候選卡片等）這一批不處理；存 AI 草稿時配 ID 是之後的工作。

### 4. 效能

一篇 2,000 個學習目標、每個 3 題的卡組（程式產生），`parseDeck` 在電腦上 200 ms 內解析完，寫成測試。
