## 1. 介面

`src/core/study/index.ts` 只匯出下面這些（W4 會在同一個模組加佇列）。內部怎麼拆檔案由 Codex 決定，但 FSRS 的部分放在 `fsrs.ts`；測試只透過這些匯出測。

```ts
import type { Files } from '../files.ts';

// ── 時間 ──
// offset：時區，UTC 以東的分鐘數，+08:00 是 480（和 Date.getTimezoneOffset() 正負相反）。
export function formatTime(ms: number, offset: number): string;   // '2026-10-16T20:15:03.250+08:00'；一律到毫秒、一律寫時區（offset 0 寫 +00:00）
export function dayOf(ms: number, offset: number): number;         // 清晨 4 點換日的日序（D-071）：floor((ms + offset·60000 − 4 h) / 1 天)
export function dayStart(day: number, offset: number): number;    // 那一天清晨 4 點的 ms；dayOf(dayStart(d, o), o) === d

// ── 一行紀錄 ──
export type Rating = 'easy' | 'good' | 'near' | 'miss';

export type LogEntry = ReviewEntry | UndoEntry | ChangeEntry;

interface Stamp {
  t: string;        // 原文，取消紀錄靠它比對
  at: number;       // t 換成的 ms
  offset: number;   // t 的時區；Z 當作 0
}
export interface ReviewEntry extends Stamp {
  kind: 'review';
  lt: string;
  r: Rating;
  v: string | null;     // 錯題補強沒有指紋
  src: string | null;   // null 是一般複習；'mistake'、'check'；認不得的值原樣保留，當一般複習
}
export interface UndoEntry extends Stamp {
  kind: 'undo';
  undo: string;         // 被取消那一筆的 t
}
export interface ChangeEntry extends Stamp {
  kind: 'change';
  set: string;          // 'cap'、'retention'、'semester'、'status'、'filter'；認不得的種類原樣保留
  deck: string | null;
  lt: string | null;
  val: unknown;
}

/** 要寫的內容；t 由寫入的程式補上。 */
export type NewEntry =
  | { lt: string; r: Rating; v: string; src?: 'check' }
  | { lt: string; r: 'miss'; src: 'mistake' }
  | { undo: string }
  | { set: 'cap'; val: number }
  | { set: 'retention'; val: number }
  | { set: 'semester'; val: string }
  | { set: 'filter'; val: string[] }
  | { set: 'status'; deck: string; val: '草稿' | '啟用' | '暫停' }
  | { set: 'status'; lt: string; val: '啟用' | '暫停' };

export function encodeEntry(t: string, entry: NewEntry): string;   // 一行 JSON，不含換行
export function parseLine(line: string): LogEntry | null;          // 空白行與讀不懂的行回傳 null（原因由 mergeHistory 記成 problem）

// ── 寫紀錄 ──
export const LOG_FOLDER = 'Essence Cards/紀錄';
export function logPath(device: string, ms: number, offset: number): string;   // `${LOG_FOLDER}/2026-10 ${device}.jsonl`，月份照 offset 的當地時間

export interface LogWriter {
  /** 立刻回傳這一筆的 t，不等寫入；寫入在背景照順序進行。 */
  write(entry: NewEntry): string;
  /** 等到目前排隊的都寫完（包括重試失敗的）；還是失敗就 reject。 */
  flush(): Promise<void>;
}
export function createLogWriter(files: Files, options: {
  device: string;                        // 例如 'iPhone-7f3a'，由外掛產生並存在本機
  now?: () => number;                    // 預設 Date.now
  offset?: (ms: number) => number;       // 預設 -new Date(ms).getTimezoneOffset()
  onError?: (error: unknown) => void;    // 寫入失敗時通知；預設不做事
}): LogWriter;

// ── 讀紀錄 ──
export interface History {
  reviews: ReviewEntry[];     // 照時間排好；去掉重複的與被取消的
  changes: ChangeEntry[];     // 照時間排好；去掉重複的
  problems: { path: string; line: number; message: string }[];   // line 從 0 起算
}
export function mergeHistory(sources: readonly { path: string; text: string }[]): History;
export function readHistory(files: Files): Promise<History>;    // 列出 LOG_FOLDER、讀檔，交給 mergeHistory

// ── 記憶狀態（fsrs.ts） ──
export interface Memory {
  stability: number;
  difficulty: number;
  last: ReviewEntry;   // 最後一次有效的作答
  reps: number;        // 有效作答的次數，包括錯題補強
}
export function review(memory: Memory | null, entry: ReviewEntry): Memory;      // 作答一次之後的記憶狀態
export function replay(reviews: readonly ReviewEntry[]): Map<string, Memory>;  // reviews 已照時間排好；照 lt 分開，依序呼叫 review
export function intervalDays(memory: Memory, retention: number): number;      // 長期的間隔天數
export function dueAt(memory: Memory, retention: number): number;             // 到期的 ms
export function recall(memory: Memory, now: number): number;                  // 現在還記得的機率，0～1
```

## 2. 紀錄：syntax.md 沒寫到的細節

### 寫

- **欄位順序**固定，照 syntax.md §5 的例子：作答是 `t, lt, r, v, src`；取消是 `t, undo`；變更是 `t, set, deck 或 lt, val`。沒有的欄位不寫（例如沒有 `src` 就不寫 `"src":null`）。`JSON.stringify` 的預設寫法，不加空白，中文不跳脫。
- **時間不重複**：同一個 writer 寫出的 `at` 一定嚴格遞增；`now()` 和上一筆相同或更早時，用上一筆加 1 毫秒。
- **背景寫入**：`write` 把這一行排進佇列就回傳；佇列一次只送一個 `files.append`，照 `write` 的順序。`append` 失敗時呼叫 `onError`，那一行留在佇列最前面，下一次 `write` 或 `flush` 時再試，後面的行不能跳過它先寫。
- 路徑在 `write` 當下決定（跨月時，月底那一筆寫進舊月份的檔）。

### 讀

- `readHistory` 只讀 `LOG_FOLDER` 底下**直接的** `.jsonl` 檔；子資料夾（例如 `AI 輸出/`）和其他副檔名不讀。iCloud 的衝突副本（檔名不同、內容大多重複）照樣讀進來，靠下面的去重處理。
- **一行**：去掉頭尾空白（包括 `\r` 與檔首的 BOM）後是空的就跳過，不算問題。
- **讀不懂的行**：`JSON.parse` 失敗時，從這一行最後一個 `{"t":` 開始再試一次；成功就用它，並記一個 problem（前一次寫入可能被中斷，下一行接在它後面）。還是失敗，或缺必要欄位、`t` 格式不對、`r` 不是四個代號之一，就跳過並記 problem。認不得的欄位忽略。
- **判斷種類**：有 `undo` 是取消；否則有 `set` 是變更；否則要有 `lt` 與 `r` 才是作答。
- **`t` 的格式**：`YYYY-MM-DDTHH:mm:ss`，可以有 1～3 位小數，結尾是 `±HH:mm` 或 `Z`。
- **去重**：解析後每個欄位都相同的兩筆只留一筆（衝突副本）。
- **取消**：一筆取消，讓所有 `t` 和它的 `undo` 字串完全相同的作答失效，不管在哪個檔、哪個月份、取消在前還是在後。找不到對象的取消忽略，不算問題。取消只作用在作答，不作用在變更與其他取消。
- **排序**：依 `at`；相同時依檔案路徑的字串順序，再依行號。

## 3. 記憶狀態：FSRS 怎麼用

用 `ts-fsrs` 的 `FSRSAlgorithm`，參數是 `generatorParameters({ enable_fuzz: false })`，也就是 FSRS-6 的預設參數（D-112）。**只用它的記憶模型**（`next_state`、`calculate_interval_modifier`、`forgetting_curve`），不用 `FSRS.next`、`Card` 與學習步驟：答錯後多久再出由我們自己決定（D-062）。

- **自評換成 FSRS 的等級**（D-062）：`easy` → 4、`good` → 3、`miss` → 1。`near`（差一點）：穩定度照 1 算，難度照 2 算，也就是 `stability` 取 `next_state(…, 1)` 的、`difficulty` 取 `next_state(…, 2)` 的。這就是「算沒想起來，難度只加沒印象的一半」。
- **經過幾天**：`dayOf(entry.at, entry.offset) − dayOf(last.at, last.offset)`，各用各自那一筆的時區；小於 0 時當 0（兩台裝置的時鐘不準）。同一天（0 天）時 `next_state` 會用 FSRS 的短期公式，不用另外處理。
- 第一次作答：`next_state(null, 0, 等級)`。
- 錯題補強（`src: 'mistake'`）、考前抽測（`src: 'check'`）都和一般作答一樣更新記憶狀態。
- **`intervalDays`**：`round(stability × calculate_interval_modifier(retention))`，限制在 1～36500。retention 由呼叫的人給（平常 0.8，考前 0.9，D-078），不存在 Memory 裡：同一份 Memory 換一個保持率就能重算到期日，不用重播。
- **`dueAt`**，依最後一次作答決定：
  - 錯題補強：`last.at`，立刻到期。學生不在複習中，下次打開就和其他到期的卡一起出。
  - `miss`：`last.at` 加 1 分鐘；`near`：加 10 分鐘（D-062 的「剛答錯再出」）。
  - 其他：`dayStart(dayOf(last.at, last.offset) + intervalDays(memory, retention), last.offset)`，也就是到期那一天的清晨 4 點。
- **`recall`**：`forgetting_curve(經過的天數, stability)`，經過的天數是 `max(0, (now − last.at) / 1 天)`，帶小數。
