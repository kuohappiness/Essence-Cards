## 1. 介面

加進 `src/core/study/index.ts` 的匯出（W3 的匯出保留）。內部怎麼拆檔案由 Codex 決定；測試只透過 `index.ts` 的匯出測。

```ts
import type { Deck, Target, Prompt } from '../deck/index.ts';

// ── 輸入 ──
export interface DeckEntry {
  path: string;   // vault 裡的路徑；同時是排序與「當日卡」的鍵
  deck: Deck;     // W2 parseDeck 的結果
}
export interface Settings {
  capMinutes: number;          // 每日時間上限，全部科目加起來（D-104）
  retention: number;           // 目標保持率，例如 0.8（D-078）
  filter: readonly string[];   // 濾網（§2-2）
}
/** 目前生效的考試範圍；沒有生效的範圍時傳 null。由之後的「範圍與目錄」模組產生（D-110），W5 先傳 null。 */
export interface ExamScope {
  contains(entry: DeckEntry, target: Target): boolean;
  hasPeriod: boolean;   // 填了考試期間（D-098）；生效就表示結束日還沒過
}
export interface TodayInput {
  decks: readonly DeckEntry[];
  history: History;     // W3 readHistory／mergeHistory 的結果；只用 reviews，不讀 changes
  settings: Settings;
  exam: ExamScope | null;
  now: number;
  offset: number;       // 時區，同 W3
}

// ── 今天的份 ──
export type Lane = 'relearn' | 'exam-due' | 'exam-new' | 'due' | 'new';

export interface QueueItem {
  lt: string;
  deck: string;              // DeckEntry.path
  subject: string | null;    // 卡組的「科目」；學業以外的卡組是 null
  lane: Lane;
  seconds: number;           // 估計要花的秒數（§2-6）
}
export interface Today {
  day: number;               // dayOf(now, offset)
  share: QueueItem[];        // 今天的份，照出卡順序
  more: QueueItem[];         // 「再複習一些」，接在 share 後面的順序
  problems: { deck: string; line: number; message: string }[];
  // 其他內部資料（記憶狀態等）不屬於介面，測試不讀
}
export function planToday(input: TodayInput): Today;

// ── 複習中：下一張 ──
export type Pick =
  | { subject: string | null }   // 入口某一科（D-095）
  | { deck: string }             // 目錄某個單元的「當日卡」（D-097）
  | { more: true };              // 「再複習一些」（D-071）

export interface Card {
  lt: string;
  deck: string;
  target: Target;
  prompt: Prompt;            // 這次出哪一題（§3-2）
  isNew: boolean;            // 從來沒有作答過：卡片角落標「新」（D-069）
  typed: boolean;            // 要打字（prompt.kind === 'qa' && prompt.typed !== null）
  early: boolean;            // 剛答錯、還沒到時間就提早出（D-062）
}
export type Next =
  | { kind: 'card'; card: Card }
  | { kind: 'done' }         // 這個範圍今天沒有卡了
  | { kind: 'stale' };       // 已經過了清晨 4 點：要重新 planToday
export function nextCard(today: Today, input: TodayInput, pick: Pick): Next;

// ── 入口的進度 ──
export interface SubjectRow {
  subject: string | null;
  done: number;
  total: number;
  remainingSeconds: number;
  inExam: boolean;           // 這一科有學習目標在考試範圍裡
}
export interface Progress {
  done: number;              // 「今日複習 10/50」
  total: number;
  subjects: SubjectRow[];    // 照 D-095 排好（§4）
}
export function progress(today: Today, input: TodayInput): Progress;

// ── 打字卡 ──
export function checkTyped(prompt: Prompt, input: string): boolean;
```

**呼叫順序與成本**（介面的一部分）：打開外掛、卡組或設定改變、讀到別台裝置新同步的紀錄時呼叫一次 `planToday`（重的那一個）。每作答一次，外掛把新的一筆加進 `input.history` 之後呼叫 `nextCard` 與 `progress`（輕的，不重播全部紀錄）。`nextCard` 與 `progress` 只讀 `today` 與 `input`，不改它們。

## 2. 今天的份：planToday

### 2-1 哪些學習目標可以出

全部都成立才是**候選**：

- 卡組：`isTranscript` 是 false、`props.status` 是 `active`。
- 學習目標：`id` 不是 null、`ok` 是 true、`fields.paused` 是 false、至少有一題。
- 沒有被濾網濾掉（§2-2）。
- 同一個 ID 出現在好幾篇卡組（複製筆記）：照 `path` 的字串順序，第一篇的算，其他的不出，各記一個 problem。同一篇裡重複的 ID，W2 已經標成錯，照 `ok` 處理。
- 中翻英的新卡要先過配對的門檻（§2-4）。

紀錄裡有、卡組裡已經沒有的 `lt`（刪掉的目標）直接忽略。不是候選的目標，記憶狀態照算，只是不出（濾網恢復後照順序慢慢補回，D-071）。

### 2-2 濾網

`settings.filter` 的每一項是一個標籤，符合任何一項就濾掉（D-120、syntax.md §5）：

- `重要性：高`、`重要性：中`、`重要性：低`（冒號全形半形都認）：比對學習目標的 `fields.importance`。
- 其他字串：比對卡組的「分類」（`props.categories`，完全相同才算），例如 syntax.md §5 例子裡的 `攝影`。

「延伸」的學習目標（出處只連到課本以外的筆記，D-083 補充）要用到出處的解析，屬於範圍與目錄模組，這一批不做；分類寫成「延伸」的卡組照上面的分類規則濾。

### 2-3 記憶狀態與「今天到期」

- **用今天以前的紀錄**：`planToday` 只用 `at < dayStart(day)` 的作答重播（W3 的 `replay`）。這樣今天的份在一天之中不會因為作答而變動；中途改了上限、卡組、濾網或考試範圍，重新 `planToday` 時才會變。
- **保持率**：一般是 `settings.retention`；`exam` 不是 null、`exam.hasPeriod` 是 true、而且 `exam.contains` 的目標，用 `max(settings.retention, 0.9)`（D-078：家長設得比 90% 高時照家長的）。
- **今天到期**：`dueAt(memory, 保持率) < dayStart(day + 1)`。
- **「記得」**（D-062 的綠或藍）：有記憶狀態、最後一筆是 `good` 或 `easy`，而且今天沒有到期。

### 2-4 英文的兩個方向（D-069）

同一篇卡組裡 `pairKey` 相同、`direction` 一個 `en-zh` 一個 `zh-en` 的兩個目標是一組。同一個 `pairKey` 和方向出現兩次時，用行號小的那個配對。

- **中翻英的門檻**：中翻英**沒有任何今天以前的作答**時，只有在英翻中「記得」（§2-3）時才是候選。英翻中不是候選（暫停、濾掉、草稿、寫錯）或不存在時，中翻英不受門檻限制。中翻英一旦開始，就和其他卡一樣排程，不再看英翻中。
- **同一天只出一個**：兩個方向都進了候選、都要出（到期，或一個新卡、一個到期）時，只留一個：今天以前的 `recall(memory, dayStart(day))` 比較低的那個；新卡當作 0；相同時留英翻中。另一個今天不出，也不進 `more`（明天重算時自然會出）。
- 一個方向已經在 `share` 時，另一個不進 `more`。

### 2-5 分道與順序（D-071）

每個候選放進一道，依序是：

| 道 | 條件 | 道內順序 |
|---|---|---|
| `relearn` 剛答錯 | 今天以前最後一筆是 `miss` 或 `near`、而且 `src` 不是 `mistake`；今天到期 | `dueAt` 早的先 |
| `exam-due` 範圍內到期 | `exam.contains`；今天到期 | 重要性高 → 中 → 低；同樣重要時 `recall(memory, dayStart(day))` 低的先 |
| `exam-new` 範圍內新卡 | `exam.contains`；沒有今天以前的作答 | 卡組 `path` 的字串順序，再依行號；不看重要性（D-120） |
| `due` 範圍外到期 | 其他到期的 | 同 `exam-due` |
| `new` 範圍外新卡 | 其他新卡 | 同 `exam-new` |

- 錯題補強（`src: 'mistake'`）之後的卡 `dueAt` 是那一筆的時間，照一般到期的卡排（`exam-due` 或 `due`），不進 `relearn`（W3 §3）。
- 沒到期、也不是新卡的候選不出。
- 所有比較最後都用 `lt` 的字串順序決定，整個順序完全由輸入決定：同樣的輸入一定排出同樣的順序（D-074「回來照常再出」靠這一點）。

### 2-6 時間上限

- **每張卡的秒數**（D-120）：這一科（`subject`，null 也算一科）有自己的紀錄時，用最近 30 天（`dayStart(day − 30) ≤ at < dayStart(day)`）的作答間隔中位數：照時間排好的全部作答（不分科、不分裝置）相鄰兩筆的時間差，算在後面那一筆的科目（照它的 `lt` 現在所在的卡組；找不到的不算）；只取大於 0、不超過 120 秒的差，那一科少於 30 個時用預設 15 秒（[試作場 T8](../experiments/load-sim/README.md) 的平均約 14.4 秒）。中位數取整數秒，偶數個時取中間兩個的平均再四捨五入。`src: 'mistake'` 的作答不算。
- **切出今天的份**：照 §2-5 的順序累加 `seconds`，加了不超過 `capMinutes × 60` 就放進 `share`；第一個放不下的和它後面的全部進 `more`（不跳過去找小的，優先順序不亂）。
- 新卡沒有張數上限（D-069）；時間到了，剩下的新卡明天接著出。積欠的卡自動分攤到之後幾天，不另外處理。

## 3. 複習中：nextCard

### 3-1 下一張

`dayOf(input.now, input.offset) !== today.day` 時回傳 `stale`。否則：

- **範圍**：`{ subject }` 是 `share` 裡那一科的項目；`{ deck }` 是 `share` 裡那篇卡組的項目；`{ more: true }` 是 `more`，但跳過配對的另一個方向今天已經有作答的項目。
- **今天的作答**：`input.history.reviews` 裡 `at ≥ dayStart(today.day)`、`src` 不是 `mistake` 的作答。範圍裡有今天的作答的目標叫「碰過」；碰過、而且今天最後一筆是 `miss` 或 `near` 的叫「等再出」，它的再出時間是今天以前的記憶狀態依序套上今天的作答之後的 `dueAt`（W3 的 `review`、`dueAt`）。
- 依序：
  1. 等再出、時間已到（`dueAt ≤ now`）的：再出時間早的先。
  2. 還沒碰過的：照範圍裡的順序取第一個。
  3. 等再出、時間還沒到的：再出時間早的先，`early: true`（D-062：沒有別的卡時提早出，不讓學生乾等）。
  4. 都沒有：`done`。
- 不寫任何東西、不記住上一次回傳什麼：沒按就關掉，再呼叫一次會得到同一張（D-074）；回看時改評分（取消＋新的評分，D-084）之後，照新的紀錄重算。

### 3-2 出哪一題（D-028）

看這個目標全部的有效作答（今天以前加今天，不含 `mistake`），`v` 對到現在題目的 `fingerprint`：

1. 今天最後一筆是 `miss` 或 `near`，而且它的 `v` 還對得到某一題：再出同一題（剛看過答案，馬上再試一次）。
2. 從來沒有 `good` 或 `easy`（不管哪一題，包括 `v` 對不到現在題目的）：基本題（第一題）。
3. 只有一題：基本題。
4. 其他：在進階題（第二題以後）裡選最久沒出的：從沒出過的先（照筆記順序），都出過就選最後一次出現最早的。

改過字的題目指紋會變，舊的 `v` 對不到，那一題就當作從沒出過（D-046）。

## 4. 入口的進度：progress

- **一科一列**：`share` 裡每個出現過的 `subject` 一列，今天沒有卡的科目不列。學業以外的卡組 `subject` 是 null，合成一列，名稱由畫面決定（D-120）。
- **`total`**：這一科在 `share` 裡的項目數。中途重新 `planToday`（例如改了上限）時會變，這是預期的。
- **`done`**：碰過、而且今天最後一筆是 `good` 或 `easy` 的項目；還在等再出的不算完成，「10/10」時這一科真的沒事了（D-120）。`share` 以外的作答（`more`、全部練習）不算進任何一科。
- **`remainingSeconds`**：還沒碰過的項目的 `seconds`，加上等再出的項目各一份 `seconds`。
- **`inExam`**：`exam` 不是 null，而且這一科在 `share` 或 `more` 裡有 `exam.contains` 的項目。
- **排序**（D-095）：沒做完的在上、做完的（`done === total`）在下；沒做完的裡，`inExam` 的先，再依 `remainingSeconds` 多的先；做完的照原本的順序；最後都用科目名稱的字串順序，null 排最後。
- 最上面的 `done`／`total` 是各列加總。

## 5. 打字卡：checkTyped

`prompt.kind === 'qa' && prompt.typed !== null` 時，`input` 和 `prompt.typed` 去掉頭尾空白後，不分大小寫完全相同才算對（syntax.md §2-3）。不是打字題時丟出錯誤。中間的空白、標點都要相同。按「沒印象」不經過這個函式（D-116）。

## 6. 紀錄的 typed 欄位

照 syntax.md §5 與 D-120，打字卡的作答那一行多一個選填欄位 `typed`：`right` 拼對、`wrong` 拼錯、`skip` 按「沒印象」沒有打字。`right`／`wrong` 由畫面用 `checkTyped` 的結果決定；評分怎麼配是 W6 的事，核心不檢查 `typed` 和 `r` 的組合。改 W3 的這三處，其他不動：

```ts
export interface ReviewEntry extends Stamp {
  // W3 的欄位不變，加：
  typed: string | null;   // 沒有這一欄是 null；認不得的字串原樣保留；不是字串時當作沒有，不算 problem
}
export type NewEntry =
  | { lt: string; r: Rating; v: string; typed?: 'right' | 'wrong' | 'skip'; src?: 'check' }
  | /* W3 其他的寫法不變 */;
```

- `encodeEntry`：欄位順序 `t, lt, r, v, typed, src`；沒有 `typed` 就不寫。
- `parseLine`：讀出 `typed`；W3 的其他規則照舊。去重時 `typed` 也算一個欄位。
- 排程、佇列都不看 `typed`。

W3 實作時如果已經照 syntax.md 的新版做了這個欄位，核對行為和上面相同，只補 T15 的測試。

## 7. 明確延後，這一批不做

- **範圍與目錄模組**：讀考試範圍檔、判斷一個目標在不在範圍（出處的跨單元解析、單元編號的自然排序）。W4 只吃 `ExamScope` 這個介面；W5 先傳 null，入口的「考試範圍與日期」做的時候再寫那個模組。附帶發現：[syntax.md §4](../docs/syntax.md#4-考試範圍) 的例子寫 `Unit 1～Unit 3`，但 §2-1 的單元編號是第一個空格前的字（英文例子是 `L1`），寫那個模組前要先釐清。
- 全部練習（目錄的「全部卡」，D-097）、考前抽測（D-107）、「常錯」與「總是答錯就提醒拆開」（D-028）、記憶配色的計算給目錄用。
- 「再複習一些」一次加多少、怎麼呈現：畫面決定，核心只給排好的 `more`。
- 統計記憶保持率時不算新卡的第一次沒印象（D-069）：第 2 階段的分析。

## 8. 驗算值與測試清單

測試的卡組用自編的 Markdown 經過 `parseDeck` 產生，紀錄用 W3 的 `mergeHistory` 從自編的 JSONL 產生；除了特別寫的，時區都是 +08:00（`offset` 480）、`retention` 0.8、`capMinutes` 30、`filter` 空、`exam` null。到期日都取自 [W3 §4 的驗算表](w3.md#4-驗算值)：

- 情境 A：`good` 2026-10-16T20:15:03.250 → 80% 到期 10-24、90% 到期 10-18。
- 情境 B：`easy` 同一時間 → 80% 到期 11-13、90% 到期 10-24。
- 「穩定度小、經過天數相同」的目標 recall 比較低（遺忘曲線單調），不用另外算數字。

下面每一組都要寫成測試，預期值就是表裡的字面值。

**T1 分道與順序**：今天 2026-10-24（`now` = 10-24T19:00）。目標 a＝情境 A；b＝情境 B；c＝第一次作答 `miss` 10-23T21:00；d＝新卡；e＝情境 A 加上「重要性：高」。全部在同一篇自然卡組，筆記順序 a、b、c、d、e。

| 考試範圍 | `share` 的 `lt` 順序 | 道 |

| null | c、e、a、d | relearn、due、due、new |
| contains d、`hasPeriod` false | c、d、e、a | relearn、exam-new、due、due |
| contains b、`hasPeriod` true | c、b、e、a、d | relearn、exam-due、due、due、new |
| contains b、`hasPeriod` false | c、e、a、d | b 沒到期（80% 是 11-13），不出 |

再加（只有 a 一個目標）：`retention` 0.9、沒有考試範圍時，今天 2026-10-18 的 a 是 `due`；今天 10-17 不出。今天 10-17、contains a、`hasPeriod` true：`retention` 0.8 時不出（用 0.9，10-18 才到期）；`retention` 0.95 時是 `exam-due`（用 0.95 不是 0.9：間隔 round(0.93) → 1 天，到期 10-17）。

**T2 recall 的順序**：今天 2026-11-14，a＝情境 A、b＝情境 B，同樣重要：兩個都到期，順序 a、b。把 b 改成「重要性：高」：順序 b、a。
