# 試作場

回答「討論難以回答、試一次就知道」的問題，例如畫面的樣式和手感（[D-065](../docs/decisions.md#d-065-試作場)）。這裡不是產品程式。

> **2026-10-20 起停用**（[D-110](../docs/decisions.md#d-110-v1-外掛的程式結構)）：v1 正式程式開始寫，之後的測試直接在正式外掛裡做。試作外掛不再維護；`tools/decisions-index.mjs` 與 T4 的製卡試用小程式照常用，等正式外掛有同樣的功能再換。

只在這裡做測試時，讀這一頁和該任務連到的說明（操作方式、結果紀錄）就好；需要決定的細節時，再查連結的文件。

## 規則

- **開工提醒**：每次開始在這裡工作時，先看下方測試清單有哪些「待做」，主動向使用者提起；使用者不會記得要自己提。

- 每個測試先寫一句「要回答哪個待決問題」；回答不了的不做。
- 誰來測依 [AGENTS.md](../AGENTS.md)：AI 能測的由 AI 測，iPhone 的測試集中成一次。
- repo 是公開的：這裡只放自己編的內容。真實教材與學生資料只放測試 vault。
- 結果在測試清單只留結論與剩下的事；輪次、數字與限制記在該任務的紀錄（資料夾裡的 README，或[製卡規則試用紀錄](../docs/card-rules/trials.md)），操作說明跟著程式放。能定案的才寫進 [decisions](../docs/decisions.md)。

## AI 怎麼測

| 對象 | 做法 |
|---|---|
| 樣式稿 | 在 app 內建的瀏覽器開，用 iPhone 尺寸（375×812）看淺色與深色；檢查版面、按鈕與主控台錯誤 |
| 排程、語法解析這類純邏輯 | 寫 Node 小程式檢查 |
| Windows 版 Obsidian | 在這台電腦開測試 vault，用遠端偵錯下命令、截圖、模擬手機尺寸與手指滑動（[`tools/obsidian-cdp.mjs`](tools/obsidian-cdp.mjs)）；要先把使用者開著的 Obsidian 關掉，先問過再關 |
| iPhone | 外掛自動量測，把結果寫成測試 vault 裡的檔案，經 iCloud 傳回電腦後讀取 |

工具備忘（省得下次重新摸索）：

- 樣式稿沒有 `<!doctype>`，因為發布成 Artifact 時會自動包上。本機測試時先包一層 doctype，再用 `python -m http.server` 提供給內建瀏覽器。
- 內建瀏覽器的面板隱藏時，截圖會抓到舊畫面，動畫和計時器也會變慢；功能與對比用 JavaScript 檢查就好。
- 要截圖時改用 Edge 無頭模式：`msedge --headless=new --screenshot=… --window-size=375,812 --user-data-dir=<暫存資料夾>`。它的視窗最小寬度約 500px，要先把 `html` 的寬度設成 375px 再截。
- 一次比較很多狀態時，做一頁並排的 iframe（每格 375×812，用網址參數設定深淺色、版面與點擊步驟），用 Edge 無頭模式加 `--virtual-time-budget=6000` 截成一張對照圖。內建瀏覽器的截圖放在 `browser_batch` 裡常逾時，單獨呼叫才穩。

### T1 複習畫面樣式｜完成

- 問題：哪種樣式讓學生複習時一直覺得舒服？（[D-058](../docs/decisions.md#d-058-複習畫面的樣式)）
- 結論：安靜樣式，自評按鈕不顯示間隔（[D-070](../docs/decisions.md#d-070-複習畫面採用安靜樣式)）。之後的修改都接到 T5 的樣式稿，目前應參照哪份見[樣式稿說明](mockups/README.md#目前應參照)。
- 過程與 AI 測試結果：[樣式稿說明的 T1](mockups/README.md#t1-複習畫面樣式)。

### T2 複習畫面原型｜完成

- 問題：React 與 Preact 的啟動時間、翻卡與滑動手勢的動畫、能否藏起 Obsidian 的上下欄、卡片裡的圖片、公式與音檔（[D-051](../docs/decisions.md#d-051-複習畫面用-react)）。另測回看上一張的左右滑動會不會打開 Obsidian 側欄、會不會和長答案的上下捲動混淆（[D-084](../docs/decisions.md#d-084-回看上一張與滑動手勢)）。顯示答案的模糊效果沒有採用（D-096），不必量。
- 照 T5 選定的畫面做：[入口與顯示答案樣式稿](mockups/entry-and-reveal.html)第 16 版（[樣式稿說明](mockups/README.md#目前應參照)）。
- 誰測：AI 測 Windows；iPhone 由使用者最後確認，和 T3 一起做。
- 做法：[試作外掛](plugin/README.md)（Codex 照[任務說明](plugin/TASK.md)寫，Claude 檢查），React、Preact 兩個建置；T3 的連續複習 15 分鐘與三年份紀錄也做在同一個外掛裡。要量什麼、💡 通過門檻、iPhone 測試清單都在試作外掛說明。
- 結論：iPhone（2026-10-19）全部過門檻：第一次打開 React 40 ms、動畫掉格 ≤ 4.2%、全螢幕蓋住 Obsidian、側欄一次都沒被滑開 → 維持 React、全螢幕並攔截觸控、往左滑一次一張（[D-109](../docs/decisions.md#d-109-複習畫面原型的實測結論)）。數字見[結果紀錄](plugin/README.md#結果紀錄)。

### T3 實機驗證｜完成

- 問題：在測試 vault 測離線作答、兩端同時修改、附件與單一檔案救回；確認 `紀錄/` 裡的 `.jsonl` 檔能正常同步，iPhone 不會因為 iCloud 移除本機檔案而讀不到（[D-035](../docs/decisions.md#d-035-複習紀錄格式)）。
- 做法：可沿用 2026-10-07 原型的「五分鐘驗收」清單（`git show a5b7c5f^:experiments/obsidian-ui-probe/README.md`）。
- 加測（使用者同意，D-074）：在 iPhone 連續複習 15 分鐘，約每 10 秒自評一次，每次自評立刻在背景寫進當月的 `.jsonl`；看畫面是否一直順暢，iCloud 同步是否正常。外掛可以自動按，量測結果寫進測試 vault。
- 加測（使用者同意，[D-105](../docs/decisions.md#d-105-回測要用的紀錄先收好)）：AI 產生三年份的假紀錄（每天約 150 次作答，約 16 萬行、72 個月檔，含少量變更行），放進測試 vault，量 iPhone 第一次讀全部紀錄（沒有快取）要等多久，以及之後只讀當月的時間；電腦上 AI 自己量。
- 誰測：iPhone 與兩端同步需要使用者；和 T2 的 iPhone 部分集中成一次。兩項加測由[試作外掛](plugin/README.md)自動量測。
- 結論（2026-10-19）：離線連續複習 15 分鐘、離線重開、恢復連線後同步都通過，紀錄一行不少；iPhone 讀三年份紀錄 0.24 秒、當月 5 ms。兩端離線改同一篇筆記會遺失一邊、裝置代碼要存本機（記入 [backlog](../docs/backlog.md#其他待決)）。附件已由 T2 的範例卡驗證；單一檔案救回在電腦用 Git 做，不需要 iPhone，留到寫 v1 時一起處理。

### T4 API 模型實測｜待做

- 問題：轉錄、製卡與錯題分析的預設模型各用哪一個？轉錄稿夠不夠準，只用轉錄稿製卡的品質如何？（D-076）（[D-072](../docs/decisions.md#d-072-ai-服務的推薦與設定方式)、[AI 模型推薦](../docs/ai-models.md)）
- 現況：轉錄用 GPT-6 Sol、製卡用 GPT-5.6 Terra，只用轉錄稿製卡可行（[D-085](../docs/decisions.md#d-085-首選-openai-gpt-56-terra)）。剩下：錯題照片（照 [D-113](../docs/decisions.md#d-113-錯題整頁拍題號選填)：使用者把 2～3 張字跡潦草的真實考卷整頁拍，放進測試 vault；比較 Terra 與 Sol 讀手寫的準確度、量實際 token）、Mistral 的其他模型（Large 不在免費方案，改測 Medium 或 Small）。
- 程式與操作：指令、正式格式的製卡流程、`check-syntax.mjs`、一般知識的參數與誰測，見 [T4 說明](t4/README.md)；程式規格見[任務說明](t4/TASK.md)，由 Codex 撰寫。提示詞（`t4/prompts/`）與模型清單（`t4/models.json`）由 Claude 維護。教材與結果都只放測試 vault。

- 評比轉錄時要打開每一張裁切的圖看，不能只看數量。
- 紀錄：模型選型（第一～三輪）在 [T4 說明](t4/README.md#模型選型結果紀錄)；第四輪起改測製卡規則，在[製卡規則試用紀錄](../docs/card-rules/trials.md)。

### T7 Jev 判斷模型｜待做

- 問題：Jev（TypeSafe AI 的判斷模型，只回答是／否機率與評分、不寫字）能不能接手 T4 的逐題品質檢查，讓 Claude 只看被標出的題目？能不能替學習目標排序，讓外掛照分數截斷上限（[backlog](../docs/backlog.md#其他待決)的目標上限問題）？夠準的話，再評估放進外掛當選用的「草稿品質提醒」。評估見專案的 `JEV-影響評估.md`（2026-10-18）。

### T8 每日時間上限模擬｜完成

- 問題：每日時間上限（全部科目加起來）預設 15 分鐘夠不夠？要不要改成 30、最多開到 90？（設定頁討論，[D-102](../docs/decisions.md#d-102-學生也能調每日時間上限)、[D-018](../docs/decisions.md#d-018-成功標準與驗證情境)）
