# 試作場

回答「討論難以回答、試一次就知道」的問題，例如畫面的樣式和手感（[D-065](../docs/decisions.md#d-065-試作場)）。這裡不是產品程式；開始寫 v1 正式程式後就停用。

只在這裡做測試時，讀這一頁就好；需要決定的細節時，再查連結的文件。

## 規則

- 每個測試先寫一句「要回答哪個待決問題」；回答不了的不做。
- 誰來測依 [AGENTS.md](../AGENTS.md)：AI 能測的由 AI 測，iPhone 的測試集中成一次。
- repo 是公開的：這裡只放自己編的內容。真實教材與學生資料只放測試 vault。
- 結果在測試清單記一行；能定案的才寫進 [decisions](../docs/decisions.md)。

## AI 怎麼測

| 對象 | 做法 |
|---|---|
| 樣式稿 | 在 app 內建的瀏覽器開，用 iPhone 尺寸（375×812）看淺色與深色；檢查版面、按鈕與主控台錯誤 |
| 排程、語法解析這類純邏輯 | 寫 Node 小程式檢查 |
| Windows 版 Obsidian | 在這台電腦開測試 vault 測 |
| iPhone | 外掛自動量測，把結果寫成測試 vault 裡的檔案，經 iCloud 傳回電腦後讀取 |

工具備忘（省得下次重新摸索）：

- 樣式稿沒有 `<!doctype>`，因為發布成 Artifact 時會自動包上。本機測試時先包一層 doctype，再用 `python -m http.server` 提供給內建瀏覽器。
- 內建瀏覽器的面板隱藏時，截圖會抓到舊畫面，動畫和計時器也會變慢；功能與對比用 JavaScript 檢查就好。
- 要截圖時改用 Edge 無頭模式：`msedge --headless=new --screenshot=… --window-size=375,812 --user-data-dir=<暫存資料夾>`。它的視窗最小寬度約 500px，要先把 `html` 的寬度設成 375px 再截。

## 測試清單

### T1 複習畫面樣式｜完成

- 問題：哪種樣式讓學生複習時一直覺得舒服？（[D-058](../docs/decisions.md#d-058-複習畫面的樣式)）
- 第一版有紙卡、安靜、明亮三種樣式（在 git 歷史 `d2d724c`）。和舊外掛的複習視窗相比：粗體與圖片正常顯示；改成全螢幕，按鈕放在拇指按得到的下方；路徑不顯示 `#`，也不顯示英文卡片類型；加上進度條；背面附出處連結。
- 結果：2026-10-12 使用者選「安靜」，自評按鈕不顯示間隔（[D-070](../docs/decisions.md#d-070-複習畫面採用安靜樣式)）。[樣式稿](mockups/review-styles.html)只留安靜樣式，並加上中→英拼字卡（D-066）、理解題重點的標示（D-068）、新卡的「新」標籤（D-069），完成畫面改成「今天複習了 N 張」。使用者看過後：黃色螢光筆太花，改成粗體加紫色細底線；路徑加上年級（科目 › 年級 › 單元）。
- AI 已測（2026-10-12，寬 375px）：深淺色 × 中英文 × 5 張卡的正反面與完成畫面，流程、文字對比（WCAG AA）、版面都正常；拼字比對不分大小寫、忽略前後空白，能標出漏打、打錯、多打的字母；點拼字卡本身不會翻面，Enter 可確認；畫面上沒有「答錯」「失敗」。
- 工具備忘補充：Edge 無頭模式在 Windows 上 `--dump-dom` 沒有輸出，測試結果改在內建瀏覽器用 JavaScript 讀。
- 待補進樣式稿（下次改樣式稿時一起做）：完成畫面改成「今天的份完成了！」加「再複習一些」（D-071）；加上「復原上一張」（D-074）。

### T4 API 模型實測｜待做

- 問題：轉錄、製卡與錯題分析的預設模型各用哪一個？轉錄稿夠不夠準，只用轉錄稿製卡的品質如何？（D-076）（[D-072](../docs/decisions.md#d-072-ai-服務的推薦與設定方式)、[AI 模型推薦](../docs/ai-models.md)）
- 做法：同一份提示（製卡規則加教材）送給 Gemini 3.8 Flash、Gemini 3.5 Flash-Lite 與 OpenRouter 的一個免費模型。教材是一節自然課本（2～4 頁）與 2～3 題錯題照片；教材與結果都只放測試 vault。Gemini 的免費和付費是同一個模型，測免費的就知道付費的品質。
- 轉錄：同一節課本由 Gemini 3.8 Flash 與 3.5 Flash-Lite 各轉錄一次，對照原頁計算錯字與漏掉的圖表；再分別用「原頁加轉錄稿」和「只有轉錄稿」製卡，比較差多少。
- 誰測：AI 寫小程式送出，檢查格式、繁體與台灣用語、和課本不符的地方、錯題的手寫字與錯因，先打一輪 ✅✏️❌。使用者要做三件 AI 做不了的事：申請 Google AI Studio 與 OpenRouter 的金鑰（開帳號、處理金鑰只能本人來）；把教材放進測試 vault（教材在使用者手上，有版權不能進 repo）；最後從前兩名裡挑一份，看的時候不標模型名稱（哪一份比較好審要由家長判斷）。

### T5 顯示答案的方式｜待做

- 問題：答案用什麼方式藏起來、怎麼揭曉，畫面最簡潔又不容易按錯？（D-070 的延伸）
- 使用者 2026-10-13：喜歡舊外掛的眼睛圖示，覺得比「顯示答案」文字簡潔；另提議把答案霧化，點了才顯示；之後做幾種樣式稿挑選。
- 樣式稿比較三種：
  - A：「顯示答案」文字按鈕（目前的樣式稿）
  - B：眼睛圖示
  - C1：霧化真正的答案加眼睛圖示
  - C2：霧化「和答案一樣長的假文字」加眼睛圖示
- 💡 共同要求（助理提案）：
  - 觸控範圍是整個答案區，圖示只是視覺。
  - 答案區先留好位置，揭曉時按鈕不移位。
  - 字數提示可以保留：使用者 2026-10-13 認為「答案是 3 個字 → 努力想 3 個字 → 想到了 → 很開心」也是主動回想，還能強化動機。助理同意字數是一種提示下的回想。
  - 但要避免透露字形：真的答案模糊後，英文字的高低輪廓認得出來，學生是「認出來」而不是「想起來」，考試時沒有這個輪廓（原則 1）。所以比較 C1 與 C2，看 C2 是否兼顧字數提示與不透露字形。
  - 揭曉動畫用透明度淡入，不做模糊半徑的動畫。
- 效能：一張卡只模糊一小塊區域，由瀏覽器交給顯示晶片處理，對 iPhone 負擔很小。真正費力的是「模糊半徑的動畫」與「整個畫面的背景模糊」，兩者都不採用。T2 原型一起量。
- 誰測：AI 做樣式稿並檢查淺色與深色；使用者挑選。
