要回答的問題：多一格空白、全形字這些平常的打字習慣，會不會改變出處的讀法？換一種讀法能不能解決？

## 三種讀法的公平比較

使用者 2026-11-02 要求：不能因為工程量決定不重寫，要客觀比過。`readers.mjs` 有現在的讀法、小修版、重寫版（和一個學期跟著前面走的變體），`compare.mjs` 用獨立 agent 出題、依真人讀法標答案的考卷評分。

**標準在看考卷之前定好，工程量不列入**：

1. **歸錯單元**（多算沒提示＋漏算沒提示）：重寫版不能比小修版多。這一項最重要，歸屬會影響考試範圍。
2. **默默丟資料或要家長白改**（位置默默丟、位置默默錯、要家長改）：重寫版的總數比小修版少兩成以上。
3. 兩項都成立就採用重寫版；第 1 項輸了不採用；第 1 項沒輸但第 2 項不到兩成，交給使用者看逐題差異。

**限制**：題目是 AI 模擬的家長，不是真實資料；第 1 次跑的結果才算公平，之後改程式再跑都要標明。提示只在試作裡模擬，沒有接 Obsidian。

Codex 第二輪查出這份標準有漏洞（提示被當成免責、`key` 由考生決定），所以第一份考卷的分數不定勝負，只當開發集。

## 第二次比較（`judge.mjs`，定稿在第二份考卷出題之前）

比的是 `readers.mjs` 的現在（不做）與小修、`readers-merged.mjs` 的合併版、`readers-fable.mjs` 的 Fable 定稿。使用者 2026-11-03 同意這個做法。

**考卷**：一個沒看過任何讀法的 agent 出題並標答案，另一個只拿到字串的 agent 再獨立標一次；兩份不同的題標成「有爭議」，兩種讀法都算對，另外報。

**第 0 關，機械的安全（要 0）**：索引與材料不能改歸屬（清空、順序反過來、多幾個單元、加像編號的標題、加和原文相同的標題）；同一個意思加打字雜訊，歸屬與位置不變；建議寫成標準字，讀回來同一個意思。

**第 1 關，歸屬**：提示不免責。分開報默默多算、默默漏算、提示但已多算、按套用才歸錯，以及放著提示不管還缺單元的題數。

**第 2 關，家長**：每題走到一條路：沒提示就對、提示但已讀對、提示後按一下就對、提示後要手改、提示本來就該（自由文字）、沒提示位置錯、沒提示歸屬錯、按套用才歸錯。「按一下」是模擬：所有讀法都用同一個建議引擎（Fable 定稿），只先填索引裡有或原文明寫的單元；真正的表單還沒做。

**判定**（工程量不列入）：

1. 合併版比小修好：第 1 關的默默多算加默默漏算不比小修多，而且沒提示就對多兩成以上。
2. Fable 定稿比合併版好：第 0 關沒有修不掉的違反，第 1 關四項加起來不比合併版多，而且沒提示就對比合併版多。
3. 第 1 關和第 2 關互有勝負：不自動判，把逐題差異交給使用者決定。

**限制**：題目與標答都是 AI 模擬的，不是真實家長；出題的 agent 仍會在系統背景裡看到專案規則與近期 commit 標題；表單沒做，家長會不會細看沒有資料；合併版的作者看過第一份考卷與所有攻擊字串。
